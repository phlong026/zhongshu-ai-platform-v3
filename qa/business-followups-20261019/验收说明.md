# 业务模块调整与审批规则验收

状态：通过。2026-10-19，本轮业务、设计流程按用户最新确认的审批规则实施；工程界面的并行调整由另一任务负责。

## 页面与设计业务

- 首页使用暖色待办区、白色任务卡片，标题改为“今日待办”。三个统计数字跳转到对应客户集合，常用功能顺序为内容创作、方案设计、报价测算、登记客户。
- 创作结果直接进入发布设置，在发布时选择账号。发布后必填作品链接，标题、文案、话题、封面、账号、人员、作品和发布时间自动关联，保留待回采来源。来源继续带入咨询、线索和客户。
- 设计首图采用右侧完整图片、左侧标题及按钮，四项入口为灵感库、AI平面、AI立面、快速预算，标题为“精选灵感”，删除重复底部入口。
- 参考 [zhongshu-home-design](https://github.com/phlong026/zhongshu-home-design) 的前端交互，核对版本为 `138bae1976f61e5c9a5cefd3f37197425a31fa32`。复用本项目界面和业务记录，未引入参考仓库后端。
- 8条模拟灵感覆盖一至三层、两种风格，每个楼层均有示意平面；编号、名称、风格、层数及尺寸筛选可用。按±1米匹配近似尺寸，选择参考案例后保留客户目标尺寸及参考版本。
- AI候选数量和保存的楼层数量按实际参数处理。平面、立面、参考案例、预算、正式报价均保留同一客户关联。
- 基础、结构、屋顶、外装开关实际参与模拟预算计算，保存分项、数量、单价和价格版本。预算结果可以继续实测报价，再办理老板审批和合同。
- 客户、预约、待办、草稿、视频作品和三条参考链接已有模拟数据；初始化不会覆盖已有记录。收藏按实际人员隔离。

## 已确认的审批规则

完整规则见 [业务审批规则](../../docs/业务审批规则_20261019.md)。

| 事项 | 当前处理 |
| --- | --- |
| 正式报价、合同金额、服务费、首尾款及材料付款 | 老板审批当前版本金额及依据。合同必须绑定已批准报价；服务费获批后才产生付款事项，每期付款仍由老板审批 |
| 正式设计、施工图、设计变更 | 设计师发起，设计负责人审核。总部参与设计人员回避本版；加盟商在后台分别配置两岗位，可同一实际人员兼任 |
| 变更金额及变更正式文件 | 技术由设计负责人审核，金额由老板审批；双方协议后，设计师提交变更正式文件，设计负责人审核后才可登记客户签认 |
| 客户成果签认 | 上传真实客户凭据、核对日期和版本后保存生效，无内部二次确认；已签认版本只读 |
| 施工阶段验收及复验 | 工程人员和负责人同人配置直接生效；分人配置进入负责人的独立验收待办，未通过不能完成节点 |
| 施工交付 | 施工和交付资料齐备后直接交付并可归档，无单独交付核验 |
| 退款、金额更正、付款结果不明核实 | 本轮关闭入口、待办和执行接口，保留历史记录 |

本店配置设计师和设计负责人后，新需求使用本店设计团队；未配置时延续总部设计。已经提交的需求不自动改换设计组织。本店实际设计费用需要登记实际收款人，经老板审批及财务核对，不生成本组织对本组织的往来到款。既有服务约定缺少新版老板审批时，历史实际付款仍保留在账簿中，老板可以审批原约定后继续后续付款，不能因新版规则丢失历史收付款展示。

## 测试账号与流程

在“我的→登录”中选择“业务兼岗人员”，使用同一人员切换业务员、业务负责人完成主测试。金额事项切换“赵老板”；门店财务、总部财务、工程人员分别使用各自兼岗账号。总部设计师与设计负责人仍按独立审核规则办理。

主链已经从参考视频二创、生成作品、直接发布和链接登记，连续走到咨询分配、本人接收、跟进转客户、AI方案、预算、实测报价、老板审批、合同签署、服务费审批、首尾款支付及总部实际到账、设计派单与审核、正式下发、客户一次签认、施工图审核、工程接收、实际开工、三节点材料和验收、直接交付及归档。

“我的→全流程模拟演示”保留134个阶段，含当前主链、分人阶段验收、设计变更和其他既有模块的示例入口；268个前后状态页面均可打开。连续案例不会在切换岗位时替换业务数据。阶段演示明确载入该阶段的模拟前置状态，并提供恢复原数据入口。
