## 4. 问题清单

### P1-1 列表接口返回空壳对象（主项目，最高优先级）

`CustomerController.java:51-53`、`CommissionController.java:97-100`

```java
return success(BeanUtils.toBean(customerService.page(...), Customer.class));
```

`BeanUtils` 底层是 hutool `BeanUtil.toBean`，目标类型是 **record**（`CrmRespVos.Customer`）。record 没有 setter，hutool 静默跳过所有字段。我用项目真实类实测：

```
DO             = 123 / 张三 / 13800000000
toBean(record) = Customer[id=0, name=null, phone=null, ... ownerUserId=0, revision=0]
of(DO)         = Customer[id=123, name=张三, phone=13800000000, ... ownerUserId=9, revision=3]
page list      = [Customer[id=0, name=null, ...]]      ← 接口真实返回
```

**影响**：`GET /franchise/customers` 和 `GET /franchise/commissions` 会返回正确条数的空行，小程序列表页全是空白卡片。`total` 对、`list` 全废，前端排查会很痛苦。M2.7 接线第一天就会撞上。

**建议**：两个列表都改成显式映射（同文件详情接口已经这么写了）：

```java
return success(CollectionUtils.convertPage(page, Customer::of));
```

一行一个，改完建议补一条断言 `page.getList().get(0).id() != 0` 的单测——这类"编译过、字段全空"的错只能靠断言抓。

### P1-2 小程序登录后永远不带 `X-Post-Id`（v3）

`miniprogram/api/auth.js:35-39`

```js
if (result.posts && result.posts.length) { http.saveSession({ postId: result.posts[0].postId }); }
```

后端 `WechatLoginRespVO` 只有 `needPhone / userId / accessToken / refreshToken / expiresTime` 五个字段，**没有 `posts`**。所以 `saveLogin` 里的岗位选择是死代码，登录后 `zs-api-post-v1` 永远为空，`http.js` 不发 `X-Post-Id`，随后所有 `/franchise/**` 都会被 `CurrentPost.require()` 拒掉。

**建议**：登录后显式串一次 `myPosts()` → 选岗位 → `switchPost()`，或让后端登录响应直接带上 `posts`。README §接入顺序里其实写的是前者，是 `saveLogin` 的实现偏离了文档。

### P1-3 401 分支不会触发（v3）

`miniprogram/api/http.js:53`

```js
if (res.statusCode === 401) { clearSession(); ... }
```

后端 `AuthenticationEntryPointImpl.commence()` 调的是 `ServletUtils.writeJSON(response, CommonResult.error(UNAUTHORIZED))`，而 `writeJSON` 只写 body、**不设 HTTP 状态码**，所以响应是 **HTTP 200 + body.code=401**。这个分支永远进不去，token 过期时用户看到的是"请求失败（HTTP 200）"，会话不清、也不跳登录页。

**建议**：判定改成 `if (res.statusCode === 401 || (body && body.code === 401))`。

### P1-4 我的任职列表会返回 null 元素且 N+1（主项目）

`MyPostController.java:44-49`

```java
posts.stream().map(post -> staffPostService.findActivePost(userId, post.getId())
        .map(StaffPost::of).orElse(null)).toList()
```

- `listActivePosts` 已经筛出有效任职，再逐条 `findActivePost` 是**同一份数据查两遍**，岗位多的员工是 N+1。
- `orElse(null)` 会在 JSON 数组里留下 `null` 元素（`Stream.toList()` 允许 null），前端 `posts.map(p => p.postId)` 直接 TypeError。
- 两次查询之间如果任职被撤销，就会掉进 `null` 分支。

**建议**：`flatMap(...).toList()`，或给 `StaffPostService` 加一个批量 `listActiveSnapshots(userId)` 一次查完。

### P2-1 待办计算的 N+1 与重复查询（主项目）

`FranchiseTodoProvider.java:85 / 110 / 176 / 194`

- `:85` 和 `:110` 各自调一次 `commissions.listVisible(post)`，**同一个全量查询跑两遍**。
- `:176` 每个"移交已提交"的委托查一次 `selectByCommission`。
- `:194` 每个"费用待审批"的委托查一次 `selectByCommission`。

老板账号下委托上百条时，首页每刷一次就是几百次查询。待办是首页首屏接口，对延迟最敏感。

**建议**：`listVisible` 结果在方法内算一次传下去；子表按 `commissionId IN (...)` 批量捞一次在内存里分组。

### P2-2 模板 milestone 靠中文名判定（v3）

`miniprogram/utils/engineering-records.js:24`

```js
milestone: name === '主体封顶' ? 'topping' : ''
```

功能说明写的是"账簿可存公司自有模板"，但只要公司把封顶节点改名（"结构封顶"），`assert(rows.some(n => n.milestone === 'topping'))` 立刻抛"模板缺少主体封顶节点"，自有模板**完全不可用**。`prepare` 分支 `:51` 还有同一处硬编码。

**建议**：milestone 变成模板字段（`{name:'主体封顶',days:15,milestone:'topping'}`），判定只看字段。

### P2-3 默认模板返回的是模块级数组引用（v3）

`miniprogram/utils/engineering-records.js:21-22`

`scheduleTemplates()` 在无自有模板时返回 `nodes: TEMPLATE`，`TEMPLATE` 是模块级常量。调用方一旦原地改节点（比如"生成后逐项调整"直接改数组元素），会**永久污染本进程内的默认模板**，后续项目全部继承被改过的日期规则。

**建议**：返回前 `nodes: TEMPLATE.map(n => ({...n}))`。

### P2-4 财务岗位的待办恒为空（主项目）

`FranchiseTodoProvider` 只处理销售线（客户/客资）与委托状态机，没有任何 `finance` 分支。财务登录后 `/platform/todos` 返回空数组，前端无法区分"今天真没活"和"这块还没做"。财务的收款登记/费用核实本来就是 M2 主链的一环。

**建议**：要么补 `finance` 线待办（至少"待登记收款"），要么在 `TodoList` 里明确表达"本域暂未覆盖财务"，别让空列表被当成没事。

### P2-5 费用进度接口仍无调用方校验（上轮遗留，重申）

`CommissionService.markProgress()` 仍只校验版本号，不校验 actor 是否财务岗位、不校验委托状态。`design-complete` 以 `firstReadyAt` 为前置——这是"钱没到不能开始设计"的唯一闸门，`DesignFeeProgressApi` 却是无锁后门。**M3 财务接入前必须补。**

### P2-6 并发登记客资的错误码仍误导（上轮遗留，重申）

`LeadService.java:84-86` 捕获唯一索引冲突后仍抛 `STATE_VERSION_CONFLICT`（"数据版本已过期"），而正确语义是 `LEAD_DUPLICATE`（就在 `:66`）。业务员看到"版本过期"会反复重试，正确动作是去处理待关联客资。
