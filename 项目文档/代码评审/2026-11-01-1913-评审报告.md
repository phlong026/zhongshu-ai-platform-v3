#### P2-2 钱包发卡在事务内做微信外部 HTTP 调用

- **文件**：`平台程序/domains/franchise/franchise-org/src/main/java/cn/iocoder/yudao/module/franchise/org/wallet/WalletSessionService.java:49`（`@Transactional`）→ `:63`（`exchangePayerOpenid`，内部 `wechatPaySessionPort.exchangeForPay` 走 HTTP）

#### P2-8 `platform-bridge.js:210` 三元与 `||` 优先级错误，任何错误都被报成「生成中」

- **文件**：`zhongshu-ai-platform-v3/miniprogram/pages/workflow/explore/platform-bridge.js:210`
- **现象**：`this.platFail(String(...).indexOf('未终态') >= 0 || (err && err.code) ? PF.STILL_RUNNING_MESSAGE : PF.errorMessageDesign(err))`。`||` 优先级高于 `?:`，条件实为 `(indexOf>=0) || (err && err.code)`。几乎所有错误对象都带 `code`（`-1`/`403`/`500`），条件恒真。
- **影响**：AI 生成链路的错误一律显示「仍在生成中」，403（无权限）、500、网络失败全部被掩盖，用户永远等不到真实原因。
- **建议**：改为 `const stillRunning = String(err && err.message || '').indexOf('未终态') >= 0;` 然后 `this.platFail(stillRunning ? PF.STILL_RUNNING_MESSAGE : PF.errorMessageDesign(err));`

#### P2-9 切岗时钱包错误码退化为 `WALLET_UNAVAILABLE`，`WALLET_STALE` 契约失效

- **文件**：`zhongshu-ai-platform-v3/miniprogram/api/wallet.js:58`（`bridgeSession`）、`:97`（`if (!token) throw WALLET_UNAVAILABLE`）、`:98`（`if (fingerprint() !== state.fp) throw stale()`）
- **现象**：`bridgeSession` 拿到新 token 后调 `saveWalletSession(data.token, fp)`，而 `saveWalletSession` 在 `fingerprint() !== fp` 时**静默 return 不落缓存**，接着 `return cachedSession()` 返回 `''`。`walletRequest` 的 `.then` 里 `!token` 判断在 `fingerprint() !== state.fp` 判断**之前**，于是抛 `WALLET_UNAVAILABLE`。
- **影响**：09 文档 §五-2 与 `recharge/index.js` 注释都要求「切岗 → 抛 `WALLET_STALE` → 消费者静默终止」。实际这条路径给的是「钱包功能未开通」，充值页会走 `loadState:'unavailable'` 并可能给用户一个「未开通」的错误暗示，而不是静默放弃。防护的**行为**没错（没继续支付），但**错误码语义**错了，且后续按 `isStale` 分支的处理全部走不到。
- **建议**：把 `:98` 的 stale 判断提到 `:97` 之前（先判身份切换、再判可用性）；或在 `bridgeSession` 中 `saveWalletSession` 失配时直接 `throw stale()`。
