## 3. 数据模型(前缀 `fr_`,均带 `company_id`)

| 表 | 要点 | 组织范围登记 |
|---|---|---|
| `fr_customer` | 归属组织、团队、负责人(owner_user_id)、称呼、手机号、需求、来源、revision;同组织同手机号唯一 | company_id |
| `fr_lead` | 每次咨询一条:登记人、来源、关联客户、关联方式(NEW_CUSTOMER / EXISTING_CUSTOMER) | company_id |
| `fr_follow_up` | 客户跟进:内容、下次回访日期、作者 | company_id |
| `fr_design_fee_policy` | 门店标准设计费用:版本、总额、首款、交付范围、总部收款方、启用、老板 | company_id |
| `fr_commission` | 设计委托:客户、经办业务、设计组织(总部)、阶段 phase、需求版本、费用(总额/首款/尾款/收款方/范围)、服务版本、授权方式、完成/下发/移交/接收字段、revision;一个客户只有一条进行中的委托 | company_id, design_org_id |
| `fr_commission_feedback` | 下发后的修改意见 | company_id |
| `fr_design_payment` | 门店付款登记:期次、服务版本、金额、日期、流水号、凭证、状态、登记人、复核人、复核方式 | company_id, design_org_id |
| `fr_design_receipt` | 总部到账登记:对应门店付款、金额、日期、流水号、凭证、状态、登记人、核实人 | company_id, store_company_id |

金额一律以分存 BIGINT。附件(凭证、成果、施工图、审核依据、客户确认)存 yudao 文件上传返回的地址。

## 4. 委托阶段

```
提交 ──┬─ 匹配标准费用 ─────────────▶ DESIGN
       └─ 不匹配 ─▶ FEE_APPROVAL ─批准─▶ DESIGN
                         └─退回─▶ FEE_RETURNED ─修改重提─▶ …
DESIGN ── 首款两边足额 + 设计行政「设计完成」 ─▶ DESIGN_DONE
DESIGN_DONE ── 尾款两边足额 + 设计行政「成果已下发」 ─▶ DISPATCHED
DISPATCHED ── 业务登记修改意见 ─▶ DESIGN(保留首尾款,已完成的设计记录留历史)
DISPATCHED ── 业务「收图并移交」(五项资料 + 指定工程负责人) ─▶ HANDOVER_PENDING
HANDOVER_PENDING ── 工程负责人退回 ─▶ HANDOVER_RETURNED ─补齐重提─▶ HANDOVER_PENDING
HANDOVER_PENDING ── 工程负责人接收 ─▶ ACCEPTED
```

付款条件(对应 `transfers-v2.js` 的 `condition`):`paid` = 本期已复核付款合计,`received` = 本期已核实到账合计;两者都 ≥ 本期应付才算满足。修改意见后重新完成、重新下发,不重新产生首尾款。

## 5. 命令与权限

所有命令:带 `revision`(委托、客户)做乐观锁;成功后写 `pf_command_event`;控制器用 `@post.has(...)`。

| 命令 | 权限码 | 谁 | 关键规则 |
|---|---|---|---|
| 登记客资 | `franchise:customer:create` | 业务员(含业务负责人) | 归属取当前岗位;同组织同手机号已有客户则关联原客户、保留原负责人;否则新建本人客户 |
| 记录跟进 | `franchise:customer:follow` | 客户负责人;管理该团队的业务负责人 | 内容必填 |
| 查询客户 | `franchise:customer:query` | 业务员看本人;业务负责人看所管团队+本人;老板/门店负责人看全店 | |
| 配置标准设计费用 | `franchise:design-fee-policy:manage` | 门店老板 | 首款 < 总额;每次保存新版本 |
| 提交/修改重提委托 | `franchise:commission:submit` | 客户负责人或所管团队的业务负责人 | 已有付款不能改费用;匹配当前有效标准(总额、首款、范围、收款方一致)即预授权,否则交本店老板审批 |
| 审批委托费用 | `franchise:commission:approve-fee` | 本店老板 | 走平台审批中心:不能自批、内容变化即作废、意见必填 |
| 设计完成 | `franchise:commission:complete` | 总部设计行政 | 首款足额;确认线下设计与内部审核已完成 |
| 成果已下发 | `franchise:commission:dispatch` | 总部设计行政 | 已完成、尾款足额、无待处理修改意见;接收人、清单必填 |
| 登记修改意见 | `franchise:commission:feedback` | 经办业务 | 已下发、未移交 |
| 收图并移交 | `franchise:commission:handover` | 经办业务 | 已下发;正式成果、施工图(含版本)、审核依据、客户确认(含日期)、交底说明齐全;接收人须为本店在岗工程负责人 |
| 接收 / 退回 | `franchise:commission:receive` | 被指定的工程负责人本人 | 退回须写原因 |
| 门店登记付款 | `franchise:design-payment:register` | 本店财务(含负责人) | 委托已授权;首款在授权后、尾款在设计完成后;累计不超过本期应付;流水号本组织不重复 |
| 门店复核付款 | `franchise:design-payment:review` | 本店财务负责人 | 不能复核本人登记;本店只有登记人一名财务负责人时,登记即同人复核 |
| 总部登记到账 | `franchise:design-receipt:register` | 总部财务(含负责人) | 对应门店已复核付款;累计不超过该笔付款 |
| 总部核实到账 | `franchise:design-receipt:verify` | 总部财务负责人 | 同门店复核规则 |

## 6. 待办(TodoProvider)

| 岗位 | 待办 |
|---|---|
| 业务员/负责人 | 费用被退回待重提;设计完成后尾款未付清(跟进尾款);已下发待收图移交;移交被退回待补充 |
| 老板 | 待审批的委托费用 |
| 门店财务 | 首款/尾款待登记;(负责人)待复核付款 |
| 总部财务 | 门店已付待登记到账;(负责人)待核实到账 |
| 设计行政 | 首款已足额待「设计完成」;尾款已足额待「成果已下发」;有修改意见待重新完成 |
| 工程负责人 | 指定给本人的移交待核查接收 |

## 7. 验收

- 每条命令覆盖:正常办理、无权岗位、他组织、版本冲突;
- 同人复核与独立复核;累计超付被拒;
- 完整主链集成测试:登记客资 → 提交委托(标准与审批两种)→ 首款两边核对 → 设计完成 → 尾款两边核对 → 下发 → 修改意见 → 重新完成与下发 → 移交 → 退回 → 重提 → 接收;
- 整机端到端:经 HTTP 用多名员工走一遍主链。
