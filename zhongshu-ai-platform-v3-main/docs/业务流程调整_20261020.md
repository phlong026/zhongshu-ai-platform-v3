# 业务流程调整与角色口径（2026-10-20 用户确认版）

本文件记录本轮已确认的四项流程调整与"专员／负责人"双角色模型，是 `业务审批规则_20261019.md` 的增量口径；冲突处以本文为准。

## 一、客资与客户（取消分配/接受/退回）

- 客资登记（内容咨询或手动登记）即归**登记人本人**，状态直接进入跟进中；不存在待分配池、负责人分配、接受与退回动作。
- 同手机号再次咨询：登记时**自动关联原客户**（保留本次来源快照与原归属，不重复建档）；跨团队无法自动关联时，保留"请求负责人核对关联"一道查重控制。
- 责任转交仅用于人员变动（离岗/调岗），由业务负责人或老板在"团队管理"中办理，不进日常流程。
- 转客户门槛不变：至少一条有效跟进。

## 二、方案报价（取消现场实测）

- 报价链路：灵感库 / AI 平面 / AI 立面 / 快速预算 → **AI 生图结果** → 直接生成正式报价。
- 报价依据 = **预算参数版本 + 已选 AI 平面/立面版本**，不再有实测记录与测量资料文件。
- 正式报价须经**本组织老板审批**后用于合同；设计成果签认后如报价未绑定新版，须重新生成并重新审批（建造报价绑定已确认设计版本的规则保留）。
- 设计委托依据同步改为预算参数（现场条件仍需核实），总部受理资料核查不含测量资料；工程移交文件清单不含测量资料。

## 三、建造签约与工程移交（取消派单）

- 按已签认设计版本生成建造报价 → 老板审批 → 建造合同 → 工程移交**直达工程负责人**（移交单指定接收人）。
- 取消"项目经理派单给指定工程师"环节；接收核查、开工条件核查均由工程负责人本人办理。
- 开工前置条件 = 业务转移内容：已签建造合同、本版施工图+专业审核通过、客户成果签认、电子交底及本版资料交接。
- 实际开工前由工程负责人指派施工人员（在实际开工登记中记录技术负责人与现场人员），节点贡献记到实际执行人。

## 四、取消设计变更段

- 下线：变更申请/审批、补充协议、变更成果提交/审核/确认、补充资料交接/接收；金额审批不再有变更来源；绩效不再有变更签约来源。
- **工程接收后设计成果只读**：不再有图纸变更通道，调整走线下并在新项目/新合同中体现；签认前的"设计修改意见"回路（设计协同）保留。
- 已签合同不能从原签署入口覆盖。

## 五、角色模型：每条专业线"专员 + 负责人"

| 条线 | 专员 | 负责人 |
| --- | --- | --- |
| 业务 | 业务员 | 业务负责人 |
| 设计 | 设计师 | 设计负责人（门店可同人配置） |
| 工程 | 工程人员 | 工程负责人 |
| 财务 | 财务专员 | 财务负责人 |

- **负责人拥有本条线全部业务办理权**：可办理本团队专员的客户/项目（写入权限已按团队授权放开）。
- **专员流程完整保留**：登记、跟进、报价、验收、付款登记等一线环节均由专员办理。
- 负责人新增**团队管理与绩效**视图（业务/工程团队页）：每名专员的客户/项目进展、本月绩效来源数与考核周期状态，直达个人目标页；绩效的提交、复核、申诉、归档与结算沿用既有规则（专员由负责人复核，负责人由老板复核，金额结算审批归老板）。
