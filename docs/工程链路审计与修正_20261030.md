# 工程链路审计与修正（2026-10-30）

## 审计范围与客户画像

本轮以同一客户、同一项目从业务移交工程开始，核对工程接收、开工准备、两期收款、实际开工、节点施工、材料计划、采购金额、到货、付款、工程交付、项目结算、资料归档。目标客户为 5–20 人的中小乡墅公司：工程人员通常同时承担现场协调、材料跟催和客户催款，老板只处理例外事项，财务只登记真实收付款。

每个跳转按五项判断：入口是否就在当前事项；下一责任人是否明确；完成条件是否可见；异常是否能回原单补救；是否增加了小团队不需要的审批。

## 本轮修正方案

### 1. 材料催到货使用原计划轻量留痕

- 材料计划超过“需到场日期”且仍未到齐时，工程待办显示逾期天数和“请催到货登记”。
- 工程人员从原材料计划进入，必须填写本次联系情况，联系日固定为实际登记当天，供应商承诺到货日可选；不新建审批单，不要求老板或财务参与。
- 同一材料计划在同一天重复提交完全相同的联系说明和承诺日时返回原记录，不重复追加历史或项目版本。
- 登记后事项进入等待区；承诺日过期仍未到齐时，自动回到待办并提示再次催办；无承诺日的当日等待供应商回复，次日自动回到待办。
- 实际到货继续由原计划登记；一旦到齐，催办事项自然结束。历史催办留在原计划，便于老板和接替人员理解上下文。

### 2. 原生连续验收同步现行规则

- 删除标准工程合同的老板审批步骤，保存开工准备后直接产生已生效的两期收款约定。
- 千元级线内人工费用提交后直接生成应付，原生流程不再寻找老板审批待办。
- 交付后必须进入项目结算，核对收款、材料和费用汇总并保存说明，然后才能归档。
- 保持同一 `ENGINEERING_CONTINUATION_SOURCE`、同一客户和同一 `projectId` 继续办理，避免用独立工程样例替代真实六角色主链。
