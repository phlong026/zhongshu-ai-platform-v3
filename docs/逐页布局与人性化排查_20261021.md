# 逐页布局与人性化排查（2026-10-21）

对照成熟商业化小程序标准，对业务主链上的页面逐页实测布局，并按人性化角度给出整改意见。与《页面样式一致性检查与整改意见_20261021.md》配套：那份讲令牌与组件，本份讲逐页布局与使用体验。

## 一、方法与范围

| 项目 | 内容 |
| --- | --- |
| 实测工具 | 微信开发者工具模拟器，`scripts/audit-layout-native.cjs`（只读，复用主链数据，结束后恢复原数据） |
| 覆盖 | 110 个页面状态，去重后 58 个路由/视图；涉及业务负责人、老板、财务负责人、总部设计负责人、总部设计师、工程负责人 6 个岗位；含各岗位 5 个入口页 |
| 实测内容 | 内容是否超出屏幕宽度、可点元素尺寸、滚到底后内容是否被底部固定栏遮挡，并逐页截图 |
| 截图人工抽看 | 报价、工程移交、开工条件核查、施工节点、工程收款、业务首页、老板首页、我的，共 8 页 |
| 局限 | 模拟器选择器只认类名，取不到文字字号和颜色，字号与对比度以前一份报告的样式源码扫描为准。老板首页、管理入口等用组件渲染的页面类名覆盖不全，只能看截图。模拟器窗口宽 430px，未覆盖 iPhone SE 与小宽度安卓。未测深色模式和大字体 |

实测结果：
- 内容超出屏幕宽度：0 页
- 滚到底后被底部固定栏遮挡：0 页（底部留白处理是一致的）
- 可点元素偏小：77 页有记录，其中 61 项低于 40px，33 项在 40~44px
- 完全无问题的页面：33 个页面状态

## 二、做得好的地方

1. **办理页骨架统一**：返回、标题、"办理身份"条、客户信息卡、"当前事项/当前责任"卡、业务卡片、底部固定主按钮，业务、设计、财务、工程接收页都是同一套结构，用户不用重新学习。
2. **底部固定栏无遮挡**：110 个页面状态滚到底都没有内容被固定栏盖住，单按钮和双按钮（次要 + 主要）两种形态都稳定。
3. **无横向溢出**：所有页面没有超出屏幕宽度的内容。
4. **"当前事项 + 当前责任"**：每页都告诉用户"现在该谁办什么"，这是面向非专业用户的好设计，建议保持。
5. **表单**：标签在左、输入在右、必填星号、单位后缀（元、㎡）齐全，符合行业习惯。

## 三、主要问题（按影响排序）

### P0

1. **工程模块与业务模块像两个产品。**
   - 工程页（施工节点、工程收款、检查验收）主按钮是偏红橙色，业务页是棕色。
   - 工程页顶部有整行大描边按钮"本项目协作动作授权"，并在客户卡下堆叠两个整行描边按钮"合同收款与放行条件""提交费用与查看成本"，业务页同类入口则是右上角小文字链。
   - 工程页没有"办理身份/当前事项"条。
   - 同一个项目从业务交到工程，用户会感觉换了系统。
2. **可点元素偏小，高频操作最明显。**
   - 业务和设计页的选项分段（审核通过/退回、批准/驳回、协作角色）约 34~37px。
   - 勾选行（开工条件核查 8 项、工程接收、门店收图确认）约 36~38px。
   - 页面内小文字链（"项目收款""项目费用""复制完整项目编号""查看全部"）约 22~26px，是最小的。
   - 表单输入框约 37px，常见标准是 44~48px。
   - 工程移交页（`workflow?handover`）一页有 16 个低于 40px 的可点项，是最集中的一页。
3. **列表卡片里放整行实心主按钮。** 业务首页"待我办理"里每张卡片都有一个整行棕色实心按钮（保存成品、保存成品、跟进客户），3 张卡就是 3 个主按钮，视觉重量过重，用户难判断先办哪个。成熟做法是卡片内用右侧小按钮或整卡可点，主按钮留给页面唯一主操作。
4. **老板首页大量"0 / 待完善"。** 本月签约 0万、有效实效 0万、在建项目 0个，下面多个金额为"待完善"，加一段灰色小字说明，没有告诉老板"下一步做什么才能让数字出来"。商业产品里这类空状态要有引导和入口。

### P1

5. **页头"返回 + 工作台文字 + 标题"挤在一起**，右侧还有胶囊按钮，"工作台"小字与返回箭头重复。
6. **同一卡片套多层底色**：白卡 → 米色信息表 → 浅橙提示条，在需求与委托、老板审批、报价、工程接收页都出现，层次过多。
7. **页面过长，缺少分段导航。** 工程移交、工程收款、需求与委托都要滚动 2~3 屏才能看到全部字段，没有锚点或进度提示；只有底部主按钮提示完成，用户不知道"还差几项"。
8. **提示信息与操作混排。** 建议文案以灰色小字散落在表单中间（如"设计确认后再核算建造价"），读者容易忽略。
9. **进度表达不统一。** 开工条件核查用"已满足的绿色对勾 + 待核对的空方框"两种图标混在同一页，项目办理页用实心绿对勾列表，节点页用状态胶囊。
10. **"工作台"回到哪一级不明确。** 深层办理页只有左上角返回，没有"当前在第几步/共几步"的提示。

### P2

11. 工程页图片与文字比例：头图缩略图较小，客户名在窄栏内换行（"武汉乡/墅"被截成两行）。
12. 老板首页底部 Tab 为"首页/财务/绩效/我的"，业务首页为"首页/创作/方案/客户/我的"，不同岗位 Tab 个数不一致，图标线条粗细也不一致。
13. "我的"页面列表尾部被底部 Tab 压住一半，缺少底部安全留白（滚动到底可见，但初次进入视觉上像被截断）。

## 四、整改建议

### 立刻改（改动小、效果明显）

1. **全站可点热区统一不低于 88rpx 高**：分段选项、勾选行、文字链用 padding 扩大热区，视觉大小可不变。优先处理工程移交、开工条件核查、工程接收、审核/审批选项。
2. **页面内文字链改为"文字 + 右箭头"整行可点**（项目收款/项目费用并入"相关入口"整行）。
3. **业务首页待办卡片**：去掉卡内整行主按钮，改为整卡可点加右侧"去办理"小按钮，仅最紧急一条用主色。
4. **表单输入框高度提升到 88rpx**，与底部按钮高度一致。

### 统一风格（和样式整改一起做）

5. **工程模块换用与业务一致的主色、按钮、"办理身份/当前事项"条**；顶部的"协作动作授权"整行按钮改为页头右上角入口，两个并排的"合同收款与放行条件""提交费用与查看成本"改为一行两个次要按钮或"相关入口"整行。
6. **去掉卡内套卡**：卡片内信息表改行分隔线，提示条统一一种样式。
7. **页头只保留返回箭头与标题**，"工作台"入口放进右侧菜单。

### 体验提升

8. **长表单加分段与进度**：顶部显示"2/4 已填"，必填项缺失时按钮保持可点，点击后滚动到第一个缺失项并高亮，而不是置灰让用户猜。
9. **老板首页空状态加引导**：0 值卡片下加"去登记第一笔签约"等入口；"待完善"改成可点的具体动作。
10. **提示信息就近放**：校验提示放在字段下方，红色；建议文案放在卡片标题下方，不要混入表单中间。
11. **勾选类清单加"全部已核对"与进度（已 3/8）**。
12. **深层办理页加步骤条**（设计委托 → 首款 → 设计 → 尾款 → 移交 → 工程接收），用户知道自己在主链哪一步。

## 五、验收建议

- 重跑 `node scripts/audit-layout-native.cjs`，P0 的"可点元素低于 40px"降到 0，P1 的 40~44px 降到 5 项以内。
- 工程与业务页面主色、按钮、顶部条一致，同一项目从业务交到工程，视觉没有断层。
- 增加 iPhone SE（375px）和安卓 360px 宽度的实测，以及大字体、深色模式。
- 重跑 `npm run check:business:flow:native`，确保整改不破坏流程。
