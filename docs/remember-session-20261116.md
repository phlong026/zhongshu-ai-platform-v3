# 关闭小程序后恢复登录（2026-11-16）

用户确认问题发生在关闭小程序再打开，要求记住账号后直接登录。原来的选项只保存公开账号资料；登录响应中的 refreshToken、expiresTime 被丢弃，首页启动也没有恢复后台账号及岗位。

本次把选项明确为“记住账号并自动登录”：成功登录后保存后台续登凭据，冷启动复核本人有效任职，恢复上次岗位并进入对应工作台。密码不落盘。不勾选时凭据只在当前运行进程中保留；主动退出和“忘记账号”都会清理访问、续登凭据。旧版本丢弃的续登凭据无法恢复，因此升级后需要正常登录一次。

复用 B 已有 `POST /system/auth/refresh-token`，凭据通过表单正文提交，无 Authorization 和 X-Post-Id，不放进 URL。线上默认访问凭据 1800 秒，刷新凭据 2592000 秒（30 天），期限由后台控制；吊销、禁用及到期仍要求重新登录。本次无需修改或重启后端。

访问凭据即将过期或服务端返回 HTTP/body 401 时，单次续期并重试一次。并发续期合并；同用户续期保留岗位、会话代次。退出、换账号或切岗期间的迟到响应不能恢复旧会话。同一刷新凭据跨切岗的续期串行，避免服务端两个续期相互吊销。断网、429 和 5xx 保留凭据，允许稍后重试。钱包独立会话不参与平台续登；公开协议及登录查询不携带旧凭据。头像上传适用相同续登处理。

发布快照基于 `1.0.20261116.11`，路径 `.tools/remember-session-20261116/frontend`，仅替换五个运行文件及相关测试、检查命令，保留已有培训等功能。见 `qa/remember-session-20261116/source-manifest.json`。

- 杀进程后重载真实前端模块，仅保留模拟微信 storage，覆盖老板、员工进入原工作台、30 分钟到期、并发 401、退出、换账号、切岗、断网、钱包隔离、头像上传。
- 真实 B 接口验证使用独立临时测试账号，无任职、无加盟账号、不接触老板或员工密码。真实前端 http/auth 模块完成刷新、重载后保留凭据、服务器注销后拒绝旧刷新凭据。见 `live-refresh.json`。
