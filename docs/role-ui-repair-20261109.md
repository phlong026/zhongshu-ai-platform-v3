# 多岗位页面缺口修复与验证

承接 `role-ui-native-check-20261109.md` 中 UI-01～UI-06 的修复前发现。本轮同时修复材料入口的空项目跳转，以及成员管理的普通岗直达、切岗迟到回写问题。未恢复旧本地演示登录或业务账簿，也未新增依赖。

## 已实施

| 范围 | 修改与实际行为 |
| --- | --- |
| 资料、消息、工作身份 | 识别 API token 与当前任职，删除不存在的 auth.token 调用；九岗位三入口不再误回登录。旧设备/订单等未接入页面仍有门禁 |
| 工程、设计行政首页 | 使用 API 岗位优先分流，残留本地身份不能覆盖；从 tab 换根统一 reLaunch |
| 财务默认态 | 财务进入 desk；总部/门店默认付款/收款口径不同；显式 view/tab 保留 |
| 我的资料与入口 | 使用任职 orgName；不再显示错误的“未选择公司”。老板成员管理、团队绩效与负责人业务入口进入已实现页面，不经退役聚合页误跳财务 |
| 工程工作台 | 数值、筛选与真实 statusKey 对齐；空数据四卡显示0；最近项目有有效详情 URL，未知进度不冒充百分比；失败保留卡片骨架与重试 |
| 老板工作台 | 经营、月账本、业务卡消费真实指标；平台待办实际加载；工程状态与最多3个项目预览来自项目接口。切月不复用旧月数据，缺来源显示“—”，失败可重试 |
| 材料入口 | 未指定项目先到项目列表选择，指定项目/节点保留原上下文；去除不执行的旧模板，保留品牌、加载与失败重试 |
| 成员管理 | 仅有效 API 老板/门店负责人可进入和调用管理动作。确认期间切岗不提交；五类写操作发出后换岗，迟到成功/失败均不覆盖新岗位的结果、表单、忙状态或提示 |

主要文件为 `pages/account`、`pages/profile`、`pages/admin/{owner-page,home,finance-desk}`、`pages/build/{home,materials}`、`pages/{business,engineering}` 与两个平台视图工具。`platform-owner-home.js` 仅做真实接口到页面的适配；没有另建一套业务模型。
