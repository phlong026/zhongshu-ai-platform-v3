# 管理模块重构最终方案与工作任务清单

> 日期：2026-10-28。本文是管理 Tab 重构的最终交付：修改方向、对标吸收、重构思路与分批任务清单。
>
> 依据：[财务绩效模块业务逻辑分析_20261028](财务绩效模块业务逻辑分析_20261028.md)（问题诊断与三轮老板反馈）、[管理工作台四Tab设计_20261022](管理工作台四Tab设计_20261022.md)（内容规格与对标）、[页面样式一致性检查与整改意见_20261021](页面样式一致性检查与整改意见_20261021.md)（视觉统一证据）。
>
> 已确认的三条产品约束：**① 零新增底部 Tab；② 管理动作做减法，减少摩擦；③ 老板审批动作不放线上，系统只做登记、通知、计算、提醒。**

## 一、方案总览

管理 Tab 的最终形态：**老板的经营驾驶舱 + 财务的作业台，同一个 Tab、两个直达入口、零线上审批流。**老板看到的还是四页（首页/经营/绩效/我的），财务看到的还是财务工作台，Tab 数量一个不加；中转页删除；钱的链路按"三类钱"模型收敛；视觉以工程模块和财务桌面两套最新类系统为基准收敛到一套全局令牌。

七个修改方向：

| # | 方向 | 一句话内容 |
| --- | --- | --- |
| D1 | 入口直达 | 删双人格中转页，老板/财务进 Tab 即达各自工作台 |
| D2 | 财务作业流 | 待办收敛为单一作业流，复核改月末对账 |
| D3 | 老板经营驾驶舱 | 首屏三件事：回款、单项目毛利、预警 |
| D4 | 审批下线与自动化 | 首款计划生成即生效；费用/付款审批删；业务垫付报销链路；薪酬批量结算 |
| D5 | 绩效任务化 | 老板派任务 + 系统自动采集 + 责任人手动补充，薪酬三步审批天然消失 |
| D6 | 视觉与风格统一 | 一套全局令牌，向 fin-\*/eng-\* 基准收敛 |
| D7 | 代码域化与后端前置 | admin 子包按域整理目录，后端账本表结构定型前评审域边界 |

## 二、修改方向详解

### D1 入口直达（Tab 不变，删中转页）

- 底部 Tab 完全不动：老板 首页/经营/绩效/我的；财务 财务工作台/收支/项目/我的；业务、工程不变。
- `pages/management/index` 现在是"按角色变形"的双人格页（老板重定向、财务原地渲染），改为像工程角色直达 `pages/build/home/index` 一样：财务直达财务工作台（`admin/finance-desk` 首屏化）、老板直达 `admin/home`，中转页退役。
- 可选减法（需老板拍板）：财务的"收支""项目"两个 Tab 合并为一个"账本"Tab，页内分段（流水/应收/应付/项目账）。

### D2 财务作业流（一个入口办完所有钱的事）

- 财务待办从"三处跳转"（`admin/index`、`admin/operations`、`workflow`）收敛到财务工作台的单一待办流，一条待办一个办理页，办完回列表。
- 逐笔独立复核改为**月末集中对账**：按月生成对账单（登记台账 vs 实收实付汇总，`F.summary` + 流水清单），一键核对标注差异；单人财务登记即生效，不再弹回避提示（autoReview 静默化）。
- 资金期初：手输即生效，凭据选填，每月自动从上月快照结转（`funds-confirm` 简化）。

### D3 老板经营驾驶舱（对标同行首屏三件事）

对标结论（装企 ERP / 好业财 / Buildertrend / JobTread 共同点）：老板端首屏是**回款 + 单项目毛利 + 预警**。我们数据基础已有，缺组织：

- **回款**：应收合计、逾期金额（红）、下一期到期日——`receivable()` 已有，搬到经营页首屏。
- **单项目毛利**：预计/已承诺/实际成本并排展示（`cost().total/committed` 字段已有），毛利在成本发生时就能看到变化，不等交付。
- **预警**：三类（工期延误超 3 天、成本超支、未来 7 天应付 vs 现金覆盖）——`payableDue`、进度偏差（工程模块 2026-10-28 已提交进度偏差与逾期预警，直接复用其数据）。
- 待我办理列表只留"登记类待办"（确认到账、报销登记、放行登记），审批类全部消失（见 D4）。

### D4 审批下线与自动化（系统零审批流）

| 现状 | 改后 |
| --- | --- |
| 合同分期 pending 待老板批 | `submitTerms()` 生成即生效（`status:'approved'`），历史 pending 数据一次性自动批准迁移 |
| 费用提交→老板批准 | 线下定；财务按事实登记付款；业务模块设计费走垫付链路：小程序支付（已有双账落账）→ 自动通知供应商财务+总部财务 → **自动生成"业务报销"应付** → 财务凭报销单登记报销 |
| 付款审批（pay-approval） | 删除线上入口；财务直接登记 |
| 业主直付三步 | 到货确认页标注付款方即可 |
| 收款闸门老板例外（credit-exception 审批） | 拦截页一键"放行登记"（谁/何时/原因，可附微信截图），留痕不审批 |
| 绩效逐人核准 | 批量生成结算单供老板线下核对；发放=财务登记一笔付款 |

### D5 绩效任务化（老板派任务，系统采数，责任人不填表）

取代"固定指标体系 + 目标设置"的旧方案：绩效不再是一张预定义的指标表，而是**老板每月派发的一张任务单**。

- **老板派任务**（绩效页新增"派任务"，一分钟派完一组）：一句话标题 + 责任人 + 期限；可选任务类型（回款金额/签约金额/完成节点/按期节点/内容发布/有效线索/到货合格批次——均为系统可自动统计项）与目标值；可选填奖金。
- **自动任务零操作**：选了类型的任务由系统实时采集完成度（复用现有 `facts()` 归集引擎，每条完成度都可下钻原单），责任人什么都不用填。
- **手动任务一键完成**：系统统计不了的事（跑通供应商、处理客诉、专项整改），责任人点"标记完成"，附一句话说明 + 拍照留痕即可，不走确认审批（符合"审批下线"原则），老板月底核对。
- **派任务时的参考值**：现有指标体系（业务 9 项/工程 3 项/财务 3 项）不删除，降级为任务类型的自动采集来源——派任务时展示该责任人上月实际值供老板参考，老板不用懂"指标体系"。
- **月底定版与结算**：任务完成情况自动进周期归档（复用 `archives` 与申诉机制）；**奖金在派任务时老板已经定了，系统月底只做汇总**——薪酬的"配规则→生成→核准"三步天然消失，只剩"定版 + 财务登记发放"两步。
- 数据结构（同时是 A4 后端建表的输入）：`performanceTasks: [{ id, period, title, assigneeId, due, type: 'auto:指标键'|'manual', target, collected, bonus, manualDone:{at,note,photos[]}, status, history[] }]`，存储沿用按组织+月份的组织方式（`zhongshu-owner-goals-v1` 的模式）。
- 仍需老板拍板：自动任务"回款金额"派给业务还是工程（原决策项 1，任务化后变成派任务时的习惯问题，但口径要统一）。
- 催收待办（工程侧，逾期应收进项目经理待办、两键登记）是唯一的经营类新增动作，与绩效任务化正交，见批次 A3。

### D6 视觉与风格统一（以最新两套类系统为基准）

现状证据（样式检查文档）：1012 处硬编码颜色、445 种取值、42 种字号、5 套互不相通的令牌前缀、7 套页面头部、8 个各自定义的 `.solid` 主按钮。而工程模块（`styles/engineering.wxss`，`eng-*`）与财务桌面（`styles/finance-desk.wxss`，`fin-*`）是最新交付，已经自然形成基准语言：主色 `#89512a`、米白底 `#faf8f4`、白卡 22-24rpx 圆角、棕色竖条标题、数字用 tabular-nums、警示色暖橙（`#ad431b`）。

统一动作：

1. **一套全局令牌 `--zs-*`**（约 20 个：主色/按压/浅底、文本四级、分隔线、卡片、成功/进行/待办/逾期四语义色、两档圆角、两档阴影），以 fin-\*/eng-\* 的取值为准定稿；`admin/layout.wxss` 里的 `#9c501f/#925020/#985423/#995624` 等棕色变体和渐变按钮全部映射收敛。
2. **字阶收敛到 6-7 级**（正文 ≥26rpx、辅助 ≥24rpx，消灭 27 处小字号主力文本）；`.muted` 对比度从 3.3:1 提到 4.5:1。
3. **状态色语义化**：成功/进行中/待办/逾期四色全局唯一定义，进度对勾、胶囊、卡片描边统一引用，不再各页自配。
4. **头部组件 7 套→1 套**：保留"返回箭头+标题"，去掉与胶囊重叠的"工作台"文字链。
5. **主按钮一个定义**：`eng-primary/eng-outline` 的实现提升为全局组件（88rpx 触控已有 `unified.wxss` 兜底），`.solid` 渐变版本退役。
6. **标题字体定规则**：ZSAdmin 自定义字体与 `.section-title` 的宋体二选一全局启用（建议衬线标题仅用于页面级大标题，卡片标题用黑体加粗——与工程/财务现状一致），决策项交老板确认。
7. 管理模块老页面（`admin/layout.wxss` 体系、`owner.wxss` 38 处 `!important`）随 D1-D4 改版逐页迁移到 fin-\* 基准，不单独做大改版。

### D7 代码域化与后端前置

- `pages/admin` 子包目录按域整理：`owner-*`（老板经营域）、`finance-*`（财务作业域）、`operations`（经营台账域）各归其位，`authority-v2.js` 的 `admin()` 五角色巨型函数按域拆成三个小权限表；纯代码移动，不改路由。
- **后端前置**：monorepo 数据访问层正在建账本表结构（提交 `0fd622e`），域边界（三类钱、应付分类、绩效快照）必须在表结构定稿前评审通过，避免把混合结构固化进服务端。此项是文档评审动作，随批次 A 启动，不依赖代码。

## 五、附：绩效任务化设计规格（D5/F1 的实施依据）

绩效从"固定指标体系 + 目标设置"改为"老板每月派发任务单"：能自动统计的系统采数，统计不了的责任人一键标记留痕，奖金在派任务时即确定。

### 5.1 数据模型

```js
// 存储键：zhongshu-performance-tasks-v1，按 组织 + 月份 组织（沿用 owner-goals 的结构模式）
{
  companies: {
    [companyId]: {
      periods: {
        '2026-11': {
          tasks: [{
            id: 'task-1690000000000',
            title: '周建国项目封顶款回款到位',      // 一句话，老板怎么派活怎么写
            assigneeId: 'sales-dual',               // 责任岗位
            assigneePersonId: 'person-...',         // 人员 ID，换岗留痕不归零
            due: '2026-11-30',
            type: 'auto:collectionsAmount',         // 自动任务；手动任务为 'manual'
            target: 5000000,                        // 分；自动任务的目标值
            collected: null,                        // 分；系统采集值，实时刷新，归档时定版
            bonus: 200000,                          // 分；可选，派任务时即确定
            status: 'active',                       // active | done（手动完成）| archived
            manualDone: null,                       // 手动任务完成留痕 {at, note, photos[]}
            sourceIds: [],                          // 自动任务完成度对应的原单 ID（下钻用）
            ...actor(),                             // createdBy/by/at
            history: []                             // 改派/修改留痕
          }]
        }
      }
    }
  }
}
```

### 5.3 交互规格（三个视角）

**老板 · 派任务（绩效页"派任务"）**：字段 6 个以内——标题（必填）、责任人（在岗人员）、期限（默认当月末）、任务类型（可选）、目标值（选类型后出现）、奖金（选填）。选中责任人后展示其上月同类指标实际值作参考。当月任务单可随时增补、改派（留痕）。

**责任人 · 我本月任务（工作台首页任务卡或绩效入口）**：自动任务显示进度（35万/50万、3/5 个）并可下钻原单，零操作；手动任务一个"标记完成"按钮，一句话说明必填、拍照选填，无确认环节。逾期未完成的任务置顶提醒。

**老板 · 月底核对与定版**：任务单总览（已完成/进行中/未完成，手动任务可点开留痕）；一键"定版归档"——自动任务按采集值定版，手动任务按留痕状态定版；生成奖金汇总（Σ 已完成任务奖金）→ 财务登记发放（衔接 D2）。归档后原单发生变化的，走既有 `supersedes` 重开复核机制，不手改。

### 5.4 替换与兼容

- **删除**：薪酬规则配置（payroll-policy）、逐人生成（payroll-submit）、线上核准（payroll-approve）、DEPARTMENTS 固定指标表 UI、目标设置页。
- **保留并降级**：`facts()` 归集引擎成为自动任务的采集源；`archives` 周期归档与 `supersedes` 重开；申诉机制；发放进应付链路。
- **兼容**：历史归档与已生成结算只读保留，新周期起用任务单；首次切换月提供"按上月指标生成建议任务"一键初始化。
