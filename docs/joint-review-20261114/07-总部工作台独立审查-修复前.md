# 总部运营工作台与 AI 并发保护独立审查

## 结论

**REQUEST CHANGES。** 用户截图对应的是 `admin-ui/src/views/platform/home/index.vue` 的“总部运营工作台”，路由与 B 端本地运营 API 已接通，后端权限和租户隔离未发现越权；但首发 200 个组织时，首页的核心指标与两张趋势图会确定性少算或显示错误口径，并且任一子接口失败会被伪装成 0/无数据。修复并补回归测试前，不应把该页面作为上线运营看板验收通过。

`RemoteDesignAdmission` 的单进程资源保护实现可通过代码审查：同步计数、单组织上限、幂等释放以及前置拒绝均成立；它只是过载保护，不是“100 人同时发起均成功”的容量证明。现有测试明确是 100 个调用中接受 16、拒绝 84。

## Stage 1：需求与真实产品身份

- 实际首页：`admin-ui/src/router/modules/remaining.ts:61-69` 加载 `views/platform/home/index.vue`，标题为“总部运营工作台”；与用户截图一致。
- 总部菜单：`admin-ui/src/utils/projectNavigation.ts:105-135` 只保留 `/platform-ops` 本地运营实体，并按各权限码过滤。
- 业务路由：数据库迁移把钱包、套餐、订单、流水、异常、设计定价、设计成本、审计映射到 `platform/wallet/index`；组织开通映射到 `zs/platform-org/index`。
- API：前端 `admin-ui/src/api/platform/operations.ts:67-149` 对应 B 端 `/admin-api/platform/ops/**`；组织开通 `admin-ui/src/api/zs/platform-org.ts:20-22` 对应 `/platform/org/onboard`。

## Findings

### [HIGH] 首页把分页样本当成全平台钱包总量

- 前端证据：`admin-ui/src/views/platform/home/index.vue:125-139` 对 `wallets.value` 求和并以数组长度作为“钱包总可用点数/组织钱包数”；`328-340` 只请求 `pageNo=1,pageSize=100`。
- 后端证据：`platform-wallet/.../admin/WalletOperationsService.java:43-50,94-108` 是有上限 100 的普通分页，没有聚合；仓库中没有可复用的钱包 `SUM/COUNT` dashboard summary。
- 触发：首发 200 个组织，且钱包超过 100 条。
- 风险：两个卡片必然少算；`home/index.vue:203-225` 的“各组织钱包”top10 也只是第一页内部 top10。
- 修复：在 `WalletOperationsService` 增加同租户聚合 DTO/查询（至少 walletCount、availablePointsTotal、全量 top10），通过新的只读 summary 端点返回；复用现有 `requireTenant()`、10 秒 query timeout 与 `@ss.hasPermission`，不要在浏览器循环抓多页后求和。
- 验收：构造同租户 200 个钱包、另一租户若干钱包；summary 的 count/sum/top10 与数据库聚合一致，另一租户不可见；首页卡片使用 summary，而不是列表长度。

### [HIGH] 任一子接口失败会让整页显示 0/“无”/“暂无”，故障被掩盖

- 前端证据：`admin-ui/src/views/platform/home/index.vue:328-349` 用单个 `Promise.all`，没有 `catch` 或错误状态；任一请求 403/5xx 后，所有赋值都不执行，`finally` 只关闭 loading。默认值来自 `116-123`，随后在 `129-185` 被渲染为 0/“无”；图表在 `42-64` 显示“暂无”。
- 触发：账号缺少七项权限中的任意一项，或钱包/设计/审计任一服务短暂失败。
- 风险：总部会把服务故障误判为没有订单、没有异常、没有资产；也导致已有可用数据一起丢失。
- 修复：优先用一个有明确权限和一致口径的 dashboard summary；若图表仍分接口加载，使用独立状态/`allSettled`，失败卡显示“获取失败”并提供重试，不能回退为业务 0。权限不足的区块隐藏或明确标识。
- 验收：分别让任一接口失败，其他卡片仍显示真实值；失败区块显示错误和重试；恢复后可更新；绝不显示 0/“无”冒充成功结果。

### [HIGH] 套餐数、活跃定价与“近 30 日”趋势的业务口径不真实

- 套餐：`admin-ui/src/views/platform/home/index.vue:151-156` 永久硬编码 0，虽然 `operations.ts:69-70` 已有套餐查询 API。
- 定价：`home/index.vue:166-169,334-345` 把 `getDesignPrices().total` 标成“生效设计定价”；后端 `DesignOperationsService.java:35-42` 返回所有历史版本，未过滤 `active=true`。
- 流水：`home/index.vue:241-292,333` 只对最新 100 条明细按日/业务类型分组，却标为“近30日趋势”和“类型分布”。高峰 100 个 AI 请求即可很快超过该样本。
- 风险：卡片与趋势在真实运营量下失真，无法用于上线监控和财务判断。
- 修复：summary 端点直接返回 `planCount`、`activeDesignPriceCount`、近 30 日按天聚合与业务类型聚合；所有查询按 tenant 过滤。若暂不做聚合，必须把图名准确改成“最近 100 条流水样本”，但这不能替代 200 组织钱包核心总量修复。
- 验收：插入历史价目与多条 active 价目，卡片只计 active；插入 30 日内超过 100 条和 30 日外数据，趋势包含全部 30 日内记录且排除区间外记录；套餐数来自数据库事实。

### [MEDIUM] 首页没有针对真实业务口径的行为测试

- 证据：`admin-ui/tests` 中没有 `home/index.vue`、钱包总额、套餐数、部分失败或 30 日聚合测试；当前类型检查只能证明语法/类型成立。
- 修复：添加前端行为测试覆盖 summary 映射、部分失败/重试和空数据；后端集成测试覆盖 200 钱包、跨租户、active 价格、30 日边界与 top10。

### [MEDIUM] Admission 测试未覆盖异常释放与 recovery 忙时不改命令

- 实现证据：`RemoteDesignGateway.java:33-40` 用 try-with-resources 覆盖正常/异常调用；`173-184` 的 recovery 在取 permit 后才 claim，busy 时不触碰持久命令。`RemoteDesignAdmission.java:21-45` 在同一 monitor 内增减并清理组织计数，double-close 幂等。
- 已有测试：`RemoteDesignAdmissionTest.java:23-65` 验证 100 并发接受16/拒绝84和后续复用，`67-76` 验证单组织限制与 double-close，`78-91` 验证过载拒绝不持久化/不远调。
- 缺口：没有验证 transport/命令存储抛异常后 permit 释放；没有验证 recovery 在 gate 已满时 `claim`/状态均不变；没有超时慢调用下的 HTTP 层行为。
- 修复：补三类回归；实际 HTTP 混合负载另作容量验收。

## 安全、权限和隔离核对

- **通过（源码/现有测试证据）**：总部钱包控制器逐端点使用独立 `@ss.hasPermission`，见 `WalletOperationsController.java:20-52`；设计价格/成本亦分别授权，见 `DesignOperationsController.java:19-30`。
- **通过（源码/现有测试证据）**：`WalletOperationsService.java:94-123` 所有查询先校验管理员用户与 tenant 上下文一致，并在 SQL 中绑定 tenant；组织筛选只解析规范正整数，不拼接用户输入。`WalletOperationsIntegrationTest.java:43-63` 已覆盖同租户跨组织、他租户不可见、SQL 注入样式输入和租户冒充拒绝。
- **通过（源码/现有测试证据）**：异常核对按 tenant 校验目标，`OperationsAuditService.java:57-84`；现有事实集成测试覆盖跨租户拒绝与 append-only。
- **路由接通**：组织开通使用平台级 `platform:org:onboard`，`OrgOnboardController.java:46-53`；菜单迁移 `V20261104.707__pf_org_onboard.sql:8-17` 将页面和按钮权限授予 tenant 1 的超管角色。是否与生产管理员账号角色一致仍需部署后角色 UAT。

## 容量判断

`RemoteDesignAdmission(16,4)` 是每个 B 进程的快速拒绝门。它能保护 64 个 Tomcat worker，不会排队占满线程；但在一个进程、100 个同时调用的现有测试中，业务结果是 16 接受、84 返回繁忙。上线验收仍需使用真实 HTTP、数据库、Redis 与可控慢 provider，验证 100 人发起时产品是否允许可理解的重试、无重复扣费/命令、错误率与恢复时间；不能把单元门禁测试写成“100 并发通过”。
