## 问题

### [HIGH-01] 定时记录永久停在 `scheduled`，用户到时仍无法登记链接

- 前端：`miniprogram/pages/studio/index.js:373-384` 提交 `scheduledAt`，WXML `:34` 明确提供定时入口。
- 后端：`ContentPublicationService.java:64-72` 创建时置 `scheduled`；现有 `verify` 仅允许 `publishing → verify`（`:130-133`），`link` 只允许 `verify → published`（`:105-127`），`fail` 只处理 `publishing`（`:136-143`）。全仓未找到 `scheduled → publishing` 的定时任务或手工动作。
- 前端状态机：`platform-content.js:117-121` 对 `scheduled` 直接报“当前发布状态不能登记链接”。
- 触发：选择未来至少一分钟的发布时间并创建记录；时间到后刷新，记录仍为 `scheduled`，无法推进。
- 修复建议：首发若不交付真正的定时发布，隐藏/禁用定时入口并拒绝 `scheduledAt`；若交付，则新增可恢复的到期迁移任务与并发/幂等测试，再允许回执。不能只改前端把 scheduled 当 publishing 绕过后端状态机。

### [HIGH-02] API 发布链使用两个演示账号，服务端没有组织/人员授权校验

- `miniprogram/utils/studio.js:5` 和 `pages/studio/index.wxml:31` 固定 `douyin-adviser`、`channels-design`；`index.js:377-379` 注释称“组织配置”，实际直接上送硬编码值。
- `ContentPublicationService.java:62-64,83-85` 只检查 `accountId/platform` 非空和长度，未查询组织发布账号或操作人员授权。任意有内容写权限的用户可提交任意不超过 64 字符的账号标识并形成组织发布记录。
- 本地演示链 `growth.js:12-13,27` 原有账号授权在 API 在线链没有执行。
- 修复建议：首发前由后端提供当前组织且当前岗位可用的发布账号列表，创建时再次校验组织归属、启用状态和操作者授权；前端按返回列表渲染。若真实账号管理尚未交付，应禁用账号选择和在线发布创建，不能把演示账号标成真实组织配置。

### [MEDIUM-01] PNG 参考图一律声明为 JPEG，complete 会被魔数校验拒绝

- `platform-bridge.js:416-432` 允许相册/相机任意图片，但申请票据和 PUT Content-Type 都固定为 `image/jpeg`。
- A `AssetContentScanner.java:38-42` 强制实际魔数等于声明 MIME；PNG 字节会得到 `REJECTED`。A 的 `DESIGN_REFERENCE` 本身允许 JPEG/PNG。
- 现有测试只用字符串 `image` 且 mock complete=ACCEPTED，没有使用真实 JPEG/PNG 魔数。
- 修复建议：从文件字节魔数（优先）或可靠的文件元数据确定 `image/jpeg`/`image/png`，用同一 MIME 申请票据和 PUT；补真实最小 JPEG、PNG 两条测试，并断言声明、SHA、字节一致。

### [MEDIUM-02] 销售首页客户源失败仍显示 0，且没有降级提示/重试

- `business/index.js:35-40` 已获得逐源 `fulfilled`；但销售分支 `:83-84` 不看 `known[0]`，对失败后传入的空客户数组计算 `todayCount/overdueCount/appointmentCount=0`。
- WXML `:14-19` 的销售首页没有 `platformStatus==='degraded'` 提示与重试；错误卡只在老板分支 `:22`。
- 触发：销售岗位的 `crmApi.customers.page` reject，其余三个源成功，页面把未知客户待办展示为三项 0。
- 修复建议：销售分支也按 `known[0]` 显示 `—`，并复用明确的降级提示/重试；行为测试直接执行真实页面定义，覆盖“客户失败、佣金成功”和反向组合。

### [MEDIUM-03] 上传验收用例模拟了错误的后端端点，证据会误导发布评审

- 实际页面：`pages/workflow/explore/index.js:12` 注入 `api/franchise/design`，调用 `/franchise/design/assets/**`。
- 测试：`scripts/verify-joint-review-miniapp.cjs:12-36,89-99` 把 upload URL 模拟为 `/admin-api/franchise/assets/{id}/content?...`，这是 B 本地资产端点，不是设计远程票据返回契约；测试标题还称 `local-proxy` 成功。
- 修复建议：生产候选测试只把设计 API 的 COS 绝对 HTTPS 票据列为成功路径，并断言外部 PUT 无平台认证头；`local://` 明确断言“不支持并给出可操作提示”，不能宣称本地上传成功。B 内容资产的相对 URL 测试应放到实际调用 `/franchise/content/assets/**` 的页面/模块。
