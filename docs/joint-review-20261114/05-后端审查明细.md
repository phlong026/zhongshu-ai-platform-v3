### P1-1 金融写接口允许缺省幂等键，超时重试可重复落单

- 证据：`/Users/honor.pei/Documents/企业FDE项目/众墅之家AI赋能平台/.worktrees/joint-review-20261114/平台程序/domains/franchise/franchise-finance/src/main/java/cn/iocoder/yudao/module/franchise/finance/controller/admin/FinanceController.java:233`（以及应付、付款、退款、异常资金、银行确认等）将 `Idempotency-Key` 声明为 `required=false`。
- 证据：`/Users/honor.pei/Documents/企业FDE项目/众墅之家AI赋能平台/.worktrees/joint-review-20261114/平台程序/domains/franchise/franchise-org/src/main/java/cn/iocoder/yudao/module/franchise/org/FranchiseCommands.java:32-35,48-55` 对空键不重放且记录 `NULL`。
- 触发：客户端提交成功但响应丢失，以空键重试；交易号又为空时，第二次会形成新的财务记录。
- 影响：重复实收、应付、付款、退款或异常资金记录，直接污染对账与经营口径。
- 最小修复：所有财务写入口要求非空、长度受限的稳定幂等键；服务层也 fail-fast，不能只依赖 Controller。保留同键同 payload 返回首次结果、同键异 payload 拒绝的既有语义。
- 现有测试边界：`.../FinRefundThreeDirectionIntegrationTest.java:219-257` 已证明“提供同一非空键时并发至多一行”；未覆盖 HTTP 缺省键或空键重试，因此不能抵消本问题。
- 验收：每类资金写操作覆盖“无键=4xx 且零写入、同键顺序重试=同 ID、同键 20 并发=恰一业务行且所有调用最终可重放同结果、同键异内容=冲突”；同时核对命令事件、交易号与业务表数量。

### P1-3 短信发送限流不是原子操作，同手机号并发会发送多个验证码

- 证据：`/Users/honor.pei/Documents/企业FDE项目/众墅之家AI赋能平台/.worktrees/joint-review-20261114/平台程序/platform/platform-identity/src/main/java/cn/iocoder/yudao/module/platform/identity/SmsCaptchaService.java:42-58` 依次执行 `hasKey`、日计数 `increment`、写验证码、写 60 秒间隔、调用渠道，未使用 `SET NX`/Lua 原子门禁。
- 触发：双击或两个节点对同一手机号同时发码；两请求都可能在 interval key 写入前通过检查。
- 影响：产生两次短信费用，后写验证码覆盖前一条，用户收到的第一条必然验证失败；日上限边界也会被已拒绝请求继续递增。
- 最小修复：用 Redis Lua 或 `SET NX EX` 先原子占用手机号发送许可，再在同一原子脚本中维护日计数；通道失败后的保留/释放策略显式化。不要增加共享 IP 限流导致企业 NAT 用户互相影响。
- 现有测试边界：`.../SmsCaptchaServiceTest.java:49-80` 只用 Mockito 顺序验证 60 秒/日限额/写码顺序，没有真实 Redis 或同手机号并发用例。
- 验收：真实 Redis 下同手机号 20 并发只有 1 次渠道调用、只生成 1 个有效验证码；第 11 次明确拒绝且计数不继续漂移；不同手机号不相互阻塞；渠道超时/失败符合既定 60 秒防风暴策略。

## 已通过的关键设计

- B 部署隔离：Compose project、API/PG/Redis、用户、数据卷、密钥挂载和端口均独立；API 只读根文件系统、cap drop、no-new-privileges。
- 组织隔离：加盟域虽有显式 `company_id/org_id` 模式而非统一租户插件，但抽查财务、远程设计命令、积分账户均从当前 `PostSnapshot` 取组织并在查询/锁行中带组织条件。
- 公司积分：`OrgPointService.reserve` 先锁组织账户，再检查同业务键、权限/月额度，以 `balance >= amount` 条件扣减并写唯一流水；同组织并发串行，余额不透支。
- AI 财务一致性：设计任务、公司积分预扣、计费绑定由外层事务统一；远程设计写要求非空 Idempotency-Key，持久化命令、收据查询和 UNKNOWN 恢复避免盲重发付费调用。
- 财务分页：新管理后台主链五张表均为 DB 分页且 `pageSize<=100`。
