## 1. 本版结论

本版把设计委托到工程接收收敛为一条可恢复、可追踪的同项目流程：

1. 无参考预算时，设计委托页明确指出缺少预算，保留当前已填需求、金额和模拟附件，进入同一客户预算页；预算完成后返回原委托继续办理。
2. 完全匹配老板标准设计费用时引用既有预授权自动通过；只有例外费用进入一张逐单审批，由老板同时核对设计总金额、首付款、自动计算的尾款、交付范围和实际收款方。首款、尾款不拆成两次老板审批。
3. 费用获得标准预授权或例外审批后，门店必须先完成线下首款支付并在线登记足额付款；登记完成即开放总部设计办理待办，同时产生总部财务首款实际到账待办。总部首款确认不再阻塞设计开始。
4. 设计完成后，尾款沿用同一次老板审批。正式成果下发仍要求总部财务确认本版首款、尾款均已足额实际到账。
5. 业务准备同一项目的正式设计成果、本版施工图、线下审核依据、客户确认凭据四类 V1 模拟资料，直接点击“移交给工程”。页面不再要求业务指定个人，也不显示暂存、页底说明或“客户需修改，登记意见”。
6. 系统按本组织职责分工自动投递给默认工程岗位；工程负责人在本人工作台收到同项目待办，核对后接收原单，再沿既有施工链办理。

本报告是 [预算到工程交付连续验收报告](预算到工程交付连续验收报告_20261023.md) 的规则补充。原报告记录的是当时已执行的 28 步历史实测；B04 后执行 B05 是当时的人工操作顺序，不代表旧代码要求总部先确认首款才能设计。旧代码实际在费用授权后即可设计，本版新增“门店首款足额登记后才能设计”的门禁；业务在移交页指定工程人员的旧行为也已由本版规则覆盖。

## 2. 卡点根因与修复

### 2.1 截图卡点

截图中的需求、交付范围、金额、附件和核对勾选均已填写。真实卡点是该客户没有有效参考预算，`budgets.length` 为 0。

旧实现把预算、需求、范围和勾选合并在同一个通用校验中，只返回“请核对有效预算、需求、尺寸和交付范围”。页面没有说明具体缺少预算，也没有保留当前表单后去补预算的入口，因此人工操作会停在提交按钮处。

旧 28 步连续验收从“预算已保存”开始，覆盖了预算后的主链，没有覆盖“客户尚无预算但直接进入委托”的入口，所以此前主链通过不能证明这个入口可恢复。

## 4. 门禁与历史数据兼容

### 4.1 首款和尾款

- 首款支付动作在线下完成；王财务在线登记即表示门店已实际支付。
- 首款必须由门店足额登记后，林设计才获得设计办理待办。总部财务对首款的实际到账确认与设计办理并行。
- 设计完成后才开放尾款登记；尾款继承同一老板审批。
- 正式下发要求罗财务确认本版首款、尾款均足额实际到账。部分到账只更新累计值和差额，不开放下发。
- 历史记录已经存在 `completed`、但首款未登记时，保留历史设计完成事实；系统先提示补首款，补登记前不开放尾款。补登首款不会重复制造设计完成记录。

### 4.2 组织默认工程岗位

- 真实组织只读取老板在“职责分工”中保存的工程默认负责人；未配置、人员离岗或岗位不符时明确阻止移交，不生成半截 `handover`。
- 移交页面传入的人员 ID 不作为派发依据，跨组织人员不能劫持移交。
- 退回后重新移交时，原负责人仍在岗且具有工程岗位则保留原责任；原负责人已离岗或岗位失效时，改派当前组织配置的有效默认工程负责人。两者都无效时明确阻止移交，避免原单锁死或生成无人接收的待办。
- 体验模拟数据只在 demo 会话且工程分工字段缺失时补 `engineering-dual`。已有自定义分工和明确空配置均不覆盖；真实会话不补模拟负责人。

### 4.3 个人页

李业务、张老板、王财务、罗财务、林设计、张工程六类角色的“我的”页面已删除“跨设备联调”入口和对应按钮，避免把调试工具暴露为正式业务功能。

## 5. 同客户、同项目、同版本的数据要求

本版恢复和移交始终使用原 `customerId`、`projectId`、业务负责人和设计服务版本：

- 补预算只新增当前客户预算版本，不复制客户或项目。
- 返回委托页后，需求、费用和附件仍属于原客户；新预算只使旧核对失效。
- 四类模拟资料正文包含当前客户、项目、V1 版本、资料来源和用途，用于体验流程，不要求用户选择本地文件。
- 移交保存正式资料包后，工程待办仍指向原客户和原项目；工程接收在原单上落回执。
- 测试及报告不读取、提交或引用本地用户存储备份；本报告只使用脱敏的业务规则和定向回归结论。
