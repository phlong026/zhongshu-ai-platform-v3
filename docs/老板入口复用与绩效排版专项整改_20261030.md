# 老板入口复用与绩效排版专项整改

本轮承接《小程序逐页布局审计_20261030》，继续检查34个注册路由的同类问题：重复入口、岗位下钻页跳回首页、导航选中错误、输入控件占位、长文字挤压和按钮层级。源码检查覆盖全路由，原生截图覆盖本文列出的14个状态；不代表全部子视图、真机或线上数据验收。

## 整改方法与边界

先核对入口的实际目标及角色数据范围，补回归，再删除重复入口、复用已有页面，最后在微信原生模拟器检查实际框体与文字。保留已有系统黑体、棕色品牌、浅色卡片、32rpx标题、28rpx正文及88rpx常用控件规范。不新增页面框架或依赖。

实现位于独立工作树，基于已提交的 `dbd93d5`，避免覆盖原工作目录中其他任务的未提交修改。本轮未包含另一任务正在开发的绩效目标卡片。

## 问题、结论与修复

|位置|确认的问题|最终处理|
|---|---|---|
|绩效任务派发表单|原生form直接承担卡片布局，框体不能稳定包围字段；输入框固有高度叠加上下内边距，文字占位不足|块级卡片包裹form；字段上下排列；输入高度88rpx且至少44px、取消垂直padding；textarea独立高度|
|绩效长标题、改派、完成凭证、归档|长标题与状态抢宽；关闭区被挤压；空操作区留白|标题flex:1/min-width:0并换行；状态不收缩；关闭按钮至少44px；无操作时不渲染操作区|
|绩效操作层级|建议任务和派发任务均为实心主按钮；员工单一tab重复“我的任务”|建议/归档使用描边，派发保留主操作；只有一个tab时隐藏tab条；月份说明简化|
|绩效责任人|默认显示第一位员工，但表单尚未选择责任人|未设置assigneeId时明确显示“请选择责任人”，避免显示与提交值不一致|
|老板我的：绩效任务|快捷卡片与门店管理重复进入同一任务页|保留顶部快捷卡片，移除门店管理项|
|老板我的：历史委托费用授权|与“我的规矩→设计费用规则”指向同一policy页面|移除直接入口，保留我的规矩维护路径|
|老板我的：其余指定入口|管理模拟联调、工程负责人交接、项目回款提成增加非核心入口密度|按要求撤下入口；保留既有业务记录、原页面和财务角色流程|
|老板首页：绩效目标|与现行绩效任务为同一目标|撤下首页链接；任务由我的快捷卡片进入|
|老板首页：经营明细|属于独立报表，并非同一页面重复|按要求撤下首页链接；经营汇总、明细数据和原单入口仍保留|
|老板经营详情/历史目标页|仍残留任务及提成快捷按钮，绕回已清理入口|同步撤下这些旁路入口，保留历史数据与规则链接|
|老板客户列表与跟进|入口进入客户页后，被业务岗位守卫送回首页|允许已激活老板复用原客户页，展示本店所有可见负责人客户；搜索、筛选、分页、记录沿用原能力|
|老板客户状态|写跟进权限被误用于待跟进统计，老板工作台显示0，逾期显示灰色“未跟进”|展示事实与写权限分开；工作台和列表共用due投影；昨天预约显示红色逾期、红点并排前；canFollow仍为false|
|老板工程项目/计划/材料/款项|快捷入口混用旧工程总路由与新工作台页|复用工程现有项目列表和材料页；计划/款项通过列表destination进入对应项目|
|老板下钻页|复用员工根页后仍选中员工导航，且缺返回入口|客户下钻选中老板业务，项目/材料下钻选中老板工程，并显示返回；员工根页保持原导航|
|老板首页业务/工程概览|仍进入另一层旧概览，与工作台复用路径不一致|直接复用客户列表及工程项目列表|
|设计委托规则表单|与绩效页相同的原生input/textarea占位风险|input明确高度及水平padding；textarea明确独立高度和行高|
|设计委托项目/区块标题|长项目名或标题挤压状态及辅助文字|文字区域可收缩换行；状态和右侧辅助文字不收缩|
|保留的管理模拟页|双列网格最小内容宽度可能撑出卡片|采用minmax(0,1fr)，窄屏单列；老板菜单不再展示该工具|

## 复用与权限

|入口|复用目标|
|---|---|
|老板业务→客户列表与跟进；老板首页→客户与跟进|`/pages/customers/index`|
|老板工程→全部项目；老板首页→工程项目|`/pages/build/projects/index`|
|老板工程→施工计划|`/pages/build/projects/index?destination=schedule`|
|老板工程→材料计划|`/pages/build/materials/index`|
|老板工程→节点款项|`/pages/build/projects/index?destination=payments`|
|老板我的→我的规矩→设计费用规则|`/pages/workflow/commission/index?view=policy`|

“所有客户/项目”是当前老板组织权限下的本店数据，不包含其他门店。数据仍由原business/access/engineering模型过滤。老板列表不显示业务登记、写跟进或工程新增项目控件；处理函数也检查原岗位权限。工程深层页面原有老板财务/规则能力继续按既有权限运行，本轮未扩大经办权限，不应称为所有深层页面绝对只读。

## 变更与回退

产品修改集中在profile菜单、admin首页/任务/旁路入口、客户页、工程项目/材料页、委托样式，以及sales-workspace/workbench展示投影。测试修改集中在入口去重、岗位页面复用、绩效原生布局和既有相关断言。

简化包括：删除重复入口与未用样式、移除绩效页无关owner样式导入、删除伪造canFollow的筛选变通、共用原页面和待跟进计算。没有数据迁移、新依赖或新业务流程，提交前检查反向补丁可应用。Git提交/远程分支、微信官方上传和后台设置体验版分别记录；上传开发版本不代表已设置体验版。
