# 生产切换：残留模拟数据盘点（2026-11-07）

对照基线是已合入 `main` 的 PR #4（`441f01b1`，含 `3c7fdcab`）及其清单 `docs/生产切换-模拟数据剔除与凭据注入清单-20261107.md` 第六节「留置项」。本仓只有小程序、`scripts/` 与 `server/`。平台 Java 不在本仓库，本轮不能复核后端 profile 装配。

盘点口径：`demo` / `mock` / `sample` / `seed` / `假` / `模拟`、本地会话门禁、演示支付、种子列表，以及开发专用开关。默认不删仍有体验门禁或产品缓做的代码。

结论先说：PR #4 写明继续留置的条目，代码仍在、门禁仍在，没有一条已经过时到可以当已删除。正式岗位还会碰到的，是展示用静态目录和发布时上送的两个固定账号 id，不是假客户、假账或模拟支付。本轮没有删代码。

## 3. 后端 Java

本仓库没有 `*.java`。PR #4 写的「后端 stub 经三重防护，生产 profile 零装配」无法在本树复核，既不能标成已过时，也没有新证据推翻。平台侧 mock / stub / Fake 要到平台程序仓再盘。

`server/` 三份本地服务是开发替身，不是 Spring profile，见上表第 15 条。

## 4. 建议立即修

只有第 1 条是正式岗位请求里仍会带上的固定标识。它依赖后端账号主数据，工作量不是改一个前端常量就能收口，本轮不改、不删。

第 2–4 条正式用户看得到，但是静态目录或 4.5 缓做展示，不是假账。第 5–14 条有体验门禁或已经没有页面入口。第 15–16 条不进包。

本轮没有发现可以安全删掉、且证据已经足够的小块模拟数据。
