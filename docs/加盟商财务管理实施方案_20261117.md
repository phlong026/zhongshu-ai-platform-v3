# 加盟商财务管理最终实施方案

日期：2026-11-17  
适用对象：约10人的中小型乡墅加盟商  
状态：业务与实施方案；本轮未修改业务代码、数据库或发布环境

本版替代此前讨论中的泛化报销方案，统一采用已确认的规则：业务可以垫付平台设计费并报销；正常材料采购由公司付款；退款在线下完成，财务在系统据实登记；系统外发生的真实收支可以补记；项目账从底部Tab进入，首页不再放平台账簿或项目账本卡片。

## 一 最终判断与产品边界

“以项目为中心，把业务、工程自动产生的数据和财务手工补记放进同一本账”的方向正确。但只有收入和支出两列还不够，必须同时分清三个问题：

1. 公司实际收了多少、付了多少：资金收支。
2. 项目已经确认发生了哪些费用：费用归集。
3. 业主还欠多少、公司还欠供应商或员工多少：待收待付及往来。

三者来源相互关联，但不能直接相加。例如员工垫付设计费已经形成项目费用，公司尚未付款；供应商预付款已经发生公司资金支出，不代表材料已经到货或全部成为已确认费用；退料也不代表供应商已经退款。

界面仍然保持简单。财务日常只需要登记收款、登记付款、办理报销、查账和核对异常。上述区分由选项、原单关联及系统计算完成，不能要求使用者手工维护三套账。

第一版采用“项目收支与待收待付工作台”的定位。项目费用口径是经确认的经营管理数据，不能把收支净额或采购计划金额直接称为会计利润。复杂收入确认、税务申报、总账凭证和存货计价不在本次范围。

### 行业场景依据

本方案按包工包料为主，同时兼容包工不包料、部分承包、业主自购材料的情况设计。农村住房施工示范文本包含多种承包方式、材料提供方约定、工程增减费用、分阶段付款、竣工结算及保修，因此系统需要容纳这些情况，不能把三个固定收款节点当成全部可能业务。此处用于识别产品场景，不将某地合同模板当成所有加盟商的统一合同规则。[国家市场监管总局合同示范文本库：甘肃省农村住房建设施工合同](https://htsfwb.samr.gov.cn/View?id=6dc6bfcc-fb56-4614-8689-aa17d73ef122)

## 四 从头到尾的业务分工

| 阶段 | 业务/工程负责什么 | 财务负责什么 | 系统衔接 |
| --- | --- | --- | --- |
| 获客、量房、洽谈 | 客户、建房事项、量房及委托资料 | 有真实定金或前期费用时登记；无资金事项不建财务待办 | 可在建工程前建立该建房事项账本 |
| 设计委托 | 确认方案、服务内容、版本和平台费用；申报本人真实垫付 | 收业主设计款、登记公司直付或核实个人垫付、办理报销 | 业主收入与平台费用分别记录，按委托关联 |
| 签约 | 确认合同总额、收款计划和此前定金抵扣 | 登记实际到账，核对各期余额 | 抵扣以前实收只改变分配，不新增收款 |
| 开工准备 | 工程确认施工安排、材料和人工需求、预计用款时间 | 查看待收待付与资金安排 | 资金计划只用于安排，不自动变成实际费用和付款 |
| 材料采购 | 工程提供规格、数量、项目、供应商及采购依据；采购经办可由指定人员兼任 | 核对依据、线下向实际收款方付款、登记分次付款 | 采购应付和付款关联；工程实时看付款进度 |
| 到货与施工 | 工程验收、记录数量差异、人工完成量和新增费用依据 | 登记供应商余款、班组款、零星费用 | 付款不自动确认到货，到货不自动确认付款 |
| 工程变更 | 业务/工程确认增减内容、业主确认依据与金额影响 | 根据有效变更调整待收待付，登记实际款项 | 原合同、变更、实收各自留痕 |
| 退料、退款 | 经办人提供退料或取消依据；财务取得线下处理结果 | 登记已实际退付/退回，匹配原单 | 数量、合同/采购金额、资金退款分别更新 |
| 交付与结算 | 工程完成交付；业务确认最终合同价和业主结算 | 对清业主款、供应商款、人工款、员工垫付款 | 交付状态与财务结清状态并列 |
| 质保与售后 | 工程记录维修事项、责任及材料人工依据 | 登记售后支出、尾款或约定留款收付 | 挂回原项目；归档后补记保留原结算版本 |
| 公司日常 | 经办人提供房租、水电、工资、营销等依据 | 记公司日常账及资金往来 | 不硬塞进某一个项目，也不自动平均分摊 |

小团队允许同一人兼任业务、采购或工程负责人。系统按当前岗位授权，不强迫配置多名审批人。正常事项沿原业务依据直接办理；确有争议、金额变更等情况可以留负责人确认依据，不建设每笔都必须走的多级审批。

老板以看项目、看欠款、看异常为主；财务负责资金事实；工程负责现场事实；业务负责客户合同事实。总部仅核对与总部有关的设计等往来，不默认获得加盟商全部内部账。

## 五 账本组织方式

### 1 项目账从第一笔相关事项开始

账本跟随“一项具体建房/设计事项”，不等开工才出现，也不按客户姓名自动合并。同一客户两处建房、设计后未成交、工程中途取消，都能保留各自记录。

建议增加轻量账本标识bookId或等价的关联实体，连接客户、设计委托、合同与后续工程项目。保留已有projectId、commissionId、contractId及原单关系；建立工程时关联已有账本，不复制一套历史流水。

仅有客户线索、没有财务事项时不必自动创建大量空账本。前期形成委托、合同、真实收支或明确待收待付时建立即可。

### 2 项目账内容

项目详情以“累计实收、累计实付、收支净额、待收、待付”为主要摘要；进一步查看已确认费用及员工往来，不增加首页指标。

账内用轻量筛选查看：

- 收支明细：真实收付款和退款。
- 待收待付：业主、供应商、班组、员工等尚未结清事项。
- 费用分类：设计、材料、人工/分包、机械租赁、运输、现场杂费、提成、售后、其他。
- 原单与凭据：合同、委托、采购、工程费用、报销、手工登记。

应付、费用依据和付款可能在详情中同时出现，但汇总分别计算，不能把同一事项累计三次。列表行明确显示“应付”“公司付款”“员工垫付”等性质。

### 3 公司日常账与待归属

“项目账本”Tab列表中保留公司日常账入口，用于房租、水电、办公、工资、营销以及公司资金往来。

尚不能判断归属的旧记录或到账进入“待归属/待认领”清单。它是一种核对状态，不是把所有空projectId都默认变成公司费用。实际到账已核实但归属未定时，可反映公司资金事实；不能先增加某项目回款、业绩或工程放行金额。

## 六 收款、线下补记与退款

### 1 业主收款

推荐默认流程：业务/工程提交到账信息或凭据 → 财务核实实际到账 → 形成唯一有效收款 → 回写合同期次、项目账和相关状态。

如果财务直接登记，可以跳过申报。已有代码中已经有效的历史实收只核对、补资料，不再重复登记。要采用上述职责分工，须调整现有销售collect权限及入口，不能只加“待财务确认”文字而保持原接口直接入账。

收款登记先选“关联合同/收款事项”或“其他实际收款”。能关联原单时自动带出项目、客户及剩余金额。合同款不能只做一笔manual项目收入，否则合同待收和工程条件可能不变化。

### 2 施工前定金、超额款及提前到账

预收定金、尚未明确期次的款项可以先登记为该建房事项的预收/待分配。签约或明确用途后分配到合同期次，只改变关联，不产生第二笔实收。

真实提前到账不应被“节点未完成”拒绝记录。工程节点完成与收款事实分开：先记录预收或分配，工程放行仍按约定规则判断。超出某一期余额的款项进入待分配，不把它偷偷挪到另一合同或伪造新收入。

不同客户、不同建房事项不可仅凭姓名或金额相同自动认领。已有收款、银行到账匹配和手工登记共用防重复识别，确认匹配只增加关联，不生成第二笔钱。

### 3 没有系统业务单的数据

财务可以在项目账或快捷入口直接登记，默认带入当前项目。核心字段为：

| 字段 | 规则 |
| --- | --- |
| 归属 | 具体项目账或公司日常账；未知时进入待归属 |
| 性质 | 收款、付款、客户退款、支出退回、往来等 |
| 分类 | 少量常用选项；原单自动带出 |
| 金额 | 真实金额，内部按分存储；收支方向由性质决定 |
| 实际日期 | 实际到账/支付日期；补录时间另外保留 |
| 对方 | 业主、供应商、班组、员工或其他对方 |
| 账户/方式 | 公司管理的收付账户及银行、微信、现金等方式 |
| 原因与依据 | 摘要、原单或说明；原单有资料时不重复上传 |
| 凭据 | 转账记录、收据、发票等；支持后补与关联 |

无原单零星支出采取一个表单：系统在同一事务内形成费用/应付依据及实际付款，前台不要求先建应付再点付款。若已经有采购单、工程费用或报销单，必须复用原依据。

这里只是补录真实事项，不能用“手工”绕过已有委托费用上限、合同余额、公司归属、退款额度或原单权限。

### 4 退款不建设独立审批流

“没有线上退款审批和转账流程”是确认的方向；“退款在系统里完全没有关联”则不适合。

| 类型 | 实际方向 | 入口 | 必须关联 |
| --- | --- | --- | --- |
| 退给业主 | 公司资金流出 | 付款登记中的客户退款或原收款详情 | 原收款、项目、原因及实际退款信息 |
| 供应商/平台退回公司 | 公司资金流入 | 收款登记中的支出退回或原付款详情 | 原付款、项目、原因及实际到账信息 |
| 退给原垫付员工 | 员工收到款，未必涉及公司资金 | 原垫付/报销事项 | 原垫付、实际收款人及员工往来 |

退款不当作新业务费用或新营业收入。不能用作废原单替代真实退款；作废用于纠正错误登记，退款保留原真实收付。

同时区分业务原因：

- 多收/多付退回：原合同或采购总额可能不变，只调整资金及分配。
- 取消、减项或退料：除了实际退款，还要依据已确认变更调整应收/应付及费用。
- 尚未拿到退款：保留待退/待收回事项，不先虚记到账。

例如采购10000元已付清，确认退料2000元并收到2000元退款，应付调整为8000元，有效净付8000元，待付为0；如果只登记退款、不调整采购义务，系统会错误显示还欠供应商2000元。

退款不能自动替业务决定合同是否取消，也不能在尚未退款时自动减少真实资金。财务登记时引用变更依据，必要时提示原单经办人补齐变更。

## 七 设计费与员工报销

### 1 必须分清三种款项

- 业主付给加盟商的设计服务款：加盟商收款。
- 加盟商应付平台的设计服务费：项目费用及对平台结算事项。
- 公司偿还业务人员的个人垫付款：员工往来结清及公司付款。

三者不能因为都叫“设计费”就合成一条流水。平台设计费由委托版本及期次确定，仍使用现有结算规则。

### 2 两条正常付款路径

公司直付：委托形成平台应付 → 财务线下付款并登记 → 平台核收 → 更新设计结算状态。无员工报销。

业务垫付：业务提供真实支付信息及凭据 → 核实出资人、委托、版本、期次 → 记录平台实际已收及员工垫付 → 公司欠该员工 → 财务分次或一次报销 → 结清员工往来。

平台是否收到钱与公司是否已报销给员工是两个状态。平台确认真实收到足额款后，可以按现有设计业务条件推进；不应再等公司内部报销完成。

### 3 2400元案例

| 时点 | 已确认项目设计费 | 公司实际付款累计 | 应付业务人员 |
| --- | --- | --- | --- |
| 业务个人垫付2400元并核实 | 2400 | 0 | 2400 |
| 公司先报销1000元 | 2400 | 1000 | 1400 |
| 公司再报销1400元 | 2400 | 2400 | 0 |

公司报销只结清往来，不再增加一次设计费用，也不能再次标记一笔付给平台的钱。公司与员工分别出资时，按各自实际份额记录；不能先虚记公司全额付款再冲销。

现有设计结算依赖门店payment与总部receipt的关联，需要扩展为能够表达出资来源的实际结算事实或等价结构。新增出资类型、实际付款人及原资金凭据；总部核收仍匹配真实原付款。个人出资部分不进入公司现金统计，报销付款则不重复冲抵平台应付。

### 4 报销界面与退款

报销首期以业务垫付设计费为重点，同时兼容确实存在的小额差旅等个人垫付。正常材料采购不走工程垫付报销。

最少状态：待核实、待补资料、待报销、部分报销、已报销。财务可依据业务提交，也可为已发生的垫付代录；保留真实垫付人和经办人，不能把代录人当收款人。无需另建复杂审批引擎。

平台退回设计费时，要记录退给谁：

- 未报销，平台退给业务人员：相应减少该员工尚待报销额，并按有效取消/减费依据调整费用。
- 已报销，平台又退给业务人员：形成员工应归还公司的金额，不能当作公司已经收到退款。
- 平台直接退给公司：登记公司实际收回；员工此前未获偿还的垫付款仍单独核对。

员工往来允许出现“公司应付员工”与“员工应还公司”两个方向，不能把负数一律归零掩盖应收回款。

当前模拟收银台结果和积分消费只属于模拟/非现金业务状态，不创建真实垫付、真实报销或真实公司资金记录。

## 八 材料采购、人工与工程费用

### 1 材料库与采购付款的关系

材料资料、参考价格、选型或需求计划本身不产生财务应付。形成明确的采购金额、供应方、项目和依据后，才成为财务付款事项。采购经办可由工程负责人或指定人员兼任，但付款主体默认公司。

流程：工程提出需求并确认采购依据 → 生成/关联原采购应付 → 财务向实际收款方线下付款并登记 → 工程查付款进度、确认到货与验收 → 财务根据实际约定处理余款及退料结算。

向本地供应商采购，收款方是供应商；若未来存在总部供货，收款方按真实交易约定设为总部。不把所有材料交易默认套用设计平台结算。总部代垫与员工垫付是不同往来，不能共用“员工报销”按钮。

必须支持采购订金、分次付款、到货后余款以及约定到期日。没有约定日期时不标逾期。正常采购不要求工程先垫资再报销；若历史上确实发生个人代付，作为例外真实往来处理，不能为守流程而丢失真实付款。

### 2 到货、退料与跨项目分配

到货数量、验收结果、已付金额、已确认采购金额分别维护。已付清不等于已到齐，到齐不等于已付清。

退料要关联原采购，分别跟踪退料数量/金额依据、采购金额调整及实际退款。现有退料待结算状态需要有真实后续办理入口。

一次采购或转账用于多个项目时，保存一笔资金事实，按项目分配金额；分配合计必须等于该笔已分配金额，未确定部分留待分配。不能将同一银行转账全额重复登记到多个项目。

项目A余料用于B，只调整材料归属及经确认的费用分配，不再生成一笔公司付款。第一版支持简单手工分配和留痕，不建设复杂仓库成本计算。

### 3 业主自购与代付抵扣

两种情况必须区别：

- 业主自购、合同不由公司承担的材料：工程记录到货/验收，财务不虚增公司付款或公司材料费用。
- 业主经确认代公司付供应商并抵工程款：保存业主直付凭据和抵扣依据，结清相应合同与采购余额，但标识为非公司现金结算；不能伪造一进一出的公司流水。

只有实际出现该场景才在表单展开相应选项。未开发完整抵扣能力前，不用普通收付款冒充处理完成。

### 4 人工、班组及其他费用

沿用工程已有费用依据及应付，支持按确认的工程量/结算金额分次付款，并保留班组或收款人、所属项目、结算期间、付款凭据。

人工合同预计总额、已确认结算额、已经付款分别显示。预付班组款不代表该阶段已经全部完成；结算时引用原预付分配，不能再登记一次付款。

运输、机械租赁、临时水电、检测、现场杂费和售后费用可复用工程费用或财务手工补记。材料价款已含运费时不能再重复归集同一运费。

提成已存在生成应付的代码，应接入同一付款列表。业主退款可能影响提成条件，保留现有待人工核对机制，不自动删除已发提成、不自动扣薪。项目归属清楚的提成进入对应费用；公司固定工资进入公司日常账，首期不做自动工资分摊。

## 九 容易遗漏、必须给出处理方式的事项

| 事项 | 最简处理 | 本次边界 |
| --- | --- | --- |
| 合同增减项 | 原合同加变更记录、金额、依据、对应期次调整 | 真实已生效变更留痕，不直接覆盖原合同总额 |
| 尾款与约定留款 | 保留默认三期，允许明确追加期次/到期条件 | 不预设所有项目都必须有质保金，也不硬编码比例 |
| 预收、预付 | 先记真实资金，再匹配后续合同或结算 | 匹配不重复产生实收实付 |
| 押金、保证金 | 记录应收回/应退回的往来 | 押金支付不默认项目费用，退押金不当经营收入 |
| 员工备用金 | 借支、实际用途、余额返还分别关联 | 不与员工自掏钱垫付混为一类；发生时启用 |
| 老板垫资、股东借款 | 公司日常往来，记录对方及偿还关系 | 不算业主回款、经营收入或业绩 |
| 公司账户互转 | 两个账户匹配一笔内部调拨 | 不进入公司对外收付及项目收入支出汇总 |
| 公司管理的个人收款账户 | 明确其为纳入公司资金管理的账户 | 与员工个人垫付资金区别，避免报销重复 |
| 不明到账 | 财务确认真实到账后待认领 | 不先计入具体客户合同、项目回款或提成条件 |
| 未取得发票/收据 | 独立缺资料标记，后补附件 | 已真实支付不能因此显示未付款 |
| 施工中止或取消 | 保留发生事实，逐项明确待收、待退及对外欠款 | 不能删除项目及历史流水；未确定事项继续挂起 |
| 售后返修 | 归入原项目售后费用，关联维修事项 | 不因为工程归档就禁止登记真实款项 |
| 历史期初欠款 | 单独录期初待收待付及必要来源证据 | 不伪造本期收付款来凑余额 |
| 历史退款缺原在线单 | 关联核实的历史/期初结算依据并限制剩余额度 | 不创建一笔虚假的当期原付款解锁退款 |

上述场景不各建一个大模块。多数可以通过现有登记页的性质、对方、原单和归属字段表达；少量暂未实现的能力要清晰标识待处理，不能让财务用错误分类绕过。

### 交付、结算、归档要分开

当前代码对工程交付使用累计全额收款门禁。若约定存在交付后尾款或留款，应按合同到期条件判断，而非要求所有最终款项提前收齐。保留必要的业务控制，但不能把后续才到期的款项误判成阻止交付的欠款。

项目至少并列两个状态：工程状态、财务状态。财务状态可以简化为有未结事项、已核对结清；保留未到期尾款/留款的明确标记。

结算页展示完整项目范围：前期设计、采购、人工、手工费用、报销往来、退款及售后，而不只合计工程域的材料与费用表。

归档锁住已确认资料的无痕改动，仍允许授权补记真实尾款及售后费用。更正必须记录操作者、原因、原值与新值，并标明原结算之后新增的金额；不能反复修改历史让老板以为当时就已知。

## 十 统一统计口径

### 1 公司现金与项目管理金额

首页金额反映公司纳入管理账户的实际对外资金收付。个人自有资金垫付、业主非现金抵扣、模拟支付、积分以及本公司账户互转，不计入对外现金指标。

沿用已确认的普通收付款与退款分开记录方式：

- 已登记收款R：普通有效实际收款，不含支出退回。
- 已登记付款P：普通有效实际付款，不含客户退款；包括实际支付给员工的报销。
- 客户退款CR：实际退给客户的金额。
- 支出退回ER：供应商、平台等实际退回公司管理账户的金额。
- 收支净额 = R + ER - P - CR。

在净额详情展开两类退款，避免用户误以为净额永远等于首页前两格之差。公司借入款、归还借款、押金等若纳入实际收付，必须标记往来性质；经营分析按性质单独筛选，不把它们当营业收入和项目费用。

月度统计按实际收付日；补录时间另记。实际日期不明的历史记录进入待核日期，不用创建日期或今天代替。历史月份切换应覆盖统计、列表和导出，而不仅修改页面文字。

收支净额不是利润，也不是账户余额。只有期初余额与该账户全部收付均可靠时，才可展示账户余额；第一版无需承诺自动银行余额。

### 2 待收待付与费用

合同待收按有效合同及变更、已分配净回款、确认抵扣计算；采购待付按有效采购/结算金额、已分配净付款、确认抵扣计算。每笔计算后再汇总，超收超付单独列出，不能用A单的超付抵掉B单的欠款。

现金付款全额进入资金统计，只有实际分配到原应付的部分才冲减原单余额。已有pendingLink金额属于这笔实际付款中的未分配部分，不是另一笔支出。

供应商已被员工代付的部分不再显示欠供应商，转为欠员工；报销结清员工往来，不再累计原费用。项目待付总额要去重，不能同时将原供应商应付与员工报销应付各算一次。

费用按已确认的采购、服务或费用依据归集；计划预算、可退押金、单纯预付、报销还款不直接新增费用。材料金额未确定、班组未结算时明确提示数据不完整，不以付款代替真实费用。

### 3 所有端共用

财务首页、项目账、老板账本、合同余额、工程付款进度、绩效条件、PC与导出复用统一聚合规则。现有老板待收查询部分仍使用工程历史收款表；待付及提成付款读取对退款/待分配处理也有差异，应集中修正。

新projects/{id}/ledger与旧project-accounts接口若同时保留，要共享口径，不能让两个入口显示不同项目结余。可建立共享查询服务，不再存储另一套容易漂移的“老板账”。

## 十二 待办、办理中与日常操作优化

待办文案用“项目＋事项＋当前动作”，如“张先生建房 · 平台设计费报销 · 待报销2400元”，不把长数据库编号当标题。单据编号在详情中保留。

| 情况 | 首页呈现 |
| --- | --- |
| 业务提交了到账信息 | 今日待办：核实业主收款 |
| 采购依据已确认且约定需要付款 | 今日待办：办理采购付款 |
| 业务垫付资料齐全 | 今日待办：办理设计费报销 |
| 原资料不完整 | 指向原单补资料；明确谁需要补 |
| 已报一部分 | 正在办理：已报/剩余；有当前待办时避免重复占两张卡 |
| 已付款等待总部核收 | 正在办理：等待平台核收 |
| 不明到账/退款关联异常 | 今日待办：认领或核对异常 |
| 原事项已经完成 | 待办消失，消息仍可查历史 |

未到付款时间的普通余额在待收待付中展示，不把所有未付款都堆成“今日必须办”。可选到期日用于排序；不约定日期就不制造逾期。

常见原单点击后自动带项目、客户、类别、对方和待付金额。报销默认不再要求重新录入设计费用；补凭证不新增付款。一个事项当前只显示最需要处理的动作。

财务可按以下节奏使用：每天核对到账、办理付款和报销、补记零星收支；每周查看项目待收待付及异常；月末按真实账户流水核对收付、归属和缺凭据。复用现有对账能力，不为了第一版引入银行直连。

## 十三 优先级、迁移与实施顺序

### 首次可用版本必须完成

1. 统一账本归属、收支/退款/费用/往来口径；盘点存量来源。
2. 修正首页月份、指标、项目账Tab及真实办理入口。
3. 打通原合同收款、工程采购/人工付款、项目与公司手工补记。
4. 完成真实设计费垫付与报销，平台结算与公司现金分别正确。
5. 补退款与原合同/采购变更关联、默认三期以外的必要尾款处理。
6. 接通待办、办理中、补凭证和原单追溯。
7. 对齐老板、工程、设计、绩效、PC及导出。
8. 完成权限、重复登记、历史数据及核心业务场景验收。

前后端分批落地，但首页改完只能称页面完成，不能据此宣布财务管理闭环完成。

### 在真实场景出现时补齐的扩展

业主代付抵扣、合并转账跨项目分配、员工备用金、总部材料代垫和更细的押金往来，应按实际使用频率安排。如果上线时已有这类存量或在办业务，则纳入首次可用范围；没有时不在首页增加入口，但不能将其误归成普通收入或费用。

### 可以后置

复杂多级审批、自动发薪、复杂预算预警、自动费用分摊、完整进销存成本核算、银行直连、OCR自动审核、自动税务处理和正式会计利润报表。

账实一致、原单关联、对象权限、审计、幂等和错误态不能后置。

### 存量迁移

- 从合同期次关系、工程receiptId、采购/费用payableId、设计委托版本等可靠关联回填。
- 不按姓名、金额或创建时间接近自动合账；空projectId不自动转公司日常。
- 真实日期未知保留待核，旧模拟记录不转真实资金。
- 期初待收待付单独记录，不伪造本月收支。
- 迁移前后有效实际资金总额守恒；归属或分类变化留痕。
- 历史报销须核对原费用与原公司付款，避免迁移再次创建费用或付款。
- 存量结算快照保留版本；历史更正后的新汇总标记更新，不能无痕替换旧报告。
