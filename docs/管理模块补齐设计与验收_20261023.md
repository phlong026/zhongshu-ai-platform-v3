# 管理模块补齐设计与验收

## 范围与已确认规则

移植基线为 `b89a9d5`，已同步工作区最新 `eb10b15`，分支 `feat/management-completion-20261023`。本次继续完成前次报告列出的功能，不导入旧合同链，不改变 V3 财务只登记实际收付及总部独立确认到账的规则。

- 用户确认：交接沿用授权人员直接办理，只提醒离岗、停用或明确标记需交接的内部责任事项；不增加申请审批。
- 用户确认：数据同步采用模拟服务及独立测试会话，不要求接入生产后端。
- 用户确认：老板逐项目录入已确认的提成总额及归属人；开工款、封顶款分别足额到账后各解锁50%；退款或冲正后暂停未付部分，已付差额列为待人工核对，不自动追回。
- P2 的 AI 简报、同店对比与现金流预测仍不在本次范围。

新增布局要求：财务首页及收支、项目列表参考当前工程和业务页面，沿用米白底、白卡及棕色按钮。首页固定为欢迎语、数据卡片、待办事项、常用快捷办理、正在办理五区，删除面向开发的技术说明。保留真实财务流程和权限。

## 实施契约

1. 首页六指标点击进入精确筛选的原记录列表；预约到店和内容获客使用明确的跟进、发布与线索记录。交接不把全部在岗工作当作待办。
2. 经营报告只读现有整数分账簿，提供六个月趋势、收支构成、账龄、工程回款率、资金覆盖、预计毛利与获客成本。未知数据保留空态，不从名称猜分类。
3. 推广费复用公司费用及稳定应付、实付链，增加明确用途。月末经营快照单独保存不可变版本：相同来源幂等，来源变化须显式追加修订版；缺少快照不得混入当前余额。
4. 催款文案只从原收款约定、剩余金额及最新真实现场资料生成，由用户复制，不自动发送。
5. 公司、部门及人员按月份设置目标。按用户最新决定，运营、设计、业务统一为“业务”考核，工程和财务单列；同一业务人员只出现一次。旧三部门目标按指标读入统一业务，新保存版本采用三部门结构，旧历史保留；兼岗业务、工程、财务目标彼此隔离。
6. 门店资料只编辑展示名称、联系人、电话及地址，组织编号只读。审批设置编辑在岗职责分工，金额老板审批、线下设计审核及实际收付规则保持固定。
7. 新设计委托保存发生时责任人；责任转交不改写历史归属。历史缺少可靠责任证据时显示待核对，不批量猜测。
8. 模拟同步复用现有沙箱业务模型和原子持久化，使用独立数据文件与会话。验证两个会话间可见、版本冲突、幂等重试、服务重启恢复及组织隔离。

## 并行边界

- 首页实现：`owner-home.js`、首页 WXML/WXSS、独立首页专项脚本。
- 经营实现：经营报告模块、`owner-business.js` 的经营部分、经营页面、operations 的用途及快照动作、独立经营专项脚本。
- 绩效实现：独立绩效及配置模块、绩效页面与独立表单模板、独立绩效专项脚本。
- 主代理：共享 owner-model/controller/detail 模板整合、历史责任戳、模拟同步、字体、文档、原生验收及最终提交。

各实现者不得覆盖他人的文件或提交；共享入口由主代理按约定接线。

## 验收清单

- 首页：六指标金额和数量与明细一致；当前/历史月份隔离；有效客户排除系统登记；交接仅真实需办事项且办理后关闭；原单权限及分页不漏。
- 经营：修订、退款和分次付款不重复；六个月跨年；账龄边界；零分母及成本不全空态；快照幂等、修订与原版本保留；推广费沿原单付款；催款不虚构金额、日期或附件。
- 绩效配置：兼岗部门互不覆盖；目标及公司隔离；已归档来源与历史责任不被转交修改；资料及分工候选人权限与版本校验；提成按用户确认规则验证。
- 模拟同步：两会话读取/写入同一状态；陈旧版本拒绝；同幂等键重放不重复；跨公司、停用或越权拒绝；持久化失败不能回报成功。
- 回归：现有管理专项、完整业务 22 脚本、跨设备模拟联调、静态/字体/凭据/依赖检查。
- 原生：实际点击四 Tab、六指标及原单、目标与资料保存、经营报告和快照、催款复制、交接及提成关键路径；独立模拟项目，结束后恢复存储。真机和正式发布仍需真实环境验收。

## 模拟联调接口

服务默认监听 `127.0.0.1`，使用独立数据文件。连接资料文件权限为 `0600`；会话凭证只在客户端私有存储保存，服务端只保存哈希。

| 接口 | 输入与结果 |
| --- | --- |
| `POST /sim/v1/sessions` | `inviteCode` 换取绑定公司、员工及实际人员的测试会话 |
| `GET /sim/v1/snapshot` | 使用 Bearer 会话读取本组织裁剪后的管理数据与 revision |
| `POST /sim/v1/commands` | `expectedRevision`、`kind`、`form`，并携带 `Idempotency-Key`；目标、门店配置和提成规则分别检查版本 |

支持月度目标、门店资料、职责分工、月度结账、提成确认、应付生成和人工核对。陈旧版本返回冲突；越权、停用或人员更换立即拒绝；保存失败不返回成功。网络响应不确定时保留原幂等键，只允许同服务、同身份接回后核实，不能盲目另建操作。目标快照按“业务、工程、财务”规范化返回，未保存草稿不会被轮询覆盖。
