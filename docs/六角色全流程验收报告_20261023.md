## 1. 验收目标与口径

本轮验收覆盖业务模块、工程模块、管理模块及跨模块主业务链路，按六名固定人员逐项办理。验收重点不是单页能否打开，而是同一客户、同一项目、同一责任人和同一资金事实能否在上下游持续对应，异常分支能否回到原事项继续办理，不在中间形成无入口、无责任人或无法恢复的死路。

流程范围以 [六角色全流程验收清单](六角色全流程验收清单_20261023.md) 为准，共 42 条：B01–B10、D01–D04、E01–E13、C01–C06、M01–M06、R01–R02、X01。

本轮采用以下产品口径：

- 业务采用已确认的精简链路，不恢复旧报价签约链和线上设计生产审核。
- 总部设计行政登记线下已完成的设计事实及成果下发，不在系统内模拟专业设计生产。
- 门店财务和总部财务只登记实际付款、实际到账；工程成本核对和最终财务结清线下办理。
- 工程归档可独立完成，归档页保留实际收付、成本和历史原单回查，不提供已关闭的线上结清动作。
- 管理工作台按四页简单版及本轮 P0 验收；收支趋势、账龄、资金覆盖、盈利分析、跨部门独立目标等旧 P1 不在本轮完成范围。

## 3. 模拟数据一致性契约

### 3.1 连续主链

本轮连续主链使用“周建国家”。客户和项目不是写死的展示编号，而是通过作品发布、内容咨询和客资建档动作实际生成：

| 字段 | 原生业务链实际值 |
| --- | --- |
| 客户名称 | 周建国家 |
| 客户 ID | `customer-from-lead-1792695340953-eskzem` |
| 项目 ID | `project-from-lead-1792695340953-eskzem` |
| 业务负责人 | 李业务 `sales-dual` |
| 设计委托版本 | B05 后保持 `requestVersion = 2` |
| 正式成果版本 | B08 为 V1，B09–B10 为 V2 |
| 工程移交版本 | B10 为 `handoverVersion = 1`，退回后仍回到原客户和原项目 |

B01–B10 的 8 个关键检查点中，`customerId`、`projectId`、`ownerId` 始终一致；设计修改沿原委托形成 V2，不重复生成费用和付款。B10 生成的工程接续文件直接保存原状态，后续工程验收必须沿这组 ID 继续，不能重新造客户或项目。

### 3.2 历史阶段样例

默认陈先生数据明确分为三套互不冒充连续链路的阶段样例：

- 业务前段：`customer-chen/project-chen`。
- 工程阶段快照：`demo-chen/snapshot-engineering-chen`，无伪造业务来源客户。
- 财务历史快照：`snapshot-finance-chen`，保留原收款、付款和退款关联 ID。

旧缓存不迁移，登录和演示初始化不得抢回人工转交过的客户，不得把其他人员的存量业务自动改归李业务。历史阶段样例只用于对应模块的独立校验，不参与“周建国家”完整主链的合同、图纸或资金累计。

### 3.3 金额、版本与人员约束

- 业务设计费按元保存；工程合同、收付款和退款按分保存，展示时统一显式换算。
- 业务负责人、跟进作者、内部工作责任人保持同一人员语义；内部交接只改变当前责任人，不改写历史作者。
- 门店“已付”和总部“已实际到账”分别登记，不以一方动作代替另一方事实。
- 设计 V1/V2 共用原委托和原资金事实；修改不得重复收费。
- 工程纠错在原材料、原到货、原现场和原节点记录上留痕，不创建无来源的新项目。
