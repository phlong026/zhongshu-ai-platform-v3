# 财务与老板链路审计及修正方案（2026-10-30）

## 审计目标与口径

本次沿用同一客户、同一 `projectId` 的六角色连续案例，检查门店财务、总部财务、材料供应商应付与老板经营页面。目标客户是 5–20 人的中小乡墅公司，因此判断标准是：日常事项直接流转，金额或经营例外才交老板；同一事实只登记一次；每个待办都能回到原单，办理后消失或生成明确的下一责任人待办。

供应商在当前产品中不是登录角色。供应商提供名称、采购依据、金额、到货与收款对象等原单事实；工程人员登记采购和到货，门店财务登记实际付款，老板只处理超规则例外。这符合小团队无需给每个外部供应商开账号的成本边界。

## 已确认问题

### P0：总部材料代垫卡片显示空金额

`finance-desk` 的材料往来展示模型提供 `receivedText`（总部已核收），页面却读取不存在的 `paidText`，同时把该数字命名为“加盟商已登记付款”。用户会看到空金额，无法判断门店归还是否已由总部确认。

修正：页面直接显示“总部已核收 `receivedText` · 待核 `pendingText`”。不新增状态、不改账务，只纠正已有事实的名称与字段。

### 已修正：老板催款只读入口缺失

原应收页面只有催款话术，老板无法确认负责工程是否已经联系业主。工程模块实际上已经有 `recordFlow.dunning` 和“逾期待催收 → 已催收等待付款 → 承诺日过期再次催收 → 财务足额收款后消失”的完整状态机，因此不需要再造客户跟进表。

本轮在实时应收原单增加“查看催收记录与跟进”入口，使用工程记录 ID 打开 `/pages/build/record/index?view=collection&stage=start|topping`。老板只能查看；页面明确标出负责工程人员，实际联系结果仍由该工程人员在原工程记录登记。复制话术只复制文本，不写入“已联系”状态。这样符合小公司一人负责、老板看例外、财务只记实际到账的分工，并避免重复填报和新增审批。

### P1：供应商协同止于内部付款

当前闭环能证明“采购依据—到货—应付—实际付款”，但供应商报价确认、预计到货承诺与供应商回执仍由线下完成。对 5–20 人公司，现阶段保持供应商不登录是合理的；建议后续在材料原单补一个可分享的只读确认页或回执二维码，不引入完整供应商账号体系。

### 已修正：财务提交页面夹具编排落后

准备脚本原来仍调用已经取消的 `plan-approve`、`payroll-policy`、`cost-confirm` 和逐笔 `approve-pay`，回归脚本还等待已经取消的到账复核待办与费用逐笔老板审批。现已按当前规则改为付款计划直接生效、线内费用与材料应付自动批准、工程到账单人登记即生效、旧薪酬入口跳绩效任务；同时增加环境变量指定夹具和结果路径，可在临时目录完成回归而不覆盖共享验收产物。

## 本轮修改计划

1. 以真实 WXML 渲染锁住总部代垫的 `receivedText` 与 `pendingText`，修正卡片字段和文案，不改变账务历史。
2. 复用工程催收原记录，给老板实时应收增加只读入口与负责工程提示；不新增模型、审批或写权限。
3. 以真实 Page/WXML 点击覆盖应收 → 催收页、复制无写入、工程登记后待办变化和老板刷新可见，再运行财务、管理和老板定向回归及项目静态检查。

## 体验版验收重点

体验版用同一项目依次验证：门店财务分笔支付设计首款 → 总部财务分笔确认到账 → 总部设计开始；材料计划登记金额 → 门店财务付款 → 原待办消失；总部代垫 → 门店归还 → 总部材料卡显示“已核收/待核”；老板进入逾期应收 → 查看原工程催收记录 → 负责工程登记催收 → 老板刷新看到记录 → 财务足额登记后催收待办消失。真实银行流水、真实供应商回执和真实多设备后台同步仍需在体验版账号及真机单独验收。
