# 绩效任务化实施

> 范围更新：2026-10-30 用户明确“薪酬与奖金不在这个小程序进行考虑”。本记录以此为准，覆盖此前实施中的金额与发放方案。

## 任务边界

- 老板派发、改派本组织任务；员工只办理本人任务。
- 自动采集正式签约、实际净回款、完成节点、按期节点、发布、有效客资、合格到货七类事实；手动任务提交说明及 0–6 张选填照片。
- 老板按上月真实实绩初始化建议；无事实不生成零目标任务。完全相同自动任务不可重复派发，不同目标的阶梯任务保留。
- 任务同时冻结岗位与真实人员，原单有 person 证据时优先使用；不能稳定归属的旧事实显示“归属待核对”，不回猜新任人员。
- 月度归档冻结任务定义及原单来源；原事实更正产生修订版，旧版保留。跨月无关收退款不会污染已归档月份。
- 每项自动任务保留来源 ID 与可下钻原单 URL。

## 薪酬与奖金排除

- 删除任务奖金输入、奖励计算、奖金汇总、奖金应付及付款衔接 API。
- 任务页只有“团队任务 / 我的任务 / 任务归档”；组织任务归档仅老板可读，财务与其他员工只看本人任务。
- 旧薪酬规则、新建结算和奖金生成命令均不可办理；历史薪酬、旧任务金额字段和历史账簿不迁移、不删除。
- 历史薪酬或任务奖金不再生成待办，也不能借通用付款命令继续结算；此前已付现金事实仍保留在历史账簿。
- 当前绩效入口进入任务管理，旧绩效指标仍按显式历史入口只读查看。

## 实现与验证

- 数据独立保存在 `performanceTasks`，不覆盖旧目标、旧绩效归档或业务原单。
- `utils/performance-tasks.js` 提供任务命令、归档与修订，页面位于 `pages/admin/tasks/`。
- `verify-performance-tasks.cjs` 验证真实人员权限、幂等、事实来源、跨月隔离、归档冻结与兼容读取。
- `verify-performance-task-ui.cjs` 验证老板派发、员工完成、老板归档及修订；断言无奖金/付款控件。
- `verify-legacy-payroll-retirement.cjs` 验证历史数据保留及退役命令/待办/旧直链不会重新开放薪酬奖金。
- 这些为本地事实模型与 Page/WXML 验证；真实后端、多设备同步和真实设备仍须另验。
