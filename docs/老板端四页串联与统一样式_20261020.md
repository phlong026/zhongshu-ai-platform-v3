## 已串联流程

| 入口 | 后续路径 | 保留的业务规则 |
| --- | --- | --- |
| 首页 · 待我审批 | 原客户的正式报价、设计服务费或原项目付款申请 | 携带原ID、事项种类、当前版本；审批仍在原单办理 |
| 首页 · 业务概览 | 本组织客户 → 原客户工作区 | 原客户归属、授权与设计流程保持关联 |
| 首页 · 工程概览／重点项目 | 原工程项目 → 准备、施工、验收与交付概览 | 接收不自动开工，验收不自动完成节点 |
| 财务 · 项目账目 | 按月搜索项目 → 原项目收支明细 → 原笔收付款详情 | 仅有效核算结果进入汇总，待核算／待复核分别展示 |
| 财务 · 收支总览 | 待我审批、待核算、待付款复核 → 原事项或只读回执 | 老板审批与财务登记、复核分别办理 |
| 绩效 · 目标设置 | 设置本组织、本月份及人员目标 → 四页刷新进度 | 目标与实际数据分开，保留配置版本及历史，归档周期不能覆盖 |
| 绩效 · 团队进展 | 人员 → 本月已签合同或计划节点 → 原记录 | 不引用其他人员来源；未设置目标不编造完成比例 |
| 绩效 · 结果复核 | 原考核周期／申诉 → 原复核表单 | 仅获授权负责人办理，不能复核本人周期 |
| 我的 · 常用管理 | 成员岗位、审批分工、门店资料、项目经理交接 | 金额仍由老板审批，原任务、实际经办与交接历史保留 |
| 我的 · 服务与设置 | 原个人资料、消息、课程、门店服务、帮助、隐私 | 使用原账号与服务模块 |

收支结余 = 有效实收 - 有效已付，不代表利润。当前范围没有新增退款、金额更正或付款结果不明核实入口。

## 统一文字与间距

四个主页面及新增概览／目标页面共用 `miniprogram/pages/admin/owner.wxss`。共用品牌头部和四栏导航组件。

| 语义 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 正文 | 28rpx / 42rpx | 400 |
| 项目、人员及记录名称 | 28rpx / 42rpx | 500 |
| 辅助文字、日期、说明 | 24rpx / 36rpx | 400 |
| 栏目标题、页面标题 | 32rpx / 46rpx | 700 |
| 问候、个人姓名 | 36rpx / 52rpx | 700 |
| 经营数据 | 46rpx / 60rpx | 700 |
| 行内金额 | 34rpx / 48rpx | 700 |
| 行内主操作 | 26rpx / 38rpx | 500 |
| 底部导航 | 24rpx / 36rpx | 500 |

字体统一为内置 Noto Sans SC（ZSAdmin），使用真实400、500、700字重。已保留既有字符并补足新页面文字。卡片内边距22rpx、间距20rpx、圆角24rpx、页面左右留白28rpx；底栏预留滚动空间和安全区。

微信当前设备实测：正文14px／21px，名称14px／21px，辅助文字12px／18px，标题16px／23px。四页相同语义样式的字体、字号、字重与行高逐项相等；卡片内边距、纵向间距也逐项一致。圆角由共用样式和视觉对照核实，自动化样式接口未返回圆角值。

## 数据与权限

- 经营、审批、账目、合同、项目与人员均读取现有本组织原记录，不把图稿数值写成经营结果。
- 新增月度目标保存于 `zhongshu-owner-goals-v1`，按组织和月份隔离，只允许有效老板／门店负责人配置。
- 目标设置不会改写合同、收付款、工程验收或既有考核规则；金额审批继续遵守老板独占权限。
- 旧版真实新增客户缺少登记日期时，仅对已知自动生成ID格式读取其创建时间；没有日期的历史示例不推定月份。
- 新四页继续使用项目既有本地演示数据与表单；没有接入新的银行、支付或服务端接口。
- 微信检查使用独立夹具，结束后已逐项恢复原本机业务存储。当前截图日期、成员人数与数量以夹具原记录为准。
