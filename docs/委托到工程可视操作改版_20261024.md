# 委托设计到工程建项的可视操作改版

用户已确认方案并授权直接完成开发、逐岗位点击验证、提交与开发版上传。

## 实现与清理计划

- 复用现有面积计价、一次性模拟订单、财务抄送、设计成果下发和工程原子建项协议。
- 新委托改用内容创作式的卡片、任务进度、成果缩略图、预览与底部主按钮；历史首尾款继续保留原页面。
- 微信与支付宝使用官方发布的品牌素材，分别提供绿色/蓝色模拟收银台、方式选择、处理中和支付成功界面。保留小型体验标识，不采集密码或真实银行信息。
- 删除日常页面的模拟成功/失败测试按钮、重复字段及大段说明；异常通过真实交互结果提示，底层保留失败/取消回归覆盖。
- 总部设计生成可预览的本项目成果，确认后下发；业务补客户确认凭据和交底后整包移交；工程接收后直接显示建项成功并进入真实项目。
- 所有资料沿用客户、项目与图纸版本；完成本岗动作后检验下一岗位待办。模拟支付不计正式财务现金指标。

## 验证顺序

先保持既有回归为绿，新增失败的页面/收银台与资料归属测试，再实现改版。模型、Page/WXML、历史回归、静态与敏感信息检查后，在隔离微信开发者工具中逐角色点击、截图并目视核对。最后将与原生指纹一致的已提交快照上传开发版。

体验版激活此前被工具安全策略拒绝，本轮沿用开发版上传边界，不重试该操作。

## 与现有流程的衔接

| 现有节点 | 责任岗位/验收人物 | 实际办理动作 | 接续结果 |
| --- | --- | --- | --- |
| 预算完成后的设计委托 | 业务负责人/李业务 | `commission-submit` | 在原客户上保存需求、预算及计价版本，生成一次性订单 |
| 原订单付款 | 原经办业务/李业务 | 收银台确认后调用 `commission-pay` | 原订单变为已付；双方财务获得消息，总部设计获得工作台待办 |
| 付款知会 | 门店财务/王财务、总部财务/罗财务 | 从原消息中心打开付款凭据 | 金额、订单、付款方式和时间与业务支付结果一致；不新增确认门禁 |
| 设计办理 | 总部设计/林设计 | 生成本项目成果、预览并执行 `design-complete` | 本版三份成果随完成记录保存，重新进入页面仍可继续 |
| 正式成果下发 | 总部设计/林设计 | `design-dispatch` | 原业务工作台接续收图与移交待办 |
| 成果与交底移交 | 原经办业务/李业务 | 预览总部成果、生成客户本版确认凭据、`packet-submit` | 原工程工作台出现核对接收待办，完整资料包共5项 |
| 接收自动建项 | 工程负责人/张工程 | `packet-receive` | 沿用原子建项逻辑创建唯一工程项目，成功页直达原工程详情和项目资料 |
| 标准费用及历史例外 | 老板/张老板 | 新委托使用已配置单价；历史首尾款仍走原授权 | 本轮标准流程不新增重复审批 |

所有新界面操作继续使用原客户ID、项目ID、委托版本、图纸版本和待办来源。收银台只是 `commission-pay` 的交互入口；成功页只在原订单成功保存后出现。工程成功页读取接收动作已经创建的原工程项目，不另外建立演示项目。

## 页面效果

- 委托页：步骤、客户概况、面积费用卡、需求与附件、底部提交。
- 微信支付：官方标识、绿色收银台、零钱/零钱通、取消、处理中和成功结果。
- 支付宝：官网当前标识、蓝色收银台、余额/余额宝、取消、处理中和成功结果。
- 财务：原消息中心的支付卡片与付款凭据，保留体验标识且不计正式实收实付。
- 设计：任务卡片、成果生成状态、三份文件缩略图及纸张式预览。
- 移交：同版成果包、客户确认、现场交底和接收建项。
- 工程：建项成功后进入现有工程页面，仍可预览原移交文件。

品牌素材来源：[微信支付官方素材](https://pay.wechatpay.cn/wiki/doc/wxfacepay/develop/sdk-logo.html)、[支付宝官网](https://www.alipay.com/)。使用官方原始图片，通过图片视窗显示标识；原始URL、字节数和SHA256保存在 `qa/design-journey-20261024/brand-assets.json`，没有用自绘图标替代品牌标识。

## 简化与验证

- 移除日常页面的“模拟成功/失败”测试控制、大段过程说明和重复表单字段。
- 延续原办理命令，页面专用展示放在既有业务分包；没有新增依赖或数据库迁移。
- 输入事件只更新表单；资料与阶段改变后再刷新成果视图，避免每次输入都扫描业务和财务数据。
- 新增支付保存失败回归：原单回滚为待支付，退出收银台后明确提示重试，不产生虚假的成功状态或下一岗待办。
- 保留取消、重复支付、金额/计价版本和文件归属门禁；资料在业务与工程之间逐项核对。

本轮是体验模拟界面与资料预览，没有调用微信/支付宝真实支付SDK或输入密码、银行卡信息。图纸和确认凭据是本项目模拟预览。正式支付与真实文件服务需另接，不以此轮模拟代替真实收款或用户手机验收。

## 逐岗位操作清单

1. **业务负责人李业务**：从已完成预算的客户发起设计委托，检查400㎡、20元/㎡及8,000元一次性费用；填写需求，添加本项目需求资料并预览，确认后提交。订单保留原客户、项目和预算版本。
2. **李业务**：选择微信或支付宝，进入收银台，选择付款方式后确认。取消后保留原待支付订单；保存失败提示重试；只有成功保存才展示成功页。微信项目选择零钱通，另一个客户用支付宝验证取消与重试，两个订单互不串联。
3. **门店王财务、总部罗财务**：从原消息中心点击设计费支付消息，查看与业务相同的订单编号、金额、付款方式和支付时间。收到知会即可，不增加人工核收门禁；体验记录为只读，不增加正式现金指标。
4. **总部林设计**：从原首页待办进入设计办理，生成三份本项目模拟成果，点击缩略图查看图纸和审核记录，确认设计完成。重新从原首页下发待办进入，同一组三份文件已经带入，确认后下发给原业务负责人。
5. **李业务**：从原业务工作台待办进入成果与移交，三份总部成果自动带入。检查版本，点击客户确认生成本版凭据，填写现场交底，勾选收齐后移交工程。不要求选择本地文件或另填工程接收人。
6. **工程张工程**：从原工程工作台待办打开核对接收，检查设计成果、施工图、审核依据、客户确认及电子交底五项资料；确认接收后自动创建唯一工程项目。点击进入项目，在原项目资料中仍能预览同版图纸，返回原工程工作台无报错。
7. **老板张老板**：本轮新委托按总部配置单价执行，没有新增老板审批门禁；历史首尾款的标准授权及例外审批沿用旧流程，并由相关回归验证。本轮原生连续点击覆盖前述五个实际办理岗位，没有把老板计为已点击岗位。
