# 审批流程简化方案（批次 D）——大白话版

日期：2026-10-28
分支：`docs/approval-flow-review-20261028`
说明：这份文档给老板和业务同事看，不用懂技术。每个改动涉及的代码位置附在文末，供开发用。
前置：《小程序全页面审批流程梳理_20261028》（技术底账）

---

## 一、这件事一句话说清楚

现在系统里，需要老板点"同意"的事情有 **13 种**，太多了。

改完之后，老板只用管三件事：

1. **钱没到，不开工** —— 这条保留，它是保命的。
2. **先定好规矩** —— 多少钱以内不用问、报价按价目表来。规矩之内系统自动办，出了规矩才找老板。
3. **每天看一眼账** —— 今天要付谁钱、昨天付了谁的钱，一页清单，打开小程序第一眼就能看到。

其他那些"等老板点同意"的环节，大部分删掉，小部分改成上面三件事。

---

## 二、为什么要改（打个比方）

现在的系统，像公司门口站了个保安：不管办多小的事，都得老板签字才放行。

可这是家十来个人的小公司，老板、工程、财务天天见面。工地上要买批瓷砖，工程人员微信问老板一句"380 一平行不行"，老板回个"行"——现实里 30 秒就办完了。

但在系统里，这件事变成了：工程掏出手机填单子 → 提交 → 等着 → 老板晚上看见了点同意 → 工程第二天再看一眼批了没。**工人和材料就卡在这一天里。**

问题不在老板点那一下，在于"等批准"会卡住干活的人。

还有个更直白的例子：买材料的价格，之前已经定好规矩——只有财务或老板能填进系统。也就是说，**填价格的人就是老板（或财务）本人，系统后面再让老板"批准"这笔付款，等于让老板批准他自己五分钟前刚做的事。** 白点一次。

所以方向不是"少管点"，是把老板的精力挪个地方：

- 老板的精力花在**大事**上：开工款到没到、这个项目到底赚不赚钱；
- **小事**交给规矩和系统自动拦：不能多付、不能重复付、每笔钱必须有凭证。

---

## 三、老板真正要防的是哪几件事

咱们这行真正能伤到公司的，按厉害程度排：

1. **垫资干活** —— 客户的钱没到就开工，收不回来就完了。头号杀手。
2. **项目亏了不知道** —— 材料加工人工悄悄超过合同价。
3. **口说无凭** —— 跟班组、材料商口头约定，事后扯皮。
4. **付错钱、重复付** —— 手一抖，同一笔钱付了两次。

对照一下现在的 13 条审批：**真正防第 1 件的只有一条**（钱没到不开工）；防第 3、4 件的靠的不是审批，是系统里已有的硬规矩——付钱必须传凭证、流水号不能重复、付过的金额锁死改不了。

剩下那十条审批，防的都是日常小事，却占掉了老板 90% 的点击。

**力气用错了地方：小事占满老板，大事只占一条。**

## 四、13 条审批，一条一条说清楚

### 原样保留的（7 条）

| 事项 | 现在怎么办 | 为什么留着 |
| --- | --- | --- |
| 钱没到不开工 | 没收到开工款，系统不让登记开工；封顶款没到，不让交付 | 保命的，全系统最重要的一条 |
| 项目提成 | 老板定好提成规矩，之后按规矩自动算 | 这本来就是"定规矩"，不是逐单批，不用动 |
| 绩效每期确认 | 老板看一眼这期绩效，确认后封存 | 一期就点一下，防止事后改账 |
| 工程移交接收 | 业务把图纸资料交给工程，工程核对后点"接收"或"退回" | 防交接丢东西说不清，很轻 |
| 客户签收图纸 | 图纸发给客户后，业务登记客户签了字 | 留凭据，防扯皮 |
| 客资撞单确认 | 一个老客户两个业务员在跟，负责人确认归谁 | 防撞单，很轻 |
| 门店方案确认 | 总部出方案，门店老板点头才往下走 | 本来就该门店老板做主 |

### 要改的（5 条）

**1. 报价/设计费要老板批 → 改成"按价目表"**
- 现在：业务每报一单价格，都要老板批一次。
- 以后：老板把常用价格先定好（比如设计费 198 元/㎡），业务按价目表报，系统直接放行；想报价目表外的价，才需要老板来批。
- 为什么行：小公司的单子，价格基本都是老板亲自跟客户谈的。这条审批防"业务员乱报价"，可这种情况很少见，却让每一单都多等一轮。

**2. 每笔付款要老板批 → 删掉，改成"每天一张清单"**
- 现在：付任何一笔钱（材料款、设计款、费用），都要老板先在系统里点同意。
- 以后：不用点了。系统守住三条底线：付的钱不能超过说好的数、同一笔钱不能付两次、每笔付款必须传凭证。然后老板每天打开小程序，第一屏就是"今天要付哪几笔、昨天付了哪几笔"。
- 为什么行：真实转账本来就是老板自己的手机银行在转（系统只记账，不碰真钱），钱出去之前老板本来就知情。系统里再批一遍，是重复劳动。

**3. 费用一笔一笔批 → 改成"超过一条线才批"**
- 现在：工地上的运费、人工费，每笔都要老板批。
- 以后：老板定一个数（比如 5000 块）。低于它，工程直接登记，钱直接进项目成本；高于它，才要老板点头。
- 为什么行：让老板批一笔 200 块的运费，是浪费他。看住大头就行。

**4. 工资要批两次 → 改成"批一次"**
- 现在：老板定算法 → 财务每月算出工资单 → 老板再批准一次 → 发钱。
- 以后：算法是老板定死的，工资单是系统按算法算出来的，老板看一眼总数没错就直接发。
- 为什么行：第二次批准批的是"数学题做得对不对"，这活儿该系统干，不该老板干。

**5. 客户直接付给材料商的钱，三道手续并一道**
- 现在：老板确认一次 → 财务记一次 → 再"另一个财务"核一次。
- 以后：财务记一笔、传凭证，完事。
- 为什么行：这笔钱是客户直接付给材料商的，不经过公司账户。而且公司可能就一个财务，"另一个财务"根本不存在——现在系统里写着"同一个人就自动算复核过"的补丁，等于自己承认这道手续凑不出人。

### 要删的（2 处）

**1. 老版本"验收要负责人再审一遍"** —— 新做法里已经不用了（工程人员记录完节点自动算验收过），这条只活在要淘汰的老版本页面里，跟着老版本一起删。

**2. 十二种"僵尸审批"** —— 之前改版时定了"这些事线下办"，但代码留着没删，界面上按钮还在，点了就报错（比如"绩效申诉"那个按钮，用户真点得中）。全部删干净。

## 五、改了之后会有什么不方便（丑话说在前面）

1. **"老板看不到每笔付款了？"** 看得到。每天有清单，每笔付款都带凭证，付重了系统拦。变化是：从"不批就付不了"变成"付了你要看一眼"。
2. **"有人把 15000 拆成三笔 4900 绕开那条线？"** 同一个收款方短时间重复报钱，系统会发现；每个项目总共花多少，老板随时看得到，三笔运费一起挂在成本页上很显眼。再说十几个人抬头不见低头见，为几百块拆单，不值当。
3. **"业务员贴着价目表下限报了个亏本价？"** 有这个可能。所以价目表得留足利润，这是老板定价时的责任；合同价和报价对不上，系统会要求重新确认。
4. **"老板不打开小程序看清单怎么办？"** 这是最大的软肋，说实话：以前是不批走不了（强制），现在是老板得主动看（自觉）。缓解办法是把清单放在老板打开小程序的第一屏，一打开就看见，不靠消息推送。**如果老板本人就是"每笔都要点同意才踏实"的性格，那这条就别改，或者先留着"付款审批"这一条试运行。**
5. **"改错了想退回来？"** 每条审批相互独立，删了哪条觉得不放心，单条加回来就行，不是拆了就装不回去。

## 六、分几步做（批次 D，接在 A/B/C 后面）

- **D1 清垃圾**（最安全，先做）：删掉 12 种僵尸审批的代码和死按钮；删掉老版本验收审批。做完系统行为不变，只是不再有点了报错的按钮。
- **D2 清单+价目表**（核心）：老板首页加"今日收付款清单"；报价改为价目表内自动通过。
- **D3 改流程**：费用加阈值线；工资两次批改一次；业主直付三道并一道。

每一步做完都能单独试用、单独回退。
