## 页面行为

沿用现有新增人物、补充定位布局。九个字段的简短示例仅放在 placeholder 中，不写入用户数据。参考本机乡墅爆款视频项目 `client/src/studio/PeoplePages.tsx` 的身份与业务、受众问题、表达风格、真实资料、代表口播及禁用承诺；真实资料示例不编造资质、年限或案例。

输入、表达标签和启用状态变化立即同步写入按租户、公司、用户、工作身份、人物区分的本机草稿。停顿700毫秒后串行同步云端；离开、恢复页面和恢复网络时补同步。新增人物未填写姓名也可保留草稿。两个子页面共用完整表单，关闭后重新进入可恢复。

保留“保存定位”作为正式确认：等待最新云端草稿同步后事务性创建或更新人物。未完成草稿不进入组织人物库，不参与文案改写。网络结果未知时冻结输入并重试同一确认版本，防止重复创建；确认成功后清除本机草稿，后端保留版本墓碑和确认回执。

页面只显示一行保存状态；同步失败保留本机内容并可点状态重试。云端版本冲突不自动覆盖，点状态选择保留当前填写或使用云端草稿。

## 后端

- `GET /franchise/content/personas/drafts/{key}`：当前公司、当前用户的私有草稿；key为new或人物ID。
- `PUT /franchise/content/personas/drafts/{key}`：`{revision, form}`，严格字段/类型/长度检查与版本比较。
- `POST /franchise/content/personas/drafts/{key}/publish`：`{revision}`，确认保存，事务内消费草稿并返回正式人物；重试返回同一人物。
- 错误码 `1114000009`：草稿版本冲突。
- 迁移 `V20261117.945__content_persona_drafts.sql`。提供防止清除非空草稿或确认回执的回滚脚本。

身份与所属公司取自登录工作身份；业务员只维护本人IP，负责人可维护组织IP，但不能读取其他用户的私有草稿。旧正式人物接口保持兼容。
