# 跨设备到账与模拟微信联调

本轮在 `feat/design-cross-device-20261022` 接通共享 HTTP 服务、独立角色会话、到账待办及模拟微信网关。用户已确认先用模拟微信网关联调。所有客户、金额、流水及图纸下发均为测试数据。

## 办理流程

1. 门店登记设计付款后，总部财务取得对应的到账任务。本轮预置一笔设计委托：总额 100 元、首款 40 元、尾款 60 元，设计已完成，门店已登记两笔付款。
2. 财务按实际到账金额、日期、流水和模拟凭据逐笔确认。少收一分钱仍保留差额；首款到账不提前开放图纸下发。
3. 当前委托版本的首尾款均足额到账且设计完成后，同一服务端事务保存到账原单、行政站内消息及通知发件箱。行政端在前台自动同步待办和未读消息。
4. 行政先模拟授权一次通知，模拟网关再自动投递。未授权、网关失败均保留站内待办；网关失败单独显示发送记录。授权可在到账前或到账后办理。
5. 行政点击模拟通知，沿网关返回的页面路径恢复本机服务端会话，核对授权项目，登记接收人、交付清单和渠道。确认下发后，原单保存下发记录并清除对应待办。

费用批准后仍可开始设计；正式图纸下发才核对总部实际到账。业务规则继续调用现有 `sales-flow`、`design-receipts` 和财务原单命令。

## 启动与连接

需要 Node.js 18 或更高版本，不增加运行依赖。

```sh
PORT=8787 npm run demo:design-collaboration
```

服务默认监听 `127.0.0.1`；省略 `PORT` 会分配空闲端口。启动后只输出地址及连接文件路径。每次启动生成独立的随机接入码，保存在被 Git 忽略的 `.tools/design-collaboration/connection.json`，文件权限为 `0600`。按该文件中的 `hq-finance`、`hq-design-admin` 各取本人的测试接入码，分别填写到两个客户端的“我的 → 跨设备模拟联调”。两端填写相同服务地址。

开发者工具使用隔离测试项目；原生自动化脚本仅在隔离副本关闭域名校验，不修改源工程配置。当前测试不改原有账号及业务账簿；每台客户端仅保存自己的服务端会话及授权数据投影。

如需后续局域网设备联调，可启动：

```sh
HOST=0.0.0.0 PORT=8787 npm run demo:design-collaboration
```

客户端需填写电脑可达的局域网地址，不能使用 `0.0.0.0` 或手机自己的 `127.0.0.1`。实体手机的网络、微信调试及域名配置仍需另行验收。本服务仅供模拟联调，不连接银行或生产数据。

`DESIGN_COLLAB_PRIVATE_DIR` 可指定另一个私有数据目录。服务重启保留原单、会话、幂等结果及投递事实；同一个数据文件只能有一个服务实例。停止使用 `Ctrl+C`，服务会等待正在运行的事务和通知发送结束后释放数据文件锁。

## 接口契约

统一前缀 `/sim/v1`，JSON 响应。除会话创建外均使用 `Authorization: Bearer <本机令牌>`。身份由服务端接入码确定，客户端不提交财务或行政人员身份。

| 方法与路径 | 用途 |
| --- | --- |
| `POST /sessions` | 用 `inviteCode` 取得角色会话 |
| `GET /snapshot?sinceRevision=N` | 获取当前角色的完整授权投影及版本 |
| `POST /receipts/:id/confirm` | 确认总部实际到账 |
| `POST /commissions/:id/complete` | 登记设计完成 |
| `POST /commissions/:id/dispatch` | 登记正式成果下发 |
| `POST /subscriptions` | 模拟接受或拒绝一次通知授权 |
| `POST /messages/:id/read` | 将本人的站内消息标为已读 |

写请求必须有 `Idempotency-Key` 和 `expectedRevision`。到账还需服务端快照给出的 `taskVersion`，绑定原单、阶段、版本及剩余金额；金额按元字符串提交，服务端按整数分处理。凭据仅接受 `mock-bank-receipt`。

保存结果未知时，客户端保留原请求和幂等键，自动重试一次；仍未核实则显示“核实上一笔操作”。明确的业务或权限拒绝不会自动重试。断网不回落到本地记账。服务端在原子保存后发生异常时重新读取磁盘；无法恢复一致性则停止后续写入。

行政投影只包含项目、需求、可办动作、消息及本人办理历史，不含银行流水、金额、凭据或客户电话。财务沿用现有权限，只取得授权到账任务；本轮没有为财务扩大客户图纸读取权限。

## 模拟微信网关

发件箱在业务保存后异步发送，具有授权检查、有限重试、超时和错误记录。事件编号作为网关幂等键；默认网关将已接受的事件记录在私有文件，服务重启不会重复模拟送达。

模拟投递记录单独显示在“消息 → 模拟微信通知”，不等同于微信已送达。通知链接只带项目编号，不带登录令牌、接入码或财务信息；打开后重新按本机服务端会话校验项目权限。行政停用不会阻止合法财务入账，重新启用后按当前业务事实重新派生待办并重新取得模拟授权。

真实微信接入还需要正式小程序配置、模板、账号绑定及用户主动授权。官方约束见[客户端授权接口](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/subscribe-message/wx.requestSubscribeMessage.html)和[服务端发送接口](https://developers.weixin.qq.com/miniprogram/dev/server/API/mp-message-management/subscribe-message/api_sendmessage.html)。本轮未调用真实微信发送接口。

## 验证与交付边界

```sh
npm run check:design-collaboration
npm run check:business:simplified
npm run check:design-collaboration:native
```

服务测试覆盖分笔差额、双财务并发、同请求幂等、停用、版本及权限隔离、服务重启、写盘异常和网关失败。客户端测试覆盖独立存储、断网、结果未知重试、自动同步停止及通知深链。

原生验收使用一个隔离行政模拟器与一个独立财务客户端进程，两者只通过真实 HTTP 服务共享业务事实。行政不手工刷新即可收到足额到账后的待办、未读消息及模拟微信投递，并通过投递链接办理下发。测试结束恢复行政模拟器原数据，检查本地原业务数据未改变及原生异常数为零。原生截图、结果和恢复记录位于 `qa/design-collaboration-20261023/native/`。

本轮未上传微信版本，未验收两台实体手机，未证明真实微信通知送达。生产后端、真实身份和微信配置的接入是后续独立交付步骤；本轮提供可运行、可复测的模拟闭环。

2026年10月23日验收结果：服务端故障与主链回归通过；客户端六组及页面四组通过；业务精简全套二十二个脚本通过；原生五组主链通过，恢复记录 `restored: true`，异常数为零。新增原生布局检查确认页头只占位一次，办理按钮跟随内容且不覆盖确认区域。服务端、客户端独立审查均通过，无剩余阻断问题。

项目静态检查、全部新增 JavaScript 语法检查和差异空白检查通过；生产依赖 `npm audit --omit=dev` 为零漏洞，无新增依赖。提交前检查不含真实密钥、令牌或接入码；私有连接及状态文件不进入 Git。两类客户端复用同一原单命令，不增加另一套到账或下发规则。

## 六角色模拟人员对齐

本轮默认财务邀请码对应 `hq-finance-dual` 罗财务，行政为 `hq-design-admin` 林设计，成果接收人为李业务。服务器继续校验现有组织成员及岗位，仅在模拟身份白名单增加这一已存在的可见人员；历史独立会话测试人员保留。跨设备案例仍是独立的“跨端联调客户”，不覆盖周建国家连续主链。
