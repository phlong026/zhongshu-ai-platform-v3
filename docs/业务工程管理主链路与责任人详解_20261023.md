## 二、业务主链路

主链：**李业务内容获客 → 李业务建档跟进 → 李业务预算与委托 → 张老板费用审批 → 王财务首款付款 → 罗财务核实到账 → 林设计登记完成 → 王财务尾款付款 → 罗财务核实足额到账 → 林设计下发 → 李业务确认/登记修改 → 林设计修改后再下发 → 李业务移交 → 张工程接收。**

| G06-2 开工阶段足额 | 王财务 | 按原项目和开工期次登记实际收款，核对有效净收款 | 足额才解锁约定提成总额的 50%，不足额保持等待 |
| G06-3 生成第一期应付 | 王财务 | 从阶段提成入口生成原项目开工提成应付 | 同阶段幂等，不重复生成；老板已确认规则，不再增加一次逐笔规则审批 |
| G06-4 支付第一期 | 王财务 | 进入该应付原单，登记实际付款日期、流水及凭据 | 应付与已付分别保存，只有实际付款计入支出 |
| G06-5 封顶阶段足额与支付 | 王财务 | 封顶期次实际净收款足额后，生成并实际支付第二期提成 | 解锁剩余 50%；奇数分余数归封顶阶段；不会把政策总额、应付、实付累计成三次支出 |
| G06-6 收款变化后的暂停 | 王财务核对收款事实 | 原收款发生有效退款、冲正或更正后，检查该阶段净收款和已付额 | 暂停有风险的未付部分；已付差额列为人工核对，不自动追回、不篡改旧支付 |
| G06-7 人工核对与恢复 | 张老板 | 在净收款重新足额后，核对原提成规则、变化依据和原支付，记录说明与凭据 | 满足条件后恢复原应付可办理状态，再由王财务继续实际支付 |
| G06-8 责任转交与历史 | 张老板/有权经办人查看 | 工程或客户后续转交后回查该规则和原阶段记录 | 原提成归属不随当前负责人变化，保留规则和核对历史 |

提成专项采用独立测试项目验证过 `100.01` 元拆为 `50.00＋50.01` 元等分币边界。它不代表给周建国家主案例新增了这笔提成；实际使用时按张老板对该原项目确认的总额与归属办理。历史退款仍按原单只读规则查看，上表未增加新的退款发起入口。

## 六、流程连通和数据核对要点

| 核对项 | 谁负责源事实 | 上下游如何对应 |
