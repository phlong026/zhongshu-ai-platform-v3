## 执行与证据

1. 开发检查：`npm run check:flow:all`。逐脚本输出写入 `.tools/full-flow-acceptance-20261023/checks/`。
2. 本地提交并推送本次开发分支，记录代码提交号。
3. 原生逐控件：`npm run check:flow:native`。独立项目和端口默认 9983；不占用其他聊天的原生项目。结果与截图位于 `qa/full-flow-acceptance-20261023/`。
4. 对发现的问题先复现、修复、复测，再提交推送。报告区分代码、Node 页面集成、微信原生模拟器、独立客户端与实体设备。
5. 完整验收报告记录实际通过、受限项、缺陷与修复、最终提交和远程一致性。所有场景保留可重放模拟数据；测试结束核对原存储恢复。

原生验收完成后，`npm run demo:flow -- --list` 列出 B/E 主链逐步数据及 C 纠错分支。`npm run demo:flow -- B06` 将指定快照载入本轮独立微信项目，随后可通过六人真实登录继续办理，客户及项目不重建。`npm run demo:flow -- --restore` 恢复手动载入前的原数据。该工具只操作本轮独立项目，不覆盖原开发项目或真实业务存储。

实体手机、真实银行、真实微信通知和生产身份服务不以本地模拟结果替代。现行关闭或推迟功能不计作本轮应完成功能，但检查其入口是否清楚且不会形成死路。
