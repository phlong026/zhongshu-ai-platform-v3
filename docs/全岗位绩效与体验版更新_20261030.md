# 全岗位绩效与体验版更新

本轮接续 `c91bd86`，包含前一轮游客登录图标、设计费用知会展示、待办排序、客户全流程进展与李业务个人绩效修复。源码分支为 `fix/todo-order-login-20261030`，目标 AppID 为 `wxe584f6fad7b54487`。

## 业务规则与改动

- 所有当前启用岗位共用本人月度目标、完成圆环和原单详情。门店覆盖业务员、业务负责人、工程人员、工程负责人、财务专员、财务负责人、老板、门店负责人；总部覆盖设计行政、财务专员、财务负责人、老板，共 12 个“组织类型×岗位”组合。
- 同一实际人员兼任多个岗位，读取同一组目标；不同人员、公司、月份隔离。老板仍管理本组织任务，员工只能提交本人的手动完成凭证。
- 在既有指标源上补齐“审核通过设计成果、实际收付登记、独立财务复核”三个自动目标。完成值从原业务记录采集，保留原单链接，不用页面占位数字。
- 老板派发、改派后产生受派人的站内消息；自动目标只知会，未完成手动任务进入本人工作台待办。排序使用原派发或改派时间；提交完成凭证后退出待办，改派后原负责人不可再见。
- 业务、工程负责人从团队进入成员绩效时，使用同一任务数据并只读展示；模型层校验公司、人员和管理团队范围。
- 复用现有绩效任务库、业务事实采集、消息已读标记和待办排序工具，没有新增依赖或数据库迁移。

总部运营岗位仍按原产品配置停用；登录页保留原六个演示账号。总部老板和其他内部身份用于隔离测试，不因此开放新的真实账号或权限。

## 主要文件

- `miniprogram/utils/performance-tasks.js`：自动指标与授权成员读取。
- `miniprogram/utils/performance-notifications.js`、`account.js`：任务知会和本人手动待办。
- `miniprogram/pages/admin/tasks/`、`organization-views-v2.js`、`model.js`：共用目标页面、团队入口和人员范围。
- 业务、工程、设计、财务和老板工作台：合并本人绩效待办后按时间排序。
- `scripts/verify-all-role-performance*.cjs`、`verify-performance-notifications.cjs`：岗位、数据隔离与原生入口验证。
