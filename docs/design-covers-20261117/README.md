# 户型封面恢复、图片加速与详情入口验收（2026-11-17）

已通过微信官方开发者工具上传开发版 **1.0.20261117.1638**，AppID `wxe584f6fad7b54487`；图片交付后端已部署。可扫描 [开发预览二维码](preview-qr.png)，或在微信后台开发版本中查看。二维码为开发预览码，有时效，不代表已设置为体验版。

## 故障原因与修复

现场在“创作模块 → 方案 Tab 首页”复现：标题和尺寸正常、图片数据已返回，但封面整排空白。原生节点测量发现 `.design-case` 继承全局按钮的横向 flex 布局，`.design-case-media` 和其 image 宽度均为 **0**。修复为明确的纵向卡片布局、封面宽度 100%、固定高度且不收缩。修复后的原生截图可见与户型一一对应的封面。

源图片本身正常：原系统列表有封面资产 ID，下载票据兑换成功，图片 HTTP 200。两张示例原图 2,579,329 / 4,516,732 字节。空白的直接断点为前端布局，不是本次已发现的资产缺失或源系统下载故障。

## 图片交付与缓存

- 列表使用最长边 **640px JPEG 缩略图**；详情使用最长边 1800px 预览；点击图纸时才下载高清原图。
- 通过已使用的平台 API 域名，携带当前员工身份下载图片到本地，再交给 image 组件。后端每次检查设计权限、户型当前发布状态及图片归属；服务器只向配置中当前使用的源图片桶取图，不接收客户端提供的外部地址，不把源签名地址持久化给小程序。
- 图片后端有响应字节、像素、并发与内存缓存上限。缩略图与预览可以短期复用，图片归属检查在缓存命中前执行。原图保持原字节。
- 可见区域及临近区域才开始取封面，同时最多 3 张；每张就绪立即显示。慢图不阻塞其他卡片，失败有占位和重试；图片组件自动恢复最多一次。
- 本地文件按租户、岗位、户型、资产、版本、尺寸区分；5 分钟后重取以重新核实发布/权限并获得新图。最多 120 个文件、30MB，清理久未使用文件。退出登录清理缓存和在途回写；存储不足时使用临时文件显示。

服务端真实复核，两张缩略图分别 **78,222 / 83,108 字节**，相较原图缩小约 97% / 98%。热缓存下同一链路取图约 0.08～0.09 秒；这是服务器验收测量，不等于真机网络耗时。

## 详情页

- 立面、每层平面使用同一组底部入口：**AI设计 / 快速预算**。
- 立面默认进入 AI 立面，平面默认进入 AI 平面；携带当前户型 ID、参考版本、尺寸、层数及已有参考资料。明确从详情开始新设计时预填参数；其他参考查询的保留手填输入规则不变。
- 快速预算新建独立草稿，带入当前户型已有参数，不覆盖之前的预算。缺少地区和工程量时留给用户填写，不生成假数值。
- 收藏移至标题右侧；真实接口验证收藏、取消，并恢复测试前状态。
- 详情只加载当前图纸，点击切换再加载对应平面；点击放大再取原图。

- 后端 22 项测试通过，包括 640px / 1800px 尺寸、原图字节保持、非法来源及错误响应拒绝、原有公开案例路由。
- 前端专项 47 项通过，包括首屏按需加载、单张慢图不拖住其他卡片、并发上限、持久缓存复用、到期重取、文件丢失重取、退出登录与迟到响应、存储不足降级、自动重试限次及参数白名单。
- `npm run check` 在本轮过程中通过；最终固定上传快照另行通过完整资源引用和包大小检查。最终官方上传主包约 **1.8MB**。
- 原生模拟器使用独立测试 AppID `touristappid` 隔离同时打开的同 AppID 编译缓存，**业务页面源码与上传包一致**，使用真实 B API 与图片下载，无 HTTP mock；上传仍使用真实 AppID 和原发布配置。测试副本的空白启动页未进入上传包。此项不代替 iOS、安卓真机及微信后台域名配置验收，需用本次开发版继续手机测试。
