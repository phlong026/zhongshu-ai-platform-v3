# 业务审批规则（2026-10-19 用户确认版）

2026-10-20 用户确认增补（详见[业务流程调整_20261020.md](业务流程调整_20261020.md)）：
客资取消分配/接受/退回，登记即归经办人直接跟进；方案报价取消现场实测，按预算参数与AI方案生成正式报价；建造报价后工程移交直达工程负责人，取消派单环节；设计变更段整体取消，工程接收后图纸只读。每条专业线为"专员+负责人"双角色，负责人拥有本条线全部业务办理权并新增团队管理与绩效视图。

2026-10-20流程顺序更新：新业务先办理独立设计委托、设计费用及成果确认，再核算建造正式报价并签建造合同。设计需求和设计服务费不再以前置建造合同为条件；既有金额审批、专业审核及财务核对规则继续执行。

| 事项 | 发起 / 登记 | 审批 / 审核 | 生效条件 |
| --- | --- | --- | --- |
| 前期 AI 平面、立面、预算试算 | 业务人员 | 无 | 保存为沟通方案，不能替代正式图纸、报价或合同 |
| 正式报价及合同金额 | 业务人员 | 本组织老板 | 老板批准当前报价版本后登记双方已签合同；合同金额和报价版本必须一致 |
| 设计服务费 | 业务负责人 | 本组织老板 | 老板批准服务费总额、约定及首尾款分配后产生付款事项 |
| 设计首尾款、材料采购付款 | 原业务 / 工程事项发起人 | 本组织老板 | 每期 / 每笔付款按当前金额和依据审批，之后交财务登记实际支付 |
| 正式设计成果、施工图、设计变更 | 设计师 | 设计负责人 | 总部审核人回避本人参与的版本；加盟商在后台分别配置设计师和设计负责人，可由同一实际人员兼任 |
| 涉及金额调整的设计变更 | 设计师 | 设计负责人审核技术，老板审批金额 | 两项均完成才能登记补充协议 |
| 客户成果签认 | 获授权业务人员登记真实客户凭据 | 无内部二次确认 | 材料、日期及正式下发版本齐备后保存即生效；已签认版本只读 |
| 施工阶段验收及整改复验 | 指定工程人员 | 同人配置直接生效；分人配置交工程负责人独立验收 | 根据后台在岗人员、工程团队和实际人员标识判断；独立验收未通过不能完成节点 |
| 施工交付 | 指定工程人员 | 无单独交付核验 | 施工节点、阶段验收、整改及交付资料齐备后直接交付，可归档 |

财务实际到账、付款登记和核算继续保留原笔关联、实际凭证和人员记录，不能替代老板对金额事项的审批。原有财务专员 / 财务负责人同人自动复核、分人待办规则继续适用。总部到账与门店付款仍分别登记，不能用一侧的付款凭据代替另一侧实际到账。

本轮暂不开放退款、金额更正、付款结果不明核实。对应入口、待办和执行接口关闭，历史记录保留。视频发布沿用用户已经确认的免审核流程：选择发布账号，发布后填写链接，其余作品信息自动带入并保存待回采来源。

## 已验证

- `node scripts/verify-role-same-person-main.cjs`：12 个完整流程阶段，通过内容发布、获客、设计、正式报价、老板金额审批、合同、付款、总部设计、施工、直接交付及归档。
- `node scripts/verify-confirmed-approval-policy.cjs`：11 组权限与分工校验，覆盖老板独占金额审批、合同金额绑定、后台配置门店设计双岗位、门店同人设计和施工图审核、总部回避、分人阶段独立验收、关闭本轮排除事项、客户一次签认、设计变更正式文件的提交及审核。

以上为本地模拟业务数据及真实 Page 处理器 / 模型校验；不执行外部发布、签章、银行转账或真实 AI 生成。微信开发者工具的实际页面验收证据单独存档。

门店设计配置：本店在岗人员已分别配置设计师、设计负责人后，新需求归本店设计团队；未配置时沿用总部设计。已经提交的需求不因后来配置变化而自动改换设计组织。本店实际费用须填写实际收款人，经老板审批后由财务登记，避免生成本组织对本组织的往来到款任务。

历史金额事项：保留已有实际付款、到账及原始凭据的账簿展示。既有服务约定缺少新版老板审批时，老板可审批当前原约定，后续付款继续走老板审批；补充审批不改写历史实际收付款。
