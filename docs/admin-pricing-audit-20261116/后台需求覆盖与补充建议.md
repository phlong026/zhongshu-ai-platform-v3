# 后台需求覆盖与补充建议

2026-11-16。范围：本项目 B 平台管理后台、相关岗位业务接口及现行计费目录。

## 结论

现有后台已具备组织开通、账号维护、角色权限、组织详情、公司积分和部分运营记录，能够承担基础开通和人工管理，但尚未完整覆盖加盟商持续运营。本轮已补统一定价管理；接下来最需要补的是组织资料维护、能力开通、AI任务与积分异常工作台、现行经营指标，以及人物和课程等业务资源的维护入口。

后台应围绕“开通组织 → 开通能力 → 成员使用 → 计费结算 → 业务交付 → 异常处理”组织内容。岗位工作台承担客户、工程、财务等具体业务；平台后台应提供有权限的跨组织查询、配置和支持工具。不能把所有岗位接口直接开放给平台账号，也不能用平台账号冒充员工岗位。

本次检索了平台及加盟商域的58个控制器、295个请求方法声明。这是源码盘点，不代表295个接口已部署、已通过验收或都应直接出现在平台后台。详见 `backend-controller-inventory.json`。

## 本轮统一定价页面

入口：`https://platform.zszhj.com/admin/platform-pricing`，侧栏“定价管理”，公司积分池也提供跳转。

| 分组 | 科目 | 现行计量单位 |
| --- | --- | --- |
| 视频生成 | 数字人口播视频、AI 视频768P、AI 视频2K | 秒 |
| 数字人与声音 | 数字人形象制作、语音克隆 | 次 |
| 文案与语音 | 链接解析、文案改写、语音转写、笔记润色 | 次 |
| 设计与预算 | AI 平面、AI 立面、快速预算、提示词调用 | 次 |

页面显示单价、最低收费、配置状态和价格版本；支持分类、搜索、待配置筛选和费用试算。微积分按整数运算，数量乘单价向上取整，并遵守每笔最低收费。调整价格复用已有权限及幂等发布接口，包含原因，失败后保留原请求以便确认。

待定价不等于免费；没有发布到服务端的能力显示“待服务发布”并禁用设置。没有取得成本不等于成本为零。没有提供运营价格的项目，本轮不擅自写入生产价格。

“其他价格与成本”汇总历史充值套餐、历史设计价目、设计调用成本和配置审计入口。设计服务费按总部设计岗位授权维护；预算材料和施工报价与AI调用积分分开。旧价目不能简单同步成公司池价格，否则可能造成口径混乱或重复计费。

新增的调价历史接口读取最近200个价格版本，包含能力、单价、最低收费、状态、操作人、时间和原因，复用总部与账号门禁。不新增数据库表，不修改登录逻辑。后端补充详见后端工作副本 `docs/pricing-backend-handoff-20261116.md`。

## 本轮布局处理

- 公共内容区限制在可用宽度内；筛选条件、按钮、分页允许换行。
- 宽表使用原生滚动条，空表也可横向查看所有表头；长文本换行，保留实际内容。
- 用户管理按内容区宽度切换上下布局；账号、姓名、部门等字段设置合理最小宽度。
- 定价管理在宽窗口显示表格，在窄窗口显示完整卡片，减少来回横向查找。
- 弹窗限制在视口内，正文滚动，标题和操作区保持可访问；窄窗口表单标签放在字段上方。
- 正式后台关闭模板开发文档提示，时间戳转换成可读日期，去掉重复/空白面包屑。

实际浏览器断点检查采用390×844、1440×900，并检查默认约786像素内容视口。截图与逐页结果见本目录；未执行真实收费生成、生产调价或用户密码修改。

## 需要优先补齐的业务内容

### 组织资料维护和能力开通

当前组织详情没有完整的资料编辑入口。现场可见“所在地区”包含门店名文字，应将省市区编码与门店名称、详细地址分开维护，并支持修正资料。老板变更应关联账号、岗位和审计，不能只改显示姓名。

建议组织详情补充“资料维护”和“已开通能力”分区，显示启用能力、停用原因、关联成员权限、微信绑定状态及最近一次变更。调价和能力开通是两个不同动作：发布一个新能力的价格，不应被当成某家组织已经获准使用该能力。

平台账号与加盟商日常账号应清楚区分，多任职人员显示当前组织和岗位，不用平台角色名替代本人姓名。不能以超级管理员能打开页面，替代各岗位业务验收。

现行后端已停用员工月度额度，旧个人充值页也已退役，统一使用公司共享积分池。后续继续维护成员业务权限和实际消耗统计，不重新引入个人钱包或员工月额度。

### 任务与积分异常处理

组织详情已聚合内容任务与设计命令，但平台仍缺少跨组织处理工作台。建议按组织、人员、能力、状态和时间筛选，任务详情关联请求编号、供应商任务、使用量、价格快照、预扣、结算、释放和人工核验记录。

API错误日志中可见历史设计查询的通信异常。这种日志不能直接证明供应商任务已经失败；查询重试、重新创建任务和退款应分开处理。应优先提供只读核对，再接入已有业务权限控制下的人工核验入口，避免重复发起收费任务或重复退款。

### 现行经营指标和成本

首页已展示组织列表，但主要经营统计仍在历史钱包折叠区。建议增加有效组织数、活跃成员、现行积分余额和消耗、生成成功率、长时间在途和待核验数量，并能点击进入对应明细。指标必须注明统计时间和口径。

成本页面应分别展示已取得的供应商成本、尚未取得成本的任务和结算状态。用户积分、充值人民币、人工设计服务费、材料施工报价需分别统计。未来增加模型、清晰度或收费规格时，应扩展服务端可报价目录和价格快照。

### 业务交付和内容运营

总部设计需要桌面端的委托分派、交付进度、服务费规则与收款对账。课程、模板和公告需要可维护的目录与上下架功能。人物制作、声音、素材与作品需要按组织归属查询状态和授权，不能把系统文件列表当作全部业务资产。

如加盟签约和续期也纳入本系统，再补合同、期限、续期和附件管理；当前的组织启停状态不能代替合同状态。

## 下一阶段验收标准

| 场景 | 应达到的结果 |
| --- | --- |
| 门店更名或联系人修正 | 管理员可修改授权字段，列表与详情一致，保留修改前后值与原因；不因改名丢失账号、积分和任务归属 |
| 新能力向组织开放 | 能区分能力价格、组织开通和成员权限；未开通时有明确提示，服务端也拒绝越权调用 |
| 任务长时间未结束 | 管理员可定位组织和任务，核对预扣、远端状态与结算事实；重复操作不会再收费或重复退款 |
| 调价期间仍有在途任务 | 新任务采用新版本，原任务保留原价格快照；历史版本、原因、操作人可追溯 |
| 组织关闭或删除 | 显示在途和余额等阻止原因，按已有规则处理；历史查询与恢复入口保持清楚 |
| 总部处理加盟商问题 | 仅按授权查看业务记录，平台身份与员工岗位明确区分，支持动作留痕 |

## 下一轮可执行范围

1. 运营确定形象制作与语音克隆的真实价格后，从已上线的统一定价页面发布。
2. 建“AI任务与积分异常”工作台，优先实现跨组织只读筛选及已有人工核验的受控入口，形成任务—扣分—退款的关联查询。
3. 补齐组织资料编辑、能力开通与成员权限分区，同时更新首页现行公司池指标；沿用公司共享积分规则。
4. 再补总部设计桌面交付、课程与内容维护、成本汇总及经营报表。

## 证据与限制

源码证据来自当前项目的 `projectNavigation.ts`、`remaining.ts`、`fr.ts`、平台页面及平台/加盟商域控制器；价格来自服务端现价目录及 `BillingPriceCatalog`。组织权限、内容域人工核验、课程进度与总部设计计价分别有现存业务接口，缺的是适当的管理页面或汇总能力。

本轮截图支持界面与操作入口判断；权限测试、整数计费及幂等重试由自动化测试补充。截图不能证明全部业务流程、生产扣退分、真实成本或无障碍合规已经通过。真机登录由登录会话继续验证；各岗位完整业务流程仍需单独验收。

前端定价与相关回归47项、后端定价权限及数据库相关15项通过；通过Vue类型检查、局部代码/样式检查及Vite生产构建。最终发布版本和页面检查见 [验收与发布状态](验收与发布状态.md)。
