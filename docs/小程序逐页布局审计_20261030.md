# 小程序逐页布局审计与统一整改

日期：2026-10-30。范围为 `miniprogram/app.json` 注册的 34 个路由及其 WXML/WXSS/JS。盘点包含单路由内由 `view`、`wx:if`、`wx:elif` 驱动的子状态；逐页问题、建议和证据汇总见 `qa/layout-unification-20261030/source-inventory.json`。

方法：先从 app.json 建立路由清单，再读取各路由 WXML/WXSS/JS，统计按钮和文本节点、识别局部字号/字体/间距覆盖，最后按信息密度和操作风险排序。源码盘点只证明结构和潜在问题，不证明真实渲染；模拟器截图、真机安全区、点击命中和实际长文案换行必须另行验收。

全局已有 `styles/tokens.wxss`、`controls.wxss`、`unified.wxss`，但工程、委托、管理、创作等页面仍保留局部字体、字号、圆角、固定高度和间距。统一修改应优先删重复规则，保留业务语义和状态色；不应把所有页面强行改成同一版式。

逐页清单、view 数组和整改建议以 JSON 为准。最高优先级是 account、workflow、build/record、admin/finance-desk、studio：这些页面的按钮和文本数量高，最容易出现重复说明、多个主 CTA、卡片嵌套和窄屏换行问题。

验收分层：

1. 源码静态检查：路由、view、字号令牌、固定高度、按钮数量。
2. 模拟器截图：标题位置、按钮宽度、长文案换行、卡片密度和滚动后底部操作。
3. 真机/角色验收：安全区、点击命中、真实数据长度、权限下页面可见性。

本文逐页表属于源码检查；后文原生截图单独列出实际覆盖和缺口，不能据此宣称全部子状态或真机已验收。

## 分析结论与落地方案

目前已有统一主题，但历史页面持续增加局部覆盖，导致“令牌相同、最终观感不同”。此次采用渐进收敛：共用字体、字阶、卡片和按钮规范；首页保留品牌展示，财务保留数字主次，工程保留节点和凭据结构。页面风格统一不等于所有页面排成同一张表单。

设计参考：[华为 HarmonyOS 设计理念](https://developer.huawei.com/consumer/cn/design/concept/) 的统一架构、清晰信息和圆角卡片，以及[字节 Arco Design Mobile 官方项目](https://github.com/arco-design/arco-design-mobile)的简洁克制、触控优先和主题复用。这些是方向参考；以下尺寸是结合众墅业务密度制定的项目规范，并非声称逐项复制华为或字节的小程序。

|检查维度|发现与影响|本次处理|
|---|---|---|
|字体|工程保留 Regular/Medium/Noto 多套字体引用，业务曾保留宋体标题声明，模块之间字形/字重不同|统一到系统黑体字体令牌，导航/常用区块标题600字重|
|标题|全局section-title为40rpx，局部32rpx；不同标题行高和装饰条各自覆盖|普通导航与区块标题32rpx、行高约40–46rpx；欢迎语/经营数字继续使用40/48rpx等数据层级|
|正文|26rpx正文与28rpx业务正文混用；说明大小与主次不稳定|通用正文28rpx；辅助信息24rpx；状态/紧凑元信息22rpx；不以缩小必要信息换取空间|
|间距|26/28/29/32rpx页边距与20/22/24/28rpx卡片内边距并存|共享页边距28rpx、常用卡片内距24rpx、区块间距24rpx；品牌首屏与特殊数据网格保留场景适配|
|按钮文字|多处“记录服务方提交…”冗长，弱化实际动作|精简为“提交方案/提交成果/补交文件/优化提示词/选择合同依据”等明确动词|
|按钮排布|通用底部按钮固定88rpx，长动态文案可能两行仍被限高；链接用负边距扩张点击区|底部操作仍随内容滚动；同组等宽、可自然增高、居中换行；删除链接负边距，让容器容纳实际点击区|
|窄屏|施工节点4列菜单包含文字与数量，字体统一后更易拥挤|≤360px时改成2列；保留动作与数量完整显示|
|禁用状态|协同页busy按钮缺专属禁用背景，可能仍呈可点击棕色|补齐统一背景、边框、灰色文字与不透明度|
|组件隔离|部分导航把zs-theme放在占位节点，实际头部为兄弟节点|将主题类挂在真实头部根节点，避免隔离环境中变量失效|
|登录顺序|原生截图可见主按钮在协议确认之前，用户先看到提交再看到前提|协议确认行移到登录主按钮上方；登录处理与校验保持原路径|
|冗余和能力边界|内部研发表述与必要的模拟能力说明混杂|压缩内部口吻，保留模拟支付、模拟通知、真实微信授权待接入、课程视频准备中等真实边界|
