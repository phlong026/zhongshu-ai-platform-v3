# 六岗位闭环测试规格

- 单元/行为：customerId与commissionId分离，真实DTO与Long字符串，checked UI仅转换confirmed协议，新建后同一commission回读，版本变化/网络失败保留表单，迟到账号/岗位结果丢弃。
- 财务PG：应付双阶段幂等生成、按版本归属、分笔/净额/退款/退回、双方不足分别阻塞、足额放行、重复/并发不重计；门禁/allowedActions/todo同口径；避免循环依赖的Spring完整上下文测试。
- 资产PG/服务：PDF/PNG/JPEG真实字节上传及complete；类型/大小/哈希错误；未ACCEPTED/错误组织/伪URL/旧版本；总部上传门店业务/指定工程只读下载；跨门店及通用端点依旧拒绝；移交版本冻结。
- 规则：标准面积定价与历史首尾模式分别验，不能把历史两期费用混同建房三期。材料劳务应付、回款和工程节点事实独立；原单/资产/版本/金额可追。
- 工程：对照.3新recordFlow，准备三期之和、实际开工第一期条件、材料采购到货与付款、节点PASS留痕/撤回/更正、基础和封顶事实与资金放行、签收/结算/归档；无虚假完成。
- 项目账：同项目与前置委托费用完整分页，收付退款/退回净额和汇总一致，日期归月与未知日期明确，禁止跨组织。
- 原生E2E：真实wx.login已绑定145、六岗切换保留会话，沿已有客户/需求/预算/合同续跑；资产可使用标记TEST ONLY合成附件，文件选择器若用SDK夹具必须独立披露，文件保存/真实上传/COS/校验/下载不得mock；资金为隔离线下登记，不发起实际银行或微信支付。
- 用户边界：同人多岗不替代双人审批验收；真实渠道或必要独立人员若缺失，记录确切缺口并推进其它分支，禁止跳过服务端门禁。
- 证据：run-manifest固定前后端SHA/运行JAR/DevTools目录和文件hash；每动作method/path/HTTP/code/ID/状态/待办；控制台逐条归因；刷新/重进GET相同单据；截图可见真实数据。仅完成页壳/空态不得记全流程通过。
- 发布/回退：完整相关前后端检查和独立复审、A保护指纹、B备份与逆迁移/回退说明；只本地提交和B隔离修复，不上传或切换微信开发版体验版；商城展示不扩建。

- 校准必测：AREA_FULL为单一全额阶段、first/tail均0，独立总部计价版本与预算面积被冻结；历史split保留首款完成/双方首尾放行，不能擅自拆比例。
- 预算跨域：报价与BUDGET同事务，失败整体回滚；重放不重复方案版本，旧客户通过正常UI保存新版本，不用GET暗写或伪造ready。
- 下载：B相对票据须同B源和认证头，外部COS不能泄露头；HTTP200 JSON业务错误不能当PDF打开；过期/用尽票据重新申请，旧会话不展示文件。

- v3资金并发：全部资金变更锁先于行锁；原付款分笔核收不得超额；同阶段并发核收/退款与dispatch必须有可解释串行结果；complete后退款保留完成并阻塞dispatch，dispatch后退款保留成果事实并投影异常待办。
- v3权限：第二普通工程员工正常认证接收，提交人/接收人相同必须被拒；辅助账号非微信绑定的认证缺口独立披露，不冒称双微信真机通过。
- v3资产：manifest唯一不可变，旧版/退回/跨门店/撤岗/过期/重复票据逐项反例；消费而不只签票时核scope，第三方不收到Bearer，通用端点仍拒绝跨owner。
- v3账目：项目summary与分页ledger同查询范围，纳入sourceCommission前置设计资金，不能由不完整前端分页拼总额。

- v4：design写入缺幂等键拒绝、同键并发唯一；MANDATORY无事务调用拒绝、外层失败双侧应付/状态一起回滚；budget或pricing任一过期拒绝且保留表单；附件/客户确认误用FIN_VOUCHER或DESIGN_REFERENCE必须拒绝。
