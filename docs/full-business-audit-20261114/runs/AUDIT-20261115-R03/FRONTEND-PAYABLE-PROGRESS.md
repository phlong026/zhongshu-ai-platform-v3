# 应付余额与付款入口校准

原生主链已生成210元材料应付，财务应付列表显示原单但不显示“登记付款”。GET payables返回FinPayableDO，不含paidCents；原前端以totalCents > undefined判断，按钮恒不可用。付款选择器又将缺失paidCents当0，会错误展示已部分付款事项的未付金额。

统一以现有付款、支出退回事实按payableId/paymentId精确聚合：已核实付款减pendingLinkCents，减对应有效支出退回；作废不参与，客户退款不误扣。应付原单页批量读取三组事实，没有逐单请求；全量财务页面的付款选择器复用已加载数据。缺失/重复付款及异常金额进入既有错误态，不虚构零已付。老板只读项目账仍不调用全量财务接口。

新余额7项、老板只读8项及独立相关28项通过；修正旧PF测试替身为真实模块后，完整npm run check通过，集成157项通过。独立复审批准。原生主链将经现有“付款登记→关联应付”完成真实系统登记；新行内余额在最后客户端刷新后只读核对，不重复已成功付款。
