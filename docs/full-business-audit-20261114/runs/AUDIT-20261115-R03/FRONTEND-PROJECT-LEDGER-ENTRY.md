# 工程原项目付款入口校准

对照 `8f5e6fb3`（开发版 1.0.20261030.3），`record.operating` 原本携带当前项目 ID 进入材料应付或成本页。B 分支把入口指向固定老板首页，导致项目上下文丢失。

本次仅将 B 门店老板、门店负责人、财务专员、财务负责人的“材料及费用付款记录”真实按钮接入已有 `finance-desk?view=project&id=工程ID`。页面身份代次、当前岗位、页面工程 ID 与已加载项目 ID 必须一致；旧会话、隐藏/卸载页及 ID 不符拒绝跳转。其他岗位和原 fallback 不变，没有新增总部老板身份或首页结构。

验证脚本 `scripts/verify-engineering-project-ledger-entry.cjs` 从实际 WXML 读取按钮绑定后派发事件，覆盖四岗位正确导航、切岗/重登/旧项目拦截与总部不获门店入口。它是本地行为测试，不代表原生 UI 验收。已注册 `npm run check:engineering-ledger-entry`，并纳入 `npm run check`。

私人 Phase4 脚本只准备，未执行。后续原生路径为：微信登录145 → 选择单一门店老板 → 首页“工程项目” → 同一工程 → “项目收付款” → “材料及费用付款记录” → 同项目账。先读取 Phase3b 实际最终状态，再核对合同三期48万元与设计/材料/人工4310元付款，观察请求及控制台。脚本不会直接导航项目账冒充自然入口，也不会写业务数据或修改业务响应。

## 目标页权限补齐

复审发现原财务页仅支持财务岗位，老板虽能正确导航却落入无权限状态。现为门店 `boss/owner` 增加独立只读项目模式：必须 `view=project`、正整数项目 ID 且与进入时的登录/岗位代次一致；只请求该 ID 的 `projectLedger`，不初始化财务登记层、不请求全量收付款、设计费、用户资料或财务待办。切岗后清除已显示项目账，分页和迟到结果均受身份守卫限制，需退出旧页重新进入。

老板只读模式隐藏原有三期回款、材料采购及人工费用按钮，不能经 `go` 转入登记；财务及财务负责人原有入口、全量数据和登记层保持不变。没有开放总部老板或退款权限。`scripts/verify-finance-project-readonly.cjs` 使用真实目标页和项目读取 helper 的 VM 集成，覆盖岗位、入口、切岗及三个真实按钮的可见条件，注册到主检查链；非真实 DevTools 验收。
