# 客户跟进改为八步流程唯一口径（2026-11-26）

业务板块的“客户”模块原来有两套并行的跟进：客户工作区里的“记录跟进”弹层（写升级前的普通跟进表），和 11-25 上线的八步跟进页。两边的“待跟进”算法不同，客户也没有“流失 / 暂缓”的出口。按 2026-11-26 确认的方案和效果图，八步流程成为唯一的跟进事实，“记录跟进”从小程序下线。

- 配套后端：`backend-main` 的“八步流程成为客户跟进的唯一事实”（迁移 `V20261126.1104`）。
- 发布顺序：**后端先上线，小程序再发布**。新小程序依赖新增字段和接口，提前发布会缺数据、进不了时间线。
- 本文只记录代码改动和自动化检查结果。没有上传体验版，没有真机验收。

## 口径

服务端和小程序是同一套规则，数字来自服务端汇总接口，小程序不再把客户拉全量到端上累加。

| 名称 | 定义 |
| --- | --- |
| 今日待跟进 | 未流失，且（还没有任何跟进记录，或约定的下次跟进日期已到，含今天） |
| 预约跟进 | 未流失，且下次跟进日期晚于今天。暂缓的客户约了再联系日期，也在这一栏，置灰显示 |
| 已到店 | 未流失，且第 2 步“店面讲解”有记录，或升级前登记为“实际接待”的普通跟进 |
| 全部 | 可见范围内的全部客户，含已流失、暂缓（置灰） |
| 下次跟进日期 | 只有八步页上的“下次跟进日期”一个来源，保存步骤时写到客户上 |
| 流失 | 必须选原因：价格超预算、选了同行、方案不满意、暂不建或推迟、联系不上、其他（选“其他”自己填）。不再出现在三个分栏和待办里；恢复后下次跟进日期落到今天 |
| 暂缓 | 必须填原因和晚于今天的再联系日期；到期自动回到今日待跟进 |

## 改了什么

**客户工作区**（`pages/workflow/index`，“跟进”页签）

- “记录跟进”弹层和表单删除，改为八步进度条加跟进时间线（每页 20 条，可继续加载）。
- 时间线合并五类记录：步骤记录、补充记录、状态变更、客资再次咨询、升级前的普通跟进。
- 底部操作：进行中是“暂缓跟进”“标记流失”，已暂缓或已流失是“恢复跟进”。点击进入八步页并自动打开对应弹层。
- 只读身份（老板、没有写权限的岗位）不显示状态按钮。

**八步跟进页**（`pages/customer-flow/index`）

- 表单顶部新增“下次跟进日期”，和发生日期并排。“完成本步”必须填且不能早于今天，“仅保存”可不填。
- 第 1 步原来单独的“下次联系”由顶部的“下次跟进日期”取代。升级前的小程序保存“下次联系”时，它只留在那一步的记录里，不影响客户列表的提醒日期（沿用 #287 的决定：列表只认客户的下次跟进日期）。旧记录里已有的“下次联系”在新版保存时原样带回，不会丢。
- 顶部的流程状态可点，直接打开暂缓、标记流失、恢复跟进的弹层（`status-sheet`）。
- 标记流失：原因六选一，选“其他”必须自己填。暂缓：原因加再联系日期。恢复：直接提交。
- 提交前先读一次服务端当前版本；别人刚改过就提示刷新，不覆盖。结果未知时重试沿用同一个幂等键。

**客户列表**（`templates/sales-customers.wxml`、`utils/sales-customers-page.js`、`utils/platform-crm.js`）

- 分栏“预约回访”改名“预约跟进”。行内显示当前步骤和“N/8步 · x%”。
- 已流失、暂缓的客户置灰，仍可进入。流失行的按钮是“查看 / 恢复”。
- 流失后又有客资登记进来的客户，行内提示“再次咨询”并用提醒色显示（列表顺序仍按服务端返回，最近更新的在前）。负责人同时收到“流失客户再次咨询”待办。

**待办**（`utils/platform-todos.js`）

- “首次跟进”“到期回访”改为“待首次跟进”“约定跟进到期”，点击直接进八步页。
- 新增“流失客户再次咨询”（负责人确认是否恢复）。
- 业务负责人新增“超期未跟进”：新客户登记 2 天仍没有任何跟进记录，或最近一次跟进超过 15 天且没约下次。

**业务首页、老板首页**

- 客户数字改读服务端汇总（`customers/follow-summary`），和列表分栏同口径。
- 进入“预约跟进”分栏的入口同步改名；逾期提示改为“N 个客户跟进已逾期”。

**数据层**（`api/franchise/crm.js`）

- 新增 `followSummary`、`timeline`、`workflowStatus`；删除 `follow`。

## 与效果图的差异

效果图在 `效果图/20261126-客户模块-八步跟进-待确认/`（本机目录，不进仓库）。

- 效果图里“标记流失 / 暂缓跟进”弹层盖在客户工作区上。实现把弹层放进八步分包（主包余量不够），工作区的按钮改为进入八步页并自动打开。字段、选项、校验与效果图一致。
- “完成本步必填下次跟进日期”目前只由小程序把关。已发布的八步页版本不带这个字段，服务端现在只校验和保存，等旧版本退出后在清理批改为服务端必填。
- 主包里没有任何引用的 `pages/engineering/assets/project-chen.jpg` 改为不上传，文件保留在仓库。

## 兼容

- 升级前的小程序仍调用 `POST /franchise/customers/{id}/follows`，后端原样保留一个版本。它照常更新客户的最近跟进时间和下次跟进日期，所以并行期间老版本登记的跟进在新列表里同样生效。
- 本地样例数据的待办（`utils/sales-todos.js`）没有改，它不走后端。
