基线：`6194cf1`，当前整改分支。按业务行为保留、测试先行、每个逻辑批次独立提交执行。

1. 修复设计协作待办：已有 HTTP 回归可复现行政待办丢失。先增加命令契约检查，查明展示话术与流程识别的耦合，再修复来源；保留支付、角色及幂等规则。
2. B5：存储键集中、金额解析尾项。先覆盖旧键及各解析器的容错差异，不能因抽工具改变存量数据或有效金额。

4. B7：逐类组件迁移。保留事件、数据集、空态、权限与样式上下文；已有组件优先，属性和插槽只覆盖实际需求。
5. 整合 main 的管理 A/BCD 成果，逐项解决冲突；不重复开发已有报销、放行、账本和对账能力。
6. B8：令牌、字号、Tab/按钮规范收尾。先建立样式约束及可视基线，统一语义后复测原生交互。

每批：针对回归、`npm run check`、完整相关流程、变更文件语法/差异检查、敏感信息与依赖审计、反向补丁检查后提交。最终同步清单和实际验收边界；模拟检查不能代替真实设备、后端支付和发布验收。
