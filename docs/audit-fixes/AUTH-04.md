# AUTH-04：本人资料按账号归属缓存

## 修复范围

复用现有 HTTP 会话、请求序号守卫和 `platform-profile` 视图模型。没有引入新的登录方式、认证服务或资料接口。三种真实登录结果已有 `userId`；缓存归属使用其字符串原值，不把长整数转为 `Number`，也不从姓名、账号别名或旧岗位缓存推测身份。

HTTP 层保存当前登录用户标识，与“记住账号”选项保持一致；已有自动登录凭据中的 `userId` 可继续使用。真正 `saveLogin`（包括同一用户重新登录）清空当前资料，普通切岗和同用户令牌续期保留已确认属于该人的资料。`auth.logout`、直接 `http.clearSession`、HTTP 401 和正文 401 都清掉当前资料及其归属；旧会话的迟到 401 不能清掉新会话。

`account.load` 是共同读取边界：API 会话只接受 `apiUserId` 与可信登录用户一致的资料。无归属或归属不符的旧缓存不会作为展示、编辑姓名或头像上传时的初值。没有 token 且没有合法离线登录的旧版本资料也会清成访客；不记住登录的冷启动同样清理资料。已有合法离线登录资料继续沿用原逻辑，业务草稿与历史离线数据不被资料清理删除。

`GET/PUT /platform/profile/mine` 的完整响应为资料真源。远端 `avatar=null` 明确恢复默认头像，`mobile=null` 明确清空手机号，不保留上一份本地值；响应 `id` 与当前登录用户不一致时拒绝写入。首页、个人资料页与身份页显示明确的加载/失败提示，失败后可以重试，不把“加载中”等提示存成姓名。

## 异步与升级边界

- 资料 GET、头像上传、头像 PUT 与姓名 PUT 都沿用现有会话守卫；隐藏或卸载页面也使本页旧响应失效。复用的编辑页换账号会先清掉旧输入。
- 补上本地 `wx.saveFile` 成功和失败回调的会话/页面守卫，避免离线选的头像在新账号登录后才写入资料。正常离线头像保存仍可用。
- 成功写入资料后作废之前的资料 GET，旧读取不能覆盖刚保存的姓名或头像。
- 读取或保存中离开个人资料页，返回时重新读取，避免旧回调被丢弃后一直停在加载态。
- 极旧 token 如果没有登录用户元数据或续登凭据，不复用任何旧资料缓存。本次认证 GET 可以展示返回的本人资料；再次读取本地资料时仍要求可信登录归属。正常重新登录后即可恢复同用户缓存复用，未从旧缓存自动补身份。

测试已加入原 `check:profile-navigation`，由前端 CI 的 `npm run check` 实际执行。既有导航、资料/培训、消息序号与官方头像脚本修正为真实登录 `userId` 和完整资料 DTO，保留原权限、导航、上传失败与后发请求优先断言；没有通过放开无归属缓存让旧 fixture 继续通过。
