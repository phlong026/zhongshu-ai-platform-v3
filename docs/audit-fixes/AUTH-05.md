# AUTH-05：批量导入复用员工开户与一次性交付

## 问题与实施范围

门店的逐个开户已经建立人员、任职、登录账号和别名，并交付有期限的随机初始密码。原批量导入只建立人员和任职，因此“导入成功”并不等于已经交付密码登录账号。本项复用仓库已有的 CSV 解析、逐行校验、`StaffAccountOnboardService.open`、初始密码策略和账号交付文案，没有新增身份系统、密码找回接口或导入历史表。

`StaffImportService` 仍归组织模块、仍不包外层事务。它增加一个行创建回调和可选的账号交付结果；认证层控制器把真实 Spring 开户服务传入，所以组织模块无需反向依赖认证模块。每行的用户、岗位、账号别名和初始密码策略在同一个开户事务中完成；失败仅回滚该行，前后成功行保留。

预检完全只读。门店提交时，预检为“任职已存在”的行也重新调用开户服务，补齐历史导入缺少的账号关联；复核或补齐失败会报告该行失败，不继续宣称成功。手机号存在多个不能消歧的账号时保留已有明确业务错误，要求单独指定人员处理，不显示为临时网络故障。

## 账号与权限规则

| 场景 | 结果 |
| --- | --- |
| 新门店员工 | 创建独立用户、任职、账号和别名；仅本次返回随机初始密码，48 小时内须改密，官方微信登录会退役初始凭据。 |
| 重复导入、同人兼岗 | 复用用户和已有账号，不重置密码，不重新发放密码，不延长初始密码期限。 |
| 旧导入已有岗位但缺少账号别名 | 补账号关联，保留原姓名资料与密码；可用已有密码或官方微信手机号授权登录。原随机密码无人知晓时，不把补别名解释为已经恢复密码。 |
| 同名不同手机 | 复用既有统一命名锁与序号规则，各自为独立人员。 |
| 同手机号跨店任职 | 复用同租户人员，追加本店岗位和本店账号映射；保持原密码与其他门店任职，操作者不能提交其他组织。 |
| 非门店组织 | 保持原逐个录入同样的人员和岗位路径，不生成门店密码账号；页面明确使用平台已开通的微信或短信登录方式。 |

门店导入与逐个开户同样限当前门店老板或负责人；只有自定义 `platform:org:manage` 权限的其他岗位不能绕回旧建档路径取得开户权限。页面禁用并说明原因，服务端也在预检及提交入口核验，实际开户还会再次复核操作者有效任职。保留角色、团队和任职的现有校验继续生效。

## 凭据交付与恢复

Web 导入结果增加实际账号交付列表，每行展示姓名、门店、登录账号和密码状态，并使用同一交付函数复制账号、别名及登录说明。复制失败可在当前页面手动复制；已有账号明确显示沿用原密码或微信登录，不生成占位密码。

重提失败行时仅发送原失败输入行，已成功账号的一次性凭据继续保留在本批内存列表。同一个人兼岗返回多行时保留最初那份交付，不用后续 `initialPassword=null` 覆盖它。关窗、换文件、离页、组件卸载或切换身份都会清除内存密码和手动复制文本；正常提交期间阻止重复提交及主动离页，强制离页后的迟到响应不得重新显示凭据或成功提示。

如果服务端已经提交而整批响应丢失，重试只会复用账号，不会重新发放密码。页面明确提示让员工走小程序已有的官方微信手机号授权登录，或联系总部核验后通过现有受控重置恢复。不新增明文凭据持久化或用批量导入重置旧密码。

导入访问日志显式关闭请求体与响应体记录；统计日志仍只写组织、操作者和计数。嵌套账号 DTO 的 `toString` 不含初始密码。前端不向 localStorage/sessionStorage 写入交付数据，也不把账号交付字段带入重提请求。

## 验证

- 真实 `FranchiseAccountAuthServiceIntegrationTest` 增加六个 PostgreSQL/Redis 组合用例，使用真实开户、导入编排与登录服务，覆盖预检零写入、同名单个/批量账号、密码和微信登录、48 小时策略、重试与兼岗期限保持、旧导入补别名、跨店边界、已禁用账号拒绝、逐行回滚及并发手机号去重。
- HTTP 契约验证真实当前岗位传入开户回调、门店开户权限和非门店兼容路径。日志回归检查真实访问过滤器不记录响应密码，以及汇总日志和嵌套 DTO 不泄露凭据。
- 本地真实 Vue SFC 行为与模板渲染、CSV、逐个开户和组织工作区组合在最新主线重放后 67/67 通过，包括复制失败、失败行重提、关闭与迟到响应。模板渲染替换的是 Element Plus 展示组件，不等同于浏览器端到端测试。
- 新用例与相关既有导入回归已加入实际 Backend CI 固定 Java 清单及 Web 测试命令；Java/PostgreSQL 本机无 Maven/JDK/数据库运行条件，未声称执行通过，需真实 CI 验证。

无需数据库迁移、依赖变更或小程序接口变更。历史操作日志可能在外层事务回滚后留下“创建用户”的既有审计行为不在本次变更范围；本项不向这些日志写入初始密码。
