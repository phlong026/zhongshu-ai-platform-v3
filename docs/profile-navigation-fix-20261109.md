# “我的”页面循环跳转修复

## 修复范围

API 登录的老板、门店负责人和业务员进入原生“我的”页后，会被转到旧岗位个人页；旧页面使用本地演示身份判定，又转回原生页，导致页面持续重建，停留在空姓名、空岗位的初始状态。

- `miniprogram/pages/profile/index.js` 直接使用已有共享个人页，九类已开放岗位都在原生页面渲染。
- 旧 `admin/profile`、`account/sales` 页面只在 `onLoad` 单向跳转原生页，移除旧模型、错误引用和身份分流；跳转失败记录错误并提示重试。
- 原生 WXML 传入 `ownerProfile`、`managementEntries`，保留共享模板对老板字段的消费。
- 原有资料、未读消息和课程请求仍异步执行；页面先显示岗位和缓存资料，不等待接口响应。

本次未改登录协议、岗位权限、账号页守卫、其他工作台数据装配或依赖版本。此前审查发现的这些独立问题不属于本次卡顿修复。
