## 四项修改

1. **新员工初始密码**：后端统一分配小写全拼登录名；同租户重名顺序为 `lili`、`lili2`、`lili3`，对应初始密码 `lili123`、`lili2123`、`lili3123`。跨门店共用登录名空间，事务锁串行分配，覆盖带数字姓名与重名序号相互碰撞的情形。已存在的同一用户添加岗位时沿用现有密码，开户接口不重置旧凭据。首次使用初始密码仍需设置新密码，新密码规则为 6–64 位，无字母数字组合要求。
2. **人员优先的账号展示**：搜索候选、选中账号及默认账号主行显示姓名和岗位，次行显示简短组织名，单独显示实际登录账号。示例主行“裴火荣 · 老板”、次行“合家美宅 · 江西南昌高新区”。后端从结构化品牌、地区及有效岗位生成展示字段，清除片区中重复品牌；前端不再拆分长公司名。开户交付页和复制内容同步包含姓名、岗位、简短门店名。
3. **密码显示与字距**：当前密码、新密码、确认密码分别支持显示/隐藏，互不影响；输入恢复正常字距。离开登录页后，三个密码框恢复隐藏并清除敏感输入。
4. **登录协议弹窗**：删除底部固定勾选区。未同意时弹窗，支持原地阅读完整协议与隐私政策；阅读、返回或取消不会自行提交登录。同意后继续原先选择的账号或微信通道。协议版本由后端发布，本地仅缓存明确同意的版本；版本更新后重新确认。新版请求同时携带 `loginVersion: 2` 和同意信息，服务端在认证前校验；保留已上线旧版原请求格式的登录兼容。

## 前后端契约

- `GET /platform/auth/login-policy`：返回用户协议、隐私政策当前版本及密码长度规则。
- `POST /platform/auth/account/matches`：保留现有字段，新增 `personName`、`roleCode`、`roleName`、`shortOrgName`。姓名从用户资料读取，岗位与账号登录后优先进入的有效岗位一致。
- `POST /platform/auth/account/login` 与 `/platform/auth/wechat-login`：新版请求携带 `loginVersion: 2`、`consent: {accepted, agreementVersion, privacyVersion}`；未明确同意或版本过期返回 `1104000016`。前端清理失效同意记录，下次重新拉取版本。
- 开户返回增加岗位名称、简短组织名；初始密码仍仅在本次开户交付响应展示，不持久保存明文到小程序。
- 账号标识、微信绑定主体与岗位标识继续用于原认证链路；展示文案更新无需重命名存量组织或迁移账号。
