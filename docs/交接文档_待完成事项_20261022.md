## 零、必须遵守的规则

### 用户的原则（来自用户原话，优先级最高）
1. **今天的主目标**：业务模块主链路流程要跑通，每个环节能衔接，不能出现不合理的跳转及业务逻辑问题；工程和管理的主链路同样。主链路都核对完之后，再逐个核对详细页面。
2. **页面格式统一、尽量复用**：已有的模块、样式、组件优先复用，只有确实没有才新增。同类控件（退出登录、输入框、选项、待办按钮、列表行）位置、样式、点击区域必须一致。目标是商业化小程序的外观。
3. **总部设计流程已取消**：只保留“设计行政”（`hq-design-admin`）。设计师、设计负责人的流程整条删除，**不复活**。只保留新流程 `businessFlow.type='sales-offline-v1'`。
4. **退款、金额更正、付款结果不明核实、申诉：线下办理，不进小程序**（用户 2026-10-22 明确说明）。
5. **展陈设计与众墅甄选只做展示**，不与业务流程绑定；下单、订单、采购入口已下线，模型代码保留，后期深化。
6. **每个模块单独 commit**，提交信息写清做了什么、为什么安全。只用 `git add <具体路径>`，**不要 `git add -A`**；提交前 `git checkout -- qa`（`qa/` 大部分被 gitignore，但有几个被跟踪的 json 会被检查脚本改写）。

### 操作约束
- **不要删测试来绕过失败**：系统会拦截“删除测试用例”类操作。确需退役过期用例，先让用户明确同意，并在 `docs/旧验收脚本核对_20261022.md` 记录依据。
- 主工作目录可能同时有多个会话在改文件。只改自己任务的文件；改 `*.wxss` 前确认没有别的会话在整改点击区域（见任务 A）。
- 微信开发者工具：**正式 AppID 当前启动不了**（报“登录用户不是该小程序的开发者”，需要用户用开发者账号重新扫码登录）。临时方案是游客 AppID 副本 `.tools/business-main-chain-check/project`（真实文件副本，不是链接，改主目录源码不会热重载它，但副本里的是旧代码，要刷新副本才测到新代码）。**审计自动跳页期间不要手动操作开发者工具**。
- 开发者工具模拟器有 10MB 文件配额（截图临时文件 + `miniprogramLog` 会写满）。必须分批、每批前清缓存（`cli cache --clean file`）、重启；**不要在一次运行中途清缓存**（会让所有导航超时）。`selectorQuery.fields({computedStyle})` 会导致“An object could not be cloned”并毒化模拟器，改用 `boundingClientRect` + 类名选择器；标签选择器不被支持。
- 压缩成一行的 JS 文件：用“精确字符串补丁”改（草稿区有 `patch.cjs` 一类的辅助脚本，思路是 `s.includes(a)` 不满足就报错、再 `replace`）。大块删除用括号感知的块移除脚本。
- 删“未使用方法”时，**页面处理函数可能通过数据动态绑定**（例如预算结果页 `continueHandler:'continueBudget'`），模板里搜不到不代表没用。上一次因此误删过，被 `verify-business-four-flows` 发现后恢复。
- 小程序有分包：主包代码不能 `require` 子包文件（`pages/admin`、`pages/account`、`pages/workflow` 等是子包）；`verify.cjs` 的包资源检查会拦截。共用的模块放主包或根目录 `utils/`、`styles/`。

## 九、已知风险与坑

- 页面渲染快照（2478 个状态）是最可靠的“没改坏”证据，但只覆盖文字和控件，不覆盖样式；样式改动必须靠模拟器审计。
- 权限判断集中在 `miniprogram/utils/authority-v2.js`。新流程工程项目（`p.recordFlow`）：老板、经办人（`engineer` 角色且为经办）、项目经理（本人经办或属于其管的团队）可读；**只有经办人能记录**。改它必须跑 `verify-engineering-records-guards`。
- 业务岗位首页待办由 `utils/sales-todos.js`，财务待办由 `utils/finance-ledger.js` 的 `tasks()`（含 `engineering-records.financialTasks` 的“核对项目成本/确认结清”），老板待办由 `pages/admin/owner-model.js`。改任一处后要跑 `check:chain:walk` 与 `verify-sales-todo-handoffs`（在业务门禁里）。
- 老板“本月签约”= 本月提交的设计委托总额（`owner-model.js` 的 `commissions`），绩效同步（`utils/performance.js` 的 `perf-commission:`）。
- Windows 路径、`/tmp` 与 Git Bash 的路径不一致；在 bash 里传以 `/` 开头的参数会被改写；含反斜杠的正则用文件写入而不是命令行内联。
