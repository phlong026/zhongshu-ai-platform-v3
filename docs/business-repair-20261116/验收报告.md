## 委托设计和支付布局

委托页按“客户与预算 → 补充需求 → 核对委托单”组织。已有资料自动显示，仅填写缺失需求。展开一组时集中处理该组；预览只展示已填内容，费用按总部规则自动计算。底部按钮依次为“预览委托单”“确认提交委托”。

支付页突出客户、金额、微信或支付宝选项与确认按钮。订单号、委托版本和时间收进详情；保留“模拟”标识及“不发生真实扣款”。成功后显示原订单结果及“查看委托进度”，没有额外的付款、到账二次确认。

| 自动带入 | 按实际补充 | 处理原则 |
| --- | --- | --- |
| 客户姓名、电话、有效建房地址、原客户关系 | 缺失客户资料回原档案补齐 | 不重建客户，不在委托单重复抄录 |
| 项目名、预算版本、面宽、进深、层数、建筑面积 | 沟通群名称与项目名不同时可调整名称 | 提交时冻结预算与需求版本 |
| 同项目已记录的卧室、客厅、入口朝向和风格 | 房屋朝向、入口关系、常住人口、儿童老人、必备房间 | 图片横竖方向不能当房屋朝向；卧室数不能当人口数 |
| 结构化预算和已有平立面参考 | 生活习惯、特殊空间、现居痛点、新家期待、其他参考 | 不能把不同设计分支参数混进当前委托 |
| 总部单价、服务范围、服务主体、设计费 | 可选需求附件 | 金额由后端计算，前端不能覆盖 |

总部设计行政可查看设计需求与预算技术配置，客户电话及财务金额按岗位裁剪；保留结构、材料、数量等设计依据。

## 恢复的预算后业务流程

依据10月21日的岗位精简决定，以及开发版 **1.0.20261025.1** 的委托到工程流程，采用本轮确认的模拟支付：

**预算归档 → 原客户委托单 → 一次性模拟支付 → 财务知会及总部设计行政接续 → 登记线下设计完成 → 下发成果 → 业务补客户确认和现场交底 → 工程核对接收并建项。**

| 节点 | 办理岗位 | 后续事项 |
| --- | --- | --- |
| 归档预算与提交委托 | 业务 | 保存需求、预算及计价版本，形成唯一待付订单 |
| 微信或支付宝模拟支付 | 有权经办业务 | 服务端保存成功凭据；失败或取消可继续原订单；同一订单不能再次成功 |
| 查看模拟凭据 | 门店财务、总部财务 | 只读知会，不计实际实收实付，不增加重复解锁门禁 |
| 线下设计完成登记 | 总部设计行政 | 支付就绪后可办理，不恢复线上派设计师和内部审核角色 |
| 下发成果 | 总部设计行政 | 三份同版资料：设计成果、施工图、专业审核依据；通知原业务 |
| 确认和移交 | 业务 | 总部资料自动带入，补客户确认、日期、现场交底及工程接收人 |
| 接收或退回 | 工程接收人 | 合格接续唯一工程项目；退回交原业务补件重提 |

客户修改在原委托内登记，修改后下发新版本，不重复生成设计收费。历史首尾款委托保留原费用授权与实际收付门禁。参考建造预算、设计服务费和工程合同分别保存。
