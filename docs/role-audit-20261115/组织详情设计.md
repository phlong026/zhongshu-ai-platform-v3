# 组织详情

目标：总部管理员在一个入口查看组织、成员、积分与生成活动，并管理组织状态。沿用现有后台的棕色主题、表格、标签页和侧栏详情。

## 列表

默认展示未删除组织。可按组织名称、老板姓名、手机号、登录账号搜索，按组织类型筛选，并切换“包含已删除”。

列：组织名称、类型、老板姓名、手机号、登录账号、状态、详情。支持分页。

## 详情结构

顶部：组织全称、类型和状态；四项摘要：可用积分、本月消耗、在途预扣、成员人数。

| 标签页 | 内容 | 操作 |
| --- | --- | --- |
| 组织概览 | 品牌、地区、老板姓名、手机号、登录账号、查找简称、开通时间、备注 | 复制账号；重置加盟账号密码；关闭、启用、软删除、恢复 |
| 成员与岗位 | 姓名、手机号、岗位、部门、账号状态 | 分页查看；本轮不扩大到成员授权编辑 |
| 积分账户 | 可用余额、在途预扣、本月用量、积分流水、积分调整记录 | 平台超级管理员在当前组织直接增加积分，填写数量与原因，立即入账；重复请求不重复加分 |
| 生成记录 | 时间、任务编号、类型、操作人、状态、失败原因 | 分页查看；覆盖内容任务与设计远程任务 |
| 操作记录 | 状态操作、密码重置、操作人、时间、原因 | 只读追溯，不保存密码；积分变更在独立账本中追溯 |

## 状态和资金规则

1. 关闭：成员不能继续以该组织的岗位办理业务，保留历史数据和积分。存在未结算预扣时拒绝关闭。
2. 启用：恢复组织访问，不增加任何成员岗位或权限。
3. 删除：必须先关闭，余额为零，无待审核积分申请及未结算预扣；执行软删除，保留历史记录。
4. 恢复：从“包含已删除”列表操作；恢复后保持关闭，需单独启用。
5. 每次状态操作输入完整组织名称、填写原因，后端复核并记录操作者；重复请求使用同一请求编号。
6. 按用户最新要求，增加积分无需双人复核，仅平台超级管理员可直接办理。通过现有账本事务入账，记录操作人、原因、变更前后余额，保留幂等对账；不使用裸SQL改余额。

## 权限和文字

- 组织查询沿用平台组织开通权限，受租户边界约束；状态修改额外要求平台超管身份。
- 手机号和账号在受权限保护的详情内展示；不展示密码、令牌或原始生成请求。
- 密码重置同时要求组织管理及系统重置密码权限，由服务端确定该组织的老板用户；同一用户的关联账号共用密码。重置需确认组织名称与原因，撤销旧会话并保留微信绑定；当前操作者本人及平台超管账号通过系统用户管理或个人资料处理。
- 正常、关闭、删除以及未开通积分明确区分，不用空白代替错误。
- 去除接口名、实现机制、重复解释和口号；保留会影响决定的提示、必要的原因字段和风险说明。

## 本轮验收

按列表搜索、详情切换、成员查看、积分查看、生成记录、状态操作顺序截图验证。状态变更及岗位业务写入在独立测试组织内进行，不关闭或删除用户正式门店。
