# 预算后委托设计流程与字段继承

2026年11月16日。依据10月21日业务精简决定、10月23日至25日委托到工程开发版，以及本轮确认的模拟支付要求。

预算完成后沿用同一客户、项目和预算版本发起设计委托。新委托按建筑面积与总部有效单价计算一次性设计费；本阶段办理可持久保存、可重试的模拟支付，正式支付接口后期接入。总部仅保留设计行政在平台办理，内部派设计师及设计审核在线下完成。

## 预算之后的主流程

| 顺序 | 经办岗位 | 页面与操作 | 自动接续及完成条件 |
| --- | --- | --- | --- |
| 1 预算归档 | 业务 | 预算结果选择原客户，保存本版预算，继续委托 | 归档成功后才打开委托；失败保留重试入口 |
| 2 核对委托单 | 业务 | 核对自动带入的客户、项目、预算、参考方案及报价，仅补充缺失需求，预览后确认提交 | 保存需求、预算及计价快照，生成唯一待模拟支付订单 |
| 3 模拟支付 | 原业务及有权业务负责人 | 选择微信或支付宝模拟方式、确认模拟支付；取消返回后可继续原订单 | 服务端保存成功记录；单一订单只能成功一次；失败不生成下一岗完成事实 |
| 4 财务知会 | 门店财务、总部财务 | 消息打开原模拟凭据，查看客户、委托版本、金额、方式、时间及订单编号 | 仅知会；不再增加一次人工付款或到账解锁；不计入真实实收实付 |
| 5 设计办理 | 总部设计行政 | 从待办查看委托需求，线下安排设计与审核后登记完成 | 模拟支付完成后才出现可办设计待办；完成后接续本版成果下发 |
| 6 成果下发 | 总部设计行政 | 核对并下发正式设计成果、施工图、专业审核依据和图纸版本 | 三份文件绑定原委托、提交版本、下发批次；原业务获得收图移交待办 |
| 7 客户确认与移交 | 业务 | 三份总部成果自动带入；补本版客户确认凭据、日期、现场交底，核对工程接收人后移交 | 不重复上传总部成果；原工程人员获得核对接收待办 |
| 8 接收建项 | 工程接收人 | 核对设计成果、施工图、审核依据、客户确认、现场交底，接收或说明原因退回 | 合格后创建或关联唯一工程项目，接续开工准备；原业务与工程移交待办关闭 |

工程合同与后续工程收付款在工程开工准备中继续办理，不作为新面积计价委托之前的重复审批。参考建造预算、设计服务费、施工合同金额分别保存。

## 委托设计单的字段继承

| 内容 | 来源与呈现 | 业务是否重新填写 |
| --- | --- | --- |
| 客户姓名、联系电话、建房地址 | 原客户档案；只读核对，错误回客户资料修改 | 否 |
| 客户编号、设计项目编号、原业务负责人、门店 | 服务端关系绑定；界面仅显示有用名称 | 否 |
| 项目名称 | 已有项目名优先；无项目名时按客户名称预填，允许改为沟通群名称 | 仅核对或修改 |
| 面宽、进深、层数、建筑面积 | 本客户当前归档预算；只读 | 否 |
| 预算版本、分项预算、参考总额 | 冻结预算快照；缺项保留缺项状态 | 否，不能把未知预算显示为0 |
| 平面、立面及选中成果 | 与本预算同设计项目或已核对尺寸的参考方案版本 | 否，保留预览和原版本 |
| 已记录的卧室数量、客厅配置、风格、入口朝向 | 原方案的明确配置；预填后可调整需求 | 否，已有值不要求重复录入 |
| 房屋朝向、入口是否同向 | 原方案有明确记录则带入；否则补充 | 缺失才填写；入口朝向不等于房屋朝向 |
| 常住人口、有无儿童老人 | 原档案或结构化需求有记录才带入 | 缺失才填写；不能根据卧室数猜人数 |
| 必备及特殊房间、生活习惯、特殊要求 | 沿用已有需求，补充预算与方案未记录的内容 | 按实际补充 |
| 现居痛点、新家期待、风格参考 | 沿用已有需求，支持选项加简短补充 | 选填或核对 |
| 总部单价、交付范围、收款主体、设计费 | 有效总部计价规则；面积×单价由后端计算并冻结 | 否，不允许手工覆盖总额 |

图片的横向、竖向生成比例不能用于房屋朝向。全屋卫生间总数不能自动分配为一层、二层数量。不同设计分支的参数不能因同属一位客户就混入同一委托。

委托单依次展示客户与项目、预算依据、需求补充、自动费用、完整预览、确认提交。已带入内容保持可见；不再要求重复填客户联系方式、尺寸和费用。需求编辑可暂存，重新进入保留；更换账号、门店或客户时隔离草稿。

## 异常与版本规则

- 未归档预算：显示补齐预算入口，不能生成无预算委托或模拟订单。
- 预算或计价已更新：保留需求草稿，重新读取报价并要求确认；不能静默按过期价格提交。
- 模拟支付取消或失败：原订单保持待支付；重新进入继续原单，不新增收费单。
- 重复请求：提交、模拟支付、下发、移交和接收使用服务端幂等及版本检查；不能重复生成消息、成功记录或工程项目。
- 客户修改：原委托登记意见，行政登记修改完成并下发新版本；保留旧版本，不重复生成设计费。
- 工程退回：原因回到原业务待办，补充原资料包后重提；旧草稿不能覆盖已提交新版本。
- 旧首尾款委托：沿用原费用授权、实际付款及总部独立到账流程，不转换既有财务事实。

## 模拟支付与消息规则

模拟订单绑定客户、委托、提交版本、预算版本和计价快照。金额由服务端从委托读取，前端只提交方式与确认动作。支付页、凭据和知会消息保留简短“模拟支付”标识。模拟凭据存独立表，不能写入真实付款、到账和现金指标。

成功动作和下一岗位消息在同一事务中保存，消息失败可重试且不重复。业务、设计行政、两端财务及工程分别打开自己有权查看的原单。财务使用只读模拟凭据入口；总部设计行政看到需求及支付就绪状态，不通过快照泄露客户电话或财务金额。

正式支付接入时，以服务端下单、验签回调、金额核对及查单结果确认真实成功；不能把现有模拟记录补标为真实收支。

## 复测要求

核对预算归档到委托的参数一致性，覆盖无预算、同客户多方案、预算更新、账号切换、草稿恢复；核对模拟支付取消、失败、重复提交、两种方式、凭据重开及两端财务消息；核对支付前设计不可办、支付后行政待办接续、三份同版成果下发、客户修改再下发、移交退回重提和接收唯一建项。

开发者工具、本地数据库回归、真实业务后端操作、用户手机实测分别记录。模拟支付成功不能写成真实商户支付验收，历史开发版通过不能替代本轮接口和页面复测。
