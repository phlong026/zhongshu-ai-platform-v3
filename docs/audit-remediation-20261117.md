# 整改 01–06：小程序实施与验证

基线：`main 27e6b2fb`；配套后端基线 `backend-main 61f60a92`。

修改前及提交前检查全部已登记 Git 工作区。已有设计聊天已定位封面空白的直接原因：全局按钮横向布局使封面容器宽度变成 0。本分支复用已验证的纵向卡片、封面固定宽高修复；其缩略图、缓存和其他设计功能调整仍保留在原工作区，没有并入本轮。人物库旧工作区的相关草稿实现已纳入当前基线。主工作区另有任务中心未提交调整，本轮在独立分支基线上修改状态文案，未覆盖主工作区。

## 已修复

- 02：保存未解决冲突、本地原始草稿版本、已观察到的云端版本及正式人物基准版本。重开后保持冲突，禁止自动保存及发布。旧格式脏缓存保守要求用户确认；选择保留本地时，云端再次更新则重新提示。
- 03 配套：携带正式人物基准版本；正式人物冲突保留草稿并允许继续编辑，明确选择后才重置基准。发布响应丢失后重开仍能按原草稿版本查询确认结果。
- 04 配套：任务状态区分“生成完成，保存中”“生成完成，保存失败”；后端只在脚本保存成功后返回可用状态。
- 05：加载完成且确有变更后才写云端；隐藏和卸载共用在途保存，连续编辑串行提交。新建与历史任务按任务 ID 分离缓存和请求；云端版本冲突持久保留，本地输入不因慢网、读取失败、身份切换或迟到响应被覆盖。同一云端版本恢复时保留本机媒体路径。
- 06：云端草稿及生成请求统一数字秒，恢复兼容数字、数字字符串、“5 秒”等旧文本及选项索引数组；`2K` 恢复为界面 `1080P`。不支持的时长由恢复函数明确拒绝。
