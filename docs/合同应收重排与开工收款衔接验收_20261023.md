# 合同应收重排与开工收款衔接验收

日期：2026-10-23。接续《工程接收自动建档修复验收》，处理开工准备提示含糊、合同应收布局混杂、保存后无明确下一步及两期工程收款衔接。

## 修复结论

合同应收页按“项目摘要 → 本版分期卡片 → 已签合同依据 → 本岗位办理”重排。合同总额、累计已收和当前待收分开展示，开工款与封顶款分别显示进度和责任状态。

工程已经生成的两期约定不再要求老板重复手工填写。老板在同一卡片中先填写意见、核对确认，再批准或退回；确认成功后返回老板工作台，财务出现开工款待办。工程和财务查看待审批约定时只读，不显示老板审批或费用申请按钮。

开工准备原先把金额关系、合同凭据、现场说明四类失败合并为“请补齐已签合同、开工款及现场准备记录”。现在逐项说明具体原因，合法填写可继续保存。没有获得用户当次输入金额，因此不把某个具体金额错误写成用户当次报错的已证实原因。

现有两期规则保留：合同总额大于 0，`0 < 开工款 < 合同总额`，余款为封顶款；没有擅自增加或取消收款条件。

## 一并修复的问题

| 问题 | 处理 |
| --- | --- |
| 工程已提交约定与手工分期表单同时出现 | 正常工程约定只读核对；历史项目保留原有手工补录入口 |
| 合同应收页误出现费用申请按钮 | 费用申请仅在费用页显示 |
| 审批按钮与必填意见、核对项分散 | 意见、核对、退回/确认集中在一个办理区 |
| 合同确认成功仍停在原表单 | 成功返回本人工作台，下一岗位待办继续存在 |
| 已有旧批准约定时，新审批可能展示旧金额 | 当前待审批版本优先展示，批准对象与所见金额一致 |
| 真实合同按钮进入空白模拟说明 | PDF/图片走原生预览，模拟凭据仍页内预览，预览失败明确提示 |
| 开工合同参考凭据被误标为施工计划版本 | 开工准备、实际开工、工程收款使用工程合同版本 |
| 历史查账入口、合同依据入口可能被布局改版移除 | 保留老板/财务收款流水入口及历史约定上传、预览入口 |

保留原有金额与实际收款记账模型，布局展示不产生收款，不替财务跨岗登记，不新增依赖或数据迁移。

## 正常流程与责任岗位

| 顺序 | 责任岗位 | 操作 | 完成后衔接 |
| --- | --- | --- | --- |
| 1 | 项目工程人员 | 接收业务移交，自动建立工程项目 | 同一项目出现开工准备待办 |
| 2 | 项目工程人员 | 填合同总额、开工款、现场说明，选择本项目参考合同或实际已签合同，保存准备 | 本公司老板出现一项本版合同收款约定待办 |
| 3 | 老板 | 在合同应收核对本版开工款和封顶款，一次确认 | 返回老板工作台，财务出现一项开工款待办 |
| 4 | 门店财务 | 登记实际收到的开工款，可按实际到账分笔登记 | 未足额保留同一待办，足额后关闭，工程出现实际开工待办 |
| 5 | 项目工程人员 | 留存实际开工凭据并记录开工 | 进入施工节点记录，不再要求重复登记开工款 |
| 6 | 项目工程人员 | 完成主体封顶记录 | 门店财务出现封顶款待办，封顶前不会提前开放 |

验收使用同一模拟客户和项目：合同 100,000 元，开工款 60,000 元，封顶款 40,000 元；开工款两笔各 30,000 元只累计为同一期开工款，不是两期首款，也不与设计首尾款混用。
