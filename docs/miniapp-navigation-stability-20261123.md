# 小程序页面切换与刷新稳定性设计及验收

日期：2026-11-23。适用范围：F01–F10 页面切换、工作台复用、后台刷新、身份隔离与图片更新修复。

本文记录修复后的行为约束、CI 执行链和原生验收标准。自动化执行结果必须关联最终集成提交及对应流水线，不能由独立分支的结果推定。

**当前原生验收状态：尚未取得本轮修复在微信开发者工具、Android 和 iOS 真机上的连续渲染验收证据。现有 Node 回归能够验证导航调用、页面生命周期和请求行为，不能据此宣布真机无频闪。**

## 1. 问题原因与修复原则

页面横向移动与内容闪动需要分开定位。正常进入二级页面时可以存在系统转场；同一主导航操作触发多次路由、刷新期间拆除已显示内容、迟到响应覆盖新状态，才是本轮修复处理的具体问题。

| 已确认的问题类型 | 触发机制 | 修复后的行为原则 |
| --- | --- | --- |
| 主导航重复跳转 | 主入口先进入旧页面，再转交到实际工作台；连续点击没有统一处理正在进行的导航 | 销售主入口直接到声明的原生 Tab；旧直链只做一次兼容转交；导航期间保留最后一个有效点击，抵达目标后不再重复导航 |
| 刷新先清空内容 | 每次 `onShow` 都恢复初始 loading/空列表，WXML 条件随之移除卡片或列表 | 区分首次加载和已有数据的刷新；同一有效身份下保留已核验内容与必要交互状态，刷新提示及错误在对应区块显示 |
| 页面重复请求与响应竞争 | `onLoad` 和首次 `onShow` 重复请求；旧筛选、旧人物、旧月份或隐藏前的请求迟到 | 同一有效查询合并在途读取；用请求所有者、查询参数和生命周期校验响应；返回编辑页后发起新读，旧读不能覆盖写后结果 |
| 身份边界不完整 | 只比较岗位 ID 或会话代次，遗漏同岗位的角色、组织类型等权限变化 | 缓存和请求校验覆盖完整身份与授权范围；改变身份、明确拒权或岗位失效时清理对应数据；旧范围的失败不能清新范围的数据 |
| 图片签名更新造成闪空 | 签名 URL 刷新后立即改 `<image>` 的源，新图尚未可用 | 同一授权范围、同一资源版本的旧图保留到新候选预读成功；版本改变、资源撤销或拒权按实际状态更新；迟到预读结果不写回 |

### 1.1 导航与页面复用

销售的主导航使用现有原生 Tab 页面，减少额外页面跳转。原生 Tab 不通过 URL query 携带业务参数；编辑、定位等入口意图按当前身份暂存，并由目标页面消费一次。旧入口与非销售入口保留各自合法路由行为，草稿仍按原身份范围管理。

工程首页、项目、材料在工作台内复用同一 Page；门店老板的业务、工程部门视图也在同一部门 Page 内切换。进入业务详情仍使用对应页面路由。连续点击由公共导航逻辑串行处理，最终有效目标可以继续执行，已抵达的同一目标不重复重建。目标判定需要保留 query 与工作台子视图语义，不能只比较路由字符串。

本轮不通过给所有路由 API 添加 `animationDuration: 0` 来处理问题，也不要求取消正常二级页面的系统转场。验收关注的是多余转场、内容闪空和状态回退。

### 1.2 首次加载、刷新与错误

首次加载可以显示明确的初始加载状态。同一身份已有成功数据时，刷新保留已核验数据；成功返回空结果后，已加载空态也属于有效结果，不必在每次刷新时重新进入首载状态。待办展开、列表选择、数字人选择、已加载分页与尚有效的编辑状态按各模块约定保留。

普通网络失败、超时或服务端暂时错误只更新对应区块的反馈，并提供重试。已确认的 401、403、岗位失效和身份变化需要清理无权继续使用的数据，不能为了防闪而隐藏保留跨身份内容。个人资料被当前有效请求拒绝后，同时清除对应账号的持久资料缓存，防止新建 Page 再次显示已经拒绝的数据。

### 1.3 请求所有权与身份范围

每个异步回调在修改页面前都需要确认：页面仍处于可接受结果的生命周期、请求仍是当前所有者、查询或资源选择仍一致、身份范围仍有效。成功、失败与 `finally` 都遵循相同约束，避免旧请求清掉新错误、解锁新操作或重新填入旧内容。

身份范围应结合会话代次、用户、租户、组织、岗位、角色与组织类型等模块实际使用的授权字段。仅依靠 `postId` 无法识别同岗位的权限变化。页面隐藏时释放相关旧读的所有权，保留有效快照；从详情修改返回后重新读取，不能复用修改前的挂起请求。

积分返回刷新需要绕过修改前的在途读。涉及删除、保存、生成等业务操作时，继续遵守原有幂等与冻结请求规则；刷新优化不能导致重复提交，也不能用默认资源替换尚待确认的付费任务资源。

## 2. CI 执行链

```bash
npm ci --no-audit --no-fund
npm run check
npm run check:role-homes && npm run check:packages
```

`check:role-homes` 是工作流中的独立步骤。只执行 `npm run check` 不能替代完整工作流。下表列出专项回归在最终集成版本中需要保持的执行链；执行链可达不等于该版本已经通过 CI。

## 3. 真机验收准备

使用测试环境中有实际授权的账号，覆盖销售及销售负责人、工程及工程负责人、门店老板、财务、总部设计。至少准备两个用户和两个岗位，并覆盖同 `postId` 下 `roleCode` 或 `orgType` 变化。数据应包含多页列表、多个数字人人物及可用形象/音色、有版本的课程与方案封面。

冷态是当前身份尚未加载该页数据；暖态是同一有效身份范围已经成功加载。分别覆盖即时响应、延迟响应、普通失败、明确拒权和乱序返回。身份、权限与图片签名故障通过测试环境控制，不修改生产数据制造故障。

Android 和 iOS 均需执行核心路径。真实点击可见控件，同时记录 `navigateTo`、`redirectTo`、`reLaunch`、`switchTab` 的目标及时间，以及 `onLoad/onShow/onHide/onUnload` 和页面实例标识。直接调用页面方法不能独立证明真实触摸与渲染效果通过。

| A14 F09B 我的与课程 | 我的成功加载 → 离开返回；资料/课程请求延迟或 500；课程签名续期后预读成功或失败；预读时隐藏或切岗 | 同范围资料、进度和海报稳定；局部错误可重试；预读成功才替换海报；隐藏、新身份或新版本阻止旧回调；当前拒权清对应内容 | 姓名不先空，进度不先归零；海报不闪占位；错误提示不替换整页 |
| A15 F09B 拒权缓存 | 资料已缓存 → 当前资料请求 403 → 销毁原 Page 后重新打开我的并挂起新请求；另测新账号成功后旧账号 403 返回 | 当前有效拒权同时清对应账号持久缓存；新 Page 不恢复已拒绝姓名和头像；旧账号拒权不清新账号缓存 | 从新实例首帧起都不出现已拒绝资料，不能只检查原 Page 的最终画面 |
| A16 F09B 积分与财务内嵌个人页 | 进入会变更积分的业务页后返回，同时挂起旧 summary；财务首页 → 我的 → 项目账本 → 我的；隐藏时返回旧请求 | 返回使用 fresh summary/usage，不能复用操作前旧读；完整身份隔离；同范围刷新保留已核验余额；内嵌个人页收到 show/hide；拒权清理 | 余额不闪成 0 或旧账号值；隐藏个人页不被迟到结果切回；复入可重新刷新 |
| A17 F09C/D 财务与老板汇总 | 财务首页/项目账本暖刷新；老板工作台换月与汇总刷新；普通失败、权限变化、分页、隐藏后返回；一个接口失败且另一个仍挂起时主动重试 | 财务金额、账本行及分页保留，月结更新或失败时禁止确认；交易后强制新读。老板各域独立更新，显式重试不并入旧批次，换月只清相应财务汇总；拒权后即使恢复同身份，旧请求仍无权回填 | 金额与汇总无整块闪空；月份、岗位和明细一致；错误在固定位置可见且可立即重试 |

### 4.1 跨模块场景组合

对有异步数据的关键路径，至少覆盖以下组合。保留数据的前提始终是当前身份仍有权使用该数据。

| 场景 | 触发方式 | 接受标准 |
| --- | --- | --- |
| 冷态 | 第一次打开，分别即时与延迟返回 | 仅有必要首载；不能先成功、再清空、再成功 |
| 暖态弱网 | 已有成功快照，返回后延迟 2–5 秒 | 原授权内容保留，刷新反馈局部显示 |
| 暖态普通错误 | 500、超时、连接失败后重试 | 保留有效快照；错误可见可重试；成功后清错，无重复请求累积 |
| 连续切换 | 同目标与不同目标快速点击；月份、筛选、人物往返切换 | 最后有效意图生效；旧成功、失败与 `finally` 均不能污染新状态 |
| 返回编辑 | 挂起列表读，详情写入成功后返回 | 发起写后新读，旧快照不能回填 |
| 身份变化 | 换账号、组织、岗位；同岗位改角色或组织类型 | 不显示跨身份内容；仅比较岗位 ID 或会话代次不足以通过 |
| 明确拒权 | 当前 401、403、postInvalid，随后重建页面 | 清理对应数据及失效缓存；旧身份拒权不误伤新身份 |
| 图片更新 | 同版本新签名、真实版本变化、预读慢或失败、预读期间隐藏/切岗 | 有效旧图保留到新图可用；资源版本与权限正确；迟到候选不能替换 |
| 多页刷新 | 加载第 2 页后刷新，同时加载更多 | 已到达的有效分页不被旧第 1 页覆盖，无重复或跨筛选混入，加载锁可恢复 |

## 5. 连续录屏与验收证据

每项验收记录最终构建 SHA、环境/API 版本、设备型号、操作系统、微信版本、基础库版本、账号岗位、网络条件、实际路径和结果。记录中使用测试身份标识，不包含凭证。开发者工具、Android、iOS 的结果分别保存，不互相替代。

录屏应从操作前已稳定的画面开始，覆盖实际点击、请求等待、成功或失败、再次操作及最终稳定画面。弱网、连续点击、返回编辑、权限变化和图片预读场景都要保留中间过程。发现异常时，保存异常前后连续帧，并与导航、生命周期和请求时序对齐。单张截图无法证明整个切换过程中不存在频闪。

验收至少核对以下证据：

- **导航**：每次用户意图对应的 API、目标和次数，是否存在不必要的兼容页中转或重复重建。
- **页面实例**：工作台内部切换是否仍为同一实例，合法详情页与返回过程是否符合预期。
- **连续画面**：是否出现整页空白、已显示卡片消失再出现、内容先归零、旧身份内容恢复、图片闪白或位置跳动。
- **交互连续性**：展开、筛选、选择、分页及有效草稿是否按约定保留，失败后是否可以继续操作。
- **时序一致性**：乱序、隐藏、切岗后的旧响应是否被隔离，返回编辑后是否确实读取新结果。

最终结果按以下层次记录，避免混用证据：

| 验证层次 | 能证明的内容 | 通过所需证据 |
| --- | --- | --- |
| 代码与 CI | 真实函数在受控请求时序下的导航、生命周期、数据隔离；WXML 条件；包体与静态检查 | 最终集成 SHA、专项评审记录、完整 CI 结果与执行链 |
| 微信开发者工具 | 对应基础库和工具版本下的实际组件、导航与渲染行为 | 实际点击记录、导航/生命周期时间线、连续录屏 |
| Android 真机 | 对应设备与微信版本的触摸、转场、图片解码和连续画面 | 设备与版本信息、场景记录、连续录屏及异常处理结果 |
| iOS 真机 | 对应设备与微信版本的触摸、转场、图片解码和连续画面 | 设备与版本信息、场景记录、连续录屏及异常处理结果 |

只有取得对应层次证据，才能将该层标为通过。在原生验收完成前，准确结论是代码中已定位的重复路由、刷新清空与响应竞争问题已按专项修复并进入回归检查；仍需实际微信环境验证连续渲染效果。
