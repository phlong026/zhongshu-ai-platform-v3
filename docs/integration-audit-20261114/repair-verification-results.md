- AI视频：先上传真实字节及SHA-256，再提交首尾帧/参考素材assetId；选择参数索引正确映射；上传失败不创建任务。响应丢失时重试复用相同payload和幂等键，不二次上传/扣点。真实COS、接近50MB内存和付费生成仍待独立B/真机验收。
- 摘要：复用原SHA-256压缩轮，支持ArrayBuffer和带offset的字节视图；标准向量、高位字节、百万a及旧二进制字符串均与Node crypto一致，原财务/工程凭据回归通过。

第一阶段四岗修复复测记录99次观察，其中90次有渲染内容、15个实际承载路由；包含重复返回、失效恢复及补丁复测，**不是99个通过用例，也不是35个注册路由全部通过**。早段老板回款卡实际进入经营简报另有单项观察，不纳入这15路由计数。收尾针对钱包、业务汇总、手动发布和恢复登录追加14次观察，新增两个钱包路由；两阶段共涉及17个实际路由。保存的[JSON](repair-retest-summary.json)是人工整理的脱敏结论摘要，不是完整AX树或HAR。

四岗位均用当前微信员工的真实任职切换。保留普通页面按钮点击，也使用开发者工具Console的正常wx导航直达注册路由检查门禁；没有注入授权或伪造业务成功。临时wx.request监控只记录方法、路径、HTTP/业务码及数量，不记录令牌、请求头或响应个人资料；收尾移除，恢复老板工作台。

四岗覆盖：老板经营/账户/客户跟进与转交表单；业务员工作台/创作/作品/记录/任务/设计灵感及配置；工程工作台/项目/材料/准备/计划选择；财务工作台/流水/应收应付/对账/项目账和五类登记表单。项目、作品、委托与收付款缺少有效数据时，只验空态及请求，不能认定深层办理、结果回执或财务写入通过。

第一阶段收尾控制台Errors=0、Warnings=36；最终补丁后重新登录并恢复老板工作台，Errors=0、Warnings=22。热重载前累计warning更多，主要为既有WXSS选择器、灰度基础库、按需注入/预加载提示。未为得到0错误而清控制台；热重载会重建日志。两次自动化连接异常（超时重连、截图体积限制）不计为产品API错误。
