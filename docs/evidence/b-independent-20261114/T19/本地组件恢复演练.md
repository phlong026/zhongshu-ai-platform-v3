# 本地隔离组件恢复演练

日期：2026-11-14。演练使用本机 Docker 临时网络、容器和卷，全部数据为合成测试数据；未访问 A 服务器、真实 COS 或生产数据。所有临时资源在测试后确认已清理。

## 已验证

- 两套 PostgreSQL：对合成积分账本、设计成本账本和能力回执执行 custom 格式 `pg_dump`，在删除源容器和源卷后向全新空库执行单事务 `pg_restore`；恢复前后关键字段逐项一致。
- 两套 Redis：以独立备份 ACL 身份生成 RDB，`redis-check-rdb` 通过；向新卷恢复后检查积分、预留、幂等状态、过期时间、回执和 UNKNOWN 状态。
- Runtime journal：包含 completed 收据、UNKNOWN outbox 和 received 防重事实的三个测试文件经 tar 恢复到新卷，逐文件 SHA-256 一致。
- 正式备份门禁：非专用挂载目录及缺少 COS 版本清单均被拒绝；部署工具定向测试 8/8 通过。

## 未验证

这不是正式 `full-backup.py` 的端到端演练：本机不能证明 Linux thick ext4/xfs 专用卷，也没有可信的真实 COS 版本清单。本次未验证完整 B Compose 冻结、真实镜像摘要/迁移证据、COS 对象版本恢复、生产数据量下的 RTO/RPO、服务器磁盘性能或恢复后完整服务 smoke。

只有在全新 B 测试资源上完成正式发布、冻结备份、恢复和账本/对象核对后，才能认定完整灾备演练通过。禁止将演练目标指向现有 A 或覆盖正式 B 数据。
