本轮只修复 B 的部署工具并准备资料。新盘、KMS、快照和付费备份服务均暂停开通；A 的进程、配置、数据库、挂载和域名不作修改。本文不是上线成功或采购凭证。

## 存储身份方案

原规则要求每个祖先块设备提供 serial/WWN 且声明 thick；本机腾讯云系统盘未提供 serial，因此旧规则拒绝继续。新增显式 `tencent-cbs-v1` 分支，默认旧模式仍保持拒绝行为，不自动回退。

新分支核对腾讯云账号、指定 CVM、完整已挂载 CBS 清单、唯一系统盘及数据/备份盘的账号归属、实例、可用区、挂载状态和非共享属性；再与本机 metadata、文件系统 UUID 和块设备祖先关系交叉核对。根盘无序列号仅有受限例外，数据盘的实际观察 serial 必须对应控制面 DiskId。metadata 和 serial 是现场辅助，不能称为腾讯云保证的物理硬件映射、thick 或独立故障域。

云证据须在一小时内、仓库外 root 所有、0600、哈希固定；数据/备份测量报告和受信签名必须匹配。Runtime 固定绑定稳定卷身份，不把短时云证据时间戳写入 `.capacity-proof.json`，因此刷新证据无需重启。真实空间预留、fsync、块分配检查、单写者和资金 UNKNOWN 防重仍保留。

现有数据盘未加密；报告和签名必须如实绑定 `encrypted=false`。这只能是待审批的受限试点候选，不能称为正式生产加密配置。不会自动开通 KMS 或原地改造 A 的盘。

## 仍然阻断正式上线的事项

三项云端证据及服务器只读现场核验已完成：API Explorer 的临时 token 不支持 STS，改用既有 B COS 审计身份的长期凭据，通过官方 SDK 仅调用 GetCallerIdentity 成功；未增加 IAM 权限。CVM/CBS 由 MFA 后的控制台只读接口取得，合并后通过 Python 合同校验。服务器实际 inspect 对上系统盘、数据盘、UUID、元数据和祖先关系，输出 notReleaseReady=true、signedApprovalValidated=false。

代码测试通过、COS 探针恢复、候选配置和预检资料上传，分别只是对应阶段的证据；不替代 B 服务已运行或全量灾难恢复成功。
