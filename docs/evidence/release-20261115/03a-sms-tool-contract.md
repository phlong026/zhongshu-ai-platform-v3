## 一、缺陷复现（修复前基线）

基线：[03a-sms-tool-before.json](./03a-sms-tool-before.json)（verdict FAIL，动态复现）。

| 缺陷 | 证据 |
| --- | --- |
| 登录字段 `code` 违反后端契约（后端读 `captcha`） | mock 捕获登录请求体 `{'mobile':'138****1234','code':'123456'}` → 契约拒绝 → 脚本断言失败退出 1 |
| send/login 不分离：每次执行先重发验证码 | 原脚本 main() 无条件先 send，替换旧码并触发 60s 限流风险 |
| BASE/tenant/证据目录硬编码 | `BASE` 固定 `http://127.0.0.1:48080/admin-api`、`tenant-id:1`、证据相对 CWD 漂移；mock 无法注入（F1/F2 连接失败即此缺陷的体现） |
| 输出泄露完整手机号 | 「仅发码」路径的二次执行提示打印完整手机号（动态复现 `stdout 含完整手机号 = True`） |
| 发送成功即 exit 0，易误读为验收通过 | 无 MOBILE_CODE 时发送后 exit 0，语义未区分 |

## 二、修复内容（4 点，最小改动）

1. 登录请求体改为 `{'mobile': ..., 'captcha': <6位>}`。
2. 按是否存在 `MOBILE_CODE` 拆分：无 → 仅发码（明确标注"不代表登录通过"、不落证据）；有 → 仅登录（0 次 send）。
3. `CV_E4_SMS_BASE` / `CV_E4_SMS_TENANT` / `CV_E4_SMS_EVIDENCE_DIR` 显式覆盖；证据目录默认基于脚本位置解析（`B/docs/business-flow-audit-20261103/evidence/`），不再随 CWD 漂移；启动时打印解析后的配置。
4. 全输出与证据脱敏手机号；验证码/令牌不落证据；证据含 base/tenant/范围标记。
