# 加盟商开通与小程序统一登录

总部开门店老板账号；门店老板或负责人在“我的 → 成员与权限”录入员工、指派岗位并交付其独立账号。员工不共用老板凭据。公司数据属于组织，操作人由原用户ID及当前岗位区分。

## 用户操作

1. 输入正式账号、地区/门店拼音、姓名拼音或简称，点击查找。多个候选展示组织与姓名，必须明确选择；候选较多时补充查询内容。
2. 输入密码并同意协议。新用户使用初始密码时先设置新密码，服务端完成改密才签发令牌。
3. 成功获取有效任职后进入对应工作台；按需设置当前设备默认账号。默认选择不等于免密，不保存密码，可清除或切换。
4. 微信已有绑定直接使用同一用户。未绑定则先登录已有账号，再显式绑定本次微信；失败可重试或先进入工作台，不再注册另一用户。
5. 老板添加员工后，新员工账号和初始密码只在本次页面展示，可一键复制；已有员工沿用原密码。换岗、离页或重新提交会清除交付信息。

## 后端要求

新页面依赖独立B的Flyway710、`/platform/org/franchise-*`、`/platform/org/staff-accounts`、`/platform/auth/account/matches`、`/platform/auth/account/login`、`/platform/auth/wechat-bind`；与后端同批部署。所有登录继续使用现有平台Bearer、租户和有效任职，不修改组织、用户、积分及历史业务归属。

总部上线前核对存量用户可用登录方式及别名配置。旧用户不自动重设密码；无可用密码且未绑定微信时由总部主动办理现有密码重置和交付。此项未验证前，不能声称全体存量用户已完成切换。

## 验证与边界

`npm run check:account-login` 运行账号UI契约和真实Page可控Promise行为检查；`npm run check` 包含认证会话、岗位、成员、接口及其他相关回归。测试覆盖迟到查询/登录/微信绑定、切换清场、无有效任职、改密上下文、默认缓存和复制回执。

本轮未上传小程序、未发布、未对生产账号做变更；微信真实外呼与手机端显示/键盘/剪贴板验收须单独记录。回退使用前后端配套版本，保留已生成账号、密码哈希和微信绑定，不删除业务数据。
