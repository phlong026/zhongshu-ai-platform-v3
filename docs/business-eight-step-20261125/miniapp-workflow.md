# R06 客户八步跟进小程序

## 页面与范围

客户列表展示服务端内联的当前步骤、完成数、百分比和下次回访日期；行点击保留原客户详情，行按钮进入八步跟进。客户详情新增同一入口。流程页面位于独立的 `pages/customer-flow` 分包，原路由兼容。

本任务使用加盟商客户访问接口，由服务端决定当前客户可读、可写或只读。总部跨品牌只读查询由 R02 总部工作台及独立授权接口承接，本页面不会使用总部身份扩大普通客户接口的访问范围。

| 步骤 | 页面内容 |
| --- | --- |
| 01 邀约进店 | 实际日期、邀约方式、结果、约定到店日期及时间、下次联系 |
| 02 店面讲解 | 接待人、客户建房需求、讲解反馈 |
| 03 户型选择 | 从灵感库列表或详情选择真实案例、选型结果、确认版本、客户确认、外部方案附件 |
| 04 带看工地 | 工地或案例名称、地址、客户反馈、现场资料 |
| 05 现场测量 | 实测地址、测量人、面宽与进深（米）、面积（平方米）、层数、资料核对 |
| 06 别墅报价 | 正式报价金额、范围、版本、沟通结果及确认、正式报价文件；保留快速预算入口 |
| 07 合同签约 | 服务端真实合同编号、日期与金额；进入现有合同办理页 |
| 08 开工大吉 | 服务端真实工程、实际开工日期与负责人；进入工程记录或设计委托/移交页 |

每个手工步骤提供发生日期、补充记录和附件。保存记录不完成步骤；完成本步会先保存，然后使用返回的流程版本调用完成接口。是否完成及整体百分比由服务端计算，允许补录未按顺序发生的记录。已完成步骤需填写原因重新办理。

报价金额以十进制字符串转换为分，避免浮点金额误差。文本长度与后端一致：需求/反馈及补充记录最多4000字符，其余文本最多1000字符。前端每步最多10个附件，低于后端20个的保护上限。

## 版本、会话和资料

写入使用 `Idempotency-Key` 和流程 `revision`。未知结果保留原命令及原键，完成请求重试不会重复保存草稿。版本冲突保留填写；用户确认载入最新后才能覆盖草稿。写入会使已有GET失效，页面拒绝低版本读取覆盖新记录。

草稿及未完成上传仅保存在当前页面内存，不跨客户、岗位或会话保存。切岗、注销、页面卸载、客户转交及权限撤销会清理旧资料，迟到响应不能回填。离开有草稿的页面会提示确认。

附件使用 R07 的 `BUSINESS_DOCUMENT`，允许 PDF/JPEG/PNG，单文件不超过30MB。上传完成且返回 `ACCEPTED` 后才能关联节点；失败可重试，完成确认超时会复用原资产。附件上传失败期间不允许完成步骤或切步，需要先重试或取消。保存后的预览调用客户/步骤/资产专用下载票据；历史版本也通过同一授权接口读取。合同和工程凭据沿用各自业务模块入口。

历史记录按服务端分页读取，显示经办人、事件时间、字段和附件快照。灵感选择通过事件通道回传当前客户页，回传受会话保护，不写入全局设计草稿。

## 发布与验证

- 需要 R05 工作流接口和内联 `CustomerRow.workflow`。
- 资料上传和下载需要 R07 资产类型及节点下载接口同时部署；R05 旧的 `DESIGN_REFERENCE` 校验不能作为本资料链的最终配对结果。
- 合同/工程实际办理仍由原模块及 R08/R11 后续改造承接。
- `npm run check:customer-flow` 包含模型、页面行为、事件回传、附件及接口契约专项测试；已接入 `npm run check`。
- 主包仅增加入口和摘要；新表单放在独立分包，未降低既有2MiB及128KiB预留门槛。
- 当前环境的验证为 Node 页面行为、WXML条件/结构、资源依赖及包体检查。未提供微信开发者工具编译或真机验收结论；对应配对测试和微信端验证属于 R22 验证环节。
