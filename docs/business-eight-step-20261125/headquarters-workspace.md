# R01 总部全品牌只读工作台

## 实现范围

实际 API 任职为总部 `hq-admin`、`finance`、`finance-lead` 时，登录与切岗直达 `/pages/headquarters/index`。管理员默认显示概览，财务默认显示收款、应付、付款和退款。底部导航为总部、账本、我的；公司公告继续使用“我的”中的独立模块。门店岗位仍走已有专属工作台。旧设计行政流程由 R09/R10 单独迁移，本任务不删除旧岗位。

总部页面使用 R02 `/platform/headquarters` 命名空间，不将普通客户、工程、财务写页面改成跨公司入口。

| 页面 | 读取与交互 |
| --- | --- |
| 工作台概览 | 实际客户、工程数量；品牌与公司筛选；进入业务或账本 |
| 客户列表 | 所属品牌/公司、责任人、联系方式、八步当前进度；分页和条件查询 |
| 客户详情 | 八步发生日期、补充字段、说明与受控附件；合同/开工显示正式来源；跟进历史独立分页 |
| 工程详情 | 工程节点、合同、全部真实付款期次及净收款/退款/待收；资料与现场记录分别分页；交付结算附件 |
| 公司与项目账本 | 先选择真实公司，再读公司账、项目账和前期账本；金额来自现有财务汇总，不把现金结余当最终利润 |
| 财务原单 | 收款、应付、付款、退款四类列表与只读详情；凭证走所属原单的受控下载 |
| 导出 | 按已查询条件调用审计 POST，生成 UTF-8 CSV；用户再点击“保存 / 发送”调用微信文件选择器 |

品牌冲突/未关联公司只在“全部品牌”范围展示，不猜测其所属品牌。账本原接口最多提供 500 条明细；达到边界时页面明确提示，统计值仍为整个账本。导出复用服务端 50,000 行上限，不把已加载的第一页冒充全部导出。

## 身份、数据与文件

`session.js` 每次入页核对当前 token、账号、租户、岗位和总部类型，随后要求服务端 context 的 tenant、HQ org、post、role 与当前身份一致且 `readOnly=true`。异步回包绑定 `api-scope` 和页面 epoch，离页清空业务视图；任何请求返回撤权时同时作废同页其他在途请求。目录、详情和文件不写入持久化业务缓存。

文件地址只由内部白名单构造：客户节点、工程资料记录、工程正式附件或财务原单。业务 ID 保留十进制字符串，拒绝超出安全范围的数字和伪造 URL。附件下载前再次读取 context，下载后核对身份与页面代次，再核对 PDF/PNG/JPEG MIME、字节前缀与大小；JSON 错误不能打开为图片/PDF。HTTP 头只发往配置的 API 基址。旧工程外链没有受控引用时显示不可下载说明。

CSV 使用 POST 原始字节响应，校验 MIME 和 UTF-8 BOM 后才写临时文件；筛选、身份或页面变化使旧导出失效。导出前后保守比较当前筛选所覆盖的全部公司集合，记录授权公司 ID；分享前再次复核 context，任何原范围公司被停用或移出租户都会使旧文件失效并删除。失败或取消不会伪造发送成功。已打开的本地预览保留到返回页面再清理，避免微信查看器使用中的临时文件被提前删除。
