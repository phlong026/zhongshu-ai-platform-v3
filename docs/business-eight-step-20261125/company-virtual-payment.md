# R20 公司额度与微信虚拟支付

## 已复用的真实链路

继续使用 CompanyRechargeController、RechargePaymentService、WalletRecoveryJob 和公司 org_point_account / org_point_ledger。套餐、价格版本、付款人、appid、offerId、环境、币种与金额在服务端固定并复核；前端调起成功不作为到账凭证，只有后台可信查单/回调事实才入账，重复通知只记一次。

R19 已将零余额公司池建立放入公司注册事务。个人历史钱包不转入公司池，本任务不迁移余额，也不设置未经确认的注册赠额。AI 视频失败/取消按原 operation 释放预占，是消费退额；充值款退回是另一条退款账，二者不互相替代。

## 本任务变化

- 关闭 org-point 模拟购买写入口：旧配置不能重新开启，模拟套餐返回空，购买请求返回 403；历史模拟订单保留。
- 公司充值目录显示原单最新非失败退款状态：退款处理中 REFUNDING、已退款 REFUNDED、消耗后退款待核对 REFUND_REVIEW。退款单、原单、钱包与 tenant 必须同时匹配。
- 可信充值退款只冲回对应公司池一次。余额不足时进入债务/冻结核对，不写负余额，不动个人钱包。
- 小程序旧套餐深链转至现有真实公司充值页；历史模拟草稿不重放、不删除。退款状态没有继续支付按钮，支付前仍重取套餐版本与服务端订单。

## 真实退款的当前边界

当前 VirtualPaymentAdapter.requestRefund 在占额及外呼前明确拒绝自动发起退款；queryRefund 对无法证明原订单、退款单与金额一一关联的渠道结果保留 UNKNOWN。此任务保留这个边界，没有把渠道受理、聚合退款金额或前端回调当成退款成功。相关单据必须经现有后台核对流程处理。

新增集成用例使用经校验的退款事实验证账本恢复、重复回调和余额不足行为；它们不是微信真实退款验收。要启用自动退款，需要补齐可核验的渠道逐单协议与商户配置，并完成隔离环境和真机验收。

## 验证

独立专项代码评审通过；6 个 Java 文件语法解析、diff 检查通过。本地没有 Maven/PostgreSQL，真实编译和数据库测试由 PR CI 执行，包含现有充值事实校验、回调恢复、钱包安全、退款恢复，以及新增退款展示与公司账本用例。没有进行真实资金支付或退款。
