# R08：外部报价与正式签约凭证

## 业务边界

外部报价登记沿用八步流程第 06 步 `QUOTATION`：金额按分记录，保存报价范围、外部版本号、沟通结果，并关联已验收的 `BUSINESS_DOCUMENT` 文件。保存草稿不自动完成，完成条件仍由八步服务校验。报价登记不要求生成平台预算。

正式合同仍在原合同模块办理。创建合同的 `requirementId` 可以为空，也不要求存在平台报价或设计方案。R08 不改合同金额与付款计划计算，任意付款计划由 R11 提供。

未签约合同只有具备实际签约日期和有效已签合同文件，才能从 `WAIT_SIGN` 转为 `SIGNED`。历史 `SIGNED` 行缺少凭证时维持原合同状态和付款记录，八步第 07 步显示待补录；不会把旧状态直接换算成完成进度。

## 前端接口契约

所有地址前缀为 `/franchise/sales`，继续使用现有响应封装。身份、公司和租户从服务端会话取得，客户端不能在命令中指定。

### 签约

`POST /contracts/{contractId}/sign`

权限为 `franchise:sale:write`；必须提供 `Idempotency-Key`。

```json
{
  "revision": 1,
  "signedDate": "2026-11-25",
  "assetId": "1880000000000000001"
}
```

`signedDate` 不得晚于上海时区当天，`assetId` 必须是当前公司及租户内已验收的 `CONTRACT_ATTACHMENT`。附件需要通过现有类型、岗位、组织和文件验收校验。若请求中的日期或附件为空，可采用合同草稿已保存的对应字段；合并后仍必须满足同样条件。

同一原命令重试返回当前合同状态；不同的新命令不能再次对 `SIGNED` 或 `VOIDED` 合同执行签约。

### 补录或更正已签合同凭证

`POST /contracts/{contractId}/evidence`

权限为 `franchise:sale:write`；必须提供 `Idempotency-Key`。

```json
{
  "revision": 2,
  "signedDate": "2026-11-24",
  "assetId": "1880000000000000002",
  "reason": "补录纸质已签合同扫描件"
}
```

只接受 `SIGNED` 合同。日期和附件都必须明确提交，原因去除首尾空格后必填且最多 500 字。只更新签约日期、附件与合同 revision，并追加包含前后证据、原因、操作者和版本的历史记录；不重建合同、付款期、到账登记或财务记录。

签约和补录成功都返回：

```json
{
  "contractId": "1880000000000000000",
  "status": "SIGNED",
  "revision": 3,
  "signedDate": "2026-11-24",
  "assetId": "1880000000000000002"
}
```

合同和附件 ID 是不透明的数字字符串；revision 为数字。日期使用 `YYYY-MM-DD`，不应在页面中转为虚构的签约时刻。

### 合同附件下载

`POST /contracts/{contractId}/assets/{assetId}/download-tickets`

权限为 `franchise:sale:query`，无需业务请求体。服务端核对附件是该合同当前引用的文件，并复查合同、租户、公司及验收状态，然后返回既有 `{downloadUrl, expiresAt}`。票据持有服务端合同 scope，签发、读取文件前及读取文件后均复核当前合同引用和客户的负责人/团队/老板可见权限。客户转交或附件替换后，旧票据不再授权读取。

已关联合同及补录历史的文件，在通用下载链上同样应用客户可见权限，防止绕过合同端点重新取票；工程服务内部验证合同文件引用的行为保持兼容。合同文件读取还核验实际字节和验收摘要一致。下载申请进入审计。文件上传仍走通用资产接口，类型为 `CONTRACT_ATTACHMENT`，支持 PDF/JPEG/PNG，最大 20 MiB。

第 07 步不复用业务资料下载端点。它的 `attachments` 保持空数组，合同入口通过 `fields.contractId` 打开合同办理页面，合同页面通过上述端点查看附件。

### 错误处理

| code | 意义 | 页面处理 |
| --- | --- | --- |
| `1099000001` | revision 已过期 | 刷新当前合同，再由用户确认是否重新提交 |
| `1099000000` | 同一幂等键被不同内容复用 | 保留原请求核对结果，不自动换键重复操作 |
| `400` | 日期、原因、验收证据或幂等键无效 | 显示后端 `msg`，允许修正 |
| `409` | 当前合同状态不支持签约或补录 | 刷新合同状态并显示对应操作入口 |
| `1113000004` / `1099000002` | 对象、附件不属于当前范围或无权访问 | 清除相关预览并提示刷新或重新选择凭证 |

网络结果未知时重试必须沿用相同内容和相同键。幂等键去除首尾空格后为 1 至 80 字符；锁和命令记录统一采用 `franchise + userId + normalizedKey`，再锁定合同，防止并发重复记录。

## 八步进度与总部读取

第 07 步仍是只读事实，不提供手工完成按钮。来源字段保持：

```text
contractId, signedDate, totalCents, assetId, status, sourceRevision
```

来源必须是未删除且未作废的正式合同，状态 `SIGNED`、实际日期有效、金额大于零，且引用附件通过真实验收查询。附件被删除或失效后，进度重新显示待补录，合同和收款历史不被删除。

新的内部 `AssetEvidenceQueryPort.acceptedOwners` 只查询已验收元数据，核对当前租户、文件类型、状态、对象键及有效验收大小和摘要，返回数据库中的真实资产公司映射。每份合同再比对自己的公司，避免多公司错误引用同一附件时相互覆盖；正确公司仍正常完成，错误公司保持待补录。不创建服务账号、不发外链。用于八步批量读取及签约证据复核，保留 GET 只读属性。缺少验收查询能力时不会推断凭证已验收。

总部只读模块可以按真实合同引用读取附件，但必须使用其独立总部授权链。普通门店通用资产角色矩阵未扩展。合同补录前后快照位于 `fr_sale_contract_evidence_event`，不会假造第 07 步的手工节点附件或节点完成事件。

## 数据与兼容

迁移 `V20261125.1044__contract_evidence_history.sql` 新增只追加的凭证更正表，约束每次 revision 增加 1、原因非空、快照为 JSON 对象。同合同同版本只能有一条更正记录。已有 `SIGNED` 行不自动填充日期、附件或虚构证据。

迁移 `V20261125.1046__contract_download_scope.sql` 新增合同票据归属，数据库约束合同 scope 与委托/八步节点 scope 不可混用；普通岗位矩阵没有扩大。

R08 不修改 R11 的 `create/stages/paymentPlan` 逻辑。原签约命令的请求指纹保留，历史同键重试仍可读取既有结果。新增签约校验不接受使用新幂等键覆盖已签合同，明确更正应走 `evidence`。

## 验证与交付状态

新增 `SaleContractEvidencePgIntegrationTest` 使用真实 PostgreSQL、Flyway、CRM 对象访问、命令审计、LocalAssetService 文件验收和八步事实投影。对象存储为内存实现，签约验证和数据库事实为真实实现。用例覆盖无内部预算签约、日期/附件缺失和无效、草稿证据、旧合同补录、前后历史、稳定付款期、版本/幂等/并发、跨租户及跨公司、受控下载、附件失效、批量来源归属和事务回滚。下载回归覆盖客户转交、合同附件替换、历史文件的通用下载、读取过程撤权及字节篡改。

原 `SaleContractThreeStageIntegrationTest` 与 `EngGateNetReconcileIntegrationTest` 的签约 fixture 补上明确的有效合同附件及租户，以继续验证原回款/工程门槛行为。来源事实测试补充附件验收缺失的场景。新用例及两组原回归已加入后端发布 CI。

本地已进行 Java 17 语法解析和差异格式检查；当前环境没有 Maven/PG 运行条件，完整编译和真实数据库用例等待远端 CI，不将语法检查等同于测试通过。
