# R11 小程序合同付款计划

## 页面与入口

`pages/workflow/payment-plan/index` 位于既有 `business-workflow` 分包，统一承接新建待签合同、查看付款计划、调整付款计划及只读版本历史。

- 业务客户的合同页：新建合同进入该页面；已有合同进入“付款计划与变更记录”。原签约、作废、到账登记入口保留。
- 财务应收页：原“合同金额变更”改为“付款计划与变更记录”，直接按合同编号读取计划。财务无需读取 CRM 客户详情、历史需求或快速预算。
- 快速预算仍在原业务入口；新建合同可沿用已有预算总额和最近需求编号，但付款节点由业务人员确认。

## 付款计划

支持 1–20 期，可增删、重排、设置名称、金额或比例、到期条件和日期。整个计划统一按金额或比例填写；金额合计等于合同总额，比例合计为 100%。比例采用整数基点传输，由整数分换算预览，最后一期吸收分币尾差。

到期条件支持签约、开工前、工程节点完成、工程完工、指定日期和手动确认。工程节点填写 1–100 的序号；指定日期条件必须填写日期。旧合同的基础完工、主体封顶条件仅在原付款节点中保留，可改为新条件；新增节点不能使用旧专用条件。旧的 0 元未约定节点保持真实数值，编辑时提示补金额或删除，不生成默认比例。

已有节点使用服务端 `stageId`，重排或编辑均保留原编号。前端阻止删除有已确认净收款的节点，并校验金额不得低于净收款；服务端还会核对到账登记、历史收款等所有财务引用。服务端拒绝后保留草稿，供用户调整。节点名称优先使用服务端 `label`，覆盖合同列表、财务应收、到账申报和收款选项。

## 接口与权限

- 新建：`POST /franchise/sales/contracts`，新增 `paymentStages`，不再提交固定三期金额字段。
- 专用详情：`GET /franchise/sales/contracts/{id}/payment-plan`，返回 `contract`、`stages`、`customerName`、`canEdit`。
- 调整：`POST /franchise/sales/contracts/{id}/payment-plan`，提交 `totalCents`、`stages`、`revision`、`reason`。
- 历史：`GET /franchise/sales/contracts/{id}/payment-plan/versions`，展示原版本金额、节点与调整原因，不能直接回写历史。

页面以服务端 `canEdit` 为最终编辑依据，同时核对合同编号、公司编号和版本。作废或未知合同状态一律只读。创建待签合同仅开放给门店业务、业务主管及老板；财务使用按合同编号的专用读取和调整入口，不获得通用 CRM 写权限。总部跨品牌只读查看由 R02 总部工作台承接。

保存使用独立幂等键；超时或服务器结果未知时冻结原命令，原正文与原键重试。明确业务拒绝可修改草稿；版本冲突要求重新载入。保存开始即使旧读取失效，低版本响应不能覆盖高版本。切换身份、注销、客户或合同不可读时清除敏感数据、草稿、历史和待确认命令；离开页面后的历史读取不会回填。

## 与其他任务的边界

本提交依赖 R11 后端的动态付款计划、专用读取接口和旧节点条件兼容。合同草稿的签约日期仍为选填；正式签约的日期及合同附件校验、上传及补证界面由 R08 单独提交，合同附件必须使用 `CONTRACT_ATTACHMENT`。本提交不把付款计划保存视为八步流程的签约完成，也不增加真实资金支付。

## 验证

`npm run check:payment-plan` 执行模型及真实 Page/API/WXML 行为测试，覆盖整数分和尾差、20 期限制、长节点编号、比例和金额校验、旧条件保留、净已收限制、只读授权、财务专用读取、原业务和财务入口、历史、会话隔离、旧响应隔离、版本冲突及原幂等键重试。

完整 `npm run check`、WXML 结构检查和资源分包门槛继续保持；未降低包体预算。当前环境没有微信开发者工具或 `wcc`/`wcsc`，Node/WXML 测试不等同于微信真编译。固定前后端版本联调、原生编译、真机检查由 R22 验收承接。
