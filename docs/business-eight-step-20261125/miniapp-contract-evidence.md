# R08 小程序正式签约与合同凭证

## 本次变更

原合同页的“签订合同”进入独立合同凭证页，不再只提交 `revision` 就直接签约。页面核对真实合同编号、所属公司、状态和版本，录入实际签约日期及已签合同文件，再调用正式签约接口。合同页没有平台预算时提示可依据外部报价办理；原快速预算入口保留。

历史 `SIGNED` 合同显示原状态；缺少日期或文件时提供补录入口。补录或更正必须填写原因，仅提交日期、资产编号、revision 及原因，不发送合同金额或付款期次。`VOIDED` 合同只读，八步第七步仍由服务端真实签约事实计算，页面不手工推进进度。

新增 `pages/contract-documents` 独立分包，避免继续挤占已接近保留预算的业务工作流分包。原业务合同入口及路由保持兼容；可从凭证页查看 R11 付款计划。

## 权限与接口

- 读取合同：复用 R11 `GET /franchise/sales/contracts/{id}/payment-plan` 的真实合同数据。
- 正式签约：`POST /franchise/sales/contracts/{id}/sign`。
- 已签补录／更正：`POST /franchise/sales/contracts/{id}/evidence`。
- 当前合同文件：`POST /franchise/sales/contracts/{id}/assets/{assetId}/download-tickets`，再使用既有 B 资产受控下载工具查看。

只有门店业务员、业务主管、老板具有签约/补证入口，且已有显式权限列表时须包含 `franchise:sale:write`。R11 返回的 `canEdit` 只代表付款计划编辑权限，不被用于授予签约权限；财务及总部不会因为该字段获得补证能力。服务端继续做最终对象和岗位校验，总部跨品牌附件查看由 R02 独立授权链处理。

文件上传复用既有上传票据、字节 PUT 和 `/complete` 验收链，类型固定为 `CONTRACT_ATTACHMENT`，支持 PDF/JPEG/PNG，单文件最多 20 MiB。正式关联资产以服务端 `ACCEPTED` 为条件。通用 MIME/摘要能力直接复用现有财务文件工具，PDF 最终内容合法性由服务端验收。PUT 响应丢失时先对原资产执行 `/complete` 核对，不重复消费一次性上传票据；明确尚未上传后可显式选择“重新上传”，保留文件字节并领取新票。验收响应超时保留原资产继续核对；确定 `REJECTED` 后要求重新选择文件。

## 异常和会话处理

实际日期按上海业务日期处理，不能填未来日期。保存结果未知时冻结日期、文件、原因及幂等键，用原命令重试；不会自动改为另一种动作或新键。版本/状态冲突保留草稿，明确载入最新状态后重新办理。资产被拒绝时清除不可用的文件选择并保留日期，允许重新上传。

切换岗位、注销、客户或合同撤权后清除客户信息、草稿、本地文件及待确认命令。下载返回 `1099000002` 可能表示客户已转交，先清空页面，再重新读取合同确认权限；附件已被更换则显示最新文件，旧文件失效则要求新凭证。迟到读取、上传、文件选择和下载不能回填另一身份；写开始前挂起的 GET 不能覆盖签约结果。远端附件每次通过合同当前引用申请下载；只有本页尚未保存的新上传文件使用临时本地预览。

## 验证与依赖

`npm run check:contract-evidence` 覆盖真实页面处理器、WXML 条件、API 路径、文件类型/大小/验收、签约和补证命令、只读权限、长编号、原幂等键重试、版本冲突、文件与会话隔离，以及原签约入口的路由替换。该分支基于 R11 小程序提交，后端需要同时包含 R11 专用详情及 R08 证据接口。

完整 `npm run check`、WXML 结构与分包资源门槛继续执行，没有降低任何预算阈值。当前本地缺少微信原生编译/开发者工具，Node Page/WXML 测试不是微信真编译或真机验收，R22 须以固定前后端版本验证正式上传、签约、旧合同补证及附件查看。
