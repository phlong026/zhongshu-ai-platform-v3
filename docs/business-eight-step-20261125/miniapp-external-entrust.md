# R09 小程序：外部委托需求与成果登记

## 页面和入口

新增 `pages/external-entrust` 独立分包，白底棕色沿用现有业务页面。页面只有「委托需求 / 外部成果 / 历史记录」三个标签。没有恢复已删除的方案或资料 Tab，也没有新增内部出图、实体费用支付、总部设计行政审批入口。

- `/pages/external-entrust/index?customerId=...` 按客户进入，GET 不创建记录。
- `?commissionId=...` 先经现有受控委托 GET 解析客户，再读取该客户外部委托；两次返回的委托编号必须一致。
- 原业务「提交委托」、客户选择、预算归档后的 `workflow/commission?view=submit`，以及业务员/业务负责人/老板的委托进度深链在 `onShow` 转新页面，不先读取旧预算或定价前置。
- 旧委托与费用历史使用 `history=1` 返回原记录页，强制进度只读，没有继续办理、费用审批、修改或移交写入口。历史模拟记录仍保留原只读路径。
- 老板可读；办理同时要求当前真实门店业务岗位、`franchise:commission:submit`（若响应提供 permissions）和服务端 `canWrite/canConvert + allowedActions`。总部读取走 R01/R02 独立工作台。

## 需求与成果

需求登记包含实际委托日期、外部服务方和订单编号、需求说明、服务范围、可选建筑面积/层数、最多20个附件。新建无内部预算、内部收费规则或总部前置。变更需求及旧流程转换需要原因；转换必须由服务端明确允许，前端不会替历史模拟委托完成真实结算审核。

每次提交原样带回 GET 的 `currentPaymentPlanRef`；页面展示当前草案或正式合同的全部付款节点、金额、条件及版本。历史需求展示该次冻结的付款约定，和当前计划分开。付款版本变化会阻止旧表单提交，用户明确载入最新记录后重新核对。

成果登记包含实际交付日期、图纸版本、外部设计成果、施工图、专业审核依据三个文件，以及交付说明。更正当前成果必须说明原因；修改需求后原成果保留为历史，新成果绑定新的需求版本。此命令不标记八步完成、合同签约或工程开工。

所有资料使用 `BUSINESS_DOCUMENT`（PDF/JPEG/PNG，每份最多30MiB）；上传测量实际字节及摘要，只有 ACCEPTED 资产才可关联。一次性 PUT 只发一次，网络结果未知时先 complete 原资产；明确未上传后用户可以保留原文件、换新票据重传。扫描拒绝要求重新选择。

历史展开只读全量需求或成果快照、经办人编号和记录日期。查看文件使用 `requests|results/{version}` 专用授权接口；下载完成后再读取客户权限，切岗、客户转交及迟到预览均不会继续打开文件。

## 会话与请求恢复

页面身份绑定 tenant/org/post/user/权限及 session generation，切岗会清除私有表单、历史、待上传字节和预览请求。客户不可读的 HTTP 及 CRM 领域错误清空页面；资产权限变化先清理旧上下文，再 GET 重验。

保存开始即使旧 GET 失效，较低 revision 不回填。网络结果未知时冻结动作、请求体和 Idempotency-Key，禁止改写或生成第二个请求；重试只发送原请求。400 保留可改表单，409/1099000001 显示重新加载入口，替换未保存内容前确认。

## 合并依赖与范围

本分支基于 R13 实体费用模拟收银停用。后台依赖 R07 资产、R09 外部委托和 R12 付款快照端口。付款约定入口复用 R11/R12 的 `pages/workflow/payment-plan/index`；R09 单分支没有重复实现该页面，R22 固定版本组合时必须一起纳入。

R06 第05/06步办理链接以独立小提交接入该分包，避免将 R06 全部分包混入本 PR。R10 后续增加工程移交和接收页面及此处的「移交工程」入口；本任务不伪造移交成功状态。总部外部需求/成果只读入口由 R02 的整合补充承接。

## 验证

`npm run check:external-entrust` 运行24项真实 Page/WXML、模型、API 和上传恢复测试，覆盖无需内部预算首次提交、精确付款引用、历史转换守卫、三份成果、更正/需求换版、只读岗位、客户转交、切岗、迟到 GET/下载、原键重试、旧深链、30MiB及一次性票据。

原业务修复测试保留旧渲染器的权限/预算守卫断言；模拟历史改用真实 `history=1` 入口，另新增实际 `onShow` 不加载旧预算的接线测试。全量检查、角色工作台及包体门禁以本任务最终日志为准。本环境没有微信原生编译器或开发者工具，Node Page/WXML 测试不等于微信编译或真机验证；R22 仍需固定组合后的原生验证。
