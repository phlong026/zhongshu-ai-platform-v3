下文“完成度结论”保留原移植时的历史记录；以上三项以本轮实现及 [六角色全流程验收清单](六角色全流程验收清单_20261023.md) 的实际复测结果为准。P1、历史余额快照、跨部门独立目标等原边界继续保留。

1. 在独立分支移植四页与对应数据整理，先补能暴露旧规则差异的测试。

5. 审查完整差异、扫描凭据、检查反向补丁后提交；将实际完成与待验证部分分别记录。

## 验收记录

### 完成度结论

四页简单版已移植，仍有明确功能和验收边界，不能将整个管理模块称为全部开发完成。

| 模块 | 本版范围 | 保留的缺口或限制 |
| --- | --- | --- |
| 首页 | 六项经营数据、金额审批与结果复核、业务七阶段、工程概况及待办原事项跳转 | 缺“交接”待办分组；业务卡缺预约到店及内容获客汇总；六项统计仅展示数值，未提供逐项原单明细入口 |
| 经营 | 有效收支、环比、账户余额、应收、已批准未付应付、原单追溯 | 历史月份只展示已发生收支，不伪造当时的余额及应收应付快照；这些快照尚未建立 |
| 绩效 | 公司目标、部门成员结果、个人原记录、月度目标保存 | 跨部门兼岗的独立目标，以及部门多指标配置仍需后续设计；既有个人目标保持原单位与口径 |
| 我的 | 共用统一模板；消息、绩效设置、我的团队及门店管理入口 | 审批设置沿用规则说明和岗位分工入口；门店资料沿用只读信息，不等于完整可编辑的审批或门店配置后台 |

按来源设计的 P0 逐条核对，首页上述三项仍未完整落实。其中业务向工程移交与内部责任转交不是同一类事项，交接分组须明确老板实际要办理的触发事实；不能将已有交接管理入口视为待办已完成。

原设计已经推迟、当前仍未提供的 P1：收支趋势、收支构成、账龄、回款率、资金覆盖分析、盈利分析、部门三指标卡与分组切换、最近个人记录展开、推广费与支出用途分类、催款话术及按回款节点发放提成。账户余额登记复用 V3 已有资金核对入口。上述 P1 不计入本次四页简单版完成范围。

### 与源代码的适配

- 金额及单数沿用 V3 最新设计委托事实，界面标为“设计委托金额／设计委托单数”，不恢复旧合同签约链。
- 业务概况沿用 V3 七阶段；“有效客户”按本月真实跟进，“到店客户”按实际到店记录统计，不把缺少看工地事实的数据改称看工地。
- 只纳入审批有效且尚未付清的应付事项；财务仍按实际收付登记，总部确认设计款到账独立保留。
- 财务个人结果显示“登记复核”，不将登记总笔数标成“按时登记”；按时率需另外建立计划时间与实际登记时间的指标。
- 个人页继续共用 `profile/profile.wxml`，保留 V3 当前标准设计费用授权、操作记录与模拟联调入口的岗位限制；未恢复已经下线的订单和采购入口。
- 首页只传 4 条待办、3 个工地预览；经营只预览应收、应付各 3 条。“全部”列表保留原单编号、关键词搜索及每次 20 条加载，完整数据保留在页面实例中，避免首页携带完整客户或账簿。
- 原生验证补齐微信页面编码参数处理：应收分期及工程应付原单编号包含冒号时，页面先解码再匹配原记录；异常编码保留原值。
- 设计原文及效果图随本次移植保留，作为来源记录；遇到旧流程说明时，以本文件列出的 V3 适配为准。
