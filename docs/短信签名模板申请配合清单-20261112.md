### 6.6 配置归属澄清（2026-11-13 实测，纠正此前一处误判）

**此前的错误结论**：把本机 `平台程序/.env` 当成生产配置，得出「设计端 `ZS_WX_APPSECRET` 为空会卡生产启动」。
**该结论不成立**——生产读的是服务器 `/opt/zhongshu/env.merged`（systemd `EnvironmentFile`），与本机 `.env` 是两份独立配置。

实测方式：向两端登录接口提交**假 code**（无副作用），依据返回错误码判断服务器是否具备有效凭据：

| 端 | 接口 | 返回 | 判读 |
|---|---|---|---|
| 设计端 | `POST https://api.zszhj.com/app-api/design/v1/auth/wechat-login` | `1070001010 微信登录凭证已失效` | 微信已认可 appid+secret，仅 code 无效 → **生产凭据有效** |
| 员工端 | `POST https://api2.zszhj.com/admin-api/platform/auth/wechat-login` | `1104000001 登录凭证已失效` | 同上 → **生产凭据有效** |

对照：若密钥缺失或错误，两端应返回「微信服务暂不可用」类错误码（设计端 `1070001013` / 员工端 `1_104_000_002`）。

**结论**：

1. 微信两端**生产无需改动**；设计小程序当前可用，即证明其凭据已在服务器上配好
2. 2026-11-13 已把员工端 `PF_WX_STAFF_APPID` / `PF_WX_STAFF_APPSECRET` 写入本机 `.env`（原为注释与 `__PENDING_WX_RESET__` 占位），
   目的仅是**本地全链演练与新环境部署对齐**，不涉及生产
3. 微信同一 appid 只有一个有效 secret；写入后探针仍返回「凭证失效」而非「服务不可用」，
   说明所用 secret 与生产在用的是同一个，未因重置而中断

**别再把两类"未配置"混为一谈**：

| 类型 | 存放位置 | 缺失影响 |
|---|---|---|
| 环境变量（微信 appid/secret、COS、短信其余键） | 每台机器各自的 env 文件 | 只影响该台机器 |
| **云端资源（短信资质、签名、模板、套餐包）** | 腾讯云账号 | **所有环境一样发不出**，与 env 无关 |

因此当前唯一真实阻塞是**云端资源**：资质未提交（缺盖章件）→ 签名不存在 → 模板 `2774958` 已过审生效 → 套餐包/余额未确认。
