# 自动衔接优化与验收（2026-10-22）

本轮依据“真实经办人核实一次，系统自动接续下一岗位”检查设计、业务、工程和材料付款。保留实际到账核实、专业审核、必要费用审批、实际交付及工程验收，清理人工通知和重复申请。

## 核查结果

| 触发事实 | 保留的人工动作 | 自动结果 | 本轮处理 |
| --- | --- | --- | --- |
| 设计费用授权 | 老板批准例外费用；匹配标准时复用老板预授权 | 加盟商首款付款待办，原审批事项关闭 | 复测原单和授权版本；不增加逐笔重复审批 |
| 加盟商登记设计款付款 | 门店财务核对实际付款 | 对应总部出现到账确认待办 | 新增当前需求、服务版本和原付款绑定 |
| 总部确认设计款到账 | 收款总部财务核对银行流水、凭证、日期和金额 | 分笔累计实收、关闭已办待办；足额且设计完成时自动通知行政并开放下发 | 新增一次保存完成确认，不要求另点通知或二次复核 |
| 设计或修改完成 | 行政记录线下实际完成、专业审核及本次修改 | 业务跟进尾款、门店财务付尾款；满足到账条件时行政待下发 | 复测既有触发；移除“收到财务线下通知”勾选 |
| 正式图纸实际下发 | 行政登记真实下发事实、接收方及清单 | 关闭下发待办，生成业务收图并移交事项 | 增加命令层到账校验与确认版本审计 |
| 业务提交移交资料 | 业务收齐文件及客户本版确认，选在岗工程负责人 | 工程出现资料核查接收待办 | 复测既有接续；退回自动回到原业务补齐 |
| 工程确认接收 | 接收人核对资料 | 关闭原接收待办，工程工作区同步原项目 | 保留原单及负责人约束，不增加接收后通知按钮 |
| 材料计划、到货及采购付款 | 工程按原规则登记事实，老板批准必要采购，财务登记真实付款 | 财务付款计划及待办更新；已付结果回写原采购进度，等待付款事项自动消失 | 核查既有自动接续；付款页面删除线下通知提示 |
| 工程开工收款满足条件 | 财务登记真实收款，工程记录真实开工 | 工程出现可办理的开工事项，命令再次校验 | 保留既有开工条件；封顶款提醒不擅自改成阻断施工 |

费用、完成、移交主要由 `utils/sales-flow.js`、`utils/finance-ledger.js` 投影。工程接收待办由 `pages/build/workbench.js` 生成，接收后 `pages/build/model.js` 同步工程项目。材料付款条件由 `utils/engineering-records.js` 关联财务原单，`pages/admin/finance-save.js` 回写实际付款进度。设计到账新增 `utils/design-receipts.js`，站内通知新增 `utils/design-notifications.js`，其余流程复用既有实现。

## 页面优化

- 行政首页采用问候语、统计卡、今日待办、最近办理；“项目”包含当前工作和已下发历史。“待财务通知”改为“待到账确认”，等待事项不混入可办理待办。
- 财务区分“门店已付款”和“总部已到账”，不足额继续显示差额。总部只开放当前岗位可办理的确认入口；无权退款或更正的链接隐藏。
- 财务保存后，原待办自动关闭；行政直接收到可操作的下发待办与站内消息。页面进入和操作时重新校验原单状态，消息不替代权限及下发门禁。
- 付款完成后的提示统一说明系统自动更新原任务和进度，去除要求财务再线下通知的文案。表单操作区沿用随内容滚动的布局。

## 验收与复测

```sh
npm run check:business:simplified
npm run check:design-receipts
npm run check:design-receipts:native
```

完整本地回归包含22个脚本：原业务、财务、工程和导航19个，加设计到账、通知、财务到账视图3个。到账核心包含11组检查；通知覆盖人员和组织隔离、已读、退款导致关闭以及补款后重新未读。所有财务测试使用整数分并验证少一分钱、重复提交、旧版本和保存失败。

原生连续链路包含6组检查：门店已付但总部未确认时行政等待；总部从待办确认到账；原到账待办关闭；行政自动出现下发事项；站内消息直接打开合法下发页面；下发后业务自动收到移交事项。同时检查到账表单操作区随内容滚动。结果、截图及存储恢复证据保存在 `qa/design-receipts-20261022/native/`；完整本地回归记录在 `qa/business-module-simplification-20261021/regression-results.json`。

独立代码审查已通过，无遗留P1/P2；核查包含权限、组织、净额、版本、重复记账、保存失败及通知隔离。历史设计、退款和材料回款另外验证通用收款语义，不套用新设计协议的放行提示。代码语法、项目/WXML检查、格式差异检查及改动文件敏感信息扫描通过。项目没有配置独立ESLint、TypeScript或格式化器，沿用原生JavaScript格式和现有项目检查。

没有新增依赖，生产依赖审计为0项漏洞。已有开发自动化依赖仍有11项漏洞（3严重、1高、6中、1低），与本轮依赖文件未变的基线一致，记录在 `qa/design-receipts-20261022/dependency-audit.json`；本轮未扩大范围升级自动化工具链。

## 交付边界与后续接入

本轮实现处于原项目本地存储模型。以上“自动”指保存业务事实后，由同一数据状态即时推导的流程、待办和站内消息；多手机实际协作尚需后端持久化、服务端校验和事件同步。微信推送、银行自动对账、真实转账和自动发送正式图纸均未接入。原生测试为模拟人员和示例凭证，未上传或发布微信版本。
