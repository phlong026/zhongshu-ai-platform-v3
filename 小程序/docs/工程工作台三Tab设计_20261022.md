# 工程工作台三 Tab 设计：首页、进度材料、我的

2026年10月22日，第二版（以记录为中心的简化版）。第一版的效果图保留在[第一版](工程工作台效果图_20261022/第一版/)目录中供对比。

本设计基于现有小程序工程代码、[工程主链路](工程模块主链路_20261021.md)和[材料计划精简流程](材料计划精简流程_20261021.md)，并参考了同行做法。

## 一、结论

**工程模块只做一件事：让工程人员把工地上实际发生的事记下来。** 不在小程序里做验收审批、整改复验、必拍检查、逾期考核这类管控。十几人的乡墅公司，管控靠老板和工程人员当面沟通；系统要解决的是"记得下来、找得到、业主看得到、财务接得上"。

1. **三个 Tab：首页、进度材料、我的。**
2. **首页围绕"今天记了没有"。** 最显眼的是"记现场"按钮；下面列出每个在建工地今天是否已记录；再下面是最多几件"等你记一下"的事（到货、收款、新工地接收）。
3. **进度材料按工地看。** 施工进度视图展示节点条和当前节点的记录时间线；材料视图只有"报材料需求"和"记到货"两个动作。
4. **记一条现场记录只需三步**：拍照、按住说一句（自动转文字）、选今天的情况（正常施工 / 下雨停工 / 等材料 / 其他）。工地、节点、日期时间自动带上。
5. **到货、收款也都是"记录"**，会自动出现在节点的记录时间线里，一条时间线能看清这个节点发生过的所有事。

## 二、和现有代码的关系

| 现有能力 | 位置 | 简化版怎么处理 |
| --- | --- | --- |
| 工程四 Tab：首页、项目、材料、我的 | `utils/organization.js` 的 `navigation()` | 改为三 Tab，项目和材料合成"进度材料" |
| 现场记录（可只保存不完成） | `pages/build/record`（`view=node`） | 作为核心功能，独立成"记现场"弹层 |
| 节点完成 | `utils/engineering-records.js` | 保留，改为一个"这个节点完成了"按钮：拍照 + 日期即可 |
| 材料：提交计划、确认到货、财务付款 | `record` 页材料视图 | 工程端只留"报材料需求""记到货"；付款完全交给财务，工程页面不展示金额 |
| 两期收款：开工款、封顶款 | `engineering-records.js`、`pages/build/model.js` | 工程只"记收款"（金额 + 凭据），财务确认；封顶节点完成后首页提醒记封顶款 |
| 待我办理 / 办理中 | `pages/build/workbench.js` 的 `snapshot()` | 只保留"等你记一下"，去掉"办理中"和各类审核待办 |
| 验收审核、整改复验、质量处置、差异补发 | `workbench.js`、`views.js` | 新流程不展示；历史项目的旧记录保留只读 |

后端 M2 只做到"工程接收移交"。做 M3 工程域时，按本文对象建模即可：工地（项目）、节点、记录（现场 / 到货 / 收款三种类型）、材料需求。

## 三、同行做法与取舍

| 同行 | 借鉴 | 不借鉴 |
| --- | --- | --- |
| 爱空间 | 按天记录施工进度，业主能随时看 | 7×24 工地直播 |
| 一装ERP、云装天下 | 施工日志带照片，同步给业主；进度节点模板 | 扫码签到、巡检定位、自动扣罚、进销存 |
| 南京星艺装饰 | 小程序每天推送日志和照片给业主 | 500 多个验收节点、业主监理双签 |
| Buildertrend（美国） | 每日日志：照片、天气、人数、停工原因；支持语音转文字 | 甘特图、分包商门户 |
| 乡墅建房公司 | 业主在外地，靠照片了解进度；封顶是公认的收款点 | 摄像头远程监工 |

共同点是"每天的照片和一句话"最有价值，所以简化版把它放在了第一位。

## 四、三个 Tab 的内容

### 首页

1. 问候、日期、天气、在建工地数。
2. **记录区**（主色大卡片）：大按钮"记现场"，两个小按钮"记到货""记收款"。
3. **今天的工地**：每个在建工地一行，显示当前节点，以及"今天已记录（几张照片、几点）"或"今天还没记录"。还没记录的带"去记录"按钮。
4. **等你记一下**：系统提醒，只有三类：
   - 材料今天该到（来自材料需求的到场日期）
   - 收款该记了（开工准备完成、封顶节点完成后）
   - 新工地待接收（业务移交）

### 进度材料

顶部是工地卡片（可切换），下面分两个视图。

**施工进度**
- 节点条：开工 → 基础 → 一层 → 二层 → 封顶 → 屋面 → 交付（按项目层数生成，可调整）。
- 当前节点：名称、计划日期，两个按钮"记现场""这个节点完成了"。
- 当前节点的记录时间线：现场记录、到货记录按时间倒序排列，每条显示时间、人、今天的情况标签、文字和照片。
- 底部链接：前面节点的记录、把记录发给业主、调整工期。

**材料**
- "报材料需求"按钮：名称、规格、数量、需要到场的日期，提交后公司去买。
- 当前节点要用的材料：每种显示"要多少、到了多少"，没到齐的带"记到货"按钮。
- 到货记录：最近几次到货，带送货单照片。
- 前面节点的材料折叠显示。

### 我的

沿用现有个人页：个人资料、消息、工程课程、账号设置，最底部退出登录。

## 五、四种记录

| 记录 | 谁记 | 填什么 | 去哪里 |
| --- | --- | --- | --- |
| 记现场 | 工程人员 | 照片、一句话（可语音）、今天的情况 | 当前节点的记录时间线 |
| 记到货 | 工程人员 | 哪种材料、到了多少、送货单或现场照片 | 材料到货进度 + 节点时间线；财务据此付款 |
| 记收款 | 工程人员 | 哪一期、金额、转账截图 | 财务核对后计入已收 |
| 节点完成 | 工程人员 | 完成日期、照片 | 节点条往前走一格；封顶完成后提醒记封顶款 |

四种记录都不需要别人审批才生效。只有收款需要财务核对到账，这一步在财务端完成，工程端不用等。

## 六、乡墅节点模板

开工准备 → 基础工程 → 一层主体 → 二层主体 →（三层主体）→ 主体封顶 → 屋面工程 → 外墙装饰 → 水电门窗 → 竣工交付

现有 `engineering-seed.js` 只有基础、一层、二层三个节点，按此扩展。工程人员可以增删节点、改计划日期。

## 七、明确不做

验收审核、整改复验、隐蔽工程必拍、逾期提醒与考核、"办理中"等待列表、材料付款与金额展示、库存领料、扫码签到、甘特图、工地大屏、多级审批、班组长账号。

## 八、改造顺序

| 批次 | 内容 | 主要文件 |
| --- | --- | --- |
| 第一批 | 三 Tab 导航；首页改为记录区 + 今天的工地 + 等你记一下 | `utils/organization.js`、`custom-tab-bar`、`pages/build/home`、`pages/build/workbench.js` |
| 第二批 | "记现场"弹层；进度材料页（节点条 + 记录时间线 + 材料两动作） | `pages/build/progress`（新）、`pages/build/record`、`utils/engineering-records.js` |
| 第三批 | 节点模板扩展；语音转文字；把记录发给业主 | `utils/engineering-seed.js`、业主进度视图 |

旧链接 `/pages/build/projects/index`、`/pages/build/materials/index` 需要跳转到进度材料页，保证历史入口可用。
