# 材料计划精简流程与工程衔接

2026年10月21日。已接入新业务工程的记录流程：工程人员提交材料计划，公司线下采购，工程确认实际到货，财务办理实际付款。所有动作沿同一份计划继续。

材料从所属施工节点进入，列表按该节点过滤，详情显示本计划施工节点；付款及到货结果同时汇总到节点资金计划。人工等费用仍按原费用事项办理，并保留节点关联。

## 页面只做三件事

| 操作 | 办理人 | 记录内容 | 接续 |
| --- | --- | --- | --- |
| 提交材料计划 | 项目工程人员 | 材料名称、规格、数量、单位、需到场日期；自动带入项目和当前节点 | 计划提交即生效，公司可按清单采购，工程待到货、财务待完善付款资料 |
| 付款 | 公司或财务补齐采购信息，老板及财务按原金额权限办理 | 各项实际供应方、单价、运费、采购凭据，以及实际付款金额、日期、流水和凭据 | 原计划回显已付及待付，实际支出计入同一项目 |
| 到货确认 | 项目工程人员 | 本次实际合格数量、日期、说明及到货凭据 | 累计实收和未到数量，更新施工节点材料条件，保留每次到货记录 |

通常先到货后付款，需要预付款时在原计划先办理付款。付款和到货分别保留实际事实，互不替代。

工程提交时不要求先填供应商或价格。财务能从待办进入同一计划补齐实际采购信息，再沿原财务事项办理付款，不增加采购接单、供应安排或补发申请页面。

## 原计划怎样继续

一份计划支持多种材料，按实际供应方关联付款；分批到货在原计划填写本次数量，累计数量不能超过计划。价格未记录时明确显示“待记录采购金额”，不显示为已付清。

节点材料合格到齐后，工程可以记录节点完成，材料付款仍沿原计划跟进。没有新增材料的节点，工程确认现场材料已核对后直接继续。现场问题在原节点补充说明，处理好后再记录实际完成。

收付款凭据需要补充时回原财务事项，实际付款保留原记录。新流程先覆盖日常采购、付款、合格到货，不另建质量处置、退货、余料或特殊采购流程。

## 与工程和财务的衔接

| 时点 | 系统结果 |
| --- | --- |
| 工程接收及开工准备 | 形成同一项目、同一工程人员及施工节点 |
| 提交计划 | 自动维护材料需求及供应关联，后续到货和财务都能直接接续 |
| 确认到货 | 更新合格材料数量及节点条件，付款资料缺项仍由财务在原计划补齐 |
| 财务付款 | 实际付款结果回写原材料来源，原计划及项目账显示同一金额 |
| 主体封顶 | 触发客户第二期工程收款，材料付款仍是对外采购支出 |
| 施工交付归档 | 原计划未结付款继续办理，财务核对成本后完成项目结清 |

实际联动使用[工程记录服务](../miniprogram/utils/engineering-records.js)、[项目记录页面](../miniprogram/pages/build/record/index.js)、[财务来源](../miniprogram/utils/finance-ledger.js)、[财务回写](../miniprogram/pages/admin/finance-save.js)及[项目成本](../miniprogram/utils/operations.js)。历史材料沿原入口保留。
