# 管理工作台四 Tab 设计：首页、经营、绩效、我的

2026年10月22日。基于现有小程序老板端代码（`pages/admin` 下的首页、财务、绩效、我的四页，见[老板端四页串联与统一样式](老板端四页串联与统一样式_20261020.md)），以及在微信开发者工具中以"赵老板"演示账号实际打开的四页现状，对标国内装企 ERP、小微企业业财软件和海外小型住宅建造商软件，给出面向 8～10 人乡墅公司的管理模块设计结论。效果图见[管理工作台效果图](管理工作台效果图_20261022/)。

## 一、结论

1. **底部导航：首页、经营、绩效、我的，四个页面。**原"财务"Tab 改为"经营"，内容是老板视角的财务：收支、应收、应付（盈利分析放 P1）。业务和工程的情况放在首页，不单独做 Tab。
2. **首页 = 本月经营 + 待我办理 + 业务 + 工程。**
   - 本月经营只放 6 个数，放在一个面板里：签约金额、回款金额、签约单数、新增线索、有效客户、到店看工地。前三个看结果，后三个看获客和转化。
   - 待我办理只放需要老板审批或审核的事项，不再拆成"待我拍板"和"需要留意"。样式与业务首页的"待我办理"一致：顶部按类型分组（金额审批、结果复核、交接），第一条用实心按钮，其余用文字链接。
   - 业务卡片：客户在各阶段的数量（跟进中、方案设计、报价中、待签约）+ 需要关注的跟进情况。
   - 工程卡片：在建、待开工、本月交付、延期四个数 + 在建工地的节点进度与两期收款状态。
   - 暂不做 AI 今日简报。
3. **经营页先做简单版：收支、应收、应付。**深棕卡片放本月收入、支出、结余和账户余额；应收账款按客户和款项列出，逾期标红；应付账款列出到期日和状态；底部是财务待处理笔数。收支趋势、收支构成、账龄、回款率、盈利情况放到 P1。
4. **绩效页先做简单版：公司目标 + 团队。**公司目标四项；团队按部门（运营、业务、设计、工程、财务）分组列出个人，每人一行写核心结果和完成度，点进去看原始记录。部门指标卡片和个人记录展开放到 P1；不在绩效页做结算。
5. **我的沿用各岗位统一的"我的"页面。**个人卡、消息 + 绩效设置、组织与工作身份 + 我的团队、门店管理（成员与权限、审批设置、项目经理交接、门店资料）、学习培训、加盟商服务、我的订单 / 帮助与反馈 / 账号与隐私、退出登录。其他岗位在"我的绩效"的位置，老板显示"绩效设置"，统一设置公司目标、部门指标、个人目标和提成规则。
6. **这个规模要的是"看得清 + 提醒到"，不是 BI 大屏。**不做多维钻取、自定义报表、驾驶舱大屏、预算编制、费用报销审批流、考勤打卡。
7. **乡墅特有的三件事要做好：**封顶款回款（第二期收款点，最容易拖）、获客成本与转化（短视频和老客户介绍是主要客源）、资金覆盖（材料款集中付款时账上够不够）。

| 工程项目、节点计划与实际完成 | `zhongshu-engineering-v1`、`pages/build/model.js` | 首页工程卡片 |

现状的问题（来自开发者工具实测截图）：

- **首页数字多是 0 或"待完善"。**"可核对资金""合同预计毛利"在没有账户余额和项目成本时显示"待完善"，占了一整张卡；下方一段 60 多字的说明文字，老板不会读。
- **首页四宫格和 Tab 重复。**"经营报表"和财务 Tab 重复，"金额审批"和下面的待我审批卡片重复。
- **财务页顶部又放了一张"应收应付与成本"卡**，和下面的收支总览分成两处，老板要看两遍。
- **绩效页最上面是"绩效金额结算与发放"按钮**，这是月底才做一次的事，却占了首屏最显眼的位置。目标全部"待设置"时，整张卡都是灰字。
- **销售指标太少。**老板只看到签约额，看不到获客、有效客户、到店、转化率、获客成本这些销售型公司的过程指标。
- **财务信息不成体系。**没有收支趋势和构成，应收没有账龄和回款率，应付没有到期分布。

## 三、对标

| 对标对象 | 类型 | 值得借鉴 | 不照搬 |
| --- | --- | --- | --- |
| 一装ERP | 装企 ERP | **事前规则、事中预警、事后分析**；自定义预警（工期延误超 3 天、成本超支 5%、材料未按时到货）推送到手机；收款计划绑定工程进度、自动催款；新版可用自然语言问"本月签约项目延期风险如何" | 客诉、巡检、工效、损耗等几十张报表；多门店、多部门产值统计 |
| 好业财装修版（畅捷通） | 业财一体 | 首页"项目利润看板"按进度阶段显示**毛利率、回款率、成本超支预警**；每天推送**经营日报**；应收账龄、欠款超期提醒；20 人以下项目型企业版本 | 三大财务报表、银企直连、税务申报：小公司交给代账会计 |
| 云装天下 | 装企 ERP | 在建工地进度看板用**红色超期、黄色即将超期**两种颜色标注 | 完整进销存、仓库调拨 |
| 智装天下、掌赋 | 装企 ERP | 老板手机端看经营报表、物料成本和利润；按员工统计签单产值 | 签到签离、巡检报表 |
| Buildertrend | 美国住宅建造商软件 | 内置 6 张报表里最常用的三张：**盈利（预计、预测、实际利润放一起）、预算对实际、现金流**；单项目看预计毛利和毛利率 | 界面信息密度高，评测普遍认为前几周难上手；员工层面的绩效报表弱 |
| JobTread | 美国小型装修/建房软件 | **按里程碑收款**的收款看板，所有客户收款集中在一处；预计、已承诺、实际成本放在一起，**毛利在下滑时就能看到** | 与 QuickBooks 的同步、WIP 报表：国内小公司不需要 |
| 乡墅建房公司常见做法 | 行业 | 按节点分期付款（建好一层付一层，或按合同节点）；老板最关心在建工地数、回款和单栋利润；业务员提成多按回款比例分次发放 | 我们已确认开工款 + 封顶款两期，保持不变 |
| 乡住 | 自建房接单平台 | 平台给施工队提供客户管理、项目管理后台和 AI 出图，说明这个行业的老板需要"接单 + 管工地"一体 | 平台派单模式：我们是品牌加盟，客源由门店和总部内容获客产生 |

对标的共同点：**老板端的核心是"回款 + 单项目毛利 + 预警"三件事**，几乎所有产品都把它们放在首屏。国内产品多了"经营日报推送"，海外产品多了"预计毛利随成本变化实时更新"。我们现有的账簿和项目账目已经具备数据基础，缺的是把它们组织成老板一眼能看懂的样子。

## 四、8～10 人乡墅公司的管理画像

- **组织**：老板 1 人（常兼业务负责人，有时老板娘管账）；运营 1 人（短视频与内容获客）；业务 2～3 人；设计 1 人（或由总部设计协同）；工程 2～3 人（含项目经理）；财务/出纳 1 人。施工由外包班组完成，班组不进系统。
- **生意规模**：每栋 30～60 万，年签约 20～40 栋，同时在建 5～8 个工地。一单就是一个月的利润，签约和回款波动大。
- **老板每天关心**：今天有什么要我批？钱够不够付下周的材料款？哪个工地出问题了？这个月能签几单？
- **老板每月关心**：获客多少、签了多少、收了多少、钱花在哪、赚不赚钱、每个部门和每个人干得怎么样。
- **使用场景**：老板多半在外面跑客户、跑工地，用手机看，一次只看一两分钟；晚上或月底才会认真看报表。
- **乡墅特点**：客源靠熟人转介绍和短视频；签约前要看样板房或在建工地；封顶款容易拖（业主资金分批到位、春节前集中结算）；钢筋水泥价格波动直接吃掉毛利；雨季、农忙影响工期。

## 六、四个页面怎么设计

### 首页

1. 问候 + 门店与日期。
2. 本月经营：一个面板，3 列 × 2 行共 6 个数，每个数下写目标完成度或补充说明；右上角选月份。
3. 待我办理：顶部分组按钮"全部、金额审批、结果复核、交接"；每条写客户与事项类型、金额、提交人；第一条实心按钮，其余文字链接；底部"查看全部"。
4. 业务：四个阶段数量 + 三条需要关注的事项，点进业务概览。
5. 工程：四个数 + 在建工地（节点条、开工款与封顶款状态），点进工程概览。

### 经营

月份选择，注明"按有效核算统计" → 深棕收支卡片（收入、支出、结余，账户余额）→ 应收账款（合计 + 明细）→ 应付账款（合计 + 明细）→ 财务待处理。

### 绩效

月份 → 公司目标四项（右上"去设置"跳到我的 → 绩效设置）→ 团队：按部门分组，每人一行（头像、姓名、岗位、核心结果、进度条、完成度）。

### 我的

沿用各岗位统一的"我的"页面结构：个人卡 → 消息 | 绩效设置 → 组织与工作身份、我的团队 → 门店管理（成员与权限、审批设置、项目经理交接、门店资料）→ 学习培训 → 加盟商服务 → 我的订单、帮助与反馈、账号与隐私 → 退出登录。

## 七、口径约定

| 指标 | 口径 | 来源 |
| --- | --- | --- |
| 签约 | 本月已上传合同文件的合同总额 | `customer.contract`，与现有一致 |
| 签约转化 | 本月签约单数 ÷ 本月有效客户数 | 客户登记与合同 |
| 获客成本 | 本月推广费 ÷ 本月有效客户数 | P1 新增推广费登记；未登记时显示"待登记" |
| 回款率 | 本月实收工程款 ÷ 本月到期应收 | 收款计划 + 有效收款 |
| 资金覆盖 | 账户余额 ÷ 应付余额 | 账户余额登记 + `payables` |
| 回款 | 本月有效核算的收款 | `receipts`，与现有"有效实收"一致 |
| 账上可用 | 最近一次登记的账户余额 + 之后的有效收款 − 有效付款 | P1 新增账户余额登记；未登记时显示"待财务登记"，不推算 |
| 应收 | 两期收款计划中已到节点但未收的金额 | 工程节点 + 收款计划 |
| 应付 | 已审批、未付款的应付 | `payables` |
| 预计毛利 | 合同额 − 已付成本 − 已承诺未付成本 | 成本不全时显示"成本待完善"，不显示比例 |
| 部门完成度 | 部门 3 项指标完成率的平均值 | 我的 → 绩效设置中配置的部门指标 |

所有数字都从原记录汇总，点进去能看到原单；没有数据时写"待登记""待设置"，不编造。

## 八、明确不做

- BI 驾驶舱大屏、多维钻取、自定义报表
- 预算编制、部门费用分摊
