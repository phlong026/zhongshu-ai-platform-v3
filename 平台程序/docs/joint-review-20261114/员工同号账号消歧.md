# 员工同号账号消歧（2026-11-14）

`POST /admin-api/platform/org/staff` 保留原有 `orgId/name/mobile/roleCode/teamId`，新增可选 `userId`。不传时在当前租户、未删除账号中查手机号：无账号则创建，唯一账号则复用；多个账号且只有一个具有有效任职时复用该账号，其余歧义返回业务码 `1101000023`，不再抛 `TooManyResultsException` 或按编号取首条。

传 `userId` 时仍须通过管理员权限及当前组织范围校验；账号必须属于当前租户、未删除且手机号完全匹配。不存在返回既有 USER_NOT_FOUND，手机号不匹配返回 `1101000024`。校验后才追加岗位，新建账号与指派仍在同一事务内。原账号资料、历史任职与历史记录不清理、不合并。

前端收到歧义后，可用已授权查询的本店成员列表展示同号候选，按 userId 去重，由管理员明确选择后重试；无候选请总部核对。不得静默选中首项。

验证：YudaoSystemDirectoryTest 4 项、StaffPostAssignContractIntegrationTest 7 项均通过，后者使用 PostgreSQL 17 / Testcontainers。Mapper mock 未直接验证真实 SQL 的租户与逻辑删除注入；隔离依据仍包含现有 TenantBaseDO、TableLogic 与租户拦截器。

本次为独立 B 源码修复，未部署到当前 api2 共享旧包，未重启共享 A 服务。代码可 revert；没有修改线上历史数据，无数据回滚步骤。
