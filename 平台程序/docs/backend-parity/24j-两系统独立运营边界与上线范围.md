# 24j · 两系统独立运营边界与上线范围（架构决策）

> 决策来源（2026-11-13 用户拍板）：**AI 设计小程序与众墅之家赋能平台是两个不同的运营体系**；
> 旧小程序用户点数**不迁入**赋能平台；赋能平台所有内容**全新开始**。

## 一、边界原则

| 维度 | AI 设计小程序（A 系统） | 众墅之家赋能平台（B 系统） |
|---|---|---|
| 用户 | 设计侧账号（激活/开通体系，按 A 侧决策） | 加盟商员工（组织+岗位，platform-identity） |
| 点数 | 个人账户 `design_point_account`（保持现状） | **公司积分池 `org_point_account`（从零开始）** |
| 充值 | A 侧充值/支付链 | B 侧首发**关闭**（`ZS_RECHARGE_ENABLED=false`），靠总部调点/开通赠点 |
| 激活码 | A 侧机制（按 A 侧决策；B 平台不接入） | **不使用激活码**（公司整体开通 + 按量扣点） |
| 计价 | `generation_price_rule` / `service_usage_price_rule` | **`BillingPriceCatalog` 公司池科目价（独立）** |
| 运营后台 | 设计运营（`/zs` 现有页面） | 赋能总部（组织开通/公司池/额度/权限；后续按拆分方案独立） |
| 部署 | 拆分后独立后端+库 | 本仓库演进方向=B 侧 |

## 二、因此调整的三项结论

1. **B-16 存量点数迁移：不适用**（原设计是"个人点→公司池"）。
   - `DesignPointMigrationService` 保留为历史能力但**默认硬关闭**：
     `zhongshu.org-point.migration-enabled=false`（prod/pg 默认 false，模板已含），
     显式调用 `execute` 抛"点数迁移已按架构决策停用（设计小程序与赋能平台独立运营，点数不互通）"。
   - `dry-run` 仍可只读查看（不产生任何写入），仅用于分析用。
2. **B-15 身份映射：降级为可选的只读分析工具**（不再作为迁移前置、不作为上线门禁）。
3. **B-14 激活码退役：范围限定为 B 系统**——B 平台本来就不接入激活码；
   `ZS_ACCESS_CODE_ENABLED=false` 属 A 侧决策，若 A 侧仍需码可置 true，B 平台不受影响。

## 三、B 系统（赋能平台）上线范围 = 全新启用

| 能力 | 状态 |
|---|---|
| 组织开通（含设计能力/赠点） | ✅ 已就绪（幂等） |
| 公司积分池（三态结算/额度/业务权限/审计） | ✅ 已就绪 |
| 设计桥（平面/立面/修订/预算/润色→公司池） | ✅ 已就绪（App 链保持个人池，永久有效） |
| 内容创作 AI（预扣/结算/UNCERTAIN PENDING） | ✅ 已就绪 |
| CRM/销售/工程/财务/绩效等既有业务 | ✅ 原有能力不动 |
| 充值入口 | 首发关闭（总部调点替代） |
| 点数迁移 / 激活码 | **不启用** |

## 四、遗留：公司池科目价格（D8）

现状：`BillingPriceCatalog` 为代码常量（v1 默认价），**后台不可改**；
现有「出图定价/服务计费」两个页面作用于 A 侧个人池计价规则，与公司池无关。

建议下一批（价格表化，使后台可调）：
1. 表 `org_point_subject_price(subject, unit, price_micros, version, effective_at, status)`；
2. 管理页：科目价格 CRUD + 发布新版本（沿用既有"发布新版本+旧版停用"模式）；
3. 预扣仍写快照，调价只影响新任务；历史 operation 按快照结算；
4. 验收：调价后新任务单价变化、在途金额不变、旧任务重放不重算。

价格数值仍需运营拍板（当前 v1 默认：出图 2 点/张、立面 3 点/张、预算 1 点/次、提示词 1 点/次、数字人 3 点/分钟、AI 视频 768P 10 点/分钟、2K 20 点/分钟）。
