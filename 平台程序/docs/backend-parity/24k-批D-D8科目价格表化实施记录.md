# 24k · 批 D / D8 公司池科目价格表化（实施记录）

> 决策来源：用户确认方案 A ——「科目价格表化 + 后台管理页」，使 **价格可由后台配置**，而不是写死在代码里。
> 状态：**后端 + 管理页已实施，待 Codex 代码评审**；价格数值仍属运营决策（见 §六）。

## 一、目标与边界

| 目标 | 做法 |
|---|---|
| 后台可调价 | 新增 `org_point_subject_price` 配置表 + `/design/v1/org-point-price-rules` 三个端点 + `/zs/org-point-pricing` 管理页 |
| 调价不影响在途 | **预扣仍写快照**：RESERVE 时把 `subject/unit/priceMicrosPerUnit/priceVersion/minCharge/quantity/credits` 冻结进 `price_snapshot`；SETTLE 只按快照重算 |
| 开箱可用 | 无任何配置时回退 `BillingPriceCatalog` 代码默认价（v1）；停用配置同样回退默认价 —— **任何情况下都不会变成免费** |
| 可追溯 | 每次发布 = 新版本行，旧生效版自动 RETIRED；发布人 / 停用人 / 时间点全部留痕（停用不覆盖发布人） |

**时延语义**：发布即生效（无预约生效时间）。与 `usage_price_rule` 的生效窗口不同，这里刻意简化为「当前 ACTIVE 即现价」——
预扣快照已保证历史一致性，不需要时间窗来"保住旧价"。

## 二、数据模型

`V20261113.315__org_point_subject_price.sql`（commerce 段，同版本号 undo 为 DROP TABLE）：

| 列 | 说明 |
|---|---|
| `subject` | 计费科目键（与 `BillingPriceCatalog` 同一命名空间，未知科目直接拒绝） |
| `unit` | `CALL` / `SECOND`（由科目目录决定，发布时由后端写入，不接受调用方传值） |
| `price_micros` | 微积分/单位（1 积分 = 1_000_000 微积分；整数运算，无浮点） |
| `min_charge` | 最低收费（积分，≥1） |
| `version` | 科目内自增版本号（从 1 开始） |
| `status` | `ACTIVE` / `RETIRED` |
| `effective_at` / `retired_at` / `operator` / `retired_by` | 时间与操作人留痕 |

不变量（DB 兜底）：

- `CREATE UNIQUE INDEX uk_ops_price_active ON org_point_subject_price (subject) WHERE status='ACTIVE'`
  —— 每科目至多一条生效价。
- `CONSTRAINT uk_ops_price_version UNIQUE (subject, version)` —— 版本号科目内唯一，**并发发布不可能出现两个 `db-v2`**。
- 服务层再加事务级 `pg_advisory_xact_lock(hashtext('org_point_price:'||subject))`：同科目发布先锁后读 `MAX(version)`，
  把"算版本→退休旧版→插新版"串行化；锁只作用于同科目发布，不阻塞预扣计费。
- 并发/重复操作撞唯一键 → 错误码 `1_072_000_016`「价格已被他人修改或已停用，请刷新后重试」（不是通用 500）。
- `CHECK price_micros > 0`、`CHECK min_charge BETWEEN 1 AND 1e9`、`CHECK unit IN ('CALL','SECOND')`、`CHECK status IN ('ACTIVE','RETIRED')`。

## 三、计价链路变更

`OrgPointService`：

1. `resolvePrice(subject)`：DB ACTIVE 价优先（版本文本 `db-vN`）→ 否则代码默认价（`vN`）。
2. `reserve` / `quoteCredits` 统一走 `creditsFor(PriceSpec, quantity) = max(ceil(q × priceMicros / 1e6), minCharge)`。
3. `snapshot(...)` 写生效价（含来源版本），SETTLE 用 `creditsFromSnapshot` 重算，**不重取现价**。
4. `priceService` 为 `@Autowired(required = false)`：单测/裁剪装配下自动回退代码默认价，不改变既有构造约定。

**溢出防护（两道上限）**：

- `BillingPriceCatalog.MAX_PRICE_MICROS = 1_000_000_000`（1000 积分/单位）：上限 × `MAX_QUANTITY`(1e9) ≤ 1e18 < `Long.MAX_VALUE`。
  发布侧拒绝越界，换算侧再兜底一次 —— 否则脏数据会让 `q × priceMicros` 溢出成负数，`max(credits, minCharge)` 静默按最低价收费。
- `BillingPriceCatalog.MAX_MIN_CHARGE = 1_000_000_000`（1e9 积分）：minCharge 直接成为单笔预扣 N，
  不封顶时 `当月已用 + N` 会溢出成负数绕过员工额度；同时 N > 2^53 会被 Jackson 序列化成字符串，
  结算端 `asLong` 按 Number 读取会抛 `ClassCastException`（预扣成功、无法结算）。
- `enforceMemberQuota` 改为等价变形 `n > quota - used`：不再对 `used + n` 求和，从根上排除溢出放行。

## 五、管理页（admin-ui）

| 文件 | 内容 |
|---|---|
| `src/api/zs/org-point-pricing.ts` | 类型 + 四个接口封装（注意 Long → string，前端统一 `Number()` 转换） |
| `src/views/zs/org-point-pricing/index.vue` | 「各科目现价」表（来源标记：后台配置 db-vN / 系统默认 vN）+「版本历史」表（发布人/停用人可追责）+ 发布弹窗 |
| `src/router/modules/zs.ts` | 路由 `org-point-pricing`（分组 pricing，菜单名「公司池价格」） |
| `src/utils/projectNavigation.ts` | 菜单可见性映射 `commerce:org-point-price:query` |

交互要点：

- 单价按 **积分/单位** 输入，支持 6 位小数（如数字人口播 0.05 积分/秒），提交时 `Math.round(x × 1e6)` → 微积分。
- 从行进入调价时锁定科目，防误改到其它科目；顶部「调价」按钮可自由选科目。
- 发布/停用后同时刷新现价表与历史表；停用需二次确认并提示"在途按快照结算"。
- 错误提示只由 axios 全局拦截器弹一次（含 `1_072_000_016` 并发冲突文案），页面不再二次弹窗以免文案互相矛盾；
  唯一例外是 "HTTP 200 空响应"（拦截器抛空 message 的 Error、全局无提示），页面 `notifyIfSilent` 兜底一次；
  停用失败时回读真实状态（该行可能已被他人停用），避免页面停留在过期的"生效中"。
- 无查询权限时整页只显示告警，不发请求。

## 七、上线与回滚

- 上线：`V20261113.315` 由 Flyway 自动执行（空表，无需回填）；`V20261113.608` 给超管授权，超管登录后即可在「定价管理 → 公司池价格」调价。
- 灰度：首次上线可**不配置任何价格**，全部按代码默认价计费；确认数值后再逐科目发布。
- 回滚：**必须"代码 + 迁移"一起回滚**。只执行 undo 315 会留下仍注入的 `OrgPointPriceService` Bean，
  它在每次 `reserve`/`quote` 时查询已删除的表 → 计费链路直接报错，并不会"自动回退默认价"。
  正确顺序：先回滚到不含 D8 的代码版本（`priceService` 注入随之消失、回退代码默认价），再执行 undo 315 DROP 表。
  历史扣费在 `org_point_ledger.price_snapshot`，与价格表无关，回滚不丢账。
