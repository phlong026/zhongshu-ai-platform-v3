> 批次：后端化工程 · 任务 1　日期：2026-10-31　状态：V5（吸收 Codex 评审 R1-R4：17×P1 与全部 P2）

## 一、背景与目标

小程序工作台待办区目前是前端派生投影（从本地 Storage 推导）。后端已有统一待办：业务域实现 `TodoProvider` SPI 自动汇总，`GET /platform/todos` 按当前岗位实时计算。

本批目标：**小程序接入真实待办（只读展示 + 页面级跳转）**，确立消费范式。事项级定位与办理闭环随 B1-B3 页面接入打通（§9-D1）。

## 二、现状事实（已核实源码）

- `GET /admin-api/platform/todos`（Bearer + `X-Post-Id` + `tenant-id`）→ `TodoList{items, actionableCount, failedDomains}`；
  `TodoItem{domain="franchise", key, title, status, amountCents(Long可空), actionable, webUrl=null, appPath, since}`。
- `appPath` 为页面级路径（customers / workflow/commission / growth / design / engineering 页），**不带事项定位参数**。
- franchise 域全部事项 key 前缀（源码枚举）与可见岗位：
  - 仅 **sales 系岗位**（`FranchiseRoles.has(post, SALES)`，boss/owner **不继承**）：`first-follow` 首次跟进、`visit` 到期回访、`submit-commission` 预算待委托、`lead-link` 客资待关联、`tail-follow` 尾款跟进
  - **boss/owner/finance 系**：`fee-approve` 委托费用待审批、`fee-pending` 审批中、`fee-returned` 费用已退回
  - **设计行政/总部**：`design-complete` 设计完成待下发、`design-dispatch` 设计下发
  - **工程/移交链**：`handover-prepare` 成果收图移交、`handover-returned` 移交退回、`handover-review` 移交核查、`handover-waiting` 等待核查
- 小程序：`api/todos.js` 已有 `list()`；工作台待办区为 demo 派生。

## 四、功能需求

| # | 需求 | 说明 |
|---|---|---|
| FR1 | 数据通道 | `api/todos.js` 仅请求职责（三个请求头由 http 层统一携带；HTTP 200 但 `code≠0` → reject 为业务错误）。**401 会话代次**：http 层记录会话代次（saveSession 时 +1）；收到 401 时先校验该请求发出时的代次与会话身份仍为当前，仅一致才清会话并触发 onUnauthorized，否则静默丢弃响应（防旧请求 401 清掉新会话，§八含 http.js 改动）。HTTP 403 → reject 为业务错误且**不清会话**。视图映射全部在 `utils/platform-todos.js` 纯函数（无 wx 依赖、无 Storage 访问）。触发条件与生命周期见 FR6 |
| FR2 | 待办区块 | 两首页顶部区块；计数口径=**清洗后有效条目**中的 actionable 数（与服务端 actionableCount 不一致时显示有效数并在 `anomaly` 警示标注） |
| FR3 | 卡片内容 | title + **事项标签**（按 key 前缀映射表，映射对象是事项类型而非业务 status 翻译）：`first-follow`首次跟进 / `visit`到期回访 / `submit-commission`预算待委托 / `lead-link`客资待关联 / `fee-approve`委托费用待审批 / `fee-pending`委托费用审批中 / `fee-returned`委托费用已退回 / `design-complete`设计完成待下发 / `design-dispatch`设计下发 / `tail-follow`尾款跟进 / `handover-prepare`成果收图移交 / `handover-returned`移交退回 / `handover-review`移交核查 / `handover-waiting`移交核查中；未知前缀：actionable=true→typeLabel"待办理"、false→typeLabel"进行中"。**卡片两个独立字段**：`typeLabel`（上表事项类型标签）与 `actionHint`（actionable=true→"可办理"、false→"等待他人办理"），分别渲染与断言。金额：`Number.isSafeInteger(amountCents) && amountCents >= 0`（上界 2^53−1）→ 两位小数（0→"¥0.00"，最大合法值 9007199254740991→"¥90071992547409.91"）；null/小数/负数/超范围/非法 → 隐藏 |
| FR4 | 跳转 | `navigateToApp(path)`：path 在 app.json `tabBar.list` 原生清单内 → `wx.switchTab`；在主包 pages 或分包内 → `wx.navigateTo`；path 空/未注册/fail 回调 → toast"暂不支持小程序内办理，请到工作台查看"。断言目标 route 与 toast |
| FR5 | 降级与重试 | 见状态机；`degraded`/`partial`/`partial-empty` 均有"重新加载"入口 |
| FR6 | 加载生命周期与隔离 | `postKey = tenantId:orgId:postId`（含租户）；另有会话代次 sessionGen（saveSession 时 +1，见 FR1）。①触发：页面 onShow 且 `currentApiPost()` 存在；②合并：自动 onShow 仅当 `postKey 相同 且 loading 中 且 sessionGen 未变` 才忽略；**手动重载**强制新请求 loadGen+1；**会话代次变化（如 token 刷新、同岗重新登录）→ 即使 postKey 相同也触发重载**（loadGen+1）；③**有效性三元组**：请求携带 loadGen+sessionGen+postKey，success/error/finally 均校验三值与当前一致才写状态，否则丢弃；④登出：清空状态、loadGen+1、sessionGen+1，在途响应（含 401）一律丢弃且不清新会话 |
| FR7 | 清洗与状态判定顺序 | **降级分级**：整响应级（items 非 Array、响应非对象）→ degraded；字段级容错（`failedDomains` 非 Array → 空数组+anomaly、其元素非 string 丢弃+anomaly；`actionableCount` 非负整数校验失败 → 0+anomaly）→ 继续；条目级（每条须非 null 对象且 key 为非空 string、title 为 string、actionable 为 boolean、appPath 为 string 或 null）→ 非法条目丢弃+anomaly。顺序：分级校验 → 条目安全检查 → 按 key 去重保留首条 → 用清洗后条目判 ready/partial-empty（清洗后全空且 failedDomains 空 → ready 空态）→ 计数按清洗后口径（与服务端不一致时 anomaly 标注）。403 → degraded 且会话保留 |

## 五、状态机契约（视图层唯一事实源）

| 状态 | 触发 | UI |
|---|---|---|
| `idle` | 未登录后端账号 | 不渲染区块，不发请求 |
| `loading` | 触发加载 | "待办加载中…"（清空旧数据） |
| `ready` | code=0、failedDomains 空、清洗后 items 可能为空 | 空 →"暂无待办"；非空 → 渲染+计数 |
| `partial` | code=0、failedDomains 非空、清洗后非空 | 渲染 + 黄条"部分待办暂时无法加载" + 计数注明 + 重试 |
| `partial-empty` | code=0、failedDomains 非空、清洗后空 | 黄条 + "已加载部分暂无待办"（**不得显示"暂无待办"**）+ 重试 |
| `degraded` | reject（网络/超时/`code≠0`/HTTP 403/响应形状非法；均保留会话） | "待办暂时无法加载"（业务错误附 msg）+ 重试 |
| `expired` | 401 | http 层清会话+onUnauthorized；视图回 idle |

## 六、与 demo 数据的隔离规则

1. 平台区块标题"平台待办"；demo 区块保持"今日待办"原名（仓库规范禁止面向用户的"演示数据"类标签，两区块以标题区分）。
2. 计数不合并、不进红点/角标。
3. `utils/platform-todos.js` 不读不写任何 `zhongshu-*` Storage 键。
4. 非干扰测试：固定平台响应、变化 demo 数据 → 平台视图模型输出不变；反向亦然；spy 平台处理链路断言零 Storage 调用；同 key 卡片各自存在，点击与计数独立。
