## 三、设计决策（D 表）

| # | 决策 | 理由 |
|---|---|---|
| D-1 | **formatTime 三输入归一**：finite number → 毫秒时间戳（主形态，F3 推导）；字符串 → 12 位以上纯数字串按毫秒（防御，后端 NumberSerializer 界外落串的口径）否则 Date.parse ISO；其余 ''。不做 [y,m,d] 数组支持（消息时间为 TIMESTAMPTZ 非 LocalDate，不涉日期数组形态）；秒级数字形态不在支持面（当前全部序列化链路均为毫秒，后端若引入秒级需同步调整——见 §六） | M5"时间三形态归一"规矩；双形态兼容使前端对后端序列化形态零依赖，免起服实测亦不炸 |
| D-2 | **profile GET 读侧**：refresh 末尾并列 `syncApiProfile()`，仅 `v==='profile'&&reset`（onLoad 首渲染）触发；成功路径**硬约束顺序**：mergeProfile → **先 A.mutate 落 storage** → 再精准 setData（profile/maskedPhone/form.name 一次性重设，onLoad 时机用户未输入无打断）。先落 storage 的原因：page-navigation 对栈内同 URL 页面走 navigateBack 复用旧实例（仅 onShow→refresh(false) 不触发 onLoad），旧实例靠 refresh 重读 storage 兜住回填——setData 前未落 storage 则复用路径丢失回填。失败/无 token 静默降级本地演示。**不触发 refresh**（防 syncApiProfile↔refresh 递归；saveProfile 成功后的 refresh(false) 亦不再触发本拉取） | 照 syncApiMessages 降级先例；08 §十"后端为真源"仅 nickname/mobile，avatar 本地路径不上传（基-1 前既定口径） |
| D-3 | **verify 挂链**：新增 npm script `check:account-api` = `verify-message-api.cjs && verify-profile-api.cjs`（照 check:wallet 先例），不挂主 check 链 | 游离 verify 补回归门（F6/F7）；主链保持静态验证器职责不变 |
| D-4 | **契约层不回改**：消息/profile 页面直调 http 保留，不新建 api/platform/messages.js | 15 文档 D-基4-2"既有实现不改"；KISS |
