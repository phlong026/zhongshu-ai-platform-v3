## 一、背景与目标

设计点充值/点数接口（`yudao-module-commerce` App*Controller，**`/app-api`/design/v1/**`**）锚定
**identity 账户体系**（`user_session` Bearer），v3 员工持**平台会话**，两套体系互不相通。
本批交付一个端点：员工以平台身份为**当前组织**换取「组织服务账号」的钱包会话，充值进组织点数账户
（与 D11/板块 A「B 端 AI 归属走服务账号」一致），不改 commerce 既有接口语义。

## 二、架构决策（评审重点）

1. **账号模型 = 组织服务账号。** 解析唯一路径 = `StoreServiceAccountPort.requireServiceAccount(orgId)`
   （`account.external_key="fr-service:{orgId}"`，ACTIVE 校验；停用换译 1_112_000_004，禁止惰性复活/换建）。
   充值入服务账号 `design_point_account`；员工 AI 消耗扣同一账户。
   **撤权路径不复用该准入接口**（`requireServiceAccount` 有建号副作用且拒绝停用账号）：
   撤权按 `external_key` 无副作用查询既存 accountId（不限状态；缺失幂等返回），实现于
   `WalletSessionRevocation` 回调内部（§二-8）。
2. **服务账号准入（技术型 grant）。** `validateAccessToken` 对 restricted **实时重算**
   （`restricted = NOT EXISTS(ACTIVE design_access_grant)`，签发值无效），commerce 全部钱包端点
   （含 point-account/point-ledger 读）走 `requireUnrestricted`。因此
   `AccountProvisionPort.ensureActiveAccount` 对 `fr-service:` 外键账号**同步幂等补挂 ACTIVE grant**
   （identity 是账号与授权唯一写方；以账号 ACTIVE 为前提）。**配套守卫（防逆转撤权）**：
   `AccessGrantService.revoke` 等通用授权撤销入口对 `fr-service:%` 账号的 grant **拒绝操作**
   （技术型 grant 无业务语义；管理侧要断钱包 = 停用账号，走 1_112_000_004 路径）。
3. **会话 openid = 实际支付者。** `VirtualPaymentAdapter.createPrepay` 交叉校验「会话 openid = 支付当刻
   code 换出的 openid」。桥接必收请求头 `X-WX-Login-Code`，经 `WechatPaySessionPort.exchangeForPay`
   换真实 openid，session_key 换取即弃。appid 与支付签名同源（`zhongshu.identity.wechat-appid`）。
   **异常换译边界（V5）**：`franchise-org` 不依赖 identity（无法引用其异常类型）。换译契约落在
   infra 端口：`IdentitySessionIssuePort.exchangeForPayClassified(appid, code)` 返回可分类结果
   `{openid, sessionKey} | CODE_INVALID | SERVICE_UNAVAILABLE`（identity 实现内部消化
   `WechatIdentityException` 族后再分类），桥接按分类映射 1_104_000_001/1_104_000_002。
   换译表进单测（真实适配器 + 假微信 HTTP 服务驱动，不得由 stub 直接回目标码）。
4. **refresh token 不下发**：响应只透 `accessToken`；失效即重走桥接（v3 已实现自愈）。
5. **权限复用 `platform:org:manage`**：703 已种子 boss/owner；零迁移，避开与基-2 抢 pf 704。
6. **端点归属 `franchise-org`**：新增 `controller.admin` 包 + `yudao-platform-authz` 依赖
   （franchise-finance 先例）；路径 `/platform/wallet/session`。
7. **铸造/吊销经新 infra 端口**：`cn.iocoder.yudao.module.infra.zhongshu.api.IdentitySessionIssuePort`：
   `issueUnrestricted(accountId, appid, openid, deviceDigest, ttlSeconds)`（ttlSeconds ≤7200，
   **桥接固定 1800**——30 分钟收敛暴露面与撤权旁路缺口）与 `revokeForAccounts(List<Long> accountIds)`。
   identity 实现包装 `UserSessionService`。
8. **撤权回调方向（V4，消除 Maven 环）**：`franchise-api` 已依赖 `platform-org`（PostSnapshot），
   **禁止**再加 platform-org→franchise-api。改为：platform-org 定义回调接口
   `WalletSessionRevocation`（`revokeForUserOrgs(userId, orgIds)`），由 franchise-org 实现
   （解析服务账号 + 调 identity 吊销端口）；platform-org 写路径经 Spring 注入回调执行，依赖方向不变。

## 三、接口契约

### POST /admin-api/platform/wallet/session

| 项 | 值 |
|---|---|
| 鉴权 | 平台 Bearer + `X-Post-Id` |
| 权限 | `@PreAuthorize("@post.has('platform:org:manage')")` |
| 请求头 | `X-WX-Login-Code`：必填，支付者一次性 wx.login code（换取即弃，禁入日志/URL） |
| 成功响应 | `{code:0, data:{token:string, expiresIn:1800}}`（无 refreshToken 字段） |

**错误语义（契约冻结；全库 `GlobalExceptionHandler` 实际行为 = 业务失败一律 HTTP 200 + body.code，
不存在 HTTP 层 401/403/429）：**

| 场景 | HTTP | body.code | 说明 |
|---|---|---|---|
| 平台会话无效 | 200 | 401 | 平台既有语义 |
| 岗位无 `platform:org:manage` / 无岗位上下文 | 200 | 403 | `@PreAuthorize` 先拦（PostPermissionEvaluator 对无岗位返回 false→AccessDenied）；`currentPost.require()` 不可达 |
| 缺 `X-WX-Login-Code` / code 无效、已用、过期 | 200 | 1_104_000_001 | `WechatIdentityException` code 族换译 |
| 微信侧不可用 / appid 未配置 | 200 | 1_104_000_002 | 同上 |
| 岗位头缺失/失效/非法（多岗位未带 X-Post-Id 等） | 200 | 1_103_000_001/002/003 | `RequestCurrentPost` 既有语义透传 |
| 服务账号停用 | 200 | 1_112_000_004 | `ServiceAccountInactiveException` 换译 |
| 限频 | 200 | 429 | `@RateLimiter`（用户维度 10 次/分） |

> V1 的 1_070_000_002/003 系挪用 `ACCESS_CODE_*`，废弃。**上线后业务失败不得返回 HTTP 404/501**
> （前端视其为「未部署」降级）。`zhongshu.commerce.recharge.enabled=false` 时照常发卡，建单 503
> 拦截由 commerce 既有开关负责。

## 四、安全与风控

1. **凭据面最小化**：无 refreshToken；session_key 不落库不入日志；openid 只入 `user_session.openid`
   与审计摘要（SHA-256 前 8 位）；日志不打 token/code/openid 明文。
2. **撤权即时生效（用户→组织→岗位三级锁协议）**：
   - **锁序统一：先用户行、再组织行、后岗位行**（防死锁）。
   - **发卡协议**：同一事务内 ①用户行 `FOR SHARE` 复核存在且未停用（补 `userExists` 之外的
     状态复核）②组织行 `FOR SHARE` 复核 ACTIVE ③当前岗位行 `FOR SHARE` 复核 ACTIVE/归属，
     再铸造——任一复核失败按 §三表拒绝。
   - **岗位新增协议**：先用户行、组织行 `FOR SHARE` 复核，再插岗位（堵「停用期间新增岗位」窗口）。
   - **撤权协议**：成员停用先**用户行** `FOR UPDATE` 改状态（覆盖其全部组织，堵跨组织窗口）；
     岗位撤销先岗位行 `FOR UPDATE`；组织停用先组织行 `FOR UPDATE`；状态修改与同步吊销整体
     同事务提交/回滚，随后经回调（§二-8）无副作用解析并吊销相关服务账号会话。
     成员停用三事务屏障（停用 vs 新增岗位 vs 发卡）见 AC9-iii；组织窗口见 AC9-ii。
   - **挂钩清单**：①`StaffOrgAdminController` 撤岗/停用成员链路；②组织停用（`OrgServiceImpl.setOrgActive`，
     无生产 HTTP 入口——该钩子以 **Service 集成测试**验收，e2e 不覆盖）；③**已知缺口（登记 §十-1）**：
     yudao 原生 `/system/user/update-status`（`AdminUserServiceImpl.updateUserStatus`）绕过上述链路，
     v1 以 30 分钟 TTL 兜底，预留事项挂状态联动事件。
   - **跨模块契约**：吊销经 infra 端口（identity 实现）；服务账号解析全部留在 `franchise-org`
     回调实现内（§二-1 无副作用查询），`platform-org` 只调用自身定义的回调接口，不新增任何依赖。
3. **暴露面声明与收敛**：非受限服务账号会话在 TTL 内可触达服务账号在 C 端 design/commerce 接口面的
   既有能力。收敛：①TTL 30 分钟；②无 refresh；③`platform:org:manage` 门控；④§四-2 即时吊销+行锁协议；
   ⑤审计。彻底方案（钱包专用凭证+白名单）登记预留（§十-6）。
4. **审计**：franchise CommandLog 模式（雪花 revision、独立键空间），与发卡同事务：操作者 userId/postId、
   orgId、服务账号 accountId、openid 摘要、sessionId。审计写失败 → 发卡整体回滚（AC8 故障注入验收）。
5. **组织隔离**：orgId 取自当前岗位，请求体不收 orgId。
6. **限频**：复用 `@RateLimiter` + `UserRateLimiterKeyResolver`（用户维度 10 次/分）。

## 五、前端配套改动（v3，随本批前端接入步交付）

1. **前缀修正**：`api/wallet.js` 独立基址：`wx.getStorageSync('zs-wallet-base')`，缺省 =
   `http.base().replace('/admin-api','/app-api')`；`server/wallet` 路径同步改 `/app-api`。
2. **串账修复（冻结请求上下文，贯穿业务响应与支付意图）**：钱包缓存条目 `{gen, postId, token}`
   （单租户实况，tenantId 纳入指纹随 §十-5 预留）。`walletRequest` 在**发起点**冻结指纹 (gen, postId)，
   于**四个时机**复核：①缓存写入前②token 交付调用方前③401 重铸后④**业务响应交付调用方前**。
   失配以专用结果 `WALLET_STALE` 静默取消——**成功与失败分派、以及一切副作用（清会话/跳登录/
   toast/重铸/更新页面/排定重试/重开「继续支付」/发起支付）发生前均先复核原指纹**，失配统一
   `WALLET_STALE`：所有消费者（充值页轮询/对账、明细页、资产卡）识别后立即终止，禁止清会话、
   跳登录、toast、重铸（含迟到的桥接 body.code=401，不得影响新 token/新岗位）。
   **支付指纹贯穿原生支付回调与后续链路**：`dispatchPay` 拉起支付后，success/fail 回调、
   `startPolling` 每次 tick、`reconcileAfterPayFail` 及结果更新均先复核支付时冻结的指纹，
   失配立即终止（旧订单号不得进入新岗位上下文）。
   **支付意图冻结**：`confirmPay`/`continuePay` 在点击时冻结指纹并贯穿 `wx.login → 建单/重领 →
   dispatchPay` 全程（登录回调迟到期间切岗 → 建单与支付调用为零，见 AC10-iv）。
3. **桥接调用与错误分派**：`ensureSession` 先 `wx.login` 取 code 经 `X-WX-Login-Code` 头上送；
   按 §三 body.code 分派：1_104_000_001/002/429 → toast 可重试；403/1_103_000_001/002/003/
   1_112_000_004 → 资产卡隐藏；
   **body.code=401 区分来源**：桥接返回 401（平台会话失效）→ 触发平台重新登录（调用既有
   unauthorized 通道/引导登录页）；钱包业务端点 401（钱包 token 失效）→ 仅重铸一次重放（现有自愈）。
   两者都不得误清对方会话（`skipSessionGuard` 已保证后者）。
4. `server/wallet` 桥接演示端点同步要求 code 头（缺头回 1_104_000_001）。

## 六、验收标准（可执行）

- **AC1 桥接发卡**：boss stub 登录 → 带 code 调桥接 → body.code=0、token 非空、expiresIn=1800、
  无 refreshToken；库内断言：`user_session` 新行 `account_id=StoreServiceAccountPort 解析值`、
  `appid=支付 appid 配置`、`openid=code 换出 openid`、`expires_at≈now()+30min`；
  token 调 `GET /app-api/design/v1/point-account` → body.code=0。
- **AC2 充值联动**：AC1 token 建单（stub provider+自动结算）→ `fulfillmentState=CREDITED` →
  服务账号可用点数 +（base+bonus）→ ledger 两笔（BASE/BONUS_CREDIT，balanceAfter 递进）。
- **AC3 openid 一致性（分层）**：适配器单测扩展——同用户两个不同 code 均签名成功；不同用户 code →
  既有 409 拒绝；code 重放 → 拒绝。e2e 只走到账链路（stub 不消费 code，注释声明）。
- **AC4 权限（按 body.code）**：sales/finance → body.code=403；无平台会话 → body.code=401；
  无岗位上下文 → body.code=403（@PreAuthorize 先拦）。
- **AC5 code 校验与换译**：缺头/无效 code → 1_104_000_001；假微信服务返回 5xx/超时 → 1_104_000_002；
  appid 未配置 → 1_104_000_002；换译表由真实适配器 + 假微信 HTTP 服务驱动（非 stub 直回目标码）。
- **AC6 grant 语义**：删服务账号 grant（DB 层操作）→ 桥接重补挂（幂等）；已发 token 在无 grant 期间
  调 point-account 与建单**均拒**（1_070_001_001，requireUnrestricted 实时重算）；恢复 grant 后均恢复。
- **AC7 技术型 grant 守卫**：通用授权撤销入口对 `fr-service:%` 账号 → 业务码拒绝（不逆转）；
  停用账号路径不受影响。
- **AC8 限频 + 审计**：并发第 11 次 → body.code=429、不同用户互不影响；发卡成功必有审计、
  审计写失败（故障注入）→ 会话行回滚；日志/审计无 token/code/session_key/openid 明文。
- **AC9 撤权与竞态**：①撤岗后已发 token 调 point-account → body.code=401；②并发两序：
  发卡事务 vs 撤岗事务——撤岗先提交 → 桥接复核失败拒绝；发卡先提交 → 撤岗提交后该 token 立即失效；
  **iii 三事务屏障（真 PG 行锁，Service 集成测试）**：「新增岗位 → 发卡 → 组织停用」与
  「新增岗位 → 发卡 → 成员停用」并发交错——停用提交后不存在任何仍可用的相关钱包 token
  （含跨组织：用户在 B 组织新发 token 随成员停用一并吊销）。
  **iv 撤权无副作用**：对从未开过钱包的组织执行撤岗/停用 → 幂等成功、不建号不补挂；
  服务账号已停用状态下撤权 → 同样幂等成功。
- **AC10 组织切换不串账（v3 verify）**：`check:wallet` 扩展——切岗/退出换人后重铸；迟到响应三例：
  ①A 岗桥接响应迟到 → token 不落缓存不交付；②A 岗余额响应迟到 → 组件不更新；③A 岗订单/支付参数
  响应迟到 → 充值页不继续支付、不重试（WALLET_STALE 静默取消，ii/iii 以真实 Page/Component 实例驱动，
  断言无过期 setData、无新增定时器、无继续支付重开）；
  **iv** A 岗点击支付后 wx.login 回调迟到期间切到 B 岗 → 建单、重领与两种支付调用均为零
  （confirmPay/continuePay 指纹冻结）；**v** 支付已拉起后切岗，再收到支付回调或轮询 tick →
  轮询/对账/结果更新全部终止；**vi** 迟到的桥接 body.code=401 → 不清新平台会话、不跳登录、
  新 token/新岗位不受影响。
- **AC11 回归与前缀**：板块 A/B/B1 e2e、组织冒烟、commerce 单测全绿；`check:wallet` 全绿；
  e2e 全程真实 `/app-api` 路径。
- **AC12 服务账号停用**：停用 → 桥接 1_112_000_004，不复活不换建。
- **AC13 组织停用钩子**：Service 集成测试（无生产 HTTP 入口，e2e 不覆盖）。
