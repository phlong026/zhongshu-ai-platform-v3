## 一、背景与目标

阶段 0 前三项（基-3/基-2/基-1）已交付，v3 侧经 P1/P2/P3 与钱包批已积累 **8 个已验证的小程序接入实现**。各页面接入时反复解决了同一批问题（多态分流、乱序响应隔离、串台防护、金额/日期严格转换、降级提示、封存过滤、表单幂等……），但解法散落在各 utils/页面中，靠口口相传。基-4 把它们**提炼为一份模式文档 + 一个可复用工具**，使后续阶段（2 工程/3 管理/4 我的）接入时「照模式做、用工具省力」，并降低评审负担（模式有据可查）。

**非目标**：不改写既有 8 个实现（它们已验证且在线上路径中——工具供新页面采用，旧实现不动=零回归）；不做 UI 组件库；不碰后端。

## 五、可复用工具契约（`utils/platform-loader.js`）

```js
/**
 * M3 的通用执行器：会话代次 + actorKey 双重守卫的拉取（纯函数，零 wx——verify 依赖此约束）。
 * 供新页面接入后端数据时采用；既有实现（platform-todos 等）不动（D-基4-2）。
 * state 形状：{ status:'idle'|'loading'|'ready'|'degraded', rows:[], loadGen, actorKey, sessionGen, message }
 * rows 经 ctx.transform(rows) 映射后写入（transform 由调用方注入，loader 不含业务语义）。
 */
module.exports = {
  initialState(),                                  // {status:'idle', rows:[], loadGen:0, actorKey:'', sessionGen:0, message:''}
  planLoad(state, actorKey, ctx),                  // ctx={sessionGen(数值), manual}；无 actorKey→reset；
                                                   // 同 actorKey+同代次+loading+非 manual→skip；否则 load（loadGen+1）
  applyResponse(state, res, ctx, now),             // 守卫未命中→原样 changed:false；形状非法→degrade changed:true；
                                                   // 三重一致→{state(含 transform(res)), changed:true}
  applyFailure(state, err, ctx, now)               // 三重一致 → degrade（保留会话，message=err.message）；否则 changed:false
};
```

**与 platform-todos 的同名异型对照**（采用时勿混）：

| 维度 | platform-todos（既有） | platform-loader（新工具） |
|---|---|---|
| planLoad 第二参 | post 对象（内部取 postKeyOf） | actorKey 字符串（调用方拼好） |
| ctx.sessionGen | **取值函数** `ctx.sessionGen()` | **数值**（调用方在发起时快照传入） |
| transform | 无（内置 rowOf 清洗+计数） | `ctx.transform(rows)` 注入 |
| 失败语义 | degrade + failedDomains/anomaly 待办特化 | degrade 最小骨架 |

- verify（`scripts/verify-platform-loader.cjs`）：初始态 / reset / skip 合并 / load 递增 / 三重守卫命中与丢弃（乱序响应隔离）/ 形状非法 degrade / 失败保留会话 / actorKey 变化 → 新 load（旧响应由守卫丢弃；**是否清态由调用方决定**，参照 account paymentActorKey 先例）——纯函数断言零 wx。
