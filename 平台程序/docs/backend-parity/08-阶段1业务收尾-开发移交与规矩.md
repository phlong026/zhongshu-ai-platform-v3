## 一、目标与性质

把 v3 小程序**业务模块**页面从本地 Storage 切到真实后端（`api/franchise/*`），端到端闭环。**纯 v3 库工作，monorepo 零改动**（接入中发现后端缺口 → 记录待决，等 stage0 合并后补，不在本阶段改后端）。

双体系原则（继承 03 文档）：**未登录后端（guest/no-post）时页面保持演示数据原样、零请求**；登录对应岗位后切真实数据。API 态任何路径不得读写 demo Storage（verify spy 断言）。

## 三、页面↔后端字段映射（关键适配点，接入前逐条核对）

### P1 客户（crm 已对齐 M2，改动小）
- 本地客户对象字段 → fr_customer：name/phone/wechat/source/province/city/summary 直接映射；**width/depth/floors 本地演示字段在后端不存在**——接到 requirement/scheme 数据（最新需求或 formal 方案），取不到则留空
- 写操作带 `revision`（customer.update/transfer）；保存方案走 `customers.saveScheme`（旧 HTTP 接口，手动方案不带 designProjectId——AI 结果回写走 P3 的 design.saveToCustomer）
- 列表分页：后端 `pageNo/pageSize/keyword`，v3 的 tabs（今日待跟进/预约到店/全部/已到店）在**前端内存过滤**（数据量小，不过度设计）

### P2 交易流（新建映射，注意语义差异）
- 需求登记 → sales.requirements.create（version 自增，只追加）；客户工作区「方案与资料」读 requirements.list + customers.get 的 schemes
- 报价：前端**不再本地算价**——items.main/decor 行只传 label/quantity/unitPriceCents，金额以响应回显为准（服务端计算覆盖伪造值）；total ≤10^12
- 合同：创建（WAIT_SIGN+两期计划）→ sign（需 revision）→ 收款在**财务工作台**办理（业务页只展示 stages 状态：PENDING/PAID）；作废带 revision
- 交付：四节点顺序推进（乱序 → 1_113_000_003，前端禁用未解锁按钮即可）
- 方案升级：方案卡「转正式」按钮 → schemes.promote（boss 正向可用）

### P3 设计赋能（最重，三条链）
- **灵感库**：cases.page 游标分页（nextCursor）+ 筛选 + favorite（收藏在服务账号名下=组织共享，替代本地 favorites 存储）
- **AI 平面**：projects.create（SELF_UPLOAD+FLAT，requirementInputs 带 faceWidthM/depthM/floorCount——**D20：FLAT 禁参考案例/草图，平面页隐藏「选为参考」入口，引导立面线路带参考**）→ flat-jobs → aiJob 轮询（QUEUED→SUCCEEDED，interval 3s 上限 90s）→ detail?jobId 拉候选 → selectFlat
- **AI 立面**：elevation-jobs（styleCode/roofType/material/color 稳定编码，**选项值即编码**：NEW_CHINESE/MODERN、GABLE_ROOF/FLAT_ROOF、WHITE_STUCCO/GREY_STONE/WHITE_COAT、DEEP_WOOD/WARM_GREY/BLACK）→ 轮询 → selectElevation
- **快速预算**：budget.ruleInfo 预取（三元组）→ estimate（buildingArea **整数** 1-10000）→ 区间 totalLow/High 展示 + disclaimer
- **回写客户**：saveToCustomer（PLAN 必带 resultVersionId；BUDGET 必带 estimateId+width/depth/floors，area 服务端取快照）
- 取图：候选/结果图 assetId → assets.downloadUrl 现取现用（不存时效 URL）；草图上传 assets.uploadTicket → PUT/POST → complete（非 ACCEPTED 不可引用）

## 四、前端接入规矩（finance-desk 已验证模式，逐页套用）

1. **五态判定**：guest（无 token）/no-post（未选岗）/role 态（岗位匹配）/non-role/401 过期——guest 与 non-role 保持 demo 原样零请求；401 清会话回 guest（http.js 已有会话代次机制，复用）
2. **乱序隔离**：页面级 loadGen + 全局 sessionGen + postKey 三元组；切岗/登出清数据；卸载后迟到响应丢弃
3. **幂等**：写命令 Idempotency-Key（api 层已内置生成）；失败重试同键同内容；改字段换新键；同键异内容（1099000000）提示刷新不得自动换键重提
4. **错误处理三分类**：业务错误（code≠0）→ 表单保留 + 中文文案；网络异常 → 「结果未知，请刷新确认」不自动重试；刷新失败 → 降级文案 + 重试按钮
5. **封存过滤**：业务页无封存入口问题，但 **月末对账/reconcile 等 00 禁入清单动作不得出现在任何 API 态入口**
6. **verify 脚本**：每子阶段一个 `scripts/verify-<name>.cjs`（纯函数+mock，参考 verify-finance-desk.cjs 风格）+ 涉及真实链路的补 native 断言；**页面在 API 态的 demo Storage 读写必须 spy 断言为零**
