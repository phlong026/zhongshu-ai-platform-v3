# 小程序功能后端化 · 整体实现框架

> 分支：`feat/backend-miniapp-parity`（自 `feat/m2-franchise-platform` 拉出）　日期：2026-10-31
> 目标：以 v3 小程序已实现的前端功能为需求蓝本，在平台程序（芋道单体）上补齐后端能力，最终实现前后端打通。

## 一、现状结论（勘察事实）

**已对齐（后端已有，小程序未接入）：**

| 能力 | 后端 | 小程序侧 |
|---|---|---|
| 员工微信登录 + 选岗 | `/admin-api/platform/auth/wechat-login`、`/platform/posts/mine`、`X-Post-Id` | `api/auth.js` 已定义，0 页面调用 |
| 统一待办 | `/platform/todos`（platform-workflow pf_approval） | `api/todos.js` 已定义 |
| 客资/客户/跟进/方案版本 | `domains/franchise-crm`（fr_lead/fr_customer*） | `api/franchise/crm.js` 已定义 |
| 设计委托全链 | `domains/franchise-commission`（提交→费用审批→完成→下发→移交→接收） | `api/franchise/commission.js` 已定义 |

**缺口（小程序前端完整、后端空白）：**

| 小程序功能域 | 页面 | 数据蓝本（本地 Storage） |
|---|---|---|
| 财务账簿与到账 | admin/finance-desk、collaboration（确认到账） | management-v1 receipts/payables/payments/refunds |
| 工程域 | build/*（项目/材料/施工记录）、engineering 工作台 | engineering-v1 全字段 |
| 绩效与提成 | admin/tasks、admin/commission、admin/performance | owner-goals-v1、performance-tasks-v1 |
| 经营视图 | admin/home、admin/finance、admin/operations | 管理快照/预警/趋势（前端聚合） |
| 待办/消息 | 各工作台待办区 | 前端派生投影（sales-todos 等） |
| 内容创作与获客 | studio、creation、ai-video、growth | studio/creation-draft/video-draft/growth-v1 |
| 总部服务订单 | account（店招/展厅/宣传册/名片） | account-v1 orders |

小程序侧 17 个功能域全部跑本地 Storage；`miniprogram/api/` 是预置脚手架，契约已冻结：响应包 `{code:0,data,msg}`、`Authorization: Bearer`、`X-Post-Id` 当前岗位、`Idempotency-Key` 写幂等、`revision` 乐观锁。**后端必须沿用这套契约。**

## 二、总体架构

不引入新架构，完全沿用既有模式：

```
v3 小程序（按页从 Storage 切到 API）
   │  /admin-api（员工端，Bearer + X-Post-Id + tenant-id）
   ▼
yudao-server 单体 FatJar :48080
   ├── platform-*（已有：auth/org/workflow/authz/command）—— 待办与岗位体系复用
   ├── domains/franchise-crm / commission（已有，M2）
   ├── domains/franchise-finance      ← 新增：账簿/收付/到账核对/项目账
   ├── domains/franchise-engineering  ← 新增：工程项目全生命周期
   ├── domains/franchise-performance  ← 新增：目标/绩效任务/回款提成/经营快照
   └── yudao-module-design/commerce/ai-orchestration（已有，C 端设计线与 AI 任务）
   ▼
PostgreSQL 16（唯一真相源）+ Redis（缓存/锁）
```

**关键决策：**

1. **新增域走 `domains/franchise-*` 独立 Maven 树模式**（同 M2），模块间零依赖、经 Port/领域事件协作；yudao-server pom 增量挂载。
2. **持久化沿用 JdbcTemplate 手写 SQL**（本仓库约定，不用 MyBatis/JPA/DO），公共列 `tenant_id/creator/create_time/updater/update_time/deleted`，JSONB 存 payload。
3. **Flyway 续号 fr 段（8xx）**：`db/migration/franchise/`，命名 `V<日期>.<段号>__<slug>.sql`，成对 undo 脚本。表前缀：`fr_fin_*` / `fr_eng_*` / `fr_perf_*`。
4. **待办复用 platform-workflow**：新业务动作（费用审批/到账复核/付款审批/退回处理等）注册 pf_approval，统一从 `/platform/todos` 出——小程序待办区不用换接口。
5. **命名避坑**：`fr_commission` 已被"设计委托"占用；小程序"项目回款提成"命名 `fr_perf_commission_*`，不混用。
6. **员工继续走 `/admin-api`**（M1 既定），`/app-api` 留给 C 端设计线，本框架不动 C 端。

## 三、数据表规划（概要，蓝本=小程序 Storage 实体）

### franchise-finance（fr_fin_）
- `fr_fin_receipt` 实收登记：项目/客户/金额(分)/状态（待核算→已核算→已备案→待登记→已登记）/收讫与登记时间/经办、复核人/方式/凭证/来源协议
- `fr_fin_payable` 应付：项目/阶段/总额/收款方/状态/协议；`fr_fin_payment` 付款：核实状态/凭证/交易号
- `fr_fin_refund` 退款：关联实收/原因/状态
- `fr_fin_receipt_revision` 收款修订史（原额/新额/备注/操作人）
- `fr_fin_bank_confirm` 到账核对：银行流水 ↔ 实收登记双边匹配（collaboration"确认到账"场景）

### franchise-engineering（fr_eng_）
- `fr_eng_project` 工程项目：关联客户与委托移交包/合同总额/工程经理/城市面积楼层/状态/归档结清
- `fr_eng_check` 开工六查；`fr_eng_document` 图纸文档版本
- `fr_eng_plan_version` + `fr_eng_plan_node` 施工计划版本与节点（待开工/施工中/已完成）
- `fr_eng_material` 材料进场；`fr_eng_supply` 领用（供应商/单价/支付方/状态）
- `fr_eng_site_record` 施工记录；`fr_eng_inspection` 检查；`fr_eng_rectification` 整改
- `fr_eng_collection` / `fr_eng_payment` 工程收付款（写通 fr_fin 账簿，经 Port）
- `fr_eng_delivery` 交付验收归档

### franchise-performance（fr_perf_）
- `fr_perf_goal` 月度目标：公司/部门/员工三级、周期 YYYY-MM、boss 下发（销售/回款/有效实收/客户/节点五维）
- `fr_perf_task` 绩效任务：manual + auto 指标类型（回款金额/签约/完成节点/准时节点/发布量/有效线索等 10 类）、责任人、进度
- `fr_perf_commission_policy` / `fr_perf_commission_row` / `fr_perf_commission_release` 回款提成：策略/行（含阶段拆分）/发放/对账
- `fr_perf_operating_snapshot` 经营快照：预警项、收支趋势、资金往来（聚合结果物化或实时查询）

### 组织补齐（platform-*，不建新表则复用）
- 员工停用/启用、岗位指派（pf_staff_post 已有基础，补管理动作接口）

## 四、API 规划（概要，全部挂 `/admin-api/franchise/*`）

| 前缀 | 覆盖 |
|---|---|
| `/franchise/finance/receipts|payables|payments|refunds` | 收付登记、审批、复核、修订、作废 |
| `/franchise/finance/bank-confirms` | 双边到账核对与确认（对应 collaboration 页） |
| `/franchise/finance/project-accounts` | 项目账（单项目收付汇总） |
| `/franchise/engineering/projects` | 列表/详情/接管/六查/计划/材料/领用/记录/检查/整改 |
| `/franchise/engineering/projects/:id/collections|payments|delivery` | 工程收付与验收归档 |
| `/franchise/performance/goals|tasks|commissions` | 目标下发与查看、任务、提成策略/发放/对账 |
| `/franchise/ops/overview|alerts|trends` | 经营快照/预警/趋势（老板端只读聚合） |
| `/platform/todos`（复用） | 全部待办 |

写操作统一：`Idempotency-Key` 幂等 + `revision` 乐观锁（409 冲突），角色校验在 Service 层（boss/owner/finance/engineer 各岗位动作矩阵与小程序 `approval-policy.js` 对齐）。

## 五、实施批次（每批独立可验证、可交付）

| 批次 | 内容 | 依赖 | 对应小程序页面 |
|---|---|---|---|
| **B0**（本次） | 框架文档 + 分支基建 | — | — |
| **B1 财务账簿与到账** | fr_fin 全表 + 收付登记-审批-复核 + 双边到账核对 + 项目账 | — | finance-desk、collaboration 确认到账 |
| **B2 工程域** | fr_eng 全表 + 工程接收→开工六查→计划→材料→施工记录→收付→验收归档结清 | B1（收付写账簿） | build/*、engineering |
| **B3 绩效与提成** | 目标下发、绩效任务（auto 指标由业务事件驱动）、回款提成 | B1（回款数据）、B2（节点数据） | admin/tasks、commission、performance |
| **B4 经营视图** | 快照/预警/趋势/资金往来（只读聚合） | B1-B3 | admin/home、finance、operations |
| **B5 待办与消息服务端化** | 业务动作注册 pf_approval；站内消息接口 | 随 B1-B3 增量 | 各工作台待办/消息区 |
| **B6 内容创作与获客** | 口播文案（复用 ai-orchestration）、创作中心、AI 视频、获客分析 | 独立 | studio、creation、ai-video、growth |
| **B7 总部服务订单与组织补齐** | 服务工单流（下单→确认→交付→验收/取消）、员工停用/指派 | 独立 | account 服务订单、admin/profile |

**验证方式**：每批交付一个 Python e2e 脚本（仿 `script/franchise-m2-e2e.py`：stub 登录→多岗位真实 HTTP 断言全链），编译 + e2e 全绿才算完成；Flyway 附 undo 脚本。

**小程序接入**：遵循双仓库纪律——本分支只做后端；每批完成后在 v3 库出对应页面的接入清单（从 Storage 切 `miniprogram/api/`），接入工作另立分支推进。

## 六、风险与约束

1. **字段对齐以小程序实体为准**：客户/工程/账簿字段清单已勘察归档（2026-10-31 勘察报告），建表前逐字段核对，避免接入时返工。
2. **金额一律分（integer）存储**，与小程序 model 层一致。
3. **多租户**：自定义表带 tenant_id；dev 联调需 `tenant-id: 1` 头（e2e 脚本已处理）。
4. **JVM 启动须带禁代理参数**（本机系统代理污染 127.0.0.1 解析，M2 已踩坑）。
5. 真实微信/支付/COS/AI 渠道不在本框架范围（G0 门禁控制，stub 先行）。
