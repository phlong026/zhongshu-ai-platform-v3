# 24d · D6 扣费路径矩阵（批 C 设计域接入前置件）

> 任务书 24 号 §九 D6：**批 C 启动前必须产出并评审**。本文逐科目列出"现扣费链 → 路由分流 → 切换条件"。
> 结论先行：**设计域存在 3 条真实扣费链 + 1 条免费链**，全部经"来源"分流，禁止双链并行扣同一笔。

## 二、路由分流方案（批 C 落地）

### 2.1 路由判定输入：显式 `billingOrigin`，不用 ThreadLocal

| 调用来源 | 取值 | 路由目标 |
|---|---|---|
| 设计桥（`DesignAccessController` → `DesignProjectService`/`BudgetService`/`NotePolishService`） | `BRIDGE` | **公司池 `OrgPointPort`**（org 取 `PostSnapshot.orgId`，actor=userId） |
| design App C 端链（`AppDesignProjectController` → 同底层服务） | `APP` | 旧个人池（**行为不变**） |

实现约束：
1. `billingOrigin` 必须是**显式参数**（沿 `DesignProjectService` → `AiJobPortAdapter.createJobWithCharge` → `AiJobSettlementService` 透传），禁止 ThreadLocal/上下文推断——防异步线程与嵌套调用串味。
2. 缺省值 `APP`（保证存量调用与 App 链行为不变）；桥侧所有入口显式传 `BRIDGE`。
3. 路由集中在一个 `ChargeRouter`（commerce 内），只做"选择哪条链"，不重复实现计费。

### 2.2 分科目路由规则

| 科目 | BRIDGE → | APP → | 备注 |
|---|---|---|---|
| `ai_flat` / `ai_elevation` | `OrgPointPort.reserve(subject, quantity=张数)`；终态 settle（按 ACCEPTED 槽位/实付） | 原 `createJobWithCharge` 不变 | 桥侧不再写 `ai_task_charge`（避免双账） |
| `budget_estimate` | `OrgPointPort.reserve(quantity=1)` + 同步 settle | 原 `chargePrepared` 不变 | 桥侧不再写 `service_usage_charge` |
| `AI_PROMPT`（桥发起的 job） | `OrgPointPort.reserve`（reserve=提交时，settle=结果确认时；UNCERTAIN 保持 PENDING） | 原 reserve/finish 链不变 | 与 ai_flat 同 job 拆两个 operation（按科目独立三态） |
| `note_polish` | **D8 待定**：若计费则 `reserve(quantity=1)+settle`；若免费则登记"不计费" | 同左（当前无扣费） | 本批建议：**先不计费**，只在矩阵登记，后续按运营拍板 |

### 2.3 终态映射（桥侧统一）

| 业务终态 | 公司池动作 |
|---|---|
| SUCCEEDED（N 个 ACCEPTED） | `settle(actualQuantity=N)` |
| PARTIALLY_SUCCEEDED（1..N-1） | `settle(actualQuantity=ACCEPTED 数)`（退差自动） |
| FAILED / CANCELLED（0 有效） | `release`（全退） |
| SUBMISSION_UNCERTAIN / 未知 | **保持 PENDING**（禁自动退款，人工核对） |

## 三、切换条件（红线）

1. **禁止双链并行**：同一笔 BRIDGE 任务只允许公司池记账；`ai_task_charge` / `service_usage_charge` 在桥侧必须**零写入**（验收断言）。
2. **存量在途**：切换前已用个人池预扣的桥任务，终态仍走原退差链（按 `ai_task_charge.charge_id` 存在与否判定），**不迁移、不重复结算**。
3. **App 链行为不变**：`billingOrigin=APP` 的所有路径保持现状（回归断言）。
4. **失败不外呼**：公司池 reserve 在调用方短事务提交后才允许外呼（与批 A content 同纪律）。
5. **结算失败可重试**：桥侧终态结算需可幂等重试（复用批 A 的 bizKey + 重试扫描模式；`ref_type='design_*'`, `ref_id=jobId`）。
