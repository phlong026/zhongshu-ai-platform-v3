# B1 财务账簿与到账 · 需求文档与验收标准

> 批次：后端化工程 · B1（franchise-finance 域）　日期：2026-10-31　状态：V2b（吸收 Codex R1：15P1+3P2；退款口径拍板=线下事实登记制；**退役/封存逻辑清理：付款单态化、实收状态机简化、verify/review/filing 不建**）
> 流程：需求文档 → Codex 评审循环至 PASS → 开发 → 提交；决策类不确定点记 §11。

## 一、背景与目标

小程序管理账簿承载加盟商全部资金流。本批在 monorepo 建 **franchise-finance 域**（`domains/franchise/franchise-finance`），提供账簿全链 HTTP 接口。**B1 是全平台收付底座**：B2 业务回款、B3 工程收付、B6 提成/经营全部消费本域。

## 二、退款专项结论（用户点名 + 2026-10-31 拍板：线下事实登记制）

**可达性核实结论**：小程序里退款线上流程是**封存残留**——`model.js apply()` 入口断言拦截全部 refund 前缀动作（"该事项在线下办理"）、`authority-v2.admin()` 对 deferred 视图拒绝进入、`refundRequests` 申请单零创建入口；批次 D（feat/boss-workspace-d-20261029，9e6b581+627a880）已摘除退款死按钮与封存待办生成代码（未合并至当前基线）。

**B1 退款口径（用户拍板）**：
1. **线下事实登记制**：财务单方登记退款（金额 ≤ 原实收可退余额 + 原因 + 凭证 + 流水号），**登记即"已核实"**——语义="只登记线下已发生退款，不发起转账"（页面原文）。
2. **不建申请-审批双单链**（refundRequests/refund-approve 等封存流程不移植）。
3. 登记错误走**作废重登**：仅财务负责人/老板可作废（留痕原记录），作废释放可退余额。
4. **下游联动保留**（数据消费端在役）：净收款=原实收−已核实退款；回款提成基数扣减（B6 消费）；经营报表支出项；绩效指标扣减。

## 三、数据表设计（fr_fin_*，Flyway `db/migration/franchise/` 续 8xx；权限种子新增 franchise-system 段 V*.852）

**公共约束（全部表）**：金额列 `BIGINT CHECK (amount_cents > 0 AND amount_cents <= 1000000000000)`；状态列 `VARCHAR CHECK (status IN (...))`；公共列 `tenant_id BIGINT NOT NULL DEFAULT 1, creator, create_time, updater, update_time, deleted`（软删不释放交易号防重——唯一索引含 `WHERE deleted=FALSE`）；员工引用一律 `system_users.id`。

| 表 | 关键字段与约束 |
|---|---|
| `fr_fin_receipt` 实收 | company_id, project_id(可空), customer_id(可空), source_type CHECK(business/engineering/intercompany/design/manual), source_ref(如 `commissionId:version:stage`), name, amount_cents, status CHECK(待登记/已登记/已撤销——**生效终态=已登记**；已核算/已备案仅为历史数据兼容展示字段，后端不提供推进接口，reconcile 独立核算为封存逻辑), received_date, registered_at, registrar_user_id, method CHECK( bank/cash/other ), transaction_no(可空——现金无流水；**非空时归一化去空格后** `UNIQUE(company_id, transaction_no)`), voucher_file_id→fr_fin_file, revision_version INT NOT NULL DEFAULT 1, void_reason |
| `fr_fin_receipt_revision` 修订留痕 | receipt_id, base_revision_version（发起时的 receipt.revision_version）, original_amount_cents, new_amount_cents, note, operator_user_id, **UNIQUE 约束：一 receipt 至多一条活跃修订**（partial index `WHERE status='APPLIED'` 反向——即修订即生效无待审态），created_at |
| `fr_fin_payable` 应付 | company_id, project_id, stage, total_cents, recipient, status, agreement_ref |
| `fr_fin_payment` 付款 | **payable_id NOT NULL**（B1 强制关联），company_id, amount_cents, status(已核实/已作废——**登记即已核实**，verify/payment-review 独立复核为封存逻辑不建), pay_date, operator_user_id, transaction_no（同归一化唯一）, voucher_file_id |
| `fr_fin_refund` 退款 | receipt_id NOT NULL, company_id, amount_cents, status CHECK(已核实/已作废), reason NOT NULL, operator_user_id, void_by_user_id, void_reason, date, transaction_no（归一化唯一，与 fr_fin_payment 同池：`UNIQUE(company_id, transaction_no)` 跨两表用服务端查重+同池唯一表 fr_fin_txn_no(txn_no, company_id) 实现）, voucher_file_id |
| `fr_fin_bank_flow` 银行流水（模拟） | company_id, bank_ref, amount_cents, bank_date, status(待匹配/已认领), source(dev/e2e 注入) |
| `fr_fin_bank_confirm` 到账确认 | bank_flow_id NOT NULL UNIQUE, receipt_id NOT NULL UNIQUE（一对一），amount_cents, matched_by_user_id, matched_at |
| `fr_fin_file` 凭证 | company_id, file_name, storage_key, content_type, size_bytes, sha256, uploaded_by_user_id（域内自建，员工端上传/下载接口走 @post.has；不依赖 design asset 的 C 端身份体系；prod 接 COS 前本地存储） |

**索引**：每表 `(company_id, status, create_time DESC)`；receipt `(source_type, source_ref)`；refund `(receipt_id)`；payment `(payable_id, status)`；bank_flow `(company_id, status)`。项目账用单条聚合 SQL（GROUP BY），禁逐笔 N+1。

## 四、状态机与资金不变量

**实收状态机**（完整迁移表；**生效口径：`已登记` 及之后全部状态均计入有效实收**，核算/备案是财务内部标记，不构成业务生效门槛）：

```
待登记（intercompany 移交事件自动生成，计入"预期应收"，不计入有效实收统计）
  → [财务登记 incoming-register] 已登记（收款即生效）
已登记 → [核算 review] 待核算 → [核算确认] 已核算 → [备案] 已备案（顺序推进，不可跳级）
已登记/待核算/已核算/已备案 → [修订-财务直接改，全留痕] 金额更新 + revision_version+1（已备案的修订回到 已核算：原备案结论作废留痕）
待登记 → [撤销（仅跨端来源，财务负责人）] 已撤销
```

**资金不变量（不变量 I-1，数据库事务内保证）**：
- 对 `fr_fin_receipt` 的余额操作（退款登记/修订生效）统一在**同一数据库事务内**执行 `SELECT amount_cents, revision_version FROM fr_fin_receipt WHERE id=? FOR UPDATE`，校验 `Σ已核实退款 + 本次金额 ≤ amount_cents` 后写入；违反即业务异常回滚。
- 退款登记即"已核实"（无在途态），不存在占用/释放双阶段。
- 修订生效与退款登记竞争同一行锁串行化；修订生效后 base_revision_version 不符的并发写入失败重试。

**付款不变量（I-2）**：`Σ(fr_fin_payment.status = '已核实').amount ≤ fr_fin_payable.total_cents`（登记即已核实，无在途占用），登记与作废在同一 payable 行锁事务内校验；作废释放额度并留痕。

**到账核对规则**：
- 流水生产：模拟接口 `POST /franchise/finance/bank-flows`（dev/e2e 用；prod 由对账导入替代，不在 B1）。
- 预期应收来源：intercompany 移交事件（既有）自动建 `fr_fin_receipt(status=待登记, source_type=intercompany)`——已存在机制，B1 落到 fr_fin_receipt。
- 确认 = 财务对 bank_flow 选定待登记 receipt（金额=流水金额才可确认）→ **更新该 receipt 为已登记** + 建 bank_confirm（**唯一入账**：bank_flow_id UNIQUE 与 receipt_id UNIQUE 双约束防重复认领/重复匹配）。
- 金额不符：bank_flow 标记"金额不符"留痕，可重试换 receipt；待登记 receipt 被撤销后，其迟到确认 → 异常拒绝。

**动作矩阵**（权限码 `franchise:fin:{query|register|review|refund|void}`，种子 V*.852；矩阵：finance/finance-lead=query+register+review+refund；finance-lead 额外=void；boss/owner=query+void；engineer/project-manager/sales/hq-design-admin=无）：
- 所有写操作：Service 内**三重归属校验**——当前岗位 org/company、目标对象 company_id、关联链（refund→receipt→company；payment→payable→company）一致；JdbcTemplate 所有查询显式 `WHERE company_id=?`。
- `tenant_id`：fr_fin_* 与既有 fr_* 同约定（单租户种子=1，域代码不手工过滤，依赖底座租户插件 + 显式 company_id 隔离）。

## 五、API 规划（`/admin-api/franchise/finance/*`）

**通用约定**：全部写操作要求 `Idempotency-Key` 头，作用域=`fr-fin:{动作}:{对象id或新登记uuid}`，命令记录与资金变更**同事务**；幂等重放返回首次结果；权限重验在重放时仍执行。错误码段 `fr-fin` 专属（1_102_0xx）：余额不足、流水重复、状态冲突、对象不存在、越权、凭证不可用、幂等内容冲突（同 key 不同指纹）。

| 接口 | 说明 |
|---|---|
| GET `/receipts?companyId&projectId&status&pageNo&pageSize(≤100)` | 分页，稳定排序 create_time DESC,id DESC |
| POST `/receipts` | 登记实收（source_type=manual；交易号归一化查重） |
| POST `/receipts/{id}/revision` | 财务直接修订（body 携带 baseRevisionVersion 乐观锁；留痕） |
| POST `/receipts/{id}/void-pending` | 撤销跨端预期应收 |
| GET `/revisions?receiptId=` | 修订历史（审批依据查询） |
| GET `/payables`、POST `/payables` | 应付 |
| POST `/payments`、`/payments/{id}/void` | 付款登记（**即已核实**，I-2 校验）/作废释放额度留痕 |
| POST `/refunds` | **线下事实登记**（余额校验 I-1；登记即已核实） |
| POST `/refunds/{id}/void` | 作废重登（finance-lead/boss；释放余额留痕） |
| GET `/refunds?receiptId=` | 退款历史 |
| POST `/bank-flows`（dev/e2e 注入，@post.has franchise:fin:manage 之外的 dev 守卫）、GET `/bank-flows?status=` | 流水生产/列表 |
| POST `/bank-confirms` | 确认到账（bank_flow_id+receipt_id，唯一入账） |
| GET `/project-accounts/{projectId}` | 项目账聚合（应收/实收/已付/退款净额/各状态分布） |
| POST `/files`（multipart）、GET `/files/{id}` | 凭证上传/下载（@post.has franchise:fin:query） |
| GET `/platform/todos`（复用） | fr-fin 域 TodoProvider：key=`fr-fin:bank-confirm:{flowId}`（到账待确认，finance 岗）、`fr-fin:review:{receiptId}`（待核算，finance 岗）；**实时查询投影，状态变化即消失**，字段含 key/domain/actionable/appPath/amountCents |

## 六、验收标准（可执行）

**node 无（后端批次）；单测（Mockito，业务分支）：**

| # | 断言 |
|---|---|
| AC1 | 登记：交易号（归一化后）重复 → 异常；幂等键重放 → 同一条；同 key 不同指纹 → 幂等冲突 |
| AC2 | 核算/备案：跳级异常；顺序通过；已备案后再修订 → 回到已核算且原备案留痕 |
| AC3 | 修订：baseRevisionVersion 不符 → 乐观锁冲突；生效后 revision_version+1 且历史可查；金额更新即时生效 |
| AC4 | 退款：金额超 `amount−Σ已核实退款` → 异常；登记即已核实；作废（无权限角色）→ 异常，作废后余额释放、留痕保留 |
| AC5 | 付款：累计超 payable.total → 异常；作废释放；payable_id 缺失 → 校验异常 |
| AC6 | 到账确认：重复认领同一 bank_flow → 唯一约束异常；确认后 receipt 状态=已登记且计入有效实收；金额不符流水可重试换 receipt；被撤销 receipt 的迟到确认 → 异常 |
| AC7 | 归属校验：跨 company 的 refund/payment/bank_confirm 操作 → 拒绝（关联链校验）；查询隐式限定 company_id |
| AC8 | 权限：engineer 调任何 fin 接口 403；void 仅 finance-lead/boss；**不存在 verify/review/filing 接口（封存逻辑未移植的回归断言）** |

**Python e2e（script/franchise-fin-b1-e2e.py，真实 PG + 多岗位 HTTP）：**

| # | 步骤 |
|---|---|
| AC9 | 全链正向：dev-setup → 标准费用 → 非标准委托（FEE_PENDING）→ 老板批准 → 财务登记首款（幂等重放验证）→ 财务修订（baseRevisionVersion 校验+留痕）→ 项目账聚合数字精确断言 |
| AC10 | 退款并发（真 PG）：两路并发各登记 `余额/2+1` → 恰一路成功一路余额异常；串行两笔各退一半成功；作废后可再退 |
| AC11 | 修订与退款竞争：修订生效（改小金额）与并发退款竞争 → 总额不变量恒成立（Σ退款≤最终金额），败者业务异常 |
| AC12 | 付款并发：两路并发付款合计超 total → 一路成功一路异常；作废释放后可再付 |
| AC13 | 到账：dev 注入流水 → 同流水并发认领 → 恰一成功；确认后待办事项消失（/platform/todos 断言） |
| AC14 | 事务回滚：构造幂等记录成功但资金写入失败的注入场景 → 命令记录与资金同回滚（无孤儿命令） |
| AC15 | 待办契约：boss/finance 的 `/platform/todos` 返回 `fr-fin:*` 事项，字段（key/domain/actionable/appPath/amountCents）齐全；事项办理完成后按 key 精确断言消失 |
| AC16 | 越权抽查：工程岗 403；跨公司 403/业务异常 |

**回归**：monorepo 既有测试 + 三支冒烟（org-admin/sms/todos）全过；编译 clean package 成功。
