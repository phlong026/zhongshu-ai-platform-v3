# 23 · 公司账号与子账号积分体系 — 设计方案（激活码退役 + 公司池共账）

> 状态：**设计稿，待评审拍板，未授权实施**。
> 决策输入：①C 端设计小程序论证方式已改——取消激活码；②赋能体系不设任何激活码，公司整体开通后充积分即可用完整功能、按量扣积分；③账号模式对标复刻项目《乡墅爆款短视频复刻》的公司账号/子账号办法（本仓 16a 附 A 勘察底稿）；④积分消耗审计为硬要求；⑤**全平台用户均为加盟商员工（无 C 端业主用户）**——用户归属公司天然成立（登录即带 org 上下文），归属层零新增机制。
> 关联：16 号任务书 §十①（RESERVE→SETTLE/RELEASE 完整钱包结算，待决项）——**本方案与其合并为同一实施批次**；16 号 D-1.5-8 四原则全文沿用。

## 一、复刻项目模式精读（对标源：`订单项目/乡墅爆款短视频复刻` server/app）

五个核心机制，全部值得照搬：

| # | 机制 | 实现 | 关键设计 |
|---|---|---|---|
| 1 | **母钱包记账 + 消耗人分离** | `wallet_transactions.user_id=母`，`actor_user_id=子` | 资金主体与操作主体分列——这就是"共用公司积分 + 审计"的原子结构 |
| 2 | **三态计费流** | RESERVE（预扣）→ SETTLE（实扣）→ RELEASE（退回），`billing_operation_id` 贯穿一个任务周期 | 四原则：快照冻价 / 实收 min(reserved, 实际) / 超支平台自担 / 悬空预留对账 |
| 3 | **子账号月度额度** | `sub_account_quotas`（无行=不限）；当月用量**实时聚合不落库**；口径=`-SUM(available_delta)`（在途占用，防并发刷额度）；跨月退回归**操作发起月**（按 billing_operations.created_at 锚定） | 超限 403 拒单，无持久冻结状态——判定始终由「当月已用+本次预扣>额度」实时得出 |
| 4 | **子账号功能权限矩阵** | `sub_account_permissions`：12 类业务权限+2 系统权限；**无行=全允许**（fail-open 向后兼容，存量零回填）；「全开」唯一表达=删行 | 强制点在三处**写事务内、资源变更前**；独立于 credits（免费操作也受准入） |
| 5 | **账本双视图** | 逐笔流水（事实来源/对账/CSV 导出）+ 服务端**分页前合并**的"任务视图"（一条任务=RESERVE/SETTLE/RELEASE 完整生命周期） | 解决"暂扣在第 2 页、退回在第 1 页"的用户误读问题 |

另有 SUB_ADMIN（子账号管理员，`users.account_type` 状态）、月度口径=上海自然月、防呆上限（单次设置 ≤10 亿）等工程细节。

## 二、目标模型（复刻项目 → 众墅平台映射）

| 复刻项目 | 众墅平台 | 说明 |
|---|---|---|
| 母账号（个人客户） | **加盟商公司 org** | 公司账号=org 级钱包主体；开通设计/内容能力即建立公司池 |
| 子账号 | **员工**（pf staff_post）——唯一用户类型 | 全平台无 C 端用户；员工登录即带 org，归属零成本 |
| 母钱包 | **org 积分池** | 新 org 维度账户，`design_point_account(user_id)` 个人账户停用 |
| `actor_user_id` | 扣点流水的**消耗人**（员工 postId/userId） | 审计硬要求的落点 |
| SUB_ADMIN | **老板/owner 岗**（天然公司管理员） | 设额度/权限/看全员用量 |
| 12 类业务权限矩阵 | 内容科目（已有 ContentBillingCatalog）+ **新增设计域科目** | ai_flat/ai_elevation/budget_estimate/note_polish/快速预算等 |
| `sub_account_quotas` | 员工月度额度表 | 老板可设"该员工每月最多消耗 X 积分" |
| activation_code/设备单/ZPay | **不搬**——激活码退役（本方案核心），支付走平台既有通道 | 拆分方案已明确平台自有账号/权限/支付体系 |

## 三、详细设计

### 3.1 开通层（替代激活码的"开关"）
- 公司级开通状态机：`未开通 → 已开通 ⇄ 停用（欠费/违规）`，挂在 org 维度
- 复用 `POST /platform/org/onboard` 幂等语义扩展 design-enabled 维度
- **积分耗尽 ≠ 锁功能**：不删数据不锁界面，调用报明确错误码引导充值（对齐现有钱包 503 降级体验）

### 3.2 账本层（公司池 + 三态流）
- 新增 org 积分池账户（或 `design_point_account` 加 org 主体类型列——见 §五改造点）
- 所有消耗走 **RESERVE → SETTLE/RELEASE** 三态，`operation_id` 贯穿；四原则照搬（快照冻价/实收 min/超支自担/悬空对账）
- 流水**双主体列**：`org_id`（资金主体）+ `actor_user_id`（消耗人）+ 科目 + 关联资产/任务 id
- 账本双视图：逐笔（对账事实）+ 按操作合并的任务视图（老板/员工可读）

### 3.3 额度层（员工月度额度，推荐保留）
- 公司老板可为任一员工设"每月最多消耗 X 积分"（无行=不限，fail-open 存量兼容）
- 用量实时聚合（在途占用、跨月退回归原月），超限 403 拒单——**内容/AI 是高消耗业务（数字人 2.5 元/分钟级），没有这层，一个员工一夜可烧空公司池**
- 与既有 `fr_content_ai_usage` 组织日配额并存：日配额=组织级熔断（防滥用/控外部成本），月度额度=个人级管控（防内耗），两者职责不同不合并

### 3.4 权限层
- `design:use` 岗位门禁保留（公司开通=能不能用；岗位门禁=谁能用；额度/权限矩阵=用多少、用哪些）——三层各司其职
- 员工业务权限矩阵（可选启用）：按科目限制员工可用业务（视频生成/口播/拆解/改写/设计出图……），老板勾选网格管理；无行=全允许

### 3.5 审计层（硬要求）
- 逐笔流水：org_id/actor_user_id/科目/操作 id/快照单价/RESERVE-SETTLE-RELEASE 三行 —— 永久保留
- 老板视图：公司池余额 + 全员用量排行（按人/按科目/按月）+ 每笔可追溯到任务
- 员工视图：个人用量明细（自己扣过什么）
- 总部视图：调点记录 + 跨公司对账

### 3.6 归属层（因"无 C 端业主"而整体消失）
- 全平台用户=加盟商员工，登录链（员工微信/短信，platform-identity）即携带 org 上下文——**归属天然成立，无需任何锚点机制**
- 激活码退役后**不需要替代方案**：码的两个职责中，"开关"由公司开通承担（§3.1），"归属证明"由员工登录身份天然承担
- 员工用设计能力的授权判定 = 公司开通状态（org 级）× 岗位门禁（design:use）×（可选）业务权限矩阵，三层串联，无新增表

## 四、与既有决策的衔接

- **16 号 §十① 待决项**（完整钱包结算）→ 与本方案合并为同一实施批次：做公司池结算时就按母钱包+actor 结构落，避免先做个人结算再返工
- **16 号 D-1.5-8 四原则**：快照冻价/实收 min(reserved,实际)/超支平台自担/悬空预留对账——全文沿用
- **fr_content_ai_usage 组织日配额**：保留（组织级熔断），与本方案个人月度额度互补
- **充值开关**：`ZS_RECHARGE_ENABLED=false` 首发不变；公司池模式下充值入口=老板岗/总部调点
- **激活码退役**：`identity` access_code 三表停止写入、只读归档（绑定审计合规价值保留）；`/zs` 激活码管理模块 UI 退役换"公司开通"管理页；存量已兑换用户（员工）按码批次公司归属一次性映射，公司开通即顺延授权；存量个人点数按公司聚合迁入公司池（迁移脚本+双流水留痕）

## 六、待拍板决策点

| # | 决策 | 建议 | 理由 |
|---|---|---|---|
| D1 | 员工月度额度是否首批做 | **做**（复刻项目同款机制） | 高消耗业务无个人管控=公司池裸奔；机制小（一张表+实时聚合） |
| D2 | 设计小程序（第二 appid）长期定位 | **短期共存**（员工的设计工具入口），长期视产品演进决定是否收编进赋能平台小程序 | 用户已澄清全部是员工——两 appid 服务同一人群，共存理由只剩微信审核隔离；登记为产品层决策，不阻塞本方案 |
| D3 | 设计域与内容域是否同池 | **同池**（一个公司池，科目分账） | 加盟商视角"一份钱办两件事"；科目流水已可分域审计 |
| D4 | 员工个人充值入口 | **下线**，充值收口老板岗/总部调点 | 避免"公司池+个人池"两套账并存对不上 |

## 七、批次建议

1. **批 A（本批核心）**：org 积分池 + 三态结算（含 §十①）+ 双主体流水 + 合并视图 —— 账本地基
2. **批 B**：公司开通 + 老板视图（余额/用量/充值入口）+ 员工个人用量页
3. **批 C**：员工月度额度 + 业务权限矩阵（可选启用）
4. **批 D**：激活码退役/归档 + 存量迁移（已兑换码员工授权映射 + 个人点数入池）
5. 依赖关系：批 A 是地基；批 D 的激活码退役必须最后做（等公司池链路稳定运行后）

## 八、红线（承 16 号 §十一）

- 迁移成对 undo；错误码走 1_104（钱包）/1_114（内容）既有段扩展

- 流水永不物理删除（审计）；密钥不进代码/日志
- `fake` 生产硬禁不变；`ZS_RECHARGE_ENABLED=false` 首发不变
