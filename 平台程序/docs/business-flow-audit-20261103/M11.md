## 4. 权限与已有保护

- 消息接口按登录者 userId 取数据，不接受客户端指定收件人；本人标记已读具幂等语义。
- 消息类型与 route 白名单已存在，不需要另造第二套业务消息模型。
- MessageSender 幂等键按发送域与 dedupeKey；“本期生产域=空”是登记范围说明，不是运行时禁止发送的白名单，代码只校验发送域格式。
- TodoServiceImpl 对单域异常打 error 日志并回 failedDomains，不将部分失败伪装成完全成功。
- 待办前端已有 loadGen/sessionGen/postKey 三重有效性校验，是消息修复可复用的现有模式。
- 文件服务账号归组织；C_END/B_END 双入口隔离，MIME、大小与哈希都有服务端检查。
- B_END 通道对财务、工程、合同、内容按角色分派，不能把已存在的保护写成“完全无权限”。
- profile 服务以当前登录者为目标，手机号自助更新被明确排除。
- 正常员工停用清 token 与任职撤销即时校验已存在，详见 M01/M02。

## 8. 同项目跨岗位验收与负向清单

- 使用一个门店、一个项目、业务员/主管/工程/财务/老板真实任职，另建另一组织作拒绝对照。
- 业务提交→待办归当前承办岗位；切工程后业务任务不应被误认为本人可办。
- 工程/财务上传各自类型附件→本组织授权岗位可下载；其他组织同assetId拒绝。
- 权限按请求当前任职判断：当前sales读FIN_VOUCHER拒绝，当前finance读ENG_DRAWING/ENG_SITE_PHOTO拒绝；boss/owner在此矩阵允许，仍须组织与资产校验。
