# 加盟商员工 Web 管理后台界面设计（各部门岗位 × 后端关联映射）

> 版本：V1.0 · 2026-11-07
> 定位：在现有 admin-ui（C 端运营管理台，15 页）基础上，扩展「加盟协同门户」——让加盟商各部门员工在 Web 端完成小程序已有的全部管理业务，界面与后端 franchise 域 27 个 Controller / 173 端点一一关联。
> 设计基准：后端 13 岗位权限矩阵（V851-858 迁移）+ 小程序已验证角色路由（organization.js）+ OrgScope 数据范围。Web 与小程序**同构不同形**：同构=同一套权限码/待办/数据范围；不同形=Web 发挥宽屏优势重表格、重批量、重报表。

---

## 一、总体架构：双门户一体化

```
admin-ui（同一工程，两套门户）
├─ 总部运营门户（已有，/zs 路由组，6 组 15 页）
│    面向：总部运营/客服/财务后台 —— 案例/激活码/充值点数/预算报价/定价/合规
└─ 加盟协同门户（本次新增，/fr 路由组，建议 6 组约 24 页）
     面向：加盟商各部门员工（登录即按岗位渲染菜单与数据）
```

**登录即分家**：登录页新增「员工登录」模式（手机号+验证码 → platform 层 `/admin-api/platform/auth/*`，已有端点无需后端开发）。登录成功后：

1. 拉取本人任职（`GET /admin-api/platform/my/post`，MyPostController）；
2. 多岗员工顶栏出现**岗位切换器**（切换即重设 `X-Post-Id` 请求头，全站数据随岗位切换）；
3. 菜单按**当前岗位的权限码**渲染（复用 buildProjectMenus 机制，新增 fr 分组与 `franchisePermissions` 映射表）；
4. 所有列表/详情由 OrgScope 自动限定**本人当前组织**——加盟商 A 的员工永远看不到加盟商 B 的任何数据，无需前端处理。

```
顶栏（全门户通用）：[logo] [门户切换] [岗位切换器▼] [统一待办🔴n] [消息🔔n] [员工姓名]
侧栏（按岗位渲染）：六组 fr 菜单（见各节）+ 个人中心
```

## 二、五部门 × 九岗位界面总览

后端有效岗位 9 个（hq-designer / hq-design-lead / hq-operations / hq-operations-lead 四岗零权限码，暂不设计界面，权限授予后随组启用）：

| 部门 | 岗位 | Web 落地首页 | 菜单组 |
|---|---|---|---|
| 门店管理 | **boss** 老板 | 经营驾驶舱 | 驾驶舱/组织与人员/目标与提成/业务监督/审批中心 |
| 门店管理 | **owner** 门店负责人 | 工作台（同驾驶舱窄版） | 同 boss，但按钮按权限码收敛（sales 域只读） |
| 销售部 | **sales** 业务员 | 我的客户 | 客户/交易/内容获客 |
| 销售部 | **sales-lead** 业务负责人 | 客户总览 | 客户(含移交/客资处理)/交易/内容获客(含人设) |
| 工程部 | **engineer** 工程人员 | 我的项目 | 工程 |
| 工程部 | **project-manager** 工程负责人 | 项目总览 | 工程(含结算归档/增项) |
| 财务部 | **finance** 财务专员 | 财务工作台 | 财务/项目账 |
| 财务部 | **finance-lead** 财务负责人 | 财务工作台 | 财务(含退款作废/更正链)/项目账 |
| 总部设计部 | **hq-design-admin** 设计行政 | 委托队列 | 设计委托/费用政策 |

## 三、分部门界面内容设计（页面卡 × 后端关联）

> 每个页面卡格式：**页面名** → 定位一句话 → 界面区块（宽屏布局）→ 操作按钮（权限码）→ 后端 API。`fr/` 为建议路由前缀。

#### P1 经营驾驶舱（boss/owner 首页）

#### P4 提成管理（boss/owner）

#### P5 业务监督（boss/owner 只读看板组）

#### P6 审批中心（boss）

## 五、与小程序的功能边界（避免双端重复建设）

| 能力 | Web（本设计） | 小程序（保持） |
|---|---|---|
| 财务登记/对账/更正链 | ✅ 主战场（宽表+批量+向导） | 移动场景快速登记 |
| 组织人员管理/交接向导 | ✅ 主战场 | 紧急撤权随身办 |
| 经营报表/驾驶舱 | ✅ 主战场（图表） | 六格简报 |
| 客户跟进/外勤 | 列表与监督 | ✅ 主战场（拍照/定位） |
| 工程现场（拍照/质检） | 凭证审核 | ✅ 主战场 |
| 内容创作（AI 任务） | 草稿管理/归因报表 | ✅ 主战场（生成与发布） |
| 审批（费用/移交/到账） | ✅ 批量办理 | 单条随办 |

**原则：办理型重页面按数据特征分流——结构化批量操作在 Web，现场/移动/拍摄在小程序；两端共用同一 API、同一权限码、同一待办中心，任何一端办理后另一端实时一致（后端单据即真相）。**

## 六、实现路径（admin-ui 侧改造清单）

1. **登录**：登录页新增 tab「员工登录」（手机号+验证码）→ `POST /platform/auth/sms-login`；token 存储区分门户类型；请求拦截器统一附 `X-Post-Id`。
2. **岗位切换器**：顶栏组件，调 `GET /platform/my/post`；切换后重载菜单+刷新页面数据。
3. **路由组**：新增 `src/router/modules/fr.ts`（/fr 前缀扁平注册，仿 zs.ts）；`views/fr/` 目录按部门建子目录。
4. **菜单**：`projectNavigation.ts` 增加 `franchisePermissions: Record<path, 码>` 映射 + 六个 fr 分组；渲染仍走 `can(权限码)`。
5. **API 层**：`src/api/fr/` 按 Controller 分文件（finance.ts/engineering.ts/crm.ts…），与后端端点一一对应。
6. **组织开通孤儿页**：现有 `views/zs/platform-org/index.vue` 挂到 fr 组（boss/组织管理下），一并解决历史未接线问题。
