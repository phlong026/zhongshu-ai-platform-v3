# 身份配置续测与异常修复

本轮基于 Java/Web 分支 `feat/web-identity-completion-20261109` 的 `64f21fb`，承接《身份配置Web实现与验收-20261109》。小程序是另一独立 Git 仓库，本报告不代表开发版上传或真机验收。

## 复现后修复

| 场景                                               | 修复前实际结果                                                                             | 修复后复测                                                                     |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| 已选老板岗位被撤销，仍有另外两个任职，刷新人员页   | 继续读取旧 sessionStorage 权限，旧组织人员页显示加载失败、零值和管理按钮；后端已拒绝旧岗位 | 刷新先向服务端复验；撤销岗位不再出现，清除旧上下文，回到工作身份页选择有效岗位 |
| 所有任职被撤销后刷新                               | 返回短信登录表单，但没有说明原因                                                           | 明确显示“暂无有效任职，请联系组织管理员配置工作身份”；网络失败不会冒充无任职   |
| 员工业务页的访问令牌和刷新令牌均失效，确认重新登录 | 清会话后回到管理员账号密码入口                                                             | 先保留门户类型，清会话后返回员工手机号短信入口；管理员原流程保留               |

修改集中在 `admin-ui/src/store/modules/platformIdentity.ts`、`src/permission.ts`、`src/config/axios/service.ts`、`src/views/fr/platform-login/index.vue`。复用已有会话代次、服务端岗位上下文及路由；删除从缓存直接恢复权限的路径，没有新增依赖或授权模型。

四项新增行为回归均先看到断言失败，再修改并通过：缓存权限、未验证身份路由、无任职提示、过期员工入口。测试位于 `tests/platform-staff-workspace.test.js` 和 `tests/auth-tenant.test.js`。

## 浏览器续测

Chrome 独立临时用户目录 + 本地 Vite + 本地受控 HTTP 服务；手机号、令牌、组织及员工均为测试数据。真实 Vue 页面、请求层、Pinia 和路由参与测试；后端响应为夹具，不能作为真实服务授权通过的证据。

- 短信表单登录，展示三个工作身份，选老板后进入对应组织人员页。
- 新标签页有多个任职时停在工作身份页，不自动选第一个。
- 组织接口失败时显示明确错误，保留已知行；恢复后可刷新继续。
- 切换至无组织管理权限的业务员后，回工作身份页，不显示管理操作。
- 当前岗被撤、全部任职被撤、会话失效均验证上述修复前后结果。
- 岗位接口失败显示“工作身份加载失败”和重试；恢复后点击重试重新出现三个有效任职，不显示虚假的空任职。

截图、DOM 观察和请求路径记录在 `evidence/identity-continued-20261109/`。`readonly.json` 保留前一步组织接口失败的尚未消失通知，因此以当前路由、有效身份及 `managementControls=false` 判断切岗结果。没有执行真实短信、组织人员写入或外部数据变更。

## PostgreSQL 与 Controller 流程

新增 `StaffIdentityWorkflowIntegrationTest.java`，4 个流程测试覆盖：老板建部门、手机号跨组织复用账号、追加任职、本人岗位列表、精确 X-Post-Id 上下文、跨组织拒绝、撤岗、本组织停职、旧岗位失效、原手机号恢复新任职、另一组织任职继续有效。

真实部分为 OrgServiceImpl、StaffPostServiceImpl、RequestCurrentPost、Controller 组织范围及 Testcontainers PostgreSQL 17.11。账号、角色、部门目录使用既有 FakeSystemDirectory。standalone MockMvc 未组装 Method Security，**不宣称这四项测试验证了完整 `@PreAuthorize/@post` 过滤链，也未连接部署中的后端**。现有权限求值测试另行运行。
