# 设计能力契约实现设计（2026-11-11）

## 本增量边界

第一增量迁移 Java 契约、拆分融合模式适配器并修复快速预算收据重放校验。没有修改设计消费者扣点、预算价格计算、数据库 schema，也没有实现或启用新的 HTTP provider、远程客户端或 HMAC 认证链路。

`design-capability-api` 的 Maven 坐标是 `cn.iocoder.boot:design-capability-api:${revision}`。原 Java 契约沿用 `yudao-common` 的 `ErrorCode`；测试使用项目既有 JUnit Jupiter。根 POM 模块注册由构建 lane 负责。

并行 HTTP 契约 lane 后续增加 `CapabilityJson`，因此按协调要求显式声明项目既有 `jackson-databind`，版本继续由 BOM 管理，与现有 `JsonUtils` 使用同一 Jackson 系列（本次解析为 2.21.7），没有新增版本或引入另一套 JSON 库。该类实际只用 core/databind/node，不需要另加 datatype 依赖。与最初纯契约建议的差异是本模块现在还承载轻量 JSON codec；仍不依赖 design/franchise 业务实现，原 25 方法及 record 不受影响。

## 兼容的 Java 契约

`DesignServicePort.java` 和 `FranchiseDesignErrorCodes.java` 从 `domains/franchise/franchise-api` 原样迁入新模块，package 仍为 `cn.iocoder.yudao.module.franchise.api`。25 个方法的名称、参数顺序及类型、返回类型，26 个 record 的字段名称、顺序、泛型类型及公开构造方法，以及 4 个错误码均保持兼容。

`DesignServicePortContractTest` 用显式方法签名矩阵验证全部方法，用显式 record component 矩阵验证构造兼容性；不是只检查方法数量。`franchise-api` 传递依赖新模块，旧消费方的 import 不变。`yudao-module-design` 直接声明新模块依赖，同时保留 `franchise-api`，因为融合模式资产桥接仍需 `AssetAccessPort`。`AssetAccessPort` 不迁入设计能力模块。

## 融合模式的资产桥接

`FranchiseDesignAdapter` 只实现 `DesignServicePort`。新增 `LegacyAssetAccessAdapter` 实现 `AssetAccessPort`，将三个返回 DTO 的同名字段逐项转换；状态、拒绝原因、可空到期时间与异常透传不变。

资产上传调用原五参数 `createUploadTicket(serviceAccountId, assetType, mimeType, sizeBytes, sha256)`，继续进入 `AssetService.createServiceTicket` 的 B_END 类型权限校验。不能调用接受 `DesignServicePort.UploadTicketCreate` 的 C_END 重载。原公开 `assetTypeOf`、`validateReference`、五参数上传辅助方法保留，只移除已不属于接口实现的 `@Override`。

两座旧桥接统一使用 `platform.legacy-design-bridge.enabled=true`，并设置 `matchIfMissing=true`，保持融合模式默认行为。平台 B 显式设置 false，而且构建产物不得加载旧 `yudao-module-design`；关闭 bean 的开关不能替代依赖隔离。B 的配置及依赖隔离由构建 lane 验证。

历史财务文件回退采用全局资产 ID 存在性判定。只要旧 `asset` 表存在该 ID，无论属主、软删除或审核状态，都禁止按历史文件 ID 回退；只有全局不存在资产记录时才允许消费方继续验证历史文件的 tenant、org、MIME。不能将 `assetTypeOf(account,id)==null` 视为全局不存在，否则跨组织资产或已删除资产可能撞到同 ID 的历史文件。

后台内容任务使用新增的 `AssetAccessPort.createTaskDownloadUrl(orgId, assetId, requiredType)`。旧桥接显式实现该方法，以已持久化任务的 orgId 调用 `StoreServiceAccountPort.requireServiceAccount(orgId)`，再委托已有受控下载方法验证资产类型、属主与 ACCEPTED 状态后签发 URL。账号停用异常继续透传，账号解析失败时不访问资产。该入口没有新增 HTTP 暴露，B 实现的可信组织目录与既有映射恢复由资产 lane 负责。

## 快速预算收据修复

原 `createEstimateReceipt` 在首次查到已有收据时直接返回结果，绕过 `createEstimate` 的请求属主和 `request_hash` 校验。真实 PostgreSQL 测试确认，同 key 修改 buildingArea、projectId、region、structure、material 或 resultVersionId，都会错误返回旧结果；替换为其他账号的 projectId 同样未被拒绝。

两个公开入口现在共用原 `createEstimate` 的事务实现，并返回内部 `EstimateCreation(Estimate, replayed)`。保留原请求字段及插入顺序、JSON 序列化、SHA-256、`INSERT ... ON CONFLICT DO NOTHING` 和 `SELECT ... FOR UPDATE`。没有生成第二套 hash，没有变更历史收据指纹。

重放标记在同一收据行锁内判定。并发首请求只返回一次 `replayed=false`，其余返回同结果且为 true，避免调用方重复落审计。属主不匹配仍返回原资源权限错误；同 key 改参返回原 409。完全相同的成功请求在价格规则停用后仍可重放，不再次报价或扣点。

## 扩展 HTTP DTO 的约定

后续 HTTP 协议使用独立 DTO，不向上述兼容 record 追加必填参数。请求信封至少显式携带以下字段。

| 字段 | 语义与校验边界 |
| --- | --- |
| caller | 已注册服务调用者身份；必须与认证身份一致，不能直接信任 JSON 自报值。 |
| org | 租户及组织上下文；服务账号映射由能力方核验，不能任意选择其他组织的 serviceAccountId。 |
| actor | 实际操作者快照（userId、postId、roleCode 等）；与 caller、org 及操作权限一致，用于审计。 |
| operation | 稳定的操作标识及允许操作白名单；与实际路由匹配，禁止任意方法分发。 |
| requestKey | 同一业务意图在超时、断线、重试时保持稳定；不能每次生成新 key，否则会重复创建或扣点。 |
| nonce | 每次传输尝试使用新值；用于传输防重放，与业务幂等 requestKey 分开。 |
| payload | 对应操作的业务字段；金额、面积、结果版本及项目 ID 等参与既有业务指纹。 |

同一次业务重试保持 requestKey 与 payload 不变，更换 nonce；nonce、请求时间及传输签名不进入业务请求指纹。响应仍携带能力方在事务内产生的 result 与 replayed。外部超时后先按原 requestKey 恢复结果，禁止无依据地发起新业务请求。

HTTP provider 必须默认关闭（拟定开关 `design.capability.provider.enabled=false`）。开启前需独立安全评审 caller/org/actor 绑定、操作授权、稳定请求 key、nonce 存储原子性、时钟窗口、密钥轮换、规范化、签名原文、错误码和审计策略。纯契约/认证工具的其他 lane 工作不代表 provider 已可开启。本增量不实施新 HMAC，不上线远程设计调用。
