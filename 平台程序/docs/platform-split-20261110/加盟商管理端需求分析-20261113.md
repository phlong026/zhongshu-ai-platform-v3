日期：2026-11-13。版本：**R3（第二轮修订，闭环 Codex 复核 6 项 P1 残余 + 1 项 P2 残余；R2 已闭环首轮 16 条）**。性质：**最终需求文档（范围内讨论与排期依据）**。
分析对象：B独立后端（`yudao-platform-server`，48080，B仓 worktree platform-split-20261110，分支 `feat/platform-split-docker-20261110@935d3fe1`）+ V小程序（zhongshu-ai-platform-v3 worktree platform-split-20261111，**分支 `feat/platform-split-wallet-20261111@41e5cb42`**）+ admin-ui（/zs 总部 Web 与 /fr 加盟商 Web）。
写作口径：全部现状结论来自本机源码直读（路径见附节证据索引）；后端能力以控制器/服务实际签名为准，**不虚构接口**；待新增/待扩展后端的项一律标注"**需新增后端**"或"**后端契约扩展**"。

## 〇、核心判断与结论摘要

1. **三层形态定型**（对标行业通用模式，见 §二）：总部运营 Web（/zs，已上线）+ **加盟商管理 Web（/fr 门户，本文补齐对象）** + 员工/老板小程序（V，业务面已在线）。
2. **手机优先原则**：四个职能业务（工程/财务/销售/内容）的使用场景大部分发生在在线现场（工地/门店/移动）→ 手机端优先；Web 只收 PC 刚需（核对/导出/批量/看板）。
3. **R2 关键修正——后端并非"零新增"**：
   - FinanceController 现有列表查询**仅收 status、返回未分页 List**，不支持期间/项目/类型组合筛选——Web 财务核对页依赖**后端查询契约扩展（P0 前置）**；
   - 经营 analytics 返回**财务趋势/构成/余额/账龄**，不含新增客户/设计委托/工程节点——看板非纯复用（P1，数据源需扩展）；
   - **权限链是 P0 前置**：current-context 仅暴露组织查询/管理权限、/fr 路由被统一按 `platform:org:query` 过滤（财务岗缺菜单）、钱包 read 权限未默认授予财务岗、岗位头注入范围不含 /platform/wallet/；
   - 银行流水生产导入端点不存在（注入仅 dev/e2e）——银行对账移出 P0。
4. **P0 收敛**（§四）：财务核对页（含契约扩展）+ 必要导出 + 异常资金提示 + 权限链前置；经营看板与批量导入降 P1（按首批迁移规模定）；Web 财务页 P0 只读核对，**不含 POST 登记类操作**。
5. 导入事务语义为产品决策项，R2 采认：**服务端预检 + 逐行错误报告 + 部分成功（成功 n 失败 m）+ 单批上限 500 行**（§三.8 导入事务语义行）。

## 二、对标同行：加盟商管理端通用形态（行业通用模式）

> 以下为连锁/加盟 SaaS 行业通用模式归纳（美团开店宝、瑞幸合伙人、有赞连锁等公开常识性归纳；乡墅同业同理）。**未做竞品逐项实测，具体功能名不作为需求依据。**

1. **三层后台形态**：总部运营 Web（钱包/计费/组织开通/审计——对应 /zs 已上线）+ **加盟商老板 Web（财务核对、报表导出、批量操作、经营看板四类 PC 刚需）** + 员工小程序（现场作业/审批/消息）。
2. **PC 刚需四类**：财务核对（流水↔单据核对、大表筛选）、报表/流水导出（给会计税务）、批量操作（员工/客资批量建档）、经营看板（跨项目聚合）。
3. **乡墅行业特殊性**：单店单量少、客单价高、工期长 → 老板高频关注项目级收支（小程序已有），低频关注月度核对与报表（Web 补齐对象）。
4. **推论**：加盟商管理端 = 小程序（既有，增强）+ /fr Web（PC 刚需页）；不复制总部 /zs 全量运营面。

## 三、缺失功能分析（逐职能）

类别口径：〔A〕后端有 API 但前端无入口；〔B〕前后端都缺（标"需新增后端"）；〔C〕**后端契约扩展**（现有端点不满足 Web 使用形态，需改造而非新页面）。

### 3.1 后端查询契约扩展（P0 前置，财务页的前置条件）

**〔C〕FinanceController 列表查询不满足 Web 核对场景**（FinanceController.java 逐表实证）：

| 账表 | 现有端点 | 现有筛选参数（实证） | 返回形态 | 日期口径字段（DO 实证） |
|---|---|---|---|---|
| 实收 receipts | GET /franchise/finance/receipts | status（可选） | 未分页 List | receivedDate（业务日期）/ registeredAt（登记时间） |
| 应付 payables | GET /franchise/finance/payables | status（可选） | 未分页 List | **无业务日期字段**（仅 createTime） |
| 付款 payments | GET /franchise/finance/payments | status（可选） | 未分页 List | payDate |
| 退款 refunds | GET /franchise/finance/refunds | **receiptId（可选，按原收款单过滤）**——非 status，与其他三表不一致 | 未分页 List | date |
| 异常资金 | GET /franchise/finance/abnormal-funds | status + datePendingOnly | 未分页 List | businessDate |

- 通用缺口：四表均无 `pageNo/pageSize`、期间区间、项目、类型组合筛选；Web 大表核对必须服务端分页+筛选。
- 小程序 finance-desk 现状是全量拉取后本地分页（PAGE_SIZE=100），数据量小可行，不受影响。
- **需求（逐表承诺）**：
  - 实收：`pageNo/pageSize + status + receivedDate 区间 + projectId + method/sourceType + keyword`；
  - 付款：`pageNo/pageSize + status + payDate 区间 + projectId + keyword`；
  - 退款：`pageNo/pageSize + status + date 区间 + receiptId（保留既有语义）+ refundDirection（client/expense）`；
  - 应付：`pageNo/pageSize + status + projectId + keyword`；**应付当前无到期日字段（FinPayableDO 实证：id/companyId/projectId/stage/totalCents/recipient/status/agreementRef/createTime）——Web 页与导出不承诺"到期日"列/筛选**；如需到期日管理须后端加列（独立需求，不在本期）；
  - 统一形态建议新增 `/franchise/finance/xxx/page` 端点（保持旧端点兼容小程序，避免双端回归）。**列为 P0 前置后端项。**

### 3.2 财务

对账口径（FinReconciliationService.MonthReconciliation 实证）：`GET /franchise/finance/reconciliation?month=YYYY-MM` 返回 **month、grossReceiptsCents（毛实收）、clientRefundsCents（客户退款）、netReceivedCents（净实收）、abnormalPendingCents/Count（异常资金待关联）、abnormalDatePendingCents/Count（待归月）**——注意：**该口径为"实收现金"口径，应付/付款不混入**；Web 页字段命名须以此为准（初稿"应收/实收/差额"表述有误，R2 更正）。

| 功能 | 现状 | 类别 | 建议归属 | 理由 |
|---|---|---|---|---|

## 九、原则与边界（重申）

1. **停写体系**：旧融合进程 FROZEN；B 进程写自身库合法——新页面（admin-ui /fr + B 后端新端点）均在 B 闭包内实施。

4. **不虚构**：竞品细节标注"行业通用模式"；页面计数口径（app.json 34 注册页）在 §1.2 说明。
5. **文档性质**：R3 修订版为最终需求文档；实施前 P0 三项后端前置（权限链/查询契约/导出定义）需评审签字。
