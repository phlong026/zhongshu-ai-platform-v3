# 门店老板与员工统一账号

## 账号归属

总部开通加盟门店组织及首位老板账号；老板或门店负责人在本组织开通员工的独立账号和岗位。门店组织不是供所有人员共用的登录用户。每个人的密码、微信、跨门店任职都关联同一个 `system_users.id`，业务与积分继续按组织和岗位鉴权。

生成的 `hjmz-…` 是正式对外登录别名。内部底座 username 保留现有格式和编号；所有正式账号及简称只定位已有用户，不另建用户或钱包。一个人有多个门店身份时密码仍只有一份。

## 总部开通字段

品牌固定为合家美宅；省、市从现有地区树选择；门店片区、老板姓名、老板手机号必填；备注选填。系统规范省市和区县后缀，生成显示名和账号。片区/姓名拼音可人工校正多音字。

示例：江西省、南昌市、高新区、李忠 → `合家美宅-江西南昌-高新-李忠`，首次地区账号 `hjmz-jxnc-gaoxin`；冲突时新账号追加 `-lizhong`，仍冲突追加 `-2` 等序号，原账号不改名。省份代码使用固定表，城市默认拼音首字母并校正已知多音地名。不同地区可能同缩写，最终以全租户唯一账号和候选名称区分。

同名门店重复提交、并发提交复用同一记录；换手机号重复提交同名门店拒绝，不静默追加另一老板。手机号对应唯一现有用户时复用，不重设密码；历史重号不能唯一确定时拒绝自动合并。

老板新增员工时账号使用门店账号前缀加员工姓名拼音，例如 `hjmz-jxnc-gaoxin-zhangsan`；同名加序号，支持 `zhangsan`、`zs` 等简称。存量门店尚无结构化地区资料时，员工账号使用 `hjmz-store<组织编号>-<姓名拼音>`，不阻断原门店加人；后续补门店资料也不改已交付账号。

## HTTP 契约

以下路径均在 `/admin-api` 下；请求携带现有 `tenant-id`。登录匹配无需岗位，员工开通必须携当前有效 `X-Post-Id`。

| 接口 | 权限与输入 | 输出 |
|---|---|---|
| `POST /platform/org/franchise-preview` | `platform:org:onboard`；brand/province/city/area/adminName，选填 areaPinyin/ownerPinyin | orgName/loginName/aliases/areaPinyin/ownerPinyin；预览不占号，最终以正式响应为准 |
| `POST /platform/org/franchise-onboard` | 同上，加 adminMobile，选填 remark | orgId/adminUserId/postId/reusedOrg/reusedUser/accountId/orgName/loginName/aliases/initialPassword/requiresPasswordChange |
| `POST /platform/org/staff-accounts` | 当前组织老板/负责人且 `platform:org:manage`；orgId/name/mobile/roleCode/teamId，历史同号时选填 userId | 保留 StaffRow 字段，附 accountId/orgName/loginName/aliases/initialPassword/reusedUser |
| `POST /platform/auth/account/matches` | 匿名；query，2–100字，支持账号/拼音/简称/中文姓名 | items[{accountId,loginName,orgName,ownerName}]、hasMore；最多20项，不返回手机号 |
| `POST /platform/auth/account/login` | 匿名；accountId/password，首次改密选填 newPassword | 首次 `requirePasswordChange=true` 且无令牌；改密或普通登录成功后返回现有平台 userId/token、preferredPostId 和账号展示信息 |
| `POST /platform/auth/wechat-bind` | 已登录；appid/loginCode | 绑定当前用户，成功返回 true；不创建用户，不抢绑他人微信 |

`ownerName` 在候选响应中表示账号持有人姓名，员工账号返回员工姓名。首次新密码为10–64字符、含ASCII字母和数字、UTF-8不超过72字节，不能等于初始密码。首次改密通过用户级行锁复核，同人多门店不能并发覆盖密码。

账号密码错误按租户和用户累计，5次锁15分钟；更换别名不能绕过，同IP其他账号不受影响；微信、心跳和退出不消耗密码失败预算。匹配后的选择不构成认证。

## 一次性交付与默认选择

初始密码随机生成16位，新用户开通响应仅返回这一次；数据库只保存BCrypt 10哈希。重复开通、追加岗位或复用用户不回显旧密码。后台和老板成员页仅在页面内存展示交付信息，切换、离页或重新提交清除；复制成功回执才提示成功，不写浏览器或小程序持久化。

小程序默认账号仅保存本机账号ID和展示名称，成功获取有效任职后才保存。不保存密码、不跨设备同步、不免密；用户可切换或清除。查询、账号登录、微信登录、岗位加载及绑定共享取消代次；无有效任职清理平台会话，不回到旧本地身份。

微信已有绑定仍直接进入原用户；未绑定时先登录已有账号，再用新的 `wx.login` code 显式绑定。绑定失败保留已认证账号，可重试或先进入工作台。旧短信接口只保留后端兼容，新页面不再提供短信登录入口。

## 发布前存量核对

本次不自动改名、合并或重置存量用户。切换新登录页前，总部须核对每个在用老板/员工至少具有可用账号密码或已有微信绑定，补齐登录别名。已知原密码沿用；不知道原密码且未绑定微信的账号，由拥有相应权限的总部人员主动办理现有密码重置并交付，不能由本次迁移静默重置。未完成此项核对不能宣称存量账号切换验收通过。

本次未访问生产或处理真实账号；部署、存量核对、微信真实外呼及手机验收分别留证。

## 拼音数据来源

随制品附带Unicode/ICU默认汉字读音表与许可证，不新增运行时依赖。生成脚本为 `script/generate-franchise-pinyin.py`，需要维护机已有 ICU uconv。自动读音可能存在多音字，开通预览必须由管理员核对并按需校正。
