# 加盟商开通与统一账号登录

范围：独立 B 后台开通、小程序账号密码登录、账号简称匹配和当前设备默认选择、显式微信绑定。沿用 system_users 用户、有效任职与既有令牌；不访问生产、不迁移 A 数据、不新增依赖。

## 实现顺序

1. 先锁定命名、重名、账号复用、首次改密、微信同用户的行为测试。
2. 新增加盟商资料和登录别名记录，固定字段开通，现有组织及账号不改编号、不重置旧密码。
3. 总部开通表单和一次性凭据复制；小程序多候选选择、默认选择、首次改密与微信绑定。
4. 静态检查、模块集成回归、前端构建、独立只读审查、回滚检查、分别提交两仓库。

## 验收

- 合家美宅、江西、南昌、高新、李忠生成标准显示名和账号；同区域追加老板拼音，仍冲突加序号，原账号不改名。
- 多个别名指向同一用户；一个老板开多个组织保留原密码和数据。
- 初始密码仅新用户开通响应可见，不进入数据库明文、访问日志或浏览器/小程序持久化；用户主动复制到剪贴板用于交付。
- 简写多候选必须明确选定；匹配只展示名称与账号，不回手机号。
- 默认选择只保存本机账号标识，密码不持久化；迟到请求不覆盖新输入或新会话。
- 首次改密前不签发账号登录令牌；错误密码预算按用户而非 IP；停用/撤岗拒绝登录。
- 微信已有绑定直接进入同用户；首次显式绑定验证当前用户，拒绝抢绑他人微信，不自动注册第二账号。
- PostgreSQL 集成检查命名冲突、并发/重试、租户隔离、回滚；前端行为检查错误、取消、切换和重复点击。

## 回滚

本次仅新增业务表和接口。撤回代码前备份三张新增表，停用新登录入口；保留 system_users、pf_staff_post 和微信绑定及已生成数据。已有账号凭据产生外部副作用，不能只删除新增表宣称恢复。undo 迁移在新增表非空时拒绝执行。
